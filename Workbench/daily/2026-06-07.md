## 论文点评

### MobileGym
- **Title**: MobileGym: A Verifiable and Highly Parallel Simulation Platform for Mobile GUI Agent Research
- **Institutes**: 未公开（GitHub 主要作者：Purewhiter）
- **Source**: [link](https://arxiv.org/abs/2605.26114)  🔥 HF Trending ⬆️ 64   **📒 论文笔记**: [[2605-MobileGym]]
- **核心**: 浏览器托管的轻量级 Android 模拟平台，用 JSON 状态检查替代视觉/LLM judge 实现确定性评估，单机支持数百并行环境（~400MB/实例，3秒启动），专为 mobile GUI agent 的 RL 训练设计。GRPO 训练在 256-task test set 上 +12.8pp，真机迁移保留 95.1% 增益。覆盖 28 个应用（微信/支付宝/bilibili/Reddit 等）的 416 个任务模板。
- **锐评**: **好的部分**——state-based judging 直击痛点，vision judge 噪声大、LLM judge 贵且不稳定，用 JSON 状态做 ground truth 是正确的 first-principles 思路；95.1% sim-to-real retention 证明 functional modeling 抓住了本质，资源效率（单机数百环境 vs 真机几乎无法并行）让 mobile agent 的 online RL 从"不可能"变"可行"，这是基础设施级突破。**但硬伤也明显**——functional modeling 的 fidelity 边界在哪？59-task real-device subset 太小，无法证明长尾 corner case 的 sim-to-real 泛化；416 个任务模板全靠人工，scalability 存疑；真实 app 持续更新，模拟器维护成本被低估了。更关键的是，state-based judge 只适合 closed-loop 明确目标任务，open-ended exploration 怎么办？**最大风险是"模拟器刷分陷阱"**——agent 可能过拟合到简化后的 backend logic，真实世界的视觉噪声、网络延迟、UI 变化会让性能崩盘。95.1% 听起来漂亮，但 59-task 样本量根本不够建立信心。
- **Rating**: `3` 🔥，基础设施价值大（让 mobile RL 研究从0到1），但 sim-to-real 的 generalization 证据不足，需要更大规模真机验证才能确认不是"精致的玩具"

### Multi-Agent Computer Use
- **Title**: Multi-Agent Computer Use
- **Institutes**: Carnegie Mellon University
- **Source**: [link](https://arxiv.org/abs/2606.01533)  📰 HF Daily ⬆️ 6   **📒 论文笔记**: [[2606-MACU]]
- **核心**: 提出 Manager-Subagent 架构，将复杂 GUI 任务分解为 DAG 并行执行。Manager 负责规划和动态调整，多个 Subagent 并行操作界面。OSWorld +3.4%，WebTailBench +25.5%，长任务 wall-clock 时间缩短 1.5 倍。
- **锐评**: 思路简洁但不新鲜——DAG 任务分解在 planning 领域已是老套路，这里只是套在 CUA 上。最大的问题是**性价比不明**：论文炫耀 wall-clock 时间缩短，却刻意回避了 API 调用成本对比。Manager + 多个并行 Subagent 意味着更多 LLM 调用，实际生产中可能花 3 倍钱只换 1.5 倍速度。OSWorld 只提升 3.4%，说明桌面任务并行性有限，收益被高估了。WebTailBench +25.5% 倒是亮眼，但这个 benchmark 本身就是为长程任务设计的，cherry-pick 的嫌疑大。缺少 subagent 数量、并行度的消融实验，超参怎么调全凭玩家运气。失败案例分析几乎没有——DAG 规划一旦出错，下游 agent 会不会集体翻车？这种级联失败比单 agent 卡住更危险。Test-time scaling 听起来美好，但只要 Manager 不 scale，瓶颈永远在那。结论：**工程上是个优化，科学上缺洞察**。适合已经有钱烧的团队尝鲜，不适合当作突破性工作引用。
- **Rating**: `2` 👀，思路合理但缺乏深度，性价比和失败模式分析缺失，更像是工程优化而非方法创新

### GrepSeek
- **Title**: GrepSeek: Training Search Agents for Direct Corpus Interaction
- **Institutes**: 未知（网络限制未获取）
- **Source**: [link](https://arxiv.org/abs/2605.29307)  📰 HF Daily ⬆️ 102   **📒 论文笔记**: [[2605-GrepSeek]]
- **核心**: 用 grep、file read 等 shell 命令训练 search agent 直接操作原始文本语料库，完全抛弃 embedding 模型和向量索引。两阶段训练（cold-start dataset + GRPO）解决大规模语料库上 RL 训练不稳定问题，让紧凑型 agent 能找到、过滤、组合证据。
- **锐评**: 理念够激进——回归 Unix 哲学用最简单工具，但**语义鸿沟是硬伤**：grep 只匹配字面文本，遇到同义词、paraphrase 就瞎，这在真实信息检索场景是致命缺陷。效率更可疑：向量索引是 O(log n)，grep 全文扫描是 O(n)，百万级文档怎么撑？论文没给与 BM25/dense retrieval 的 head-to-head 对比，缺这个 baseline 就是在回避核心问题。GRPO 稳定训练有价值，但整体像是把 2000 年代的文本搜索重新包装成 agent，novelty 存疑。适用场景极窄：小规模结构化文本可能有戏，通用检索是痴人说梦。
- **Rating**: `3` 🔥，激进回归 Unix 工具但语义能力天花板低，适合小规模结构化场景但难以泛化

### TASTE
- **Title**: A Matter of TASTE: Improving Coverage and Difficulty of Agent Benchmarks
- **Institutes**: 未获取（疑似 Google DeepMind / UC Berkeley 相关）
- **Source**: [link](https://arxiv.org/abs/2605.28556)  📰 HF Daily ⬆️ 63   **📒 论文笔记**: [[2605-TASTE]]
- **核心**: 现有 agent benchmark（WebArena、SWE-bench）分数虚高、覆盖度窄，TASTE 用自适应对比 n-gram 建模工具序列 + 迭代难度提升，自动生成高覆盖、持续挑战的 benchmark 任务，目标是让评估跟上 agent 进化速度
- **锐评**: 问题抓得准——Berkeley RDI 已实锤 WebArena/SWE-bench 可被 game 到接近满分但不干活，benchmark 饱和是真痛点。但方法细节缺失让人起疑：LLM-judged validity 会不会把 LLM 自己的偏差烙进 benchmark？n-gram 建模工具序列听起来聪明，但长依赖怎么办、复杂 task graph 能覆盖吗？最致命的是 ecological validity——自动生成的"难题"到底是有意义的真实任务，还是只是给 agent 设的聪明陷阱？没实验数字、没 case study，说服力为零。这论文像是把 "benchmark 要动态生成" 这个正确废话包装了一层技术黑话，承诺很大但兑现存疑
- **Rating**: `2` 👀，方向对但证据不足——benchmark gaming 是真问题，自动生成是对路子，但没全文就敢上 HF Daily？要么是实验亮瞎眼但我没看到，要么是靠 motivation 骗流量

### COLLEAGUE.SKILL
- **Title**: COLLEAGUE.SKILL: Automated AI Skill Generation via Expert Knowledge Distillation
- **Institutes**: Shanghai Artificial Intelligence Laboratory
- **Source**: [link](https://arxiv.org/abs/2605.31264)  📰 HF Daily ⬆️ 109   **📒 论文笔记**: [[2605-ColleagueSkill]]
- **核心**: 从异构专家痕迹（聊天记录、代码审查、访谈）自动蒸馏出 person-grounded skill 包，包含能力轨（mental models、决策启发）和行为轨（交流风格、交互规则）双轨表示。开源系统支持跨 agent 移植、版本化更新、结构化检查。在中国科技圈引发热议，MIT Technology Review 报道反映职场 AI 替代焦虑。
- **锐评**: 切入点新颖但证据薄弱到令人不安。论文**完全没有 benchmark**——没有成功率、没有任务完成度、没有 skill 质量量化评估，只有"开源了"和"上新闻了"。SkillsBench 已证明 self-generated skills 常带来**负迁移**，且"强提取器≠强消费者"，本文对失效模式视而不见。更致命的是：从"messy real-world traces"提取 mental model 的核心技术**语焉不详**，如何区分表面行为模式与深层决策逻辑？如何验证蒸馏出的 skill 真实反映专家思维而非过拟合特定工作流？全无着落。双轨设计（能力+行为）在概念上清晰，但 trace 质量依赖、跨场景泛化能力、skill 粒度控制等工程现实问题均未触及。4 小时快速原型的工程故事很酷，但这更像一个引发社会讨论的**概念验证 demo**，而非经过严格验证的研究贡献。系统自己都承认"无法捕获完整人类专业知识"，那它到底捕获了什么、漏掉了什么、什么时候会翻车？一概成谜。
- **Rating**: `2` 👀，有趣的方向但缺乏实证支撑，当前更像是引发讨论的概念原型而非可靠的技术方案

### Crafter
- **Title**: Crafter: A Multi-Agent Harness for Editable Scientific Figure Generation from Diverse Inputs
- **Institutes**: Tsinghua University, Microsoft
- **Source**: [link](https://arxiv.org/abs/2605.30611)  📰 HF Daily ⬆️ 192   **📒 论文笔记**: [[2605-Crafter]]
- **核心**: 提出 multi-agent harness 架构生成跨类型、跨输入条件的科学配图。核心是 structured specification（typed edits 直接修改字段，避免 free-text prompt 累积矛盾）+ directive critic（per-dimension 诊断而非 scalar score）+ diversity-driven plan exploration（$K$ 个候选 plan 并行渲染）。配套 CraftEditor 将 raster 转 editable SVG（instruction-driven extraction + iterative composition）。在 PaperBanana-Bench 和新提出的 CraftBench（279 samples，3 types，4 conditions）上全面领先，Crafter 比 standalone generator 提升 30+ 点，比最强 agentic baseline PaperBanana 提升 16-22 点，CraftEditor 比 AutoFigure-Edit 高 1.13 分（8.04 vs 6.91/10）。
- **锐评**: 方法上 harness abstraction（D/E/V/R 四角色 + evolving spec）是实在的贡献，typed edits 解决 iterative refinement 的 prompt drift 问题（ablation 显示 w/o corrective layer 掉 8.90 点最多），但论文**没给完整 edit schema**——如果 edit types 需要人工设计 per figure type，"prompt-level adaptation 即可跨类型泛化" 的说法就站不住脚。实验上唯一在所有 dimension/task 全面超越 backbone，PaperBanana 在 CraftBench 上增益从 22.60 崩到 8.10、sketch task 甚至低于 baseline，暴露单任务优化的脆弱；但**对比有水分**——baseline 都换成 Nano Banana 2 以 "isolate orchestration"，削弱了与 original systems 的可比性。CraftBench 样本量偏少（279），text-to-image 占 64%，reference-conditioned tasks 仅 30-40 samples，infographic 只有 30。最大硬伤是**成本未报告**——$K$ plan 并行 + $T$ 轮 refinement，worst-case latency 和 API cost 会是 one-shot 的多少倍？没有 cost-quality trade-off 分析，工业落地存疑。Harness pattern 有潜力迁移到 scientific writing、UI design 等 structured domains，但当前 implementation 高度 domain-specific（layout constraints、arrow endpoints），泛化性待验证。
- **Rating**: `3` 👀，方法扎实（typed edits + directive critic 是可迁移 pattern），实验全面（唯一全维度全任务领先），但 edit schema 不透明、成本不报告、benchmark 覆盖有限，落地价值打折扣

### K-BrowseComp
- **Title**: K-BrowseComp: A Web Browsing Agent Benchmark Grounded in Korean Contexts
- **Institutes**: Prometheus-eval team
- **Source**: [link](https://arxiv.org/abs/2606.02404)  📰 HF Daily ⬆️ 53   **📒 论文笔记**: [[2606-KBrowseComp]]
- **核心**: 首个韩语 web browsing agent benchmark，包含 300 道人工验证题（多跳推理/并行约束）+ 100 道 AI 生成的对抗性测试题。GPT-5.5 在验证集上仅 45.67%，韩国政府巨资打造的本土模型更是惨不忍睹：K-EXAONE 10.33%、HyperCLOVAX 2.33%——在本国语言的 agent 任务上接近白卷。
- **锐评**: 这就是个"BrowseComp 韩语版"，方法论零创新。Synthetic generation？用 GPT 生成题再用 GPT 过滤，这不是 train-test leakage 是什么？更致命的是，论文完全没做语言 vs. 推理能力的解耦——韩语模型的低分到底是因为韩语理解差还是 web browsing 能力差？一个翻译对照实验就能回答，但作者选择性失明。韩国本土模型的数字确实震撼（2.33% 能发出来也是勇气可嘉），但这不能证明 benchmark 质量高，只能说明要么模型烂要么题目设计偏向特定网站结构。400 题的规模在 2026 年也太寒酸，覆盖度存疑。唯一有点意思的是 failure taxonomy 驱动的对抗生成思路，但这在 adversarial NLI 等领域早就玩烂了。对非韩语研究者价值接近于零，对韩国 AI 社区是个警钟但药方在哪？
- **Rating**: `2` 👀，填补了韩语 agent evaluation 的空白，但方法平庸、通用性差，更像是 localization work 而非研究突破
