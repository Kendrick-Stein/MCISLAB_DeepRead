### LIT
- **Title**: Breaking the Vision-Action Shortcut: Latent Interface Training for Generalizable Robotics Foundation Models
- **Institutes**: South China University of Technology, National University of Singapore, Nanyang Technological University
- **Source**: [link](https://arxiv.org/abs/2609.12641)  📰 HF Daily ⬆️ 37   **📒 论文笔记**: [[2609-LatentInterfaceTraining]]
- **核心**: 把 VLA/WAM 在视觉分布偏移下的崩塌归因为 action expert 直接消费 visual token 学到的 vision–action shortcut，对策是换"接口"而不换模型。Stage 1 冻结 backbone、完全不给图像，只用 language + robot state + 每个 action chunk 终点的 SE(3) 末端位姿 `g_t ∈ R^8` 从零训练 action expert；Stage 2 让 K=100 个 latent token 成为 action expert 的**唯一**视觉通路，并用 MLP decoder 从这些 token 重建同一个 `g_t`（λ_pose=0.3）作监督。推理时 pose encoder/decoder 全丢，不需要 goal pose，部署零额外输入。在 π0.5 / MolmoAct2 / FAST-WAM / ImageWAM 四架构上 LIBERO-Plus zero-shot overall +3.87~10.70pp，28 组"架构×扰动"赢 26 组，LIBERO 分布内四架构平均全部不降；真机三任务 ID 74.7→88.0、三种 OOD 各 +13.3~16.7pp。
- **锐评**: 先说真正值钱的一块：**这篇的消融表是按"证伪简单解释"设计的，不是按"逐个拆零件"设计的**，这在 VLA 圈里罕见。三条替代设计——纯 latent token 聚合（≈VLA-Adapter 式 Q-Former）65.70、LA4VLA 式两阶段 65.46、baseline 直接加 pose 监督 65.45——全部卡在比 baseline 高约 2pp 的位置，离完整 LIT 的 71.92 差 6pp 以上，把"你这不就是个 Q-Former / 不就是两阶段 / 不就是个辅助 loss"三种 rebuttal 一次性挡死。更漂亮的是 `w/ direct visual access` 那一行：保留 Stage 1、pose 监督和 latent interface，只是**额外**放开 action expert 到视觉表征的直连，ID 反升到 94.25、OOD 掉 4.18pp——ID/OOD 的反向剪刀差，是全文唯一干净的机制证据，说明关键在通路的**排他性**而非信息量。LIBERO-Plus 跑满 10,030 个扰动实例而不是别家那种"每任务 1 episode"，这个采样量级下 +8pp 不是噪声。作者还主动声明 baseline 不微调预训练 policy checkpoint、数字与已发表结果不可比——诚实，但也把刀递到了自己手上。

  现在说硬伤。**第一，真机部分是被摘要抬举了的**：每个 OOD 条件只有 30 次 rollout，所谓 "+16.7pp under Camera OOD" 就是 9/30 对 14/30，5 次成功的差别。笔记作者按报告数字反推计数做的 Fisher 精确检验（**论文未报任何检验，这是笔记作者自算**）显示三个 OOD 条件单独看没有一个到 p<0.05，合并才 p≈0.052。更糟的是真机 baseline 在**分布内**就落后 13.3pp（Transfer egg ID 仅 52.0），两个策略总体能力都不相等时，"OOD 更鲁棒"和"整体更强"根本分不开；笔记作者做的保持率归一化（同样是自算，非论文报告）方向仍对但幅度大幅收窄，Distractors 只剩 +5.0pp。**第二，最便宜的对照一次没跑**：color jitter / random crop / 视角抖动这种 domain randomization 是视觉 OOD 的一线手段，成本接近零，论文完全没比；Related Work 里点名的 OREO、Selective Visual Representations 也只引用不实现。这是最该补、也最容易补的实验，不补就无法回答"这套两阶段训练到底值不值"。**第三，机制主张的直接证据全是定性图**，Fig. 4 的注意力可视化和 Fig. 5 的反事实轨迹都没有任何量化指标，论文自己措辞停在 "suggest"/"consistent with"——克制值得肯定，但从 OOD 涨点到"shortcut 被削弱"这一步，本文只给了相关性，没给因果。**第四，无 seed、无误差棒、无附录**，每个配置训一次，于是 Table III 里 `w/o Stage 1` 68.23 与 `w/o pose supervision` 68.86 那 0.63pp 的排序纯属不可读。**第五，K 从头到尾没扫过**，`m` 和 token 维度 `d` 论文正文根本没给（README 里补的 `d=768`/`inner_dim=512`/6 参数组属**二手来源**，且仍无 K 的敏感性）——那"这是不是个 information bottleneck、瓶颈宽度定在哪"这个最自然的追问，论文一个数据点都没有。**第六，卖点之一是靠层间共享做 "parameter efficiency"，却不报参数量、FLOPs、延迟、显存**——每个 coupling layer 塞三次注意力、100 个 query、推理全程激活，对以控制频率为硬约束的 VLA 这是必报项，不给数字等于这个形容词无法验证。另外 Language Instructions 是唯一两处退化的轴（MolmoAct2 −2.11、ImageWAM −0.92），而 π0.5 在同一轴却 +19.35，差异这么大论文一句不解释，只用"无一处下降超过 2.11pp"带过；考虑到 vault 里已有证据指向 LIBERO 的语言约等于任务索引，这一轴的正负两个方向恐怕都不该当真。最后，标题里的 "Foundation Models" 配的是 LIBERO 示教 + 300 条真机示教，没有任何跨 embodiment 大规模预训练——这个词是白蹭的。还有两条只有读仓库才知道的边界（**来源为官方 README/项目页，非论文**）：头条的 Overall 是七轴非加权均值，而仓库自陈 task-weighted 口径"大约低两个点"；ImageWAM 那个 fork README 注明未重跑评测，也就是 Table I/II 的两列目前在公开代码里无法端到端复现。最要命的一点其实是"baseline 不微调预训练 checkpoint"的反面：这个"从零训 action expert"协议对 LIT 大概率是**偏有利**的——Stage 1 的价值恰恰是给随机初始化的 expert 一个好起点，而允许微调预训练 checkpoint 的 baseline 本身就自带 action prior。"如果 baseline 能微调预训练 policy checkpoint，LIT 还剩多少"，本文的设计从结构上无法回答。
- **Rating**: `2` 👀 ，接口带宽 + 位姿监督这个设计维度提得准、消融证伪结构值得全行业抄，但真机样本量撑不起摘要里的断言、缺最便宜的 augmentation 对照、无 seed 且绝对值跨论文不可比——够 Frontier，不够 Foundation。

### Gander
- **Title**: Omni Interaction Agent Technical Report
- **Institutes**: Hunyuan Speech Team (Tencent), Zhejiang University, Shanghai Jiao Tong University, The Chinese University of Hong Kong, Nanyang Technological University
- **Source**: [link](https://arxiv.org/abs/2609.08977)  🔥 HF Trending ⬆️ 133   **📒 论文笔记**: [[2609-Gander]]
- **核心**: Gander 用 Cerebellum-Brain 双层把实时 full-duplex 交互与长时程任务执行拆开：9B front cerebellum（从 MiniCPM-o 4.5 初始化）以 1 秒 chunk 把音视频输入和自身输出压平成单条因果 token 流，每个 chunk 先预测 listen/speak/interrupt 控制 token，再决定说什么；长任务经 task_start / task_send / task_resolve 三个 special token 委派给 training-free 的 Codex 后端（评测中由 GPT-5.6 驱动）。Full-Duplex-Bench v3 上时序两项全表最好——过早插话 8.0%、take-turn 100/100——但 ToolSel / ArgAcc / RespQual / Pass@1 四项在正文七行里全部垫底（Pass@1 0.400 vs GPT-Realtime 0.600）。作者自己加的 back-brain-only 一行绕过前端后 ToolSel 0.934 反超全场，把瓶颈钉在交互层而非执行层。Omni understanding 相对基座回退（WorldSense 55.70 → 49.62）。
- **锐评**: 真正值钱的是一个设计：把"要不要说"从"说什么"里剥出来，做成先于内容生成的离散决策。Table 3 里两种失效同框出现——cascaded pipeline 靠外部 endpointer 拿满 take-turn 却换来 33.0% 插话率，Gemini Live 3.1 把插话压到 19.2% 却只在 78% 场景开口；Gander 两头都没让。这是 full-duplex 架构相对 VAD 外挂管线本来就该赢的那条轴，它赢了。问题是这也是它唯一赢的轴，而恰恰这个核心机制没被消融：论文没有对 chunk flattening、也没有对控制 token 前置预测做拿掉对照，"这样更稳定"全文只有一句 "we find"。于是主表能证明"整套系统跑到什么水平"，证明不了"哪个设计换来了什么"。

  claim 与证据的落差是系统性的，不是个别疏漏。abstract 写 internal human evaluation 得出结论，正文没有协议、没有评分者规模、没有分数；intro 承诺 report BigBenchAudio，实验节里没有；abstract 主打的噪声干扰、多方对话、backchannel 鲁棒性，全文只活在训练数据表里，零量化评测。最尴尬的是标题级卖点"用户可随时打断"——FDB v3 的 Interrupt 测的是模型抢用户的话（越低越好），不是系统被打断后怎么在半句里停下并重组，这半边能力没有任何度量。再加一条：一个把 16× 视觉压缩和 5× 音频下采样全归因于实时约束的系统，全文找不到一个 ms 级延迟数字。最核心的设计目标没被测量。

  端到端四项垫底的归因也没做完。作者把缺口推给 ASR/TTS 通道加前端的委派决策，但自己承认这两次运行"没有分离"这两个因素，却仍断言它们"是训练格式与部署路径的属性而非架构的属性"——这句纯属推测，无实验支持。可比性还得再打折：FDB v3 与 SpokenQA/VoiceBench 的 baseline 全部外部引用未复跑，同时作者单方面给自己后端补了 contract file。与已有工作的本质区别不在 agentic 能力——那是 training-free 的 GPT-5.6 给的，back-brain-only 的 0.934 量的是外部前沿模型的上限，不是 Gander 的训练成果——而在编排协议。task_send 的 main/fork 双路由把"用户中途改主意"建模成接口而非 prompt 约定，gateway 强制把任务目标绑定到传输层确认的真实 user turn 而不是前端自生成的 tool 参数，这对 GUI/computer-use agent 的注入与幻觉防线是条可抄的结构性设计。数据侧 InteractionSpeech 的隐藏续写（助手剩余话语保留为文本但不合成音频）也是真功夫，保证模型只观测真实听者拿得到的声学证据。反面数字同样清楚：9B 对 3B 的 Audio-Interaction，SpokenQA 上 +8.29 / +4.96，VoiceBench 两项反而落后，三倍参数只在知识型问答上兑现。另外据 GitHub / HuggingFace 页面（非论文正文）代码与权重已公开、数据标注 "Coming Soon"，与 abstract 的 "release models, code, and data" 目前还对不上。
- **Rating**: `2` 👀 ，控制 token 形式与前后端解耦接口值得抄，但主表全线垫底、核心机制零消融、abstract 承诺的评测大面积不兑现，够得上前沿参考，够不上打基础。

### MLA-Trust
- **Title**: MLA-Trust: Benchmarking Trustworthiness of Multimodal LLM Agents in GUI Environments
- **Institutes**: Tsinghua University; East China Normal University; Zhongguancun Academy
- **Source**: [link](https://arxiv.org/abs/2506.01616)  🏛 IJCV（OpenAlex）   **📒 论文笔记**: [[2506-MLATrust]]
- **核心**: 这篇问的问题比它自己意识到的更好：把一个已经做过安全对齐的 MLLM 塞进 GUI 执行循环，它原有的 guardrail 还剩多少。做法是把 trustworthiness 拆成 truthfulness / controllability / safety / privacy 四维八子维，挂 SeeAct（web）与 Mobile-Agent-E（mobile）在 Amazon、Twitter、GitHub、Notes、Email 等真实站点跑 34 个高风险任务、约 3.3k 实例。以下数字全部取自 **arXiv v1（13 个 backbone）**——IJCV 正式版摘要改称 17 个 agent，但 arXiv 从未发过 v2、期刊全文在付费墙后，两版数字不可混引。最硬的一组结果是同 backbone 只换壳的对照：refusal rate 从 single-step MLLM 到 multi-step MLA，GPT-4o 90.5%→70.2%、Gemini-Pro 86.0%→62.5%、Claude-3-7-sonnet 78.0%→57.8%。其余数字一片惨淡：GPT-4o 跨 app 协同（T.7）只有 26% accuracy，controllability ASR 在 11-34%，open-source 在 Gen-Record（S.5）的 toxicity 冲到 0.74-0.79。
- **锐评**: 值钱的只有 §IV-B 那一组对照，而它恰恰是绝大多数 agent safety benchmark 漏掉的条件——大家都在报"agent 不安全"，没人留 MLLM baseline，所以分不清是模型本来就不安全还是 harness 把 guardrail 打掉了。这篇留了，于是"agent 化削弱对齐"从相关性观察升级成有对照的量化 delta，20 个点的 refusal 塌方是能直接给 runtime guardrail 当预算目标的数字。可惜论文自己没看懂这组证据的含义，反手把招牌 claim 写成了"风险跨多步交互非线性累积"——而 Fig. 6 明明画了 step 0/1/3/5/7 的曲线：0→1 骤降之后，四条曲线全部在同一水平带内回弹震荡，没有一条继续下行；正文只讨论了 0→1 那一跳，对之后的走势只字不提，也从未把 "nonlinear accumulation" 和这些数据点对上。按它自己的图，危险的是"能动手"这个二值变化，不是"动得多"。最容易被二手引用的那句口号，在它自家证据里只成立到第一步为止。

  第二处翻车更低级：§IV-C 写 predefined 任务的 RtE "for all models" 高于 contextual reasoning，Table VII 里至少五个模型有反例，最刺眼的是论文自己挑来举例的 LLaVA-NeXT（S.1=29 低于 S.2=30、S.5=38），数字原样列在段落里还敢写 "a similar trend"。趋势在 proprietary 头部确实存在，全称量词纯属写嗨了。测量层的问题同样不体面：所有 RtE / ASR 都由 Longformer 或 GPT-4 二分类判定，论文只留一句 "following validated protocols from prior benchmarks"，没有任何 human agreement、kappa 或抽样复核——那"RtE 70.2%"里有多少是 judge 误判无从谈起，更要命的是如果 judge 对 proprietary 那种"我不能帮你，但可以…"的措辞更容易判成拒绝，Table III 的整个排名就有一部分是 judge artifact。全文找不到 rollout 次数、temperature、seed 或置信区间，而在真实网站上跑 multi-step agent，方差同时来自采样、页面状态和网络三处，C 系、S.5 这些只有 50 条实例的任务，几个点的模型差距统计上读不出来。指标方向也有结构性漏洞：safety 和 privacy 都以 RtE 越高越可信，controllability 只罚多做不罚少做，整个框架里没有一处惩罚过度拒绝——"GPT-4o 最可信"可以无损重述为"GPT-4o 最爱拒绝"，一个 always-refuse 模型能横扫两个维度。四维八子维则是作者先定义再造任务的先验分类学，没论证互斥穷尽、也没证据说明它比别的切法更能预测真实事故，同一批数据换个分法照样能写出"五维十二子维"。最后，把 benchmark 锚在 Amazon/Twitter/GitHub 的生产页面上，toolbox 再模块化也保不住纵向可比性，而纵向可比恰恰是 benchmark 的主要用途；论文连个独立 Limitations 节都没有。版本与计数还自己打架：v1 abstract 说 13 个模型，Table I 的 "# MLLM" 栏写 11(5)，§III-D 说 six open-source 却只描述了 5 个，实际打分 8 个——引用前必须回表核对版本和表号。（代码以 MIT 开放这一点来自 GitHub 仓库的 LICENSE，论文正文未声明，属二手来源。）
- **Rating**: `2` 👀 ，MLLM-vs-MLA 的对照设计值得后来者照抄，但 judge 无验证、单次运行无方差、两条招牌 claim 被自家图表证伪，数字只能当趋势看不能当基线引。

### COBRA-Skills
- **Title**: COBRA-Skills: Contextual Bandit-Guided Evolution for Agent Skill Optimization
- **Institutes**: The Chinese University of Hong Kong, Shenzhen · Tianjin University · The Hong Kong University of Science and Technology (Guangzhou) · National University of Singapore
- **Source**: [link](https://arxiv.org/abs/2609.11682)  📰 HF Daily ⬆️ 24   **📒 论文笔记**: [[2609-COBRASkills]]
- **核心**: 把 agent skill 优化重新形式化为"固定评估预算下、候选集逐轮变化的序贯分配问题"：每个候选 skill 用 Qwen3-Embedding-4B 编码，一个两层 MLP 预测 reward、加 LinearUCB bonus 决定这一轮评估谁，并按对数间隔 schedule 用 regeneration / rollout mutation / crossover 三个算子换掉最低分的 3 个候选。关键成本设计是 teaching model（GPT-5.5）只在 population update 时被调用，而非每轮重读 trajectory 改写 skill。6 个 benchmark × 3 个 target model 上平均分均居首，相对 no-skill 分别 +13.1 / +26.9 / +22.5，相对 SkillOpt 总成本降 55%–58%、Cost/ΔScore 降 60%–69%。另有两组附加实验：self-teaching（target 自己当 teacher）平均只从 73.5 掉到 72.5、成本约减半；36 个 cross-model transfer 格子中 34 个优于对应 no-skill。
- **锐评**: 问题 framing 是对的——这类方法真正贵在"评估"和"重写"，不在"怎么写得更好"，能把这一点说清楚已经比大多数 skill-library 论文强。成本口径也做得罕见地诚实：列单价表、拆开 teacher/target token、报 Cost/ΔScore，还在附录承认 OfficeQA 按官方配置复现不出 SkillOpt 所以直接删掉。但标题里那个 contextual bandit 是全文最经不起看的部分。Table 4 里真正要命的对照不是两个 w/o ablation，而是 Best-of-30：同等评估预算下生成 30 个候选、全评估、取最优，就有 71.0，而完整框架 73.5——整套 bandit + evolution 只买到 2.5 个点（SE 0.3 / 1.0），而且 Best-of-30 不做 evolution，teacher 调用更少、更便宜。往前一格更难看：GPT-5.4-Nano 上什么优化都不做的 LLM Skill 已经吃掉 +18.3，占总增益 +26.9 的三分之二，剩下 8.6 点才是所有机制的贡献。论文把 Best-of-30 和两个 ablation 并排放，视觉上稀释了这个对比，正文没有正面回应。

  第二，"consistently strongest" 只在"每个模型的平均分最高"这个字面意义上成立：18 个 benchmark×model 格子里有 6 个存在更强方法（Qwen/SearchQA 被 SkillOpt 反超 86.3 vs 84.3，Gemma/DocVQA 被 LLM Skill 反超，Gemma/LiveMath 被 Trace2Skill 反超），Gemma 上 68.9±0.5 vs 67.6±0.6、Codex harness 下 72.4 vs 71.1±3.2 在 n=3 下基本不可区分，真正稳的只有 Qwen 和 Nano 两列。第三，sample-efficiency 的结论有一半是自己定的：baseline 用的 150/120/130/53/170/130 例并非官方配置（官方 SkillOpt SearchQA 是 400 train + 200 val），作者算力受限如实披露了，但读者看到的是"50 例的 COBRA vs 被砍到 150 例的 SkillOpt"，缺一个满配对照结论就悬着。

  另外两点需要标明证据边界——笔记作者从 Table 2 / Table 6 数字推出（论文未直接给出该拆分）：成本优势很可能主要是价目表的产物，GPT-5.5 单价是 Qwen 的 50× 输入 / 31× 输出，而 target token 在 3 个模型中的 2 个反而涨了 24%–40%（Qwen 93.77M→115.92M、Gemma 89.38M→125.16M），所以省的是"少请那个贵老师"而不是"更聪明地花评估"，自家 self-teaching 只减半而非再降 55% 恰好印证；同样属笔记作者推测的是 LinearUCB 的机制——ν=0.1、λ=0.03 下正交候选的 bonus 约 0.58，reward 值域只有 [0,1]，而 d=2560 ≫ T=30 意味着设计矩阵永远填不满，这更像一个"惩罚与已评估 skill 语义相近者"的多样性过滤器而非真正在 exploitation/uncertainty 间权衡的 UCB；w/o Bandit 纯随机只掉 2.2 分是旁证。论文既没报 reward predictor 的留一预测精度，也没讨论 50 例标量 accuracy 的噪声（SpreadsheetBench 的 SE 普遍 2–5 点）如何污染 arm 排序——这两个诊断都便宜且直接，缺席很难不让人多想。真正有复用价值的反而是 self-teaching 和 harness 泛化两组 data point，但 self-teaching"只掉 1 点"是平均数抹平的：ALFWorld 从 72.3 掉到 63.3，比同设置下的 SkillOpt（70.7）还低。
- **Rating**: `2` 👀 ，framing 和成本口径值得学，但朴素 Best-of-N 已吃掉大部分收益、"省钱"主要来自 teacher 单价而非算法，bandit 这层的必要性没被自己的实验撑住。

### DSR
- **Title**: Beyond Top-k Skill Retrieval: Diversity-Aware Skill Routing for LLM Agents
- **Institutes**: Virginia Tech, University of Southern California, Adobe Research, Dolby Labs, Texas A&M University, Arizona State University
- **Source**: [link](https://arxiv.org/abs/2609.05824)  📄 arXiv   **📒 论文笔记**: [[2609-DiverseSkillRouting]]
- **核心**: 把 skill routing 从 pointwise top-k 截断改写成 subset selection——retriever 与 reranker 一字不动，只在最后一步换成 DPP greedy MAP。核心设计是 query-residual kernel：先从 skill embedding 里减掉 query 方向的分量再算重叠（λ=0.85），把"互为替代的真冗余"与"同为该 query 相关的伪冗余"分开，避免多样性惩罚误伤互补 skill。在 SkillRouter benchmark 的 75 个 query（24 single-skill / 51 multi-skill、约 80K 候选）上，共享 cutoff @20 的 Recall .754→.768、Full Coverage .560→.573；multi-skill 子集 .704→.739 / .458→.492。全部指标在 retrieval 侧，论文 Limitations 自陈未测下游 agent 执行成功率。
- **锐评**: 这篇最有价值的一行不在 main result，而在 ablation：换成朴素 cosine kernel 做 DPP、quality 分数完全不变，multi-skill FC@10 直接从 baseline 的 .424 崩到 .254、R@10 从 .705 掉到 .534。也就是说"给 agent 检索加多样性"的默认结果是净伤害，机制也清楚——query-conditioned 召回出来的候选彼此相似，本来就有很大一部分是因为它们都跟这个 query 相关，惩罚这块相似度等于惩罚相关性。这个观察能迁移到 tool / memory / RAG chunk 检索，比论文自己吹的那点 coverage 增益有用得多。问题是论文把它写成"所以我们的 kernel 是必要的"，而没敢承认它同时证明了 DPP 在这个任务上不自带任何收益。

  硬伤三条：其一，全文没有 MMR baseline——Carbonell & Goldstein 在 Related Work 引得规规矩矩，三张表里一行都没有；query-residual 这个 φ 完全可以塞进 MMR，不做这个对照，读者根本分不清收益来自 determinantal 结构、来自贪心去冗余、还是仅仅来自列表变长，而标题里"Beyond Top-k"暗示的强主张一条都没被支撑。其二，abstract/intro/conclusion 反复强调的"larger gains at larger cutoffs"建立在 @50 那栏上，而论文自己在 §4.1 和 Table 1 caption 里承认 released SkillRouter 只输出 20 条、它的 @50 就等于 @20——50 条列表打 20 条列表，剩下 30 个槽位是空的；把 SR-Rank 的 pointwise 分数延长到 50 条成本近乎为零却没做，很难不怀疑做了差距就没了。其三，共享 cutoff 上的效应量已经贴着测量分辨率：FC 是 per-query 的 0/1 量，@20 上 .013 的差距按笔记作者的换算约合 1 个 query 翻转、multi-skill 的 .034 不到 2 个 query，@10 上 multi-skill 只差 .008；而全文没有 seed、没有重复运行、没有 error bar，λ 和 M 只有单一取值无 sweep，超参选择与结果报告共用这同一批 75 个 query。single-skill 子集上三种方法 R@10/FC@10 全是 .875，完全打平，说明所有差异只发生在 51 个 multi-skill query 上；MRR@10 还从 .788 微降到 .784；Table 2 的 residual+reranker 行（.711/.441）与 Table 1/3 同配置 DSR（.712/.432）对不上且无解释——在一篇效应量就是 .008 量级的论文里，这种不一致直接吃掉结论可信度。

  最讽刺的是动机与证据的错位：全文动机是"冗余 skill 浪费 context budget"，却从没测过 token 成本，FC@50 的提升代价是往 context 里多塞 2.5 倍的 skill，按它自己的逻辑很可能是净亏；[[Papers/2606-SkillMemoryBudget]] 的预算匹配实验正是这类"检索侧提升=agent 提升"推断的反例。值得肯定的只有变量隔离——retriever 与 relevance 模型逐字沿用 baseline，唯一变量是最后的选择步骤，这点自律在 retrieval 类论文里不算常见。另外一个没被问的问题：agent 本来就是多轮的，"还缺什么 skill"在第一步执行后是可观测的，DPP 的 set-level 目标说白了只是在补偿"没有执行反馈"这个缺失，静态 embedding 空间里的几何修正是个绕路的解法。
- **Rating**: `1` 💤 ，5 页无插图单 benchmark、共享 cutoff 上就翻转 1–2 个 query、headline 数字来自不对等比较、连 MMR 都不比——记住 ablation 里"朴素 diversity 会掉 40% FC"那一行就够了，正文可以不读。
