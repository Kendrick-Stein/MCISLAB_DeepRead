## 论文点评

### Long-Horizon-Terminal-Bench
- **Title**: Long-Horizon-Terminal-Bench: Testing the Limits of Agents on Long-Horizon Terminal Tasks with Dense Reward-Based Grading
- **Institutes**: Tencent HY LLM Frontier, University of Maryland, University of Georgia, University of Minnesota, Indiana University, Lehigh University, NUS, PolyU
- **Source**: [link](https://arxiv.org/abs/2607.08964)  🔥 HF Trending ⬆️ 74   **📒 论文笔记**: [[2607-LongHorizonTerminalBench]]
- **核心**: 46 个"故意做坏"的长时程终端项目（修 SLAM pipeline、气候数据分析、EDA 等），agent 平均每题烧 9.8M tokens / 239 episodes / 88.9 分钟，比 Terminal-Bench 2 高一个量级。核心创新在判分而非任务：每题分解为带权 subtasks 给 dense reward，配 hidden stress verifier 防公开测试过拟合，gold solution 必须在 hidden suite 拿满 1.0 以校验 grader 本身。17 个 frontier model 里最强的 Grok 4.5 在 R≥0.95 下 pass@1 仅 28.3%，全体均值 6.4%；62.8% 的 run 有 partial progress 但二值判分下全算零分。
- **锐评**: 这篇的真正贡献是 grader 工程而非又一个 benchmark：hidden verifier + 动态 stress cases + gold-solution-must-score-1.0 三件套是所有做 agentic 评测的人该抄的作业，dense reward 必要性也有硬数据——near-miss（[0.85,0.95) 区间 68 个 run）比通过（50 个）还多，二值判分把整个中间地带压成零。但作为 benchmark 本身硬伤不少：79% 的失败是 90 分钟 wall-clock 超时，测的一半是 serving 速度而非能力上限，Grok 4.5 的领先有多少来自 API 快？没有 budget ablation。46 题 × 单次 pass@1，1 题就是 2.2 个百分点，中下游排名纯噪声；GPT-5.3 单独用 Codex harness 破坏受控比较；abstract 说 9 类、正文说 21 类，v1 到 v2 四天内 headline 从 15.2% 跳到 28.3%——赶工痕迹明显。另外 false-finish 分析（14 个 run 在 R≥0.75 时自判完成提前退出）是全文最有信息量的小节：agent 系统性高估自己的完成度、吝于做最终验证。
- **Rating**: `3` 🔥 ，vault 正在追的"长程任务中间进度度量"这条线上，它把 dense grading 从口号做成了可复用的基建（且可直接改造成 RL 训练信号），排行榜本身可以不信，grader 设计必读。

### SEED
- **Title**: SEED: Self-Evolving On-Policy Distillation for Agentic Reinforcement Learning
- **Institutes**: Tsinghua University, Zhejiang University, The Chinese University of Hong Kong, Nanyang Technological University, Tongji University
- **Source**: [link](https://arxiv.org/abs/2607.14777)  🔥 HF Trending ⬆️ 93   **📒 论文笔记**: [[2607-SEED]]
- **核心**: 针对 agentic RL 里 terminal reward 被 GRPO 无差别广播到全部 token 的监督缺口，SEED 让同一 policy 快照兼任 rollout actor 和 analyzer：每轮把自己刚采的轨迹提炼成自然语言 hindsight skill，再对每个动作 token 在"带 skill"与"普通"两个上下文下重打分，log-prob 差经 sigmoid gate 加权变成 token 级蒸馏 loss，与 outcome RL 联合优化；skill 只在训练时存在，部署零开销。Qwen2.5-3B 上 ALFWorld 91.8%（GRPO 75.0）、WebShop 88.5（GRPO 79.8）、七个 search-QA 平均 45.7%（GRPO 36.4），60% 数据即超 GRPO 全量。
- **锐评**: 机制是真干净——teacher 和 student 是同一个模型，差别只在有没有看到自己轨迹的 hindsight 总结，不要外部 teacher、不要 reward model、不要环境重交互、不要部署时检索，比 ReSkill 那类 skill library 外挂路线省掉整套 inference 基础设施；静态 skill bank ablation 掉 7.4 分（三个组件里最大）是全文最硬的证据，直接钉死"hindsight 必须随 policy 演化"这个核心 claim。但三处虚：其一，"self-evolving"的冷启动靠 GLM-5.2 标注 1,440 条轨迹，外部强模型的知识注入和自演化机制的贡献没解耦；其二，Δ 度量的是 token 与 hindsight 建议的**一致性**而非对成功的因果贡献，skill 幻觉时 gate 无法识别有害建议，自蒸馏放大自身确信错误的风险全文零分析——这正是 EvoCUA-1.5 用 PRM-hacking 曲线警告过的 model-judged 信号陷阱；其三，实验是上一代规模：3B 模型上 GRPO 是弱基线（ALFWorld 75.0），+16.8 的 headline 有水分，对最强基线 SDAR 净增益只有 3-7 分，且 abstract 吹 "visual agentic tasks" 但主表全是文本环境、多模态藏在附录，轻度 overclaim。跟 TreeGRPO 靠环境分支造过程信号相比，SEED 只需对 logged 轨迹做 forward，对有状态 GUI 环境反而更可迁移——可惜作者没去碰 OSWorld 级战场验证这一最有价值的卖点。
- **Rating**: `3` 🔥 ，监督信号构造简洁可复用、ablation 证据扎实，是 sparse-reward credit assignment 方向必读的一条新路线，尽管实验规模拖了后腿。

### KnowAct-GUIClaw
- **Title**: KnowAct-GUIClaw: Know Deeply, Act Perfectly, Personal GUI Assistant with Self-Evolving Memory and Skill
- **Institutes**: Harbin Institute of Technology (Shenzhen), Shenzhen Loop Area Institute
- **Source**: [link](https://arxiv.org/abs/2607.12625)  🔥 HF Trending ⬆️ 56   **📒 论文笔记**: [[2607-KnowActGUIClaw]]
- **核心**: 在 OpenClaw 之上搭一个 Know-Route-Act-Reflect 闭环：host agent（Qwen3.5-397B/Kimi-K2.6）管任务分解与跨 app 数据路由，可插拔 GUI subagent 管执行；skill 从轨迹蒸馏而来、执行前逐步做 state contract 校验，失败时修复优先于新建；experience memory 借鉴 ReasoningBank 存 textual policy。全程零训练，Kimi-K2.6 配置在 MobileWorld GUI-Only 达 64.1%，超 GPT-5.5（62.4%）和 Seed-2.0-Pro（63.2%）；Kimi 轨迹蒸馏的 memory/skill 迁给 Qwen3.5-35B executor 还能带来 37.9%→41.0%。
- **锐评**: 系统设计是真扎实——blackboard 的 typed information contract（缺 input 直接 fail closed，不许模糊摘要向下游传播）和 "manifest 暴露的 intent 只是 discovery evidence、页面验证过才能升格为 one-step skill" 这两条协议，比 [[2604-SkillClaw]] 靠夜间 A/B 硬验证的做法优雅得多，也正面回应了 [[2509-Misevolution]] 的 skill 库自我污染问题。跨模型迁移实验（Kimi 经验喂 Qwen +3.1 pts）是多数 self-evolving 论文欠账的关键验证，值得表扬。但账要算清楚：64.1% 对裸 Kimi-K2.6 的 55.6% 里，大头是 host scaffolding（分解 + 非 GUI 工具直接解题），397B ablation 上 memory 只值 +2.6、skills 只值 +2.9——标题里的 "Self-Evolving" 其实是配角，主角是 multi-agent 编排。而且 MobileWorld 仅 117 个任务，64.1% vs 62.4% 差约 2 个任务，零显著性检验就敢喊 best performance；AndroidDaily 是自建集 + LLM judge + 人评三合一，拿它压 UI-TARS-1.5 的可比性存疑。最后，"OpenClaw 两大短板" 的 framing 纯属借壳营销——这就是个独立的 host-executor GUI 框架，跟 OpenClaw 的耦合薄得一捅就破。
- **Rating**: `2` 👀 ，工程协议设计（fail-closed contract、skill 修复护栏、跨模型迁移验证）值得 GUI 框架从业者抄作业，但 self-evolving 的净收益单薄、评测显著性不足，够不上必读。

### SeerGuard
- **Title**: SeerGuard: A Safety Framework for Mobile GUI Agents via World Model Prediction
- **Institutes**: JIUTIAN Research
- **Source**: [link](https://arxiv.org/abs/2607.15550)  📄 arXiv   **📒 论文笔记**: [[2607-SeerGuard]]
- **核心**: 把 mobile GUI agent 的安全防护从"看指令"前移到"看后果"：先做一次指令级筛查，然后在每个动作执行前用一个 safety-augmented world model（SAWM，Qwen3-VL-8B 上 148K 数据 multi-task SFT）预测该动作的语义后果并判定风险，unsafe 直接拦截。motivating 证据很硬——对 MobileSafetyBench 150 个 high-risk 任务重标注，91% 的风险是"良性指令 + 特定上下文中的危险执行"，纯指令级 guard 天生管不住。结果上，Qwen3-VL agent 的 risk-cost score（α=0.8）从 0.347 降到 0.130、safety-utility score 从 0.191 升到 0.596，GPT-5.1 / Gemini-3.1 的 RCS 也各降约 50%；8B 的 SAWM 在 Next-State-QA 上以 0.762 压过 235B 基座（0.651）和 GPT-5.1（0.727）。
- **锐评**: 问题选得准、91% 那个统计是真 insight，但标题里的核心 claim 恰恰缺决定性消融——全文没有"去掉 next-state prediction 目标、只 SFT 风险分类"的对照，所以"world model 预测"这个机制本身值几个点根本无从知晓，现有证据只能证明领域 SFT 数据有用。细看数字更露怯：MobileRisk 上相对未训练的基座 Qwen3-VL 只赢 1.5 pt accuracy（0.681→0.696），precision 还倒退（0.699→0.664）；且 MobileRisk / Next-State-QA 疑似自建 benchmark，训练数据又源自 MobileWorld 轨迹，分布重叠只字未提。最大涨幅（SUS +212%）来自最弱基线，GPT-5.1 在 ω=0.5 时 utility 反而掉（0.703→0.668）；"延迟降 4%"纯粹是拦截提前终止任务的统计 artifact，当卖点写是自欺。第一级筛查在 Agent-SafetyBench 上 recall 仅 0.396 还输给 PolyGuard，两级架构的第一级基本是摆设。对比已有工作：BraveGuard 是 trajectory-level 事后检测、VeriSafe 是形式化规则验证，SeerGuard 的"pre-execution 后果预测"确实是差异化的位置——而且它与 MobileWorldModelGUI"world model 不适合当 test-time verifier"的结论形成有价值的张力（安全二分类可能比成功验证容错更大）。方向对、执行糙，是篇被关键消融拖累的 borderline 工作。
- **Rating**: `2` 👀 ，problem formulation 和 91% 统计值得吸收，但 world model 必要性未被证明、benchmark 自产自评，不到必读级。

### ToolVerse
- **Title**: ToolVerse: Unlocking Massive Environments and Long-Horizon Tasks for Agentic Reinforcement Learning
- **Institutes**: Meituan LongCat Interaction Team, Peking University, Fudan University, Wuhan University
- **Source**: [link](https://arxiv.org/abs/2607.15660)  📄 arXiv   **📒 论文笔记**: [[2607-ToolVerse]]
- **核心**: 从 Toucan 数据集的 system prompt 里抽出 422 个真实 MCP、约 4438 个工具的 schema，自动改写成带 Python dict mock database 的可执行训练环境（单元测试过滤掉 20% 依赖外部服务的）。任务合成靠 Tool Dependency Graph + Dynamic Unlocking Sampling：按拓扑序解锁零入度工具生成 golden trace，再让 LLM 反写成自然语言任务、Qwen3-32B Pass@8 过滤，得到 GUST 数据集（2,987 条，每任务 3-7 次工具调用）。训练侧提出 TARA：turn 级 binary reward（dictionary matching golden tool JSON）+ group 内 local advantage + 带 consistency gate 的折扣 future advantage，套在 GRPO 上。Qwen3-8B 在 BFCL-v3 multi-turn 28.88→37.50、ACEBench-Agent 46.51→61.66、τ²-Bench 27.87→32.37，且同数据下 TARA 比裸 GRPO 再多 2.25 个点（BFCL），数据与算法贡献分离得干净。
- **锐评**: 先说致命问题：这套"可执行环境合成 + 工具依赖图 + 拓扑采样 + BFCL/τ² 评测"的配方，跟两个月前的 EnvFactory（85 环境、2,575 轨迹、BFCLv3 +15）几乎逐模块同构，而全文对 EnvFactory 零引用——大概率是撰写周期撞车，但读者只能自行脑补 novelty 边界，这在 2026 年的 agentic RL 赛道是硬伤。真正有辨识度的只剩 TARA，而它的地基值得警惕：turn 级 reward 是对**唯一合成 golden trace** 的 dictionary matching，多解任务里合法的替代工具序列一律判零，等于把 process supervision 锚死在 LLM 自己编的参考答案上；gate ablation（33.75→35.00→37.50）证明组件有用，但没回答"golden trace 错了怎么办"。此外 Pass@8 用 Qwen3-32B teacher 过滤，任务难度被 teacher 能力封顶，所谓 long-horizon 也就 3-7 次工具调用——对照 EvoCUA-1.5 的百步 OSWorld，标题里的 "Long-Horizon" 属于自我加冕。环境 scaling 只给 100 vs 422 两个点就宣称 "massive environments" 有效，曲线都懒得画。值得肯定的是：评测全在外部 benchmark 上做（不玩自建环境自测的把戏），ACEBench +15.15 和 Qwen2.5-7B 上碾压 ToolRL/SimpleTIR/AgentFlow（τ² 16.00→29.87）的数字是实打实的；"schema 真实 + 状态 mock"路线与 EnvFactory 互为独立验证，这个方向本身已经坐实。工程扎实的规模化复现 + 一个有前提缺陷的 credit assignment 组件，仅此而已。
- **Rating**: `2` 👀 ，TARA 的 turn 级 gated advantage 值得借去用，但环境配方是 EnvFactory 的放大版，reward 锚死单一 golden trace 的设计限制了上限。

### ResearchStudio-Idea (IdeaSpark)
- **Title**: ResearchStudio-Idea: An Evidence-Grounded Research-Ideation Skill Suite from ML Conference Outcomes
- **Institutes**: Nanyang Technological University, Microsoft Research, National University of Singapore, CFAR A*STAR
- **Source**: [link](https://arxiv.org/abs/2607.04439)  🔥 HF Trending ⬆️ 60   **📒 论文笔记**: [[2607-IdeaSpark]]
- **核心**: 从 1,947 篇 ICLR/ICML/NeurIPS 2021–2025 论文（1,014 Oral、260 高引、722 Reject）中用 embedding 聚类 + LLM 归纳出 15 个可复用 ideation pattern，封装成三个 skill：Paper-Search（arXiv/OpenReview/OpenAlex/S2 四源分工检索）、Scoop-Check（把 novelty claim 拆成 problem framing / mechanism / insight / domain 四轴与检索到的先行工作逐轴碰撞，worst-case 定级）、IdeaSpark（grounding → bottleneck 诊断 → pattern 生成 → 四项 audit → idea card 的五阶段工作流）。在 100 个 ICLR 2026 Oral seed 上盲评，IdeaSpark quality 3.87/4（88/100 排第一），远超 bare Opus（2.56）和 generic skill（2.57）；同时暴露 GPT-5.5 bare 的 "novel-but-empty" 失效模式——novelty 最高（3.73）但 quality 垫底（1.00），因为 idea 模糊到没有先行工作可撞。
- **锐评**: 语料分析是真功夫：含 722 篇 Reject 的对照语料稀缺，"rejects 与 orals 共享同一策略空间、差在执行"这个发现直接把分类学降级成诊断词表而非生成过滤器——连"频率先验会导致输出同质化所以移出生成阶段"这种被真实失效逼出的设计都写了，工程诚实度罕见。"novel-but-empty" 的定量刻画和 honesty tax（保留自我质疑标注会掉一个排名位）是对整个 LLM-ideation 评测领域的有效打脸。但评测是个自指闭环：novelty 评审就是自家 Scoop-Check，quality 评审是自研 skill 且跑在 Opus 4.8 上——跟 IdeaSpark 的 runtime 同一个 backbone，GPT-5.5 拿 1.00±0.00（300 判全垫底、零方差）你说服不了我这没有 cross-family judge bias。更硬的伤是 Scoop-Check 自身零校准：四轴匹配全靠 LLM 判断，无 precision/recall、无误判率，明明引了 RINoBench（1,381 条专家 novelty 判定，且结论正是 LLM novelty 判断偏离专家）却不在上面测自己的 checker；worst-case-min 规则对检索 recall 极敏感——漏检最近的先行工作 level 就虚高，且不做 as-of backdating。再加上 47.7% 语料没入簇、15-pattern 是 Opus 4.7 单次 pass 无稳定性验证、quality 是四选一强制排名（相对量非绝对量）、零人类评审。claim 倒是收得很干净——只 claim idea 阶段、不 claim acceptance，limitation 节把两个 judge bias 都自己交代了，这份自觉值得表扬。
- **Rating**: `2` 👀 ，语料分析和工作流设计（audit/修复分离、full-text hard gate、四轴碰撞分解）值得抄进自家 idea 系 skill，但评测自指且 Scoop-Check 未校准，结论打七折看。

### VLAA-GUI
- **Title**: VLAA-GUI: Knowing When to Stop, Recover, and Search, A Modular Framework for GUI Automation
- **Institutes**: UC Santa Cruz, CMU, UNC-Chapel Hill, Salesforce, UC Berkeley
- **Source**: [link](https://arxiv.org/abs/2604.21375)  📄 arXiv   **📒 论文笔记**: [[2604-VLAA-GUI]]
- **核心**: 针对 GUI agent 两大失败模式——false completion（失败任务中 >86% 是 agent 自认已成功）和重复动作循环——搭了一个单 Manager + 两个每步强制工具的框架：Completeness Verifier 双层把关（prompt 级 Completion Gate 逐步对照 1–3 条 UI-observable success criteria 自检 + 同 backbone MLLM judge 在每次 done() 时以"每条 criterion 须有直接视觉证据、副作用须有可见确认、精确值须逐字可读"的保守规则二次裁决，双方同意才准终止）；Loop Breaker 三级固定升级（同动作 2 次无变化→强制换交互模态、同屏幕 3 次→强制换整体策略、reflection judge 发 SWITCH→拉黑重复动作强制换）；外加单 query 调 Gemini search grounding 拿文本教程的 Search Agent。OSWorld-Verified 上 Opus 4.6 达 77.45%（100 步），三个 backbone 单 pass 超人类 72.4%；Sonnet 4.6 仅 15 步就到 64.13%，超过最佳已发表 50 步系统 OS-Symphony（63.61%）；WAA 61.0%。
- **锐评**: 问题选得准、量化做得干净，但头条数字要打折：77.5% 靠的是 baseline 都没用过的 Opus 4.6，同 backbone 硬碰硬时 VLAA-GUI w/ Opus 4.5（74.89%）只比 HIPPO w/ Opus 4.5（74.49%）高 0.4pp——"首超人类"更多是模型换代红利，框架自身的 ablation 贡献合计才 3–6pp。真正值钱的数字是 15 步超 50 步 SOTA（收益来自砍浪费步，不是堆预算）和失败模式账本：加了 Verifier 之后 False Done/Failed 仍 >86%、被接受的完成宣告约 1/4 是错的——所谓"解决"early stopping，其实只削掉 4–6pp，主导失败模式几乎原封不动，而且 Verifier 是同 backbone 自我审查，作者明明引了 Self-Grounded Verification 的 agreement bias 却只靠 prompt 严苛度硬扛。方法论上三级 Loop Breaker 是纯规则固定升级：阈值硬编码（2 次/3 次），Tier 3 的 reflection prompt 明文禁止推荐具体动作，零 per-mismatch 自适应——这是 fixed-escalation 家族的又一成员，而其 Loop Breaker 在 Sonnet@100 只值 +0.04pp、在 Flash@15 反而 −6.15pp，恰好证明固定恢复协议的价值高度条件化。另两处硬伤：每步强制 Reflection + Verifier 调用（每动作 3–4 次模型调用）却全文不报 token/延迟成本；Table 8 与 Table 4 的 Flash@50 数字（61.68 vs 63.14）对不上，工程报告有 sloppiness。诚实的负结果（弱 backbone 紧预算下三组件全为负、planner/memory 去掉更好）是加分项。
- **Rating**: `3` 🔥，当前 OSWorld SOTA + 全 backbone false-completion 量化 + 教科书级 fixed-escalation baseline，做 GUI agent recovery/verification 方向绕不开这篇。

### HiViG
- **Title**: A History-Aware Visually Grounded Critic for Computer Use Agents
- **Institutes**: UNC Chapel Hill, Capital One, UT Austin
- **Source**: [link](https://arxiv.org/abs/2606.11078)  📄 arXiv   **📒 论文笔记**: [[2606-HiViG]]
- **核心**: 训一个 8B critic（Qwen3-VL-8B-Thinking，52k SFT，数据源自 ScaleCUA 轨迹 + 12 维错误 taxonomy 合成扰动）给 frozen CUA policy 做 step 级 pre-execution gating。两个关键设计：历史不存 screenshot 序列，而是递归压缩成 macro-action history（"已打开 Downloads 目录" 式子目标文字记录）；"visually grounded" 是字面意义的——把 policy 提出的原始坐标以红 "X" 渲染到截图上，critic 核对坐标落点、预测 state-transition、再判任务对齐，判 Bad 则回传错误类别 + verbal 解释强制重提。Qwen3-VL-32B 三平台平均 31.0→38.3、Gemini-3-Flash 41.4→50.4，而 OpenCUA/SE-WSM/CGI/GUI-Critic-R1 五种已有 critic 对 Gemini-3-Flash 全部近零或负增益。
- **锐评**: 这篇最值钱的不是方法而是两条实验证据。第一，画一个红 X 这么土的 trick 配上 30% intent masking，ablation 掉点干脆利落（去 marker WALv2 25.3→20.8，去 masking ALab 51.5→47.1）——直接坐实了已有 verbal critic 在偷懒读 policy 的文字意图而不看图，这是对 "拿 VLM 当 judge" 整个流派的打脸；第二，baseline 全军覆没那张表比主结果更有信息量：GUI-Critic-R1 把 Gemini-3-Flash 从 41.4 拖到 36.1，说明不专门训练的 critic 是负资产。跟 vault 已有工作的本质区别：OS-Oracle 同样合成 negative + gating，但视觉验证靠 IEL 类数据隐式学、无显式坐标锚定，dynamic eval 只挤出 +1.6/+1.8；TSR 只做 training-free 状态维护不评动作，HiViG 把状态跟踪和动作评估混训进一个模型且证明协同（25.3 vs 分开 23.4）——等于回答了 TSR 留下的 "该不该合并" 问题。硬伤也不少：全程只报端到端 SR，critic 自身的判定 accuracy/F1 一个数都没有，你不知道它是靠拦对了错动作还是靠 history 提示间接助攻；benchmark 选了 WebArenaLitev2/AndroidLab/WindowsAgentArena，恰好避开 OS-Oracle 报数的 OSWorld/AndroidWorld，无法直接对线；gating 循环的 latency 和重试上限只字不提；negative 全部来自 expert action 的合成扰动，真实 policy 错误分布覆盖与否未验证。另外 abstract 的 "+5.8%" 是挑了对最强 baseline 的口径，对 base 是 +7.3——写法鸡贼但数字本身经得起查。
- **Rating**: `3` 🔥 ，intent masking 揭穿 verbal critic 文字依赖 + 已有 critic 集体失效两条证据足够改变这条线的默认做法，尽管 critic 本身精度成谜。

### VAGEN
- **Title**: Agentic Reward Modeling: Verifying GUI Agent via Online Proactive Interaction
- **Institutes**: MAIS Institute of Automation CAS, University of Chinese Academy of Sciences, Meituan, Beijing Jiaotong University
- **Source**: [link](https://arxiv.org/abs/2602.00575)  📄 arXiv   **📒 论文笔记**: [[2602-VAGEN]]
- **核心**: 把 GUI 任务的成败判定从"被动看截图的 LLM-as-a-Judge"升级为 Agentic Interactive Verification：verifier agent 在轨迹终态的环境上在线运行，带 4 个工具——按需调历史截图、execute shell 查文件属性/后台进程等 latent state、execute python 做逻辑校验、computer use 直接点开页面核对状态（与 actor 同款动作空间），按"static assessment → visual retrospection → proactive probing"三级递进取证。理论依据是验证不对称性：同一个 Claude-Sonnet-4.5 在 OSWorld 解任务 SR 55.9%（28.5 步），做验证却有 83.1% acc（17.4 步）。结果在 OSWorld-Verified 人评 GT 上 92.9% acc / 94.0% precision，碾压最强 judge baseline（FullTrajEval 84.7% acc）；AndroidWorld 泛化 93.1%。另配 read-only scaling（majority vote 免 VM snapshot 恢复）和 Best-of-N 采样（N=5 抵 baseline N=8）。
- **锐评**: 这篇打到了 GUI RLVR 最疼的骨头上。AgentRewardBench 量出的 judge precision ≤70% 天花板，根因是 partial observability——截图里根本看不到文件写没写成、进程起没起来。VAGEN 不去卷 prompt 而是给 verifier 交互权限直接消灭信息差，是结构性修复而非涂脂抹粉；最值钱的数字是 class-imbalanced（弱 actor UI-TARS-1.5-7B）下 precision 88.5 vs judge 类 ~75——RL 训练里轨迹恰恰负多正少，judge 的 false positive 会直接毒化 reward，而 ablation 里 w/o computer use 掉最多（86.2→83.4 F1）+ 工具统计里 computer use 调用最频繁，把"静态观察不够"的核心假设钉死了。成本账也算得清：验证 17.4 步、11.9 图/1218 token，比解任务便宜 40%。但两处硬伤不能放过：其一，题目叫 reward modeling、通篇引 RLVR，实验却止步于评测精度 + Best-of-N，一次真 RL 训练都没跑——verifier 与 actor 共享动作空间，actor 学会伪造 verifier 会去检查的表面证据这种 reward hacking 风险完全未测；其二，副作用控制是 prompt guidance + secondary LLM 的软约束，没有污染率量化，"rarely alters key evidence"是自述性统计，且 verifier 必须在轨迹终态环境上在线跑，离线轨迹场景直接失效。另外人评 GT 由作者方自己组织，虽有 test-script GT 交叉印证，仍需留个心眼。
- **Rating**: `3` 🔥 ，用"验证不对称性 + verifier agent 化"实打实突破 judge precision 天花板（94.0/88.5 vs ≤70），是 GUI reward modeling 的正确范式转向；扣分项是 RL 训练闭环缺席。

### OS-Marathon
- **Title**: OS-Marathon: Benchmarking Computer-Use Agents on Long-Horizon Repetitive Tasks
- **Institutes**: Microsoft, University of Oxford, Georgia Institute of Technology
- **Source**: [link](https://arxiv.org/abs/2601.20650)  📄 arXiv   **📒 论文笔记**: [[2601-OSMarathon]]
- **核心**: 提出 242 个"长时程重复性"CUA 任务（Expense Report 报销处理 + Transcript 学分认证两领域，7 个 Ubuntu 环境，160 真实 + 82 合成），agent 需对 5–30 条独立数据反复执行同一 sub-workflow，step budget 50–200。判分用二值 SR + Sub-Workflow Accuracy（SWA=处理对的数据条数/总条数）双指标。配套的 FCWD 把工作流压缩成"四阶段关键步骤截图+动作对"的少样本演示，把 AgentS2.5+GPT-5 在 Transcript L1 的 SWA 从 27.08% 拉到 91.74%（SR 0%→50%）；但 Expense 全域和 Transcript L2 以上，所有 agent（含 FCWD）SR 一律为 0，OpenCUA-7B / UI-TARS-1.5-7B 两个基线 SWA 直接全 0。
- **锐评**: 任务形态选得漂亮——"批量重复"是真实办公自动化的主体，且 SWA 的分母就是数据条数，partial credit 天然免费，比 LH-Terminal-Bench 手工分解 weighted subtasks、SaaSBench 人工设计 checkpoint 都干净；"做完头几条就自行终止"的失败模式也是单次任务 benchmark 测不出来的新东西，对本 vault 的长程可靠性线（[[Ideas/MismatchTriage-LongHorizonRecovery-GUI]]）是"premature termination 应进入 recovery action space"的旁证。但执行配不上立意：号称研究重复任务的错误累积，却**只报聚合 SWA，没有第 1 条 vs 第 20 条的逐条退化曲线**——这张全文最该有的图缺席，等于把自己最独特的卖点浪费了；评测只有 3 个 agent 配置且两个 7B 全 0 分，有信息量的对比实际只剩一组，Claude/Operator/Gemini 一个没测；SR 出现 50% 这种数字暴露每级评测子集小到个位数，242 个任务实际只跑了 L1–2；"cost-effective" 通篇没有一个成本数字。FCWD 本身也就是精心排版的 few-shot SOP prompt，无 ablation、无强制遵循机制，91.74% 的提升更多说明任务瓶颈在 workflow 逻辑获取而非方法有多妙。
- **Rating**: `2` 👀 ，benchmark 切面独特且对长程可靠性线有旁证价值，但缺逐条退化分析、评测覆盖太窄，立意 3 分执行 1 分。

### ADMIRE
- **Title**: Adaptive Milestone Reward for GUI Agents
- **Institutes**: Shanghai Jiao Tong University, OPPO Research Institute
- **Source**: [link](https://arxiv.org/abs/2602.11524)  📄 arXiv   **📒 论文笔记**: [[2602-ADMIRE]]
- **核心**: 针对 GUI agent RL 的 credit assignment 两难（outcome reward 过稀 vs LLM-judge PRM 被 hack），ADMIRE 让 GPT-4o 从 agent 自身环境验证成功的 rollout 中蒸馏有序 milestone 列表，训练中用 Sentence-BERT 把 agent 的 action description 与 milestone 做相似度匹配（δ=0.75、顺序指针防跳跃）给 step-level reward。"adaptive" 指两层：milestone 随发现更优轨迹被 GPT-4o 增量 refine，且 milestone 权重按 epoch 衰减。非对称 credit assignment 是核心设计——成功轨迹只在 milestone 命中步给分（denoising），失败轨迹给 k/K 连续进度分（scaffolding）。AndroidWorld 上 Qwen2.5-VL-7B 达 44.0%（outcome-only 39.7%、LLM-judge PRM 36.2%），并在 GRPO/RLOO/DAPO × ALFWorld/WebShop 上泛化。
- **锐评**: 先回答 vault 里的关键问题：这确实是 EvoCUA-1.5 Fig 7 指名的 milestone 方向的已有实现，但只做了**一半**。milestone 的**内容**锚定了环境 validator 判定的真实成功轨迹——这半截是扎实的；但 per-step **命中判定**既不是 state diff 也不是 validator，而是 agent 自己写的 action description 与 milestone 文本的 embedding 相似度。这是 self-reported progress：policy 原则上可以学会把描述写得像 milestone 而不真正执行，作者一边拿 "PRM 会被 hack" 当卖点，一边对自己这条更直接的 hacking 通道零讨论零实验，是全文最大的双标。数字层面有真货也有水分：真货是难任务分层（outcome-only 9.5% 反而低于 base 14.3%，ADMIRE 19.0%——sparse reward 有害的干净实证）和 ablation（失败轨迹的 k/K progress reward 贡献最大，说明 milestone 的真正价值是给失败部分学分，而非给成功加密信号——这个发现比方法本身值钱）；水分是 abstract 的 "over 10% absolute" 拿未训练 base model 当分母，对 outcome-only 的真实增益在 AndroidWorld 只有 +4.3 个点，以及 Claude-Sonnet-4 41.0% 的低配 scaffold 对比。冷启动问题（从未成功过的任务没有 milestone，只能退回 outcome-only）也未拆解。相比 LLM-judge PRM，把 promptable judge 换成冻结的 embedding 匹配 + 环境验证的 milestone 库，hacking 面确实更小、更可复现——方向对，执行没走完最后一公里。
- **Rating**: `2` 👀 ，milestone 方向的第一批认真实现，非对称 credit assignment 的 ablation 值得看，但验证锚在 agent 自述文本而非环境状态，离真正 hack-proof 还差关键一步。
