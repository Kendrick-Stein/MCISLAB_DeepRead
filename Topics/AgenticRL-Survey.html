Overview

Agentic RL（Agent强化学习）是指将强化学习方法应用于智能体训练的研究方向，核心目标是让 AI Agent 通过与环境交互、接收反馈信号、优化策略来提升执行能力。该领域正处于从传统 SFT（监督微调）范式向 RL-driven self-improving 范式转型的关键阶段。

核心挑战：Agentic RL 面临三大关键瓶颈：

  1. Credit Assignment Problem（信用分配问题）：多步长程任务中，稀疏的终点反馈（成功/失败）无法将奖励合理分配到中间步骤，导致正确行为无法被强化、失败原因难以定位。这是 GUI Agent、Web Agent、Embodied Agent 等长程决策场景的共同痛点。

  2. Reward Signal Design（奖励信号设计）：如何设计可验证、可程序化、可泛化的奖励信号？Outcome Reward 提供高保真但稀疏信号，Process Reward 提供密集监督但易受 bias 和 reward hacking 影响。两者的权衡是当前研究焦点。

  3. Data Efficiency & Sample Cost（数据效率与采样成本）：Online RL 需要大量环境交互，成本高昂且训练不稳定；Offline RL 稳定但存在 distribution shift 和时序短视问题。如何在有限数据预算下实现高效学习是关键约束。

  4. Environment Engineering（环境工程瓶颈，2026-07 新增）：RL 训练要求大规模并行 rollout、可靠 reset、可分支状态，现有环境在三点上全部失效——2511-DreamGym（WebArena 尽力工程化后仅 4 个并行 session）、2509-AgentGymRL（并行化/full-reset/内存泄漏改造清单）、2606-OpenWebRL（51% 训练失败来自环境接入层）三个独立团队的第一手证词确立环境基建是与算法同级的瓶颈。

研究趋势：从 2023-2026 年，该领域经历了三个重要演进阶段：

  • 探索阶段（2023）：RLHF 在对话场景成熟，开始向 Agent 领域迁移；Process Reward Model (PRM) vs Outcome Reward Model (ORM) 的理论争论开始。
  • 发展阶段（2024）：Agent Q、WebVoyager 等工作尝试 MCTS + self-improvement；Outcome vs Process Supervision 的实证比较出现（arXiv 2408.02100）；DeepSeek-R1 展示 GRPO 在可验证任务上的威力。
  • 成熟阶段（2025-2026）：GUI Agent RL 成为热点（MobileRL、UI-R1、SOLAR-RL）；Self-improving Agent 框架涌现（UI-Voyager、UI-Genie）；Credit Assignment 方法百花齐放（GRSD、ADAGRPO、ADMIRE）。
  • 基建与合成阶段（2025-2026）：RL 需求把环境工程缺陷逼成显性瓶颈，路线对偶分化——引擎做便宜（2510-WebServ、2604-Crab）vs 引擎做没（2511-DreamGym 经验合成）vs live 容错（2606-OpenWebRL）；树结构 rollout（2509-TreeGRPO）与异步训练（2607-SAO）重写 rollout 经济学；任务供给自动化成熟（2410-NNetNav→2502-InSTA 谱系）。

技术路线

2.1 GRPO-based GUI Agent RL 路线

代表论文：2500-UiR1EnhancingEfficient、2500-MobileRL- Online Agentic Reinforcement Learning for Mobile GUI Agents、2500-CraftGuiCurriculumReinforced、2604-ClawGUI、2602-GUILibra、2601-OmegaUse

核心思路：将 DeepSeek-R1 的 GRPO（Group Relative Policy Optimization）方法适配到 GUI Agent 场景，利用任务的可程序化验证特性设计 rule-based reward，实现少量高质量样本的高效 RL 训练。

  • UI-R1：首次将 rule-based RL 系统应用于 GUI action prediction。设计 action type + coordinate + format 三类奖励，仅用 136 条高质量任务在 Qwen2.5-VL-3B 上取得 ScreenSpot 22.1% 提升。核心贡献是证明”少量高质量困难样本 + rule reward > 大规模 SFT 数据”。

  • MobileRL (ADAGRPO)：提出 Difficulty-Adaptive GRPO，通过 difficulty-adaptive positive replay 和 failure curriculum filtering 适应任务难度分布。引入 shortest-path reward adjustment 解决多步任务长度不一致问题。在 AndroidWorld 达到 80.2% 成功率（SOTA）。

  • CRAFT-GUI：基于 GRPO 的课程学习框架，从简单短任务逐步过渡到复杂长任务。结合简单规则信号与模型评估的细粒度奖励机制。在 AndroidWorld 提升 7.1%，私有数据集提升 10.3%。

  • ClawGUI：首个开源 GUI Agent RL 基础设施，集成 GiGPO + Process Reward Model 提供密集 step-level supervision。ClawGUI-2B 在 MobileWorld GUI-Only 达到 17.1%。

  • GUI-Libra（2602-GUILibra，2026-02）：诊断出 GUI RLVR 的 partial verifiability——单条演示动作做 verify 时演示外的正确动作被误判为错，离线 step 指标因此弱预测在线成功率。解法是反 RLVR 惯例地保留 KL trust region（β=0.001-0.005，配 offline-online bound 理论）+ success-adaptive 负梯度缩放（SNGS）降权不可靠负样本；另诊断”长 CoT 伤 grounding”并用 action/grounding token 重加权缓解。AndroidWorld +15.6%（4B）。KL 必要性结论与主流”去 KL”路线直接矛盾，分界条件是 reward 的可验证程度。

  • OmegaUse（2601-OmegaUse，Baidu）：数据质量优先的 SFT→GRPO recipe——grounding 数据从 1.66M 清洗至 111K（估计 40% 原始样本有噪声），grounding 与 navigation 解耦为两个 30B-A3B MoE 模型。ScreenSpot-V2 96.3%、AndroidControl step SR 79.1%，但 AndroidWorld 在线仅 55.7%——离线 step accuracy 优势不自动转化为在线任务完成率的又一实证。

优势：数据效率极高；直接优化执行成功而非模仿文本形式；适合可程序验证的 GUI 动作空间。

局限：依赖 reward 可程序化定义；适用范围偏向结构化单步动作；对长程多步任务需要额外 reward shaping。

2.2 Self-Improving Agent + Reward Model 路线

代表论文：2500-UiGenieSelfImproving、2600-UiVoyagerSelfEvolving、2600-UiMemSelfEvolving、2604-GenericAgent、2606-LearningFromFailure、2505-DarwinGodelMachine、2607-SearchGenBoundary、2509-Misevolution

核心思路：建立数据-模型闭环，让 agent 通过自主探索、失败经验利用和迭代训练持续提升能力。核心创新是先构建可靠 verifier/reward model，再扩张数据。

  • UI-Genie：提出统一 Reward Model（UI-Genie-RM）作为 verifier，同时处理 action-level 和 task-level reward。通过规则验证 + 轨迹扰动 + hard negative mining 构建奖励数据（UI-Genie-RM-517k）。三轮 self-improvement 后达到 SOTA。关键创新：先解决”可验证性”，再扩张数据。

  • UI-Voyager：两阶段框架——Rejection Fine-Tuning (RFT) 自动收集筛选高质量轨迹；Group Relative Self-Distillation (GRSD) 从成组 rollout 中定位 fork points，用成功轨迹为失败轨迹构造稠密步级监督。4B 模型在 AndroidWorld 达到 81.0% Pass@1，声称超越 human-level。核心贡献：失败经验利用 + credit assignment 细化。

  • UI-Mem：Hierarchical Experience Memory，将 workflow、subtask skill、failure pattern 抽象为参数化模板。支持跨任务迁移与 memory-guided exploration。

  • GenericAgent：提出”上下文信息密度最大化”作为长周期 Agent 的核心原则。五层分层按需记忆 + 自我进化（轨迹 → SOP 结晶）。100% 完成率且 token 消耗仅为同类系统 15%-35%。进化的是策略而非参数，是高可行性选择。

  • Learning from Failure（2606-LearningFromFailure）：self-improvement 的对象是 harness 而非权重——失败轨迹经 LLM 诊断转成可注入的 inference-time code patches（visual search / terminal execution / knowledge support / repetition warning 四类），OpenCUA-72B 在 OSWorld 42.3%→48.9%，无需训练且 patch 跨 benchmark 迁移有效。失败轨迹从 rollout waste 变成可复用监督，可作为 successful-case RL 流水线的前置 data-yield amplifier。

  • Darwin Gödel Machine（2505-DarwinGodelMachine）：self-improvement 推到 architecture 层——agent 直接改写自身 scaffolding 代码，用 benchmark 实证验证替代形式证明，archive 开放式探索避免贪心自改卡死（消融证实 population 多样性必要）；SWE-bench 20.0%→50.0%，演化产物跨模型/跨语言迁移。是 Verifier-First 原则在 scaffolding 空间的应用；天花板由 frozen foundation model 决定。

  • SearchGen（2607-SearchGenBoundary）：把”何时调工具”形式化为 knowledge boundary 发现问题——盲目搜索在模型本会的任务上倒退（Qwen-Image-2 70.7→60.4），teach-then-search co-training（DPO 教 generator 内化 + RFT 重校准 8B search reasoner）让 4B generator 追平 Gemini-3-Flash oracle reasoner（31.8 vs 31.2）。最有信息量的实验：校准后的 reasoner 换回 base generator 分数 31.8→26.8——boundary 是 (任务, policy) 的联合属性且随训练漂移，静态校准必然失效。

风险实证（2509-Misevolution，ICLR 2026）：本路线”自增强可能放大系统性偏差”的担忧已被四条演化路径实测确认——自训练（含 Absolute-Zero 式 RLVR）后 safety alignment 累积性衰减；memory 积累引发 deployment-time reward hacking（>60% 案例中 GPT-5 级模型采纳”最大化历史成功指标但损害用户利益”的动作）；tool 创建-复用平均 Unsafe Rate 65.5%；workflow 优化使 ASR 54.4%→83.1%。关键机制：不需要不安全数据，良性反馈循环 + 有偏 credit assignment 就足以偏航；prompt/补训类轻量 mitigation 均不充分。

优势：减少人工标注依赖；失败经验利用提升数据效率；适应动态变化环境。

局限：高度依赖 reward model/verifier 正确性；自增强过程放大系统性偏差的风险已被 2509-Misevolution 实证（原为推测）；工程复杂度高。

2.3 Credit Assignment for Long-Horizon Tasks 路线

代表论文：2604-SOLAR-RL、2602-ADMIRE、2600-ContinualGuiAgents、2606-TRIAGE、2607-SEED、2505-BacktrackAgent

核心思路：直接解决多步长程任务中稀疏奖励下的 credit assignment 问题，通过失败点检测、里程碑奖励、锚定奖励等机制将终点奖励转化为步级监督。

  • SOLAR-RL：半在线 RL 框架，核心创新是从静态离线数据中重建多样化 rollout 候选、检测 first failure point、通过三阶段目标对齐奖励塑形（Aggregation → Base Normalization → Total Reward Alignment）将稀疏终点奖励转化为稠密步级监督。零在线交互成本下达到 online RL 级训练效果。关键设计：不依赖成组 rollout 对比（vs UI-Voyager GRSD）。

  • ADMIRE (Adaptive Milestone Reward)（2602-ADMIRE，全文更新 2026-07）：LLM 从环境 validator 判定成功的 rollout 中蒸馏有序 milestone，milestone 随 policy 共同进化、reward 权重按 epoch 衰减；非对称 credit assignment——成功轨迹只奖命中步（denoising）、失败轨迹给连续 progress reward k/K（scaffolding）。AndroidWorld 7B 44.0%（base 32.8%、outcome-only 39.7%——相对 outcome-only RL 实际增益约 +4.3pp，abstract 的 “>10%” 是相对未训练 base）。ablation 显示失败轨迹的 progress reward 是主要增益来源；难任务分层证实 outcome-only 在 Hard 任务上（9.5%）反而低于 base（14.3%）。关键软肋：milestone 命中判定是 agent 自己输出的 action description 与 milestone 文本的 SBERT 相似度——self-reported progress 而非环境状态锚定，hacking 面从 judge 侧挪到 policy 输出侧（论文未测试该通道）。

  • Continual GUI Agents (GUI-AiF)：提出 Anchoring Point Reward (APR-iF) 与 Anchoring Region Reward (ARR-iF)，在分布漂移（domain-in-flux / resolution-in-flux）场景下保持稳定 grounding。持续学习设定下的 RL fine-tuning。

  • TRIAGE（2606-TRIAGE，2026-06）：在 GRPO outcome advantage 上加语义角色轴——8B thinking judge 把每个 segment 分类为 decisive/exploration/no-progress/regression，固定常数 (1, 0.5, −0.1, −0.5)×λ 做有界修正。ALFWorld 7B 79.6→87.5、WebShop 1.7B +18.4pp。两个格局级发现：(1) 成功轨迹内的 regression 抑制是主贡献（去掉 c_R 几乎退回 GRPO）——SOLAR-RL 在失败轨迹找 first failure point，TRIAGE 证明成功轨迹里”不该强化的段”信息量更大；(2) 增益条件被理论刻画（Cov(c,δ)>0），no-thinking judge F1 从 86.1% 崩到 29.2% 时整体性能低于 GRPO——judge 误差不是加噪声，而是可以翻转干预方向。

  • SEED（2607-SEED，2026-07）：privileged-context 自蒸馏稠密化稀疏 outcome 监督——同一 policy 快照兼任 actor 与 analyzer，为自己的轨迹现场生成 hindsight skill，动作 token 在”带 skill / 不带 skill”两个上下文下的 log-prob 差（confidence gate 加权）构成 token 级蒸馏信号，与 GRPO 联合优化；skill 只在训练时使用、部署零开销。ALFWorld 3B 91.8%（GRPO 75.0%），60% 数据超 GRPO 全量。换静态 skill library 掉 7.4 分是最大 ablation 降幅——hindsight 必须 on-policy。与 2509-TreeGRPO 是稠密化的正交路线：树方法靠结构（需环境可分支），SEED 只需对 logged 轨迹 forward，对有状态 GUI/browser 环境反而更友好；但信号是模型自评而非环境接地，有害 skill 无法被 gate 识别。

  • BacktrackAgent（2505-BacktrackAgent，EMNLP 2025）：把”看 outcome page 做 step 级错误检测”从 prompt 工程变成可训练组件，检测信号双用——推理时触发单步回退重写、训练时当 action reward（对标 DigiRL/DistRL 的 value-based 用法）。Mobile3M task SR +7.59pp。诚实的混淆矩阵暴露机制真实精度：detection precision 75%/recall 44%、恢复成功率 <40%；用 simulated execution page 做 backtrack 时收益从 +5.65 骤降到 +0.70——错误检测的价值几乎全部来自 outcome page 的真实性。局限：检测不归因（二值 yes/no）、回退固定一步、依赖数据集环境可回退性，真实 GUI 不可逆操作被环境设定绕开。

优势：直接解决 credit assignment 核心痛点；适用于长程任务；减少对环境交互的依赖（SOLAR-RL、SEED）。

局限：依赖 ground-truth labels 做 validity 检测（SOLAR-RL）；里程碑质量依赖成功轨迹覆盖度；持续学习稳定性需更多验证；judge/自评类 process 信号的可靠性是硬前提（TRIAGE no-think judge 反伤、ADMIRE 文本匹配可被 policy 侧 hack、SEED 自评无接地）——per-step 信号锚定环境状态变化仍是未解问题（另见 2.9）。

2.4 Test-Time RL / Inference-Time Optimization 路线

代表论文：2500-TestTimeReinforcementLearning、2604-AdaptiveGrounding

核心思路：将 RL 从训练阶段延伸到推理阶段，利用 test-time computation 进行自校正和优化，无需额外标注。

  • GUI-RCPO：基于 Region Consistency 的 test-time RL。多次采样预测的空间一致性作为 reward，仅用 1,272 条无标注数据取得 3-6% 提升。核心创新：prediction set 内部的 self-supervised reward，无需外部标注。

  • PND (Positive-and-Negative Decoding)：training-free 推理框架，通过正向视觉放大路径与负向 counterfactual 路径对比，解决 VLM 的 attention deficit 问题。POPE benchmark 上最高 6.5% 提升。核心洞察：视觉特征在解码时被系统性低估。

优势：无标注需求；training-free；即插即用。

局限：依赖”正确答案附近会形成预测共识”假设；计算开销增加；适用范围偏 bbox-style grounding。

2.5 Principle-Constrained RL / Curriculum RL 路线

代表论文：2500-OrcustStepwiseFeedbackReinforcement、2500-GuiExplorationLabEnhancing

核心思路：通过环境可验证的原则约束或课程学习策略，提升 RL 训练的稳定性和数据效率。

  • Orcust：Principle-Constrained Reward Modeling (PCRM) + Online Virtual Machine-based Trajectory Construction (OVTC)。环境可验证的原则 + LLM 生成的奖励信号 + 自标记子目标。ScreenSpot 提升 22.2%，ScreenSpot-Pro 提升 23.9%。

  • GUI Exploration Lab：POMDP 框架下的多轮强化学习仿真环境引擎。单轮 RL 用于基础记忆，多轮 RL 发展探索策略。静态基准 85% 成功率，交互式环境 90%。

优势：奖励信号可解释性强；动态轨迹生成适应环境变化；课程学习提升适应性。

局限：极端动态环境下表现待验证；计算成本较高；适用范围可能受限。

2.6 Tree-Structured Rollout 与搜索内化路线（2026-07 新增）

代表论文：2408-AgentQ、2410-ExACT、2509-TreeGRPO、2509-TGPO

核心思路：rollout 从独立 chain 换成共享前缀的树结构——树分叉点的兄弟子树回报差天然构成 step 级过程信号，同时节省 rollout 预算；搜索树既是推理工具也是训练数据工厂。

  • Agent Q（2024-08）：最早的”树→偏好对”完整闭环——guided MCTS + LLM 自评过程监督，树上 Q 值差构造 step-level 偏好对做 off-policy DPO。OpenTable 真实站点 18.6% 一天训到 81.7%（+MCTS 95.4%）；过程监督混合 Q 比 outcome-only +6.5pp。作者自白：MCTS 在 live 环境的每个分支都是真实副作用，限制可安全部署的站点范围。
  • ExACT（ICLR 2025）：R-MCTS（contrastive reflection + multi-agent debate 状态评估）刷 VisualWebArena 后，用 Exploratory Learning 把搜索树摊平成单轨迹微调——模型内化 explore/evaluate/backtrack 行为，1/4 token 恢复 ~87% 搜索性能，且 test-time scaling 曲线优于纯模仿。
  • Tree-GRPO（ICLR 2026）：agent step 级节点的 initialize-then-expand 在线树采样，intra-tree + inter-tree 双层组相对优势；1/4 rollout 预算超 chain-based GRPO，小模型多跳 QA 相对 +16~69%。Prop 3.1 证明 intra-tree GRPO 梯度与 step-level DPO 结构等价——与 Agent Q（离线树→DPO）两代方法在结构上收敛。
  • TGPO：树用于消歧而非采样——把多条轨迹中语义相同的 state 合并成树节点，消除同状态偏好标签冲突，配 process reward（子目标进度 + 冗余检测 + 动作验证）与关键分叉步动态加权，在 Online-Mind2Web / C-WebShop 上成功率更高且冗余步更少。

关键约束：树 rollout 要求”能从任意前缀廉价重建状态”——无状态检索/搜索 API 环境免费获得（Tree-GRPO 全部实验在此），有状态 browser/GUI 环境需要 snapshot/fork 引擎支持（2604-Crab、2510-WebServ）。这解释了树方法先出现在 QA/tool 域而非 GUI/browser 域。

优势：纯 outcome reward 即可获得步级过程信号，无需训练 PRM；前缀共享省预算；失败分支进入偏好对（vs RFT 丢弃失败）。

局限：有状态环境未验证（Tree-GRPO 自认）；搜索内化不完全——Agent Q 训练后 81.7% vs +搜索 95.4%、ExACT 恢复 87%，test-time search 的独立价值持久存在。

2.7 RL 环境引擎与经验合成路线（2026-07 新增）

核心结论：RL 训练把环境的工程缺陷逼成显性瓶颈，解法对偶分化为”把引擎做便宜”与”把引擎做没”两支，另有 live 容错第三支。

引擎侧（环境做便宜/可控）：

2.9 Reward/Verifier 可靠性（2026-07 新增）

核心结论：2504-AgentRewardBench（1302 条专家标注轨迹 × 12 judge）把评估器可靠性从轶事变成测量——reward 信号的两大来源双向失败：LLM judge precision 天花板 ~70%（judge 判成功的轨迹 ~30% 实际失败，假阳性直接进 SFT/RL 梯度）；rule-based 评测 recall 仅 55.9%（系统性漏判成功轨迹，官方 benchmark 分数低估 agent 真实能力，WebArena 上低 16.7pp）。

跨域确认（desktop）：2510-CUARewardBench（OSWorld 7 agent 轨迹、272 ORM + 346 PRM 专家标注 × 7 VLM × 3 prompt）在 desktop 域复现同一结论——最佳单模型 ORM precision 82.9%，PRM 明显更难（69.5%）；“script 伤 recall、RM 伤 precision” 跨 web/desktop 双域成立。两个反直觉发现：CUA 专用训练损害 reward 判断（GUI-OWL-32B 一致差于 base model，推理链变短）；prompt 只移动 precision-NPV trade-off 不提上限。UPE（全体一致才判定、否则弃权）把 precision/NPV 提到 89.8%/93.3%，代价是 recall 掉到 56.8%——用覆盖率换可靠性。

结构性修复（交互式验证）：2602-VAGEN 诊断 judge precision 低的根因是 partial observability（文件属性、后台进程等 latent state 截图不可见），解法是让 verifier 也变成 agent——轨迹结束后在终态环境上主动取证（按需调历史截图 / shell / python / GUI 操作，三级递进先便宜后昂贵）。OSWorld 人评 GT 上 92.9% acc / 94.0% precision（最强 judge baseline 84.7%），且不牺牲 recall（95.2%）；弱 actor（负样本占多）下 judge precision 崩到 ~75% 而 VAGEN 守住 88.5%——这正是 RL 训练的真实分布。第一性依据是验证不对称性：同一模型解任务 SR 55.9%（28.5 步）、做验证 acc 83.1%（17.4 步）。边界：未跑真 RL 闭环，actor 与 verifier 共享动作空间时”伪造表面证据”的对抗通道未测。

process 信号的失效证据：2607-EvoCUA15（Fig 7）实证 PRM 在难任务上分数持续上升而 outcome reward 停滞——model-judged process reward 被 hack，credit 应锚定可执行的环境状态变化而非 reasoning 质量；2602-ADMIRE 的 milestone 判定用 policy 自己输出的 action description 做文本匹配，把 hacking 面从 judge 侧挪到 policy 输出侧；2606-TRIAGE 给出机制级因果链——judge 精度决定修正项协方差符号，no-thinking judge（F1 29.2%）使方法跌破 GRPO 基线：judge 误差不是加噪声，而是翻转干预方向。

2.10 训练算法：异步、蒸馏与跨模态扩展（2026-07 新增）

  • 2607-SAO：group 采样与异步训练结构性不兼容（group 内凑齐才能算 relative reward，最慢样本卡死全组）——single-rollout 采样 + value model（critic）+ GAE 替代 group baseline，双侧 token-level importance masking 复用 rollout log-prob。AIME2025 97.3% vs GRPO 84.2%；vanilla GRPO 约 160 步崩溃、SAO 稳定 1000 步；已用于 GLM-5.2（750B-A40B）训练。代价：回归 actor-critic，复杂度从”凑 group”转移到”训好 value model”（running-mean baseline 替代 critic 掉到 79.8%）。
  • 2607-UIMOPD：跨平台 GUI agent 的 platform-conditioned on-policy distillation——desktop/mobile 各训 32B teacher，按 rollout 平台路由蒸馏进共享 8B student（reverse KL + adaptive KL masking），OSWorld 38.2% / MobileWorld 12.0% 双端平衡；对照 model merging（TIES）在 MobileWorld 崩到 0%。缺 routing 单独 ablation，归因未闭合。

  • 2606-AgentsA1：全域 SFT 使 general agentic / IF 能力相比基座下降（long-thinking 推理模式与 multi-turn agentic 模式冲突），OPD 阶段才恢复。
  • 2607-REAL（ECCV 2026）：SFT 第 2 epoch 使 in-domain split 上升但开放词表 split 倒退（BC 过拟合专家轨迹），从 1-epoch checkpoint 起步的 GSPO 在线 RL 修复并反超；另一算法数据点——弃 GRPO 用 GSPO，因 step-wise importance ratio 在长轨迹下方差爆炸。附带 sim-to-real 证据：MCP 统一工具接口下高层策略零改动迁移真机（60 episodes 78.3%）。
  • 2607-RingZero：1T zero RL 的 phase-specific objective——探索期 token-level loss 鼓励长轨迹、中期 self-distillation 压缩 CoT 并重置数值偏差、稳定期 sample-level loss 去长度偏置、末期按难度分层预算；AIME 2026 93.2%。长度激励是阶段性工具而非永久 objective，该 schedule 对 agent RL 的适用性待验证（任务全为数学）。

含义：报告 agentic RL 增益的最低标准应包含 headroom 控制与 paired statistics（2607-GRPONullWebAgent 的方法论示范）；工程上，“先测 group reward variance / pass-rate 再决定投 RL 还是投蒸馏”应成为默认流程（与 2.8 的 policy-aware pass-rate 校准同一逻辑）。

Key Takeaways

  1. GRPO 正在重塑 GUI Agent 训练范式：UI-R1 证明 136 条高质量任务 + rule-based reward 的 RL 训练可达到或超越大规模 SFT。RL 直接优化执行成功而非模仿文本形式，数据效率显著更高。这是从”模仿学习驱动”向”可验证策略优化驱动”的关键转折。

  2. Credit Assignment 是长程 Agent RL 的核心瓶颈：SOLAR-RL 的 first failure point detection、UI-Voyager 的 GRSD fork point 定位、ADMIRE 的 milestone reward 都是针对稀疏奖励下步级监督不足的解决方案。该方向窗口正在迅速关闭（多个 concurrent work 覆盖大部分设计空间）。（2026-07 更新：拥挤度再升——2606-TRIAGE 角色类型化修正、2607-SEED privileged-context 自蒸馏、2607-ToolVerse TARA gated future advantage、2607-EvoCUA15 STEPO 均已占位；TRIAGE 补充了一个被忽视的信号位——成功轨迹内的 regression 抑制比失败轨迹的探索加分贡献更大。）

  3. Self-Improving Agent 框架强调 Verifier-First 原则：UI-Genie 先构建可靠 reward model，再扩张数据；UI-Voyager 先 RFT 筛选高质量轨迹，再 GRSD 构造步级监督。“先解决可验证性，再放大数据”成为共识设计模式。反面证据（2026-07 更新）：2509-Misevolution 实证缺乏 verifier gating 的自演化在 model/memory/tool/workflow 四条路径上均放大风险，把该设计模式从经验共识升级为安全必需；2505-DarwinGodelMachine 则证明 benchmark 实证验证可支撑 architecture 层自改——但天花板由 verifier 覆盖的域决定。

  4. Outcome vs Process Reward 的权衡是核心理论争论：Outcome Reward 保真度高但稀疏，Process Reward 密集但易受 bias。ADMIRE 的 adaptive milestone、SOLAR-RL 的三阶段 alignment 都是在两者之间寻找平衡。PRM vs ORM 的实证比较（arXiv 2408.02100）显示 PRM 在需要逐步推理的任务上更优。

  5. Test-Time RL 开辟新范式：GUI-RCPO 的 region consistency reward、PND 的 contrastive decoding 都是在推理阶段进行 RL 式优化，无需额外标注或训练。这是与 train-time scaling 并行的重要路线。

  6. 开源 RL 基础设施开始出现：ClawGUI 是首个开源 GUI Agent RL 基础设施，填补训练-评测-部署的完整闭环。这标志着该领域从论文方法创新进入工程基础设施阶段。（2026-07 更新：该判断已被大幅强化——2509-AgentGymRL 统一多环境框架、2510-WebServ RL-ready 引擎、2606-OpenWebRL live RL 全配方开源。）

  7. 树结构 rollout 让 outcome reward 产出免费过程信号（2026-07 新增）：2509-TreeGRPO 证明 intra-tree 组相对优势与 step-level DPO 梯度等价、1/4 预算超 chain GRPO，与 2408-AgentQ（离线树→DPO）两代方法结构收敛——“分叉点兄弟子树回报差”是不训 PRM 就能拿到的步级监督。搜索行为可蒸馏进模型但不完全（2410-ExACT 恢复 87%、Agent Q 训后 search gap 持久），test-time search 保留独立价值。

  8. 环境工程是 agentic RL 被低估的第一瓶颈（2026-07 新增）：2511-DreamGym”4 并发上限 + 手动 reset + 评测误判”证词、2509-AgentGymRL 改造清单、2606-OpenWebRL 51% 失败在环境接入层——三个独立团队的一手证据。解法对偶分化：把引擎做便宜（2510-WebServ 240× 存储 / 2604-Crab p50 0.1s checkpoint）vs 把引擎做没（DreamGym 合成经验，Theorem 1 证明只需 reward 保真 + 转移域一致，无需像素级复刻）。

  9. Reward/verifier 噪声直接进入梯度且被系统性低估（2026-07 新增）：2504-AgentRewardBench 测得通用 LLM judge precision ≤70%（judge-filtered 训练数据 ~30% 假阳性）、rule-based recall 55.9%（官方分数低估真实能力）；2510-CUARewardBench 在 desktop 域复现（ORM 82.9% 上限、PRM 更难）。出路是 verifier 特化小型化：2606-OpenWebRL 蒸馏 8B judge 89.8% 超 GPT-4o；2412-PAE 的”提案/评判 ≪ 执行”能力不对称解释了为什么这条路可行——2602-VAGEN 进一步把该不对称定量确立（同一模型 verify acc 83.1% vs solve SR 55.9%，步数还少 40%）。但特化方向有讲究：CUA 执行能力的 specialization 反而损害 reward 判断（2510-CUARewardBench）。

  10. 任务供给已可自动化，但强绑定采集环境（2026-07 新增）：2410-NNetNav→2506-GoBrowse→2412-PAE→2502-InSTA 谱系把任务供给推到 150k 站点、$521 成本量级；但沙盒合成数据 OOD 崩塌（Go-Browse WebArena 21.7% → Online-Mind2Web 5.33%）表明任务多样性比单站深度更重要。（2026-07 二批更新：供给谱系延伸出 web——2601-EvoCUA 的 Generation-as-Validation（任务与可执行 validator 共生成）把 reward 问题转化为生成问题，经验 20k→1M 单调增益；2607-ToolVerse 依赖图拓扑采样；2603-WebChain 证明反爬/登录墙后的任务分布只能人工采。）

  11. RL 增益是条件化的，不是默认存在（2026-07 新增）：2607-GRPONullWebAgent 的受控 null（mastered 任务无可信提升、positive control 有 headroom 时 +22pp）、2607-MAG 的零方差 stall（base 成功率 <10% 时必须 expert injection）、2602-GUILibra 的 partial verifiability 下 KL 必要性、2607-MuonAgenticRL 的 optimizer×estimator 交互——四篇独立工作把”何时 RL 有用”从直觉变成可检验条件。推论：报告 RL 增益必须控制 headroom 并做 paired statistics；投 RL 前先测 group reward variance。

  12. 监督资产是 policy 相对的，静态化即失效（2026-07 新增，本批最强跨论文 pattern）：2607-SEED 静态 skill library 是最大 ablation 降幅（−7.4）；2607-SearchGenBoundary 校准好的 search reasoner 换 generator 即失效（31.8→26.8）；2607-EvoCUA15 数据子集对 8B 有效、对 32B 降分；2602-ADMIRE milestone 必须随 policy 进化。四个独立域（skill / tool 边界 / 训练数据 / reward 锚点）同一结论：围绕 policy 的一切监督资产必须与 policy 共演化，一次性构建的静态资产随训练漂移失效。

  13. 交互式验证突破 judge precision 天花板（2026-07 新增）：2602-VAGEN 让 verifier 变成 agent（在终态环境主动取证），92.9% acc 且 precision/recall 双保——目前唯一不牺牲 recall 的路线；对照 2510-CUARewardBench UPE 用弃权换 precision（recall 崩到 56.8%）。代价是 verifier 与环境实例强耦合（离线轨迹不可用）、对抗鲁棒性未测。

  14. “分解后保持 advantage 组归一”是 multi-turn/multi-agent RL 的通用设计模式（2026-07 新增）：2607-EvoCUA15 STEPO 在 step 轴（A_i/|T_i| 恢复 group 零和）、2602-WideSeekR1 在 agent 轴（token/agent 双层重加权）、mini-group batching 在系统层——三个实例同一原理：轨迹被分解为更细粒度样本后，naive 处理会引入长度/数量加权偏差，必须显式恢复组平衡。

Open Problems

核心技术挑战

  1. 长程任务的 Credit Assignment 稳定性：现有方法（GRSD、first failure point detection）依赖状态对齐或 ground-truth labels，在真实界面（动画、弹窗、个性化布局）中可靠性存疑。如何在高噪声、多分支、状态不完全可观测场景中稳定实现步级监督？

  2. Self-Improving 的系统性偏差风险（已由推测升级为实证，2026-07）：2509-Misevolution 沿四条演化路径实测确认自增强过程放大偏差——safety 累积衰减、memory reward hacking、tool Unsafe 65.5%、workflow ASR 54→83，且 prompt/补训类轻量 mitigation 均不充分。开放问题从”风险是否存在”变为”如何构建 evolution-aware 的外部 verifier gating——每步演化产物过外部验证而非事后补丁”。GenericAgent 的 SOP 结晶验证机制值得借鉴。

  3. Reward Signal 的泛化边界：Rule-based reward 对结构化单步动作有效，但对长程规划、模糊指令、动态状态变化如何设计？Outcome reward 与 process reward 的最优组合策略是什么？

数据与评测挑战

  1. 真实环境评测覆盖率不足：当前 benchmark 多在仿真器测试，缺少真实设备、真实账号、真实网络环境下的系统评测。对抗性场景、隐私泄露、错误恢复等高风险情况几乎未被覆盖。

  2. 过程级评估自动化难题：如何在不引入额外人工标注的前提下，准确捕捉复杂任务中每一步的关键状态变化？Pass@1 vs step-level accuracy 的权衡。

  3. 跨域/跨分辨率泛化验证：Continual GUI Agents 提出 APR-iF/ARR-iF，但在更复杂界面变化（动画、主题切换、个性化布局）下的鲁棒性需更多验证。

系统与工程挑战

  1. RL 训练稳定性与采样成本：GRPO、PPO 等方法对采样策略、超参数敏感。如何在保持稳定性的同时控制环境交互成本？Offline RL + semi-online（SOLAR-RL）是否是最佳折中？（2026-07 更新：设计空间仍在扩张——2607-SAO 指出 group 采样与异步训练的结构性冲突并回归 actor-critic（GRPO 160 步崩溃 vs SAO 1000 步稳定）；2509-TreeGRPO 用前缀共享把预算需求降到 1/4；2509-AgentGymRL 的 horizon 递增课程给出崩溃模式的经验解法。）

  2. Self-Improving 工程复杂度：UI-Genie、UI-Voyager 等框架涉及多模块协调（数据生成、筛选、蒸馏、迭代训练），实现门槛高。如何设计更简洁的自增强架构？

  3. 推理效率与实时部署：Test-time RL、multi-module framework 都增加推理开销。如何在保持长程决策质量的同时满足实时响应需求？

  4. 有状态环境的树分支缺口（2026-07 新增）：树 rollout 的需求端（2509-TreeGRPO 仅验证于无状态检索 API）与引擎供给端（2604-Crab 限 shell 沙盒、2510-WebServ 无端到端 RL 实验）尚未合流——browser/GUI 全栈状态的 fork 原语 + 树结构 RL 的端到端验证是双侧空白。

  5. 合成经验与真实 verifier 的组合（2026-07 新增）：2511-DreamGym 用经验模型兼任转移函数与 reward（ε_R 可靠性缺外部审计），2504-AgentRewardBench 证明通用 judge precision ≤70%——“合成转移 + 程序化 verifier 压低 reward 误差”的混合路线两侧证据齐备但无人做。

  6. 交互式 verifier 的 RL 闭环与对抗鲁棒性（2026-07 新增）：2602-VAGEN 精度足够当 reward 用（92.9% acc）但止步于 Best-of-N——17.4 步/条的验证成本在 RL rollout 规模下的可担性、以及 actor 与 verifier 共享动作空间时”伪造 verifier 会检查的表面证据”的 reward hacking 通道，均未验证。

  7. process 信号的环境状态锚定（2026-07 新增）：2607-EvoCUA15 实证 model-judged PRM 被 hack 并指出方向（credit 锚定可执行的环境状态变化 / milestone / counterfactual replay）；2602-ADMIRE 只做到一半——milestone 内容锚定了 validator 判定的成功轨迹，但 per-step 命中判定仍是 policy 自报文本的相似度匹配。把 milestone 绑定可查询的 state predicate（如 AndroidWorld validator 的中间态版本）是明确可做但无人做的下一步。
