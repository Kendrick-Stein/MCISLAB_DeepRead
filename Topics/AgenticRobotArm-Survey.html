Agentic Robot Arm：GUI、VLA 与机械臂闭环控制

Agent 通过接口调用机器人执行物理任务的研究见 RobotUseAgents-Survey。

Overview

Agentic 机械臂的核心问题是如何用动作后的观测维持任务进度。

机械臂系统里的「闭环」至少发生在三个时间尺度。控制器用位置、速度或接触反馈维持轨迹和约束。VLA 可以滚动生成短动作序列，根据新观测修正执行。任务级 Agent 则判断当前目标是否已经实现、出现了什么偏差，以及应该重试、改变策略还是停止。执行同一个任务可能需要三层，单层实验只能支持相应尺度的结论。2303-DiffusionPolicy · 2603-RoboClaw · 2609-LIBERORecover

2. 机械臂控制与 VLA

早期视觉—运动策略解决的是怎样从相机观测生成可执行轨迹。ACT 将若干时刻的动作一起预测，Diffusion Policy 通过条件去噪生成动作序列，再用 receding horizon 根据新观测重算。RT-2 将 VLM 扩展到机器人动作 token，使图像、语言和动作进入同一训练配方。OpenVLA 延续离散方案，π0 用连续 flow matching 输出 action chunk。OpenVLA-OFT 则表明，连续动作和并行解码也可以用于对已有 VLA 做下游微调。2303-DiffusionPolicy · 2307-RT2 · 2406-OpenVLA · 2410-Pi0 · 2502-OpenVLA-OFT · ACT / ALOHA

对部署而言，动作表示的选择决定了模型输出由谁解释、能否频繁更新，以及何时需要更强的局部反馈。下表按动作接口组织代表方法。

软件坐标、相机像素、机器人基座和工具坐标是不同状态空间。对物理触屏，通常要把屏幕位置映射到机器人可达的面内目标，再处理沿法向接近、接触、抬起和下一帧确认。对夹取和插入，末端位姿只是控制目标，执行还受夹爪、碰撞、力和轨迹约束。屏幕触点和相机中的物体框都可作为中间目标，但它们提供的深度、可达性与接触信息不同。2312-RoboTest · 2512-SeeControl · 2307-VoxPoser

动作块的预测长度、实际执行长度和低层伺服频率应分别报告。较长预测区间能让动作连续，较长的实际承诺区间则会推迟利用新观测的时刻。Real-Time Chunking 通过保留已经在执行或即将执行的部分来衔接异步生成的动作块。恢复场景里，LIBERO-RECOVER 另外报告了执行块缩短时的收益，实验只支持相应策略与仿真设置。部署比较还需要把传感到闭环动作的时延，以及停顿和重规划成本，一起纳入。2609-LIBERORecover · Real-Time Execution of Action Chunking Flow Policies

3. Agentic Manipulation 的技术路线

3.1 技能编排与显式几何

SayCan 用语言模型选择符合目标的技能，并以当前状态下技能可执行性的估计约束选择。VoxPoser 把语言指定的空间约束构造成 3D value maps，交给运动规划器生成轨迹。前者依赖技能库能覆盖任务，后者依赖能从感知中恢复足够的几何信息。二者都把基座模型的语言理解与机器人的可执行性通过显式接口连接起来。2204-SayCan · 2307-VoxPoser

这条路线允许分别检查语义目标和物理可行性，但检测到前置条件缺失后，系统还需要知道怎样补齐条件。交互反馈因此成为后续系统的核心。Inner Monologue 给规划器回传场景、执行结果或人类反馈。RoboClaw 进一步面向长程数据采集和执行，以成功判断连接子任务，并把部分可修复失败引入恢复环。2603-RoboClaw · Inner Monologue

3.2 把 VLA 当作受调度的控制器

RoboClaw 用状态判断区分能直接重试的操作与需要先恢复场景的失败。Harness VLA 把几何前置动作、运输和可观察的局部 VLA 接触操作组合起来。它的 LIBERO-Pro Table 3 在同一内部协议下报告直接运行冻结策略 50.0%，few-shot Codex 72.1%、Claude Code 82.4%。方向并非在每个场景一致。标准 LIBERO 上的整体平均变化较小，某些子集下降。真机实验由人完成初态重置与结果验收。2603-RoboClaw · C1–C4

这些结果表明，改动 VLA 之外的执行方式可以改变成功率。要判断收益由什么产生，需要固定 checkpoint、传感器和重试预算，并分别移除几何原语、记忆、验证器或额外观测。用解析动作完成原本交给 VLA 的阶段，也是系统级收益的一部分。2607-HarnessVLA · Auriga 的 planning–execution 诊断

3.3 让 VLM 直接执行语义动作

Show-Harness 让 VLM 输出细粒度语义操作单元，经硬件专属解释器落到末端指令。GUMI 把同一套操作单元做成浏览器界面，用于人或模型采集示范。在主评测里，模型直接发语义命令。因此，主评测支持「语义接口＋解释器能驱动真机」，GUMI 报告支持「GUI 可以用来采集操作数据」。两个实验回答的是不同问题。2609-ShowHarness · §§3–5

AMP1 同样让通用模型借助 harness 读图与发动作，并比较基础接口和带抓放辅助例程的接口。RoboLab-120 中从基础接口换为辅助接口，Opus 5.5 从 82.8% 降至 75.3%，Qwen3.6-35B-A3B 从 14.2% 升至 31.8%。固定模型比较接口可以识别单个系统的收益，跨模型重复同一对照才能识别这种交互。C1–C2

3.4 从一次恢复走向跨轮改进

一次回合内纠正抓取、跨回合写入经验和重训低层 policy 是三种干预。Embodied-Harness 使用冻结的 Actor 和 Reflector，将轨迹诊断写回 harness。预印本报告 Piper 真机三任务各 10 次，系统成功 29/30、π0.5 12/30。逐轮改进曲线来自仿真，因而真机横向对照和跨轮学习是两份证据。ENPIRE 及后续 ASPIRE 提供另一类研究设置，允许编码 Agent 通过试验改动控制程序或积累可复用技能。任务验证、自动重置覆盖与人为提供的执行基础设施决定这类循环的适用范围。C1–C3 · ENPIRE · ASPIRE

证明跨任务改进需要冻结一次改动后的系统，在预先隔离的任务和机器人条件上重新评测。还需与同预算重试、只扩充示范和人工维护的 harness 比较，区分持久改进与对同一批试验的适配。2611-EmbodiedHarness · 2611-AMP1

4. GUI × 机械臂的实证

物理 GUI 交互首先出现在非侵入式软件测试。RoboTest 只从外部相机观察界面，以四自由度机械臂实施触屏动作，用探索策略发现界面和潜在 bug。See-Control 把目标改为语言指定的手机任务，输入使用屏幕镜像，动作由真机械臂实施。RFNIT 提出外部摄像、LLM 推理与真实触屏的组合，正文给出视觉与物理点击原型结果，并将完整长程验证列为评测计划。2312-RoboTest · 2512-SeeControl · 2604-RFNIT

6. 失败模式与负证据

标准分数会掩盖对观测扰动的敏感性。 LIBERO-Plus Table 1 中，OpenVLA-OFT 原始设置为 97.1%，改变相机为 59.7%，改变初始位姿为 37.2%。这是同表上的单因素结果。另有独立 benchmark audit 发现部分操作任务可被捷径完成，并指出小幅增益对抽样和评测口径敏感。因而「标准设置有高成功率」与「能根据改变过的场景可靠行动」需要不同证据。 LIBERO-Plus §2.3 Table 1 · What Are We Actually Benchmarking in Robot Manipulation? §§3–6

从已知失败态启动和正常执行需要各自测量。 LIBERO-RECOVER 把从已知失败状态重新启动的测试，与从标准初态出发的测试区分开来。加入恢复数据后，从失败态启动的成绩上升，标准初态的总成功率变化较小且方向不一致。标准分数仍无法直接估计在线发生失误后的条件恢复率。失败检测、及时中断和修复动作需要分别测量。C1–C3

接口辅助的收益依赖模型与任务。 AMP1 的额外辅助抓放例程在不同模型上的消融方向相反。Harness VLA 在扰动协议中的增益也没有在标准 LIBERO 的各个子集重现。比较 agentic 架构时，接口复杂度、额外信息与执行预算都必须显式计入。C2 · C3

物理动作与数字结果会分离。 ROSWORLD 记录了触点偏离、无意触发与输入焦点错误，且多数失败在耗尽决策预算后发生。See-Control 的跨 App 成绩说明即使具备物理接触手段，任务规划、动态页面跟踪和长程状态仍能成为瓶颈。两组实验证据来自不同任务与装置，不能把差异归给单一因素。C4 · C3

跨域混合数据可能降低两域表现。 Magma 的朴素混合条件在 ScreenSpot 和两个 SimplerEnv embodiment 的指标上低于各自单域配方。引入统一标记与轨迹监督后，这三项相对于同数据配方的无标记对照提高。结论对应这组数据配方与模型，跨域共享的收益还需要在混合工作流中测量。C3

Key Takeaways

  1. 比较 GUI＋机械臂系统时先固定 GUI 的角色。 真臂触屏可从 See-Control 和 RoboTest 入手，GUI 发指令可从 Show-Harness 入手，数字任务改为物理输入的配对比较可从 ROSWORLD 入手。三类任务所依赖的观测和 verifier 不同。2512-SeeControl · 2312-RoboTest · 2609-ShowHarness · 2611-ROSWORLD
  2. 同时测任务反馈与运动反馈。 机械臂到达屏幕并不保证软件接收了预期事件。把接触事件、界面变化与终态分别记录，才能判断下一步应重做动作、换目标还是重新规划。2611-ROSWORLD · 2609-LIBERORecover
  3. 用等预算消融判断 agentic 模块的净收益。 固定同一低层策略、传感与评测任务，分别打开重规划、状态核验与经验记忆。额外执行轮数或几何捷径也要记入资源与因果比较。2607-HarnessVLA · 2611-AMP1
  4. 对持续改进做隔离后的第二次评测。 在已见任务上用执行反馈改 harness 之后，冻结版本，在同种能力但新任务族上评测首次成功和成本。逐轮重试曲线只能回答原试验协议下系统是否变好。2611-EmbodiedHarness

Open Problems

Observed Tension — GUI 到物理接触的成本来自哪里。 以 ROSWORLD 的同任务配对为起点，在真实固定工作站复跑三个设置：原生软件输入、外部相机下的校准触屏、可观测接触的触屏。固定任务计划和软件 evaluator，分别操纵几何定位与接触确认。若修正接触后任务仍失败，才能把主要成本定位到对界面状态或进度的判断。最接近的设计是 ROSWORLD 的配对协议与 See-Control 的真机接触。2611-ROSWORLD · 2512-SeeControl

Observed Tension — GUI 作为通用前端的收益是否独立于底层执行器。 让同一基座模型通过 GUI 和 schema-matched API 操作同一机械臂。两条件暴露相同观测、原语、历史和安全约束，另加有无 VLA 局部控制的二乘二消融。用任务成功、步骤、耗时和人工干预判断收益来自前端、执行器还是它们的交互。最近证据在 GUMI 的接口设计与 CUA 的软件对照，仍缺等口径真机机械臂结果。2609-ShowHarness · 2611-CUAEmbodiedGeneralists

Observed Tension — 如何把已知失败态下的恢复变成在线能力。 用同一批可恢复失误，分开比较从失败快照开始、在线检测后重规划、等预算盲重试。观测指标包括误报、发现时延、恢复率和不可恢复状态比例。最接近的 prior art 是 LIBERO-RECOVER 与 RoboClaw。对 GUI 与机械臂的混合任务，错误可能仅出现在一种状态可见性里。2609-LIBERORecover · 2603-RoboClaw

Observed Tension — 经验证的经验能否在新任务继续减少干预。 对同一机械臂、同一预算比较空白 harness、写入失败诊断、写入诊断并做独立回归验证三种设置，训练任务与测试任务按任务族隔离。主要指标用新任务首次成功、干预次数和旧任务回退。Embodied-Harness 给出接近的反思机制，AMP1 提供模型与接口交互的对照动机。2611-EmbodiedHarness · 2611-AMP1

可用一个固定工作站实现最小混合任务。软件工单给出待分拣对象和容器，机械臂完成放置，软件随后录入取自物理现场的容器标记。分别核验工单状态、对象是否在正确容器、记录中的标记是否匹配。按回合记录三次状态变化的时间与证据，可以区分 GUI 定位、实体选择、接触控制和回写错误。HomeLoop 对机器人与 IoT 的仿真协同提供了时序结果评测的参照。 HomeLoop §§3–4
