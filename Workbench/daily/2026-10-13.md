# 🔪 今日总结

本周 12 篇里有 6 篇在做同一件事：把 self-evolution 的载体从权重挪到权重之外的文件。Memento 3 改 rulebook 再编译成 Python，EviSkill 改 skill 里的单条 edit，SkillForge 给每条 skill 记 fitness 并按生命周期退役，EvoBelief 改一组可证伪的规则，PhysEvo 改 tool 和 skill 的代码，AgentGarten 改一份 Markdown playbook。六篇的 LLM 全部冻结。真正跨论文收敛的不是"演化"这个词，而是接受条件：改动必须先过一道可重放或可证伪的 gate 才生效——EviSkill 的 edit 级 replay、Memento 3 的 cell-exact replay、EvoBelief 的跨 episode 证据门槛、PhysEvo 的同场景不降分。这是本周唯一一致的设计，也是最能直接搬走的部分。

没有一篇拿到 3，问题集中在证据而不是想法。Memento 3 的 rulebook 消融只覆盖 3 个游戏、每格一个数、未声明运行次数；AgentGarten 每个世界每轮只有 1 个 episode；PhysEvo 每任务 5×1 采样；EviSkill 和 SkillForge 的主表都只有单次运行或仅评测采样 seed。头条数字还普遍借了别处的力：SRD 最亮的 +24.16 pp 出在一个本身低于未训练模型的 OPSD baseline 上，换到最强 host RLSD 只剩 0.5 到 1.5 pp；SoftwareGym 对齐数据量后输给 OSWorld 原生轨迹；Memento 3 的 mean RHAE 100.0 对应的 baseline1 已经是 99.0，而它的 harness 就是从 baseline1 改出来的。

环境合成这条线上，Trace2Env 贡献了本周最该被引用的东西，是指标而不是方法：ALFWorld 上 Direct Prompting 在 sim 内成功率 97%，把同一动作序列回放到真实环境只剩 3%（CR 0.032）。这条直接打到 SoftwareGym 和 AgentGarten——两篇都造了合成环境，都没测在自己环境里学到的东西回到真实环境还剩多少。剩下三篇走机制路线：S-Space 在 MLLM 中间层找到一个 3 维线性坐标子空间，读出准确率能反超直接作答（89.36 对 73.60），但"瓶颈在空间变换而非感知"这个结论建在给定旋转角的 oracle 上；Taming VLAs 用 proprioception 残差做零标签 test-time adaptation，真机从 43 升到 76，可惜这个主结果没有配套消融；WebMirage 把攻击目标对齐到浏览器真正执行的 action token，ASR-S 91.9% 对最强 baseline 17.4%，但全程白盒且只测小开源 VLM。

## 论文点评

### SoftwareGym
- **Title**: SoftwareGym: Scaling Computer-Use Agent Training with Diverse Synthesized Software Environments
- **Institutes**: Shanghai Jiao Tong University, Zhejiang University
- **Source**: [link](https://arxiv.org/abs/2610.12611)  📰 HF Daily ⬆️ 85   **📒 论文笔记**: [[2610-SoftwareGym]]
- **核心**: 作者用 Codex CLI + GPT-5.5 跑一条三段式流水线，从零合成独立的 Avalonia 桌面应用当 CUA 训练环境。三段分别是功能契约加多风格 UI 设计、编码实现、由 Seed 2.1 Pro 执行 GUI 测试并把失败回灌修复，最多迭代 3 版。最终得到 182 个应用、12 个类别，平均 GUI 任务通过率 91.5%（v1 54.9%，v2 81.1%）。只用这些应用上的轨迹对 Qwen3.5-9B 做 SFT，OSWorld 子集（8 域 244 题）的 Pass@3 从 41.39% 升到 56.97%，训练中不含任何 OSWorld 应用、任务或轨迹。代价是每个应用约 4 小时、\$70.76。
- **锐评**:
  - 全文最硬的发现在附录 C.2，不在主表。两种修复从同一个 50.4% 起步：GUI-guided repair 升到 83.1%，source-only repair 反降到 48.8%，36 个应用里 36 个都是前者胜出。"代码 agent 读源码自我修复"在 GUI 功能上会退化，这个反例很干净。做合成环境的人都该把运行时 GUI 反馈当必需品，而不是可选项。
  - Table 3 的结论不利于标题。在 3,715 条轨迹对齐的条件下，OSWorld-only 训练得 61.48%，SoftwareGym-only 只有 56.97%。合成环境是"够用的替代"，没有比原生环境更好。两者拼接后 OSWorld 反而掉到 58.61%，合并唯一的收益出现在 SoftwareGym-Bench（47.5%），而这个基准和训练数据出自同一个应用库。
  - "strictly out-of-domain"只在实例层面成立。12 个类别和 OSWorld 的 8 个应用一一对应（Calc 对 Table、Impress 对 Slides、VLC 对 Video 等），属于按考纲出模拟题。类别之外的软件能不能迁移，完全没有测。
  - 56.97% 对 EvoCUA-8B 的 56.56%，差 0.41 点，244 题里不到 1 题，只是平手。基座、数据、规模都不同，"合成环境路线优于合成轨迹路线"无从谈起。指标还是 Pass@3、单次运行、没有方差，部署可靠性被高估。
  - Table 2 里"40.0% 超过 Qwen3.7-Plus 38.3% 和 EvoCUA-32B 35.0%"是主场作战：120 题出自同源应用，每类 10 题，差 1 题就是 10 个点。SFT 后 Slides 从 30 掉到 20、Table 从 20 掉到 10，作者没有解释。
  - 训练轨迹由谁生成，正文没有交代，附录只提到 teacher schema 和 GPT-5.5 judge 过滤。如果教师是 Seed 2.1 Pro 一类的强闭源模型，增益里有多少来自环境、多少来自蒸馏，分不开。名字叫 Gym 却一行 RL 都没做，环境作为 RL 环境的价值（reward、重置、吞吐）一概没有验证。
  - 91.5% 通过率是"自己出题、自己考"：测试用例由 manual 生成，v1 之后固定，同一个 GUI agent 反复考，有为过测试而修的风险。它不等于功能真实正确。
- **Rating**: `2` 👀，GUI-guided 修复对比 source-only 修复的 36/36 消融值得直接借鉴，但核心卖点"合成环境可以替代原生环境训练 CUA"被自家 Table 3 打折：对齐数据量后输给 OSWorld 原生轨迹，对外比较也只和 EvoCUA-8B 打平。

### WebMirage
- **Title**: Adversarial Images Hijack Web Agents from Visual Grounding to Browser Execution
- **Institutes**: University of Utah
- **Source**: [link](https://arxiv.org/abs/2610.09240)  📄 arXiv   **📒 论文笔记**: [[2610-WebMirage]]
- **核心**: 视觉 web agent 被攻击成功的标准，本文改成浏览器实际执行了什么动作，不再看模型输出了什么。攻击者只控制页面上一张第三方图片（l∞=16/255）。WebMirage 做了两件事。第一，训练时重组页面，把同类 companion 图片和目标位置一起随机化，因为 label 到元素的映射随渲染变化，每次都按当前映射重算目标输出。第二，用 CodeQL 做数据流分析，只优化真正流进 `execute()` 的 action token，目标长度从 88.0 降到 9.5 token。在 4 种 agent 配置、2,250 个任务上平均 ASR-S 为 91.9%，最强 baseline Chameleon 是 17.4%。现有的三种 agent 级防御（WebSentinel、Consistency Check、WebGuard）下 ASR-S 仍有 86.5-91.9%。
- **锐评**:
  - 最值钱的是 problem formulation，不是优化技巧。Table 7 是证据：raw-output 监督只有 70.4%，并且在 1500 epoch 内四种配置都没收敛；改成 execution-aligned 后到 91.9%，441 epoch 收敛。增益主要来自把目标缩短，跟优化器强不强关系不大。这条可以直接用到任何 agent 攻防工作上：loss 要对准执行管线真正消费的那段输出，不对准模型文本。
  - 标题里的 "Hijack Web Agents" 说过头了。全部实验都是白盒，backbone 只有 4B-34B 的开源 VLM（LLaVA、MiniCPM-o、Phi-3-V、Qwen2-VL、CogVLM），没有任何闭源 agent。Table 6 的跨架构迁移只有 4.5-23.8%，所以对 GPT 或 Claude 这类部署中的 agent 没有任何执行级证据。说"白盒开源 agent 很脆"是成立的，说"web agent 会被劫持"没有证据支撑。
  - 91.9 对 17.4 的对比水分不小。baseline 都被改写成诱导同一个 CLICK 目标；EIA 原本是隐私泄露攻击，被硬塞进这个设定后只有 4.8-9.6%，这比的是"改造后的 baseline"。unseen 渲染下 EIA 没有数字，多步 ASR-M 也只报了 WebMirage 自己。另外分母只算 clean run 成功、并且原本没选目标的 step，ASR 衡量的是"能不能把正常工作的单个决策点掰歪"，不是端到端任务劫持率。
  - 现实威胁有几处没测。公开站是在本地浏览器里替换图片，没有经过真实平台的上传、压缩、重编码，而作者自己的 Table 8 显示 JPEG 一下就把 ASR-S 降到 75.2%。8/255 时掉到 73.2%，目标占截图 2% 时只有 62.8%，偏偏真实商品缩略图大多就是这么小（Home Service 最低，只有 69.0-80.1%）。16/255 的扰动也没做人类可感知性评估。
  - 防御结论需要按条读。identifier randomization 把 ASR-S 从 93.8% 压到 11.7%，代价是 clean acc 跌到 15.9%，这更可能是因为 agent 没在随机 ID 上训练过，不能当成"防御不可行"的证据。另外同为 16/255 白盒，平均 ASR 在主表、预算 ablation、改写实验里分别是 91.9、93.8、94.1，笔记没交代是不是子集不同，引用时要注明是哪张表的数字。
  - 方法直接排除了 coordinate-based agent（Appendix C），而 UI-TARS 这类直接出坐标的 agent 正在成为主流。核心机制依赖"candidate identifier + 可静态分析的 Python 后处理"，换到坐标式 grounding 后还剩多少攻击面，本文没有回答，这恰好是最该回答的问题。
- **Rating**: `2` 👀，"按执行管线对齐攻击目标"的设计和 Table 7 的 ablation 值得借鉴，但白盒、只测小开源 VLM、跨架构迁移弱、排除坐标式 agent，撑不起标题的威胁 claim。

### EviSkill
- **Title**: EviSkill: Grounding Skill Evolution in Replayable Evidence
- **Institutes**: School of Artificial Intelligence, Jilin University
- **Source**: [link](https://arxiv.org/abs/2610.05030)  📰 HF Daily ⬆️ 53   **📒 论文笔记**: [[2610-EviSkill]]
- **核心**: Skill 演化方法通常整包接受或整包拒绝一次 revision。EviSkill 把审核单位缩小到单条 edit：每条 edit 都绑定一张 Evidence Card，记录它来自哪条 trajectory 的哪个步骤区间。系统先复现该区间之前的前缀来重建状态，再在新 skill 下 replay 这一段，看行为是否真的变了。整包被 validation 拒掉时，再逐条做 post-rejection replay，通过的 edit 存进 Provisional Ledger，留到下一轮继续裁决。实验覆盖 ALFWorld / AppWorld / ScienceWorld 和 6 个 backbone，作者报告 18 个设定中 14 个最优，相对 NoSkill 平均高 17.93 点。
- **锐评**:
  - 最值得拿走的是"edit 级 gate"这个切分，它有直接证据支撑。被整包拒掉的 96 条 edit 里有 72.9% 后来被正式采纳，说明 revision 级 validation 确实把有用的 edit 一起扔掉了。初次 replay 有 20.7% / 41.8% / 42.5% 的 edit 没通过，说明"trajectory 读起来合理"不等于"行为真的改善"。这两组数字比主表更有信息量。
  - Teacher 强度混在结果里分不开。extractor、editor、evaluator 一律用 GPT-5.5（medium reasoning）。笔记没找到 baseline 用的优化器 LLM 是否也是 GPT-5.5，论文也没报 replay 和 post-rejection replay 带来的额外 token 与环境步数，更没有等算力基线。所以"replay 有用"和"多花了 GPT-5.5 的钱"目前拆不开。去掉 replay 后只降 2.49 / 4.56 / 2.85 点，单看消融，replay 的贡献只有几个点。
  - 统计力撑不起 14/18 这个计数。测试集只有 134 / 168 / 211 题，1 题约等于 0.5 到 0.75 个点，又是单次运行，温度 0.7，没有方差。GPT-5.5 在 AppWorld 上 94.64 对 LLM Skill 的 94.05，就是 1 题的差距。Qwen3.5-9B 在 AppWorld 上拿到 43.45，输给 SkillOpt 47.62 和 SkillGrad 46.43，而且和 LLM Skill 完全相同。作者自己也承认 AppWorld 上的优势不稳。
  - 比"EviSkill 赢了"更值得注意的是 baseline 的崩法。GPT-5.5 ScienceWorld 上，初始 LLM Skill 有 76.78，Trace2Skill / EvoSkill / SkillGrad 演化完只剩 65.40 / 54.50 / 67.30，越演化越差。这说明 baseline 在这个设置下是失效的，EviSkill 的 83.41 有一部分是赢在"没把自己改坏"。
  - 动机实验偏弱。Preliminary study 2 让 GPT-5.5 按 edit 内容挑子集，然后在训练集上评估，同时带着选择偏差，也不是 held-out 结果，不能当作"被拒 revision 里藏着好 edit"的干净证据。
  - 适用边界很窄。replay 的前提是环境能重置、能精确复现 trajectory 前缀，三个 benchmark 都是可重置的文本/API 模拟器。真实 web/GUI 环境有外部状态和不可逆副作用，这套机制不能直接搬过去，论文也没讨论。replay 只检查原失败区间有没有改善，不检查对其他任务的回归，回归仍然只靠 48 到 57 题的小 validation 集兜底。
  - 跟 SkillOpt 的本质区别只有一点：把 gate 从 revision 下沉到 edit，再加 replay。[[2607-RethinkSkillEvolve]] 指出的小 validation 集噪声问题，这篇一点都没解决。
- **Rating**: `2` 👀，edit 级 replay gate 和 provisional ledger 值得借鉴，晋升率统计也有信息量；但 teacher 强度和算力没控制、单次运行加小测试集撑不起 14/18 的 SOTA 计数，replay 又依赖可重置环境，所以算不上 Foundation。

### SkillForge
- **Title**: SkillForge: Co-Evolving Skills and Agents via Dynamic Skill Lifecycles
- **Institutes**: Institute of Computing Technology, Chinese Academy of Sciences; University of California, Merced; Tsinghua University
- **Source**: [link](https://arxiv.org/abs/2610.09832)  📰 HF Daily ⬆️ 13   **📒 论文笔记**: [[2610-SkillForge]]
- **核心**: 现有 skill-augmented RL（以 SkillRL 为代表）的 skill library 只增不删，低质量 skill 会一直留在 context 里，原本有用的 skill 也可能在策略变强后反而拖后腿。SkillForge 给每条 skill 记一个 fitness（被检索到的 episode 中成功的比例），按 trial / active / stable / retired 管理生命周期：RL 前先用 base model 的 rollout 淘汰一批差 skill 并过滤 SFT 数据，训练中每 10 步执行一次淘汰，同时让 Kimi-K2.5 根据失败轨迹改写中等 fitness 的 skill。Qwen2.5-7B 上 ALFWorld 92.4（SkillRL 89.9），WebShop Succ 78.4（SkillRL 72.7），Search-QA micro-avg 48.7（SkillRL 46.8），library 规模控制在 85-100 条。另外发布了 5,852 条记录的 SkillFurnace 数据集，包含 318 个带人工失败标注的 retirement event。
- **锐评**:
  - 增益很薄，统计检验也撑不起这个结论。Search-QA 上 2Wiki 40.4 vs 40.3、MuSiQue 20.3 vs 20.2，基本没差别，+1.9 的平均提升主要由 125 样本的 Bamboogle（77.2 vs 73.8）带出来。p<1e-3 的检验是对同一个训练好的模型取 5 个评测采样 seed，再对 SkillRL 的单个点估计做 one-sample t-test，衡量的是采样噪声，没有涉及训练方差。而且 Table 10 里 baseline 的单数据集数字直接抄自各自原论文，并非同设置复现。
  - 组件归因和叙事不一致。消融里贡献最大的是 pre-retirement（-1.7/-3.5/-1.2），它实际删掉的 skill 通常只有 0-3 条，本质上是在过滤 SFT 数据。论文没有设计"只过滤 SFT、不改 library"的对照，最大那块收益来自哪里并没有拆清楚。标题里撑起 "co-evolving" 的 mutation 贡献最小（-0.6/-1.6/-0.5）。
  - 缺一个关键 baseline：同样调用 Kimi-K2.5 周期性重写 library，但不做 lifecycle 规则。没有这个对照，就无法排除增益来自更强 teacher 额外注入的信息。
  - fitness 是 episode 级共享的二值 reward，作者自己承认分不清单条 skill 的贡献，只靠"共检索率 <15%"来缓解，而这个前提依赖 ALFWorld 那种按 task type 切分的检索。三个环境都是文本环境，library ≤100 条，模型只有 7B。引言里的动机是"library 膨胀后检索噪声成为瓶颈"，这个规模下根本没有测到。
  - 真正有价值的是 SkillFurnace 的 retirement 分析：被淘汰的 skill 里 57.2% 曾达到 stable，峰值 fitness 0.667，淘汰时下跌 0.278，说明 delayed obsolescence 确实存在。318 个事件中 74.5% 属于 "overly rigid ordering"，只有 3.1% 是"策略已内化"，这直接与 [[2604-Skill0]] "skill 最终会被参数内化"的叙事冲突。不过标注的初始 κ 只有 0.5，8 个类别也是作者预先设定的，比例数字要打折看。另外这 318 个事件聚合了消融 run 和 replicate run，并不完全来自主实验。
  - "w/o retirement 时 library 涨到 132/121/111，成功率反而下降"这一点比较干净，是"skill 的质量比数量重要"的直接证据。
- **Rating**: `2` 👀 ，生命周期管理和 delayed obsolescence 的统计值得借鉴，但相对 SkillRL 的提升小，且只有评测采样 seed 支撑，最大的收益来自 SFT 过滤而非标题宣称的 co-evolution。

- **核心**: PhysEvo 冻结一个 Astra 模型，让它同时扮演两个角色：task agent 负责控制机器人，meta-agent 负责读轨迹、找失败原因，并修改 tool、skill 和诊断工具。新修订要在同一初始场景上与旧版本对比，分数不降才采纳。整个过程不更新权重，也不训练 action policy。每个任务演化出一个固定的 deployment version，在 42 个 RoboDojo 任务上取得 62.00% SR（RoboDawn one-shot 为 47.17%）。在 8 个 direct Astra 难题上是 55.00% 对 1.25%，在 AgileX PiPER 真机上是 84.00% SR。实际起作用的几个改动都很具体：把控制权限放到关节级（`control_arms`），用空闲臂移动腕部相机取景，回看历史帧，以及由模型选点、由确定性工具计算几何。
- **锐评**:
  - 主结果比的对象不对等。PhysEvo 按任务演化，task-specific skill 只在本任务内使用，而 RoboDawn 是 1-shot 通用设定，VLA 是 zero-shot。62.00% 对 47.17% 实际上是"逐任务调好的系统"对"通用基线"。作者没有披露演化阶段的交互预算、模型调用量和 token 成本，也没有"同预算下 RoboDawn 加迭代修订"的对照，14.83 个点里有多少来自额外算力无从判断。
  - 分维度看，增益来自哪里很清楚。Memory 维度是 100% 对 53.33%（+46.67），Generalization 反而是 45.00 对 50.00，落后于基线，Long-horizon 持平。Memory 拿满分更像是把具体任务的规则写进了 skill，算不上能力提升。Generalization 落后正好说明这套演化在泛化上没有帮助。
  - 统计很粗：每任务只有 5 个 layout，每个 layout 试 1 次，SR 的最小步长就是 20%。八任务子集上 55.00% 对 Simate-beta 50.83% 只差约 4 个点，又没有方差，算不上优势。采纳规则是"同场景分数不降即采纳"，没有噪声地板，在这种粒度下采纳判断很可能被噪声左右。RRSI 已经指出过这类过拟合，PhysEvo 没有处理。
  - 最有价值的发现是控制接口那组对比（TCP 40 / Joint 100 / Both 55）：给模型关节构型的权限后效果最好，同时提供两种接口反而更差。可惜这组只有 2 个 layout、6 个 episode，只能算线索，还撑不起结论。它和 Show-Harness 的思路正好相反（后者把动作收缩成离散语义单元），值得做同任务对照。
  - 标题里的"recursive"，即 meta harness 的自我改进，只有 Fig 5 一个 packing 案例作证据。没有关掉 meta 可编辑性的 ablation，分不清增益来自演化 task harness 还是演化 meta harness。另外 meta 模型和 policy 模型始终是同一个 Astra，没有试过换成更弱的 meta 模型，所以也不知道能力来自哪个角色。
  - 真机的 84% 不是 held-out 成绩：部署后还在针对评测任务继续修订 skill。真正难的倒水和写字都只有 60%，简单的堆叠和放置都是 100%，平均值掩盖了这一点。
  - 和 GUI-HARVEST 相比，整体框架基本一样：冻结 backbone，诊断轨迹，改 harness，门控采纳。区别只在诊断信号是对齐的图像、机器人状态和指令，而且门控更粗（只看分数，不看行为）。
- **Rating**: `2` 👀，关节级权限和"模型选点、工具算几何"这类接口改动值得借鉴，但主结果建立在逐任务演化对通用基线、预算未披露、每任务 5×1 采样之上，recursive 主张只有一个案例支撑。

### EvoBelief
- **Title**: EvoBelief: Falsifiable World Models for Self-Improving LLM Agents
- **Institutes**: Tulane University, Amazon
- **Source**: [link](https://arxiv.org/abs/2610.12789)  📄 arXiv   **📒 论文笔记**: [[2610-EvoBelief]]
- **核心**: 自进化的对象从"agent 怎么做"换成"agent 认为环境怎么运作"。冻结 LLM 外面挂一个由可证伪假设 (C ∧ A ⇒ Y) 组成的 world model。规则要攒够跨 episode、跨 binding 和独立测试的证据才有权改写预测、否决动作；遇到反例先收窄 scope，再 demote，最后 retire。ALFWorld 无 memory 时比 Frozen WM 高 23.9（Haiku 4.5）和 31.3（GPT-5.4）个点。MiniGrid 隐藏 key 切换后能退役旧规则、验证出新规则，成功率回到切换前水平。DiscoveryWorld Reactor Lab 上做到 83.33/58.33，所有 baseline 都是 0。
- **锐评**:
  - 标题写的是 "Self-Improving LLM Agents"，干活的却基本不是 LLM。在 ALFWorld/MiniGrid/ScienceWorld 上，规则由 typed transitions 经 code induction 得到，后果直接算出来，没有 rule-conditioned 模型调用。DiscoveryWorld 的规律也是代码拟合的。actor 从头到尾看不到规则文本（App. C）。说白了是"每个 benchmark 手写一个符号化环境学习器，冻结 LLM 只负责提议动作"。换一个新环境就得重写 adapter，这部分成本正文没讲。WorldEvolver/ITP-I 有没有拿到同样结构化的观测接口，笔记里也看不出来。
  - 最亮眼的数字恰好出在最有利的设置上。+23.9/+31.3 是"无 transition memory"条件下的结果。加上 memory 后，Haiku 只剩 68.66 vs WorldEvolver 58.96，GPT-5.4 只剩 76.87 vs 72.39，这说明规则机制的增益有相当一部分 episodic memory 也能拿到。ScienceWorld 上多数直接行为干预来自 live experiment，靠已验证规则做的决策反而少。"沉淀可复用环境知识"这个核心卖点，在这里基本没站住。
  - MiniGrid 上 Frozen WM/WorldEvolver 在 MG-C 拿到 0/0，这反映的是 benchmark 的构造，不是 baseline 太弱：任务被刻意设计成需要一个先验想不到的步骤，24 步预算也不给碰运气的余地。真正有说服力的是 MG-R 对照（83.33/78.33 vs 48.33/50.00）和实体名置换（80.8% vs 7.1%），后者说明规则绑定的是效果而不是名字。这两个设计值得借鉴。
  - DiscoveryWorld 每个 cell 只有 12 个实例。Plant Nutrients 完成率相对最强 baseline 的差，CI 包含 0，只有 knowledge 差排除了 0。而且首版实现在 6 个实例上一个都没完成，修改实现后才报告了新版本（App. F.5）。作者主动披露值得肯定，但这个 task 的结果只能算"修到能跑"，不能算证据。
  - commit 判据是计数阈值（≥2 binding、≥2 episode），前提是环境近似确定、实验可逆。到了随机环境就会失效，作者在 App. A 自己也承认了。只做了文本环境，没有 GUI 或具身实验，也没有放代码。
  - 跟已有工作的本质区别在 authority 机制：信念"存在"和信念"被允许指导行动"是两回事，靠独立证据门槛控制错误规则跨任务扩散。ALFWorld 上 >80% 的规则指导决策落在规则被验证时所在任务家族之外，这是"跨任务复用"最硬的一个数。
- **Rating**: `2` 👀，authority 门槛加反例 retire 的生命周期设计干净，drift 实验做得很到位；但规则提取全靠手写 adapter，有 memory 时增益大幅缩水，"LLM agent 自进化"这个 claim 被包装得过大。

### AgentGarten
- **Title**: AgentGarten: Code Worlds for Evolving Agents
- **Institutes**: MirroS, Tsinghua University, Peking University
- **Source**: [link](https://arxiv.org/abs/2610.12374)  📰 HF Daily ⬆️ 263   **📒 论文笔记**: [[2610-AgentGarten]]
- **核心**: AgentGarten 把训练环境拆成两部分。物理 state 和交互规则写在 simulator/game engine 的代码里，画面则交给一个共享的 neural renderer：它从 Cosmos 3-Nano 初始化，以 depth/normal 为条件，用 Adversarial Forcing（DMD 蒸馏 + exact replay + 用 VJP/JVP 精确计算 R1/R2）蒸馏，负责补出逼真的第一视角画面。因为状态转移 f_p 不读渲染画面，渲染误差不会累积进 state；同一条 state 轨迹也能换外观重新渲染。renderer 在单张 H100、480×832 下达到 36.5 FPS（16 帧 block 用时 438.8 ms）。agent 侧用 pretrained agent 只看渲染画面行动，靠逐轮继承的 Markdown playbook "练习"：hide-and-seek 中第 4 轮搭出 shelter、第 10 轮用 ramp 翻墙，另外 4 个世界各跑 4 轮，分数有所上升。
- **锐评**:
  - 真正的贡献是 "state 写在代码里、外观交给网络" 这个 problem formulation。它直接针对 Genie 类 video world model 的硬伤：state 不可检查、不可编辑、误差会累积。这是结构上的不同，不是调参。exact replay 的证据也很硬：Table 1 里 FlexAttention replay 的相对 L2 误差是 3.99%，逐 block SDPA replay 是 bitwise 0，forward 时间反而少了 5.4%，显存只多 0.2%。这一点没什么可挑的。
  - renderer 本身几乎没有定量评测。视觉质量只靠 Figure 7 和 Self Forcing 做了一组 30 秒定性对比，没有 FVD、条件遵循度或长程一致性指标，也没跟其他 geometry-conditioned video 模型比。Adversarial Forcing 的三个组件没有分别做 ablation，exact replay 对最终画质到底贡献多少无从得知，Table 1 只证明了数值一致、成本低。主打 renderer 的论文却不量化 renderer，这是最大的缺口。
  - "faithful" 是假设出来的，没有测量。renderer 只看 depth/normal，颜色和语义靠 x_0 加文本补。ramp 渲出来像不像 ramp、agent 有多少次失败是被渲染幻觉骗的，论文都没测，failure case 也没讨论。核心卖点 faithfulness 恰好是全文唯一没验证的部分。
  - agent 实验基本是 anecdote。Table 4 每个世界每轮只有 1 个 episode，没有多 seed，没有方差。quarry loader 是 30→0→30→90.9，herding 在第 2 轮之后从 90.1 掉到 87.6，这种波动没法和随机性区分开。也没有任何对照：同一个 agent 直接读引擎 state、看 ground-truth 渲染、或者不用 playbook 会怎样都没做，所以提升到底来自 renderer、playbook 还是 agent 本身，无法归因。
  - 摘要里 "4 轮 vs 传统 RL 数百万" 是标题党。正文 Sec 5.2 自己承认这不是 sample-efficiency 比值：一边是 web-scale 预训练加反思，另一边是从零开始的 self-play RL，而且 hide-and-seek 改成了 1 hider/1 seeker 的顺序变体，跟 OpenAI 2019 的设定并不等价。拿 25M/100M episodes 来衬托，属于明知不可比还写进摘要。
  - 36.5 FPS 的代价是每个 block 约 439 ms 延迟。agent 用 Python 程序发高层动作，正好回避了高频控制的问题；embodied low-level policy 能不能用这个环境，论文没给证据。从单张图构建世界依赖一串外部工具加 coding agent，构建成功率和成本也都没报。
  - 跟 DreamGym（文本抽象状态）、Agent-World（工具/数据库状态）比，这篇占了环境合成光谱的视觉这一端，"state 显式可检查" 是本质区别。但 "self-evolving" 只发生在 prompt 层的 playbook，权重不更新，跟 agentic RL 的关系仍是空白。
- **Rating**: `2` 👀 ，"state in code, appearance in net" 的拆法和 exact replay 值得借鉴，但 renderer 没有定量评测、faithfulness 没有验证，agent 证据是单 episode、无对照的 anecdote，撑不起 "learning efficiency" 的 headline。

### Memento 3
- **Title**: Memento 3: Model-Based Recursive Self-Improvement through Reflective Rulebooks
- **Institutes**: University College London, Huawei Noah's Ark Lab UK, University of Liverpool
- **Source**: [link](https://arxiv.org/abs/2610.11794)  📰 HF Daily ⬆️ 37   **📒 论文笔记**: [[2610-Memento3]]
- **核心**: LLM 保持冻结，把自己对环境规则的猜测写成一份自然语言 rulebook，再编译成可执行的 Python world model，用它做预测和规划。Reflection 阶段区分两种错误：规则错了就先改 rulebook 再改代码，只是实现错了就只改代码。新代码要同时满足两个条件才被接受：LLM 判定它忠实于 rulebook，且 cell-exact replay 能复现全部历史轨迹。rulebook 和编译产物都用 Git 做版本管理。ARC-AGI-3 的 25 个公开游戏全部通关，mean RHAE 100.0，总动作 7,518，是人类 17,135 的 0.44。Pong 上学到的控制器不调 LLM，三种开局都打出 21:0，学习用了 9.5×10^3 frames。
- **锐评**:
  - 头条数字基本是天花板效应。baseline1 已经 99.0 且同样全部通关，而本文 harness 本身就从 baseline1 代码库改出来。实际增益只有 1.0 分 RHAE，以及 8,347→7,518 动作（约 -10%）。baseline1 只在 sc25（84.2）和 tn36（90.1）两个游戏没到 100。"比 Opus 5 + Standard harness 高 59.3 分"量的是整个 harness 的工程差距，说明不了 rulebook 的作用。作者在 §6 也承认，公开集通关无法隔离 world-model 架构的贡献。
  - rulebook 是核心卖点，因果证据却很薄。Table 3 只覆盖 3 个游戏（ft09/ka59/cn04），每格一个数，没报方差，也没说跑了几次。两个变体都通关到 100，差距只有动作 617 vs 677（-9%）和 agent turns 678 vs 830（-18%）。Opus 5 extra-high 的 agentic 运行方差本来就大，单次 9% 的差距完全可能是噪声。
  - Population 那节更像一个示意。只在 wa30 一个游戏上比较了 N=2 和 N=1，动作 899→597，但 L8 上 N=2 反而更差（1.06×）。N=2 的模型构造和 LLM 调用量翻倍，而这些都不计入动作数，所以减少的动作可能只是拿算力换来的。全文没有报告 token、调用次数或 wall-clock，所谓"效率"只算了环境动作。
  - 适用前提很窄。cell-exact replay 要求环境确定、离散、可以逐格比对。到了 Pong，full-frame replay 已经有残余误差，作者只好退回到"replay 诊断 + 控制器评估"，验证标准实际被放松了。GUI/Web 环境非确定且部分可观测，这套接受条件不能直接迁移。Pong 的 baseline 沿用各自原论文的评估协议，"学习成本低 2.1×10^4 倍"这个对比不同口径，只能当量级参考。
  - 跟已有工作的本质区别：作者自己承认 language rules、executable artefacts、reflection、replay 都是已有组件。真正新的东西是"规则修订和实现修订分流"，以及 Eq. 28-29 对 self-confirming 的观察：模型在自己选的动作上总能预测对，所以永远不会被证伪。这两点有借鉴价值。Fig. 5 里 tr87 跑出 11 个 rulebook 版本、早期规则后来被推翻，是机制确实在起作用的实例。标题里的 Bayes-adaptive POMDP 和 "Recursive Self-Improvement" 包装过重：LLM 全程冻结，被修订的只是外部文件，形式化部分也没有给出任何近似误差保证。只用了公开集，没有 held-out 游戏，代码也未发布。
- **Rating**: `2` 👀，"规则错 vs 实现错"分流和 self-confirming 观察值得借鉴，但 SOTA 主要来自 baseline1 的 harness，rulebook 和 population 的增益都只有单次小样本支撑，没有重复运行，也没有成本账。

### Trace2Env
- **Title**: From Traces to Agentic Worlds: Agentic Language World Models for Interactive Environment Simulation
- **Institutes**: Nanyang Technological University, The Hong Kong Polytechnic University
- **Source**: [link](https://arxiv.org/abs/2610.06100)  📰 HF Daily ⬆️ 107   **📒 论文笔记**: [[2610-Trace2Env]]
- **核心**: 设定是原环境拿不到，只剩历史交互 trace。作者用 gpt-5.6-sol 把 trace 离线整理成一本不可执行的 worldbook，包含 schema、原始转移证据、归纳规则和溯源。在线时由一个 world model agent 查 worldbook、维护本 episode 的状态，提出状态转移，再交给 harness 校验后提交。全程 learning-free。在 7 个 next-observation 环境上，平均分比 Direct Prompting 高 6.43（gpt）和 7.04（deepseek）。在 ALFWorld 上，把 sim 里的动作序列回放到真实环境（W2R），成功率从 3% 提到 85%。
- **锐评**:
  - 最值钱的不是方法，是 W2R/CR 这个指标。ALFWorld 上 Direct Prompting 在 sim 里成功率 97%，回放到真实环境只有 3%（CR 0.032）。这说明用 LLM 当 experience model 时，"sim 内成功率"基本不可信，DreamGym 这类拿合成转移训练 policy 的工作都该补这项检查。
  - 消融把作者自己的卖点拆掉了。在 Terminal 上，abstraction 单独加进去是 −1.12±0.90；已有 evidence 时再加 abstraction 只有 +0.69±0.63；已有 abstraction 时再加 evidence 却有 +4.26±1.02。worldbook 的收益主要来自保留原始转移，规则归纳贡献很小。所谓"把 trace 重构成世界"，实际更接近结构化的 trace 检索。
  - agentic 部分在 next-observation 上的性价比差。Worldbook Prompting（静态塞进 prompt）已经到 74.35，完整系统是 75.94，只差 1.6 分。为这 1.6 分，调用次数从 1 次涨到 5 次，单条成本从约 \$0.04 涨到 \$0.187。agent 侧消融也只有 −1.79（去掉 adaptive loop）和 −0.97（去掉 state tracking），而且误差条都接近 1。
  - 最显眼的数字恰好归因最差。Table 2 的 multi-turn 对比只有 Direct Prompting 一条基线，没有 Trace RAG、Worldbook Prompting 和 Harness only。所以 3% 到 85% 这个提升里，有多少来自 trace 信息、多少来自持久状态和 validation gate，完全分不开。SciWorld 上 W2R 是 60% 对 45%，差距只有约 6 个任务。这里的 40 任务是笔记根据 Table 4 推断的，行归属没有直接确认，样本量偏小这一点要打折看。
  - 题目写 "Agentic Worlds"，正文却没有训练或评测过任何 agent，下游价值全放在 future work 里。fidelity 靠 gpt-5.2 当 judge 打 1-5 分，而 EnvScaler 三个环境本身天花板就高（Benefits 98+）。平均 +6 分里，有相当一部分来自接近饱和的环境。对比之下，SoftwareGym 和 Agent-World 都给出了下游训练收益。
  - 适用边界被藏起来了。所有观察都是文本，Android/Web 也是文本化观察，这套 schema 加规则的重构能不能用到截图类 GUI 环境，没有验证。构建 worldbook 依赖 gpt-5.6-sol，deepseek 只负责运行。Terminal 上从 20 条到 36 条 trace，分数还在涨（64.89 到 66.42），说明 worldbook 的覆盖上限由 trace 量决定，而且还没饱和。
- **Rating**: `2` 👀，W2R/CR 指标和"evidence 比 abstraction 重要"这条消融值得带走；但方法增益小、成本高，multi-turn 归因缺基线，也没有任何下游训练证据，撑不起题目里"Agentic Worlds"的说法。

- **Institutes**: Salesforce AI Research, UC San Diego, Texas A&M University, Stanford University
- **Source**: [link](https://arxiv.org/abs/2610.08077)  📰 HF Daily ⬆️ 187   **📒 论文笔记**: [[2610-SRD]]
- **核心**: GRPO 遇到一组 rollout 全对或全错时 advantage 为 0，这组样本通常被直接丢掉。在代码域，不同规模下这类组占 37% 到 98%。SRD 的做法是：让同一个 policy 在看到完整轨迹、金标准答案 y* 和错误标注之后充当 teacher，去监督它自己在交互开始前、看不到轨迹时写出的"可能踩的坑"(pitfall foresight)，用 token 级 JSD 作为 λ=0.01 的辅助损失，叠加到 GRPO / OPSD / RLSD 上，推理时不额外生成任何内容。在 Qwen3.5-4B/9B 的 10 个 benchmark 上，4B GRPO 加 SRD 后 Math/Code/Search 均值分别提升 +10.03/+8.33/+8.05 pp，9B OPSD 的 Math 均值从 39.70 升到 56.92。2B 代码设置下，GRPO 训练成功率最终为 0.0%，加 SRD 后达到 60.6%。
- **锐评**:
  - 选题准。"reward 决定教什么，不决定教不教"这个改法很干净：all-fail 组也能产生监督信号，而且实现上只多一项 loss。跟 [[2607-SEED]] 的区别也说得清楚，SEED 用 hindsight 监督 action token，SRD 用 hindsight 监督交互前的预判，两者是"hindsight 拿来监督什么"这条设计轴上的两个点。
  - 大增益主要来自修 OPSD，不来自超越强 baseline。+24.16 和 +17.22 这两个最亮的数字都出在 9B OPSD 上，而这个 baseline 本身就坏了：HotpotQA/2Wiki/LCB-v6 比未训练模型低 5.50/3.76/2.18 pp，Math 均值还出现 9B 低于 4B 的反向 scaling。换到最强的 host RLSD，SRD 在多数列只剩 0.5 到 1.5 pp，4B OJBench 还有 -0.97。所以"最高 +24.2 pp"更多说明 OPSD 需要一个稳定项，不能说明 foresight 有多强。
  - 缺一个关键对照。没有跟"直接拿 hindsight 文本做 SFT / 普通 self-teacher 正则"比，所以分不清增益来自 foresight 这个目标本身，还是来自多加了一项锚定到自身副本的正则。RQ4 里 SRD 把 OPSD 的位移从 1.97 压到 0.57，这个"锚点"效果恰好支持后一种解释。
  - 自家消融对"foresight 内容就是增益来源"这个说法并不友好。加上 Knowledge 通道不涨反跌（9B AIME26 从 65.42 降到 62.92）。推理时显式输出 foresight 几乎没用，8 个 arm 里没有一个能在 ALFWorld 全部 6 类任务上同时提升，Look 类任务的波动从 -20.13 到 +40.28 pp。既然预判写出来没用，那这些预判文本到底在训练时传递了什么，论文没有用干预实验回答。
  - 2B 的"0.0% 到 60.6%"是训练成功率，不是 held-out 结果，而且 baseline 峰值只有 1.6%。这只能说明 SRD 让训练启动了，不能当成泛化提升来引用。
  - 统计偏薄。avg@8 没给置信区间，部分对比作者自己承认只有单 seed、单规模，任务类型之间几十个 pp 的波动说明噪声不小。agentic 部分只有 ALFWorld 和 WebShop 两个文本环境，8 轮交互上限。方法依赖 y* 和错误标注，迁移到 GUI 或开放环境时这些从哪来，是悬而未决的问题。另外没有放出代码。
- **Rating**: `2` 👀 ，"all-fail 组用 hindsight 教 pitfall"是个可以直接借用的便宜设计，但最大增益建立在修复一个坏掉的 OPSD baseline 上，在强 host RLSD 上只剩 1 pp 左右，又缺 hindsight-SFT 对照和多 seed，撑不起 Foundation。

### S-Space
- **Title**: S-Space: Exploring Spatial Workspace in Multimodal Language Models
- **Institutes**: MirroS, Tsinghua University, Peking University
- **Source**: [link](https://arxiv.org/abs/2610.13527)  📰 HF Daily ⬆️ 264   **📒 论文笔记**: [[2610-SSpace]]
- **核心**: 作者对空间问题的答案 logit 差（right-left / above-below / close-far）关于 object-name token 隐状态求梯度，做 role-antisymmetric 平均后得到 3 个固定方向，张成 MLLM 中间层的一个 3 维线性子空间 S-Space；隐状态在其上的投影就是物体的水平/垂直/距离坐标，一次前向即可读出。读出结果与 Direct 作答大致同一量级（Molmo2-ER L22：91.92 / 86.92 / 96.50 对 94.40 / 90.42 / 97.83），编辑坐标后写回能定向改变空间答案而较少影响颜色答案。基于此作者把空间推理失败拆成 perception 与 computation 两段：SpinBench 视角变换上 Direct 只有 60.96，而读出坐标后施加显式旋转可达 91.10 到 95.21，结论是表征够用、变换不行。纯机制解释工作，不提新训练方法。
- **锐评**:
  - 最载重的 claim 建在 oracle 上。SpinBench 里旋转角由题目给定、答案由作者手写的确定性规则（R_left(x,z)=(z,−x)）算出，S-Space+Rotation 的 94.52 / 91.10 / 95.21 是"坐标读对了且有人替模型把变换做完"的上界，推不出"模型只差一步计算"这种普适结论。更可疑的是三个模型的无 premise Direct **全都等于 60.96**，四位有效数字在 146 题上完全撞上，这不像三次独立测量，更像三者都塌缩到同一种退化作答（按源视角直答或固定选项偏好）；那么 +33.56 里有相当一部分是在量 baseline 有多烂，而不是量表征有多强。146 题意味着单题 ≈0.68 点，论文没给任何置信区间。
  - 全文最有价值的数字被埋在附录 Table 3：Qwen3.5-4B 在 CV-Bench 上线性读出 89.36 而 Direct 只有 73.60，差 15.76 点，EmbSpatial 86.42 vs 78.50、SpatialTunnel 90.08 vs 86.33 同向。这才是"内部表征强于口头输出"的硬证据，远比正文那句 comparable 有说服力。反过来 Molmo2-ER 三个 benchmark 读出全面低于 Direct（低 1.3 到 3.5 点），把这个方向叫 comparable 是给自己留台阶。
  - 水平轴有词汇泄漏嫌疑，而且没有对照实验。轴本身是对 right-left 的 logit 差求梯度得到的，所以它完全可能部分是"把 left / right 这两个词推来推去"的 token 方向；Fig 7 里 socialist / conservative 落到水平轴左右两端，作者当成语言继承的趣闻，审稿角度这是 confound 警报。缺的实验很具体：把答案选项换成与方位无关的标签（A / B 或任意词）再测读出准确率。不做这个对照，读出准确率里多少来自空间几何、多少来自答案词的词汇偏置说不清楚。
  - 因果证据只有一个模型。所有干预都在 Molmo2-ER 上（主结果 L17 + 800 条 EmbSpatial，层扫描 L13 到 L20 每任务仅 80 例），跨 5 模型的部分全是相关性读出，所以"表征在、变换不会"这个跨模型结论的因果一半没有复现。而且 β=±30 时空间保留率 41.05%、颜色保留率 78.13%，颜色也掉了 22 点，说 little effect 偏乐观，选择性只是相对的。
  - "首次系统刻画内部空间工作区"缺最该做的对照：用同一批 COCO 坐标监督训练一个线性 probe 去回归 hidden state 里的位置。梯度法确实优雅（不需要坐标标注、一次梯度就定方向），但论文从未证明它比这个平凡 baseline 读得更准或更因果，也没有与既有 probing / steering 空间方向工作的任何定量比较。同时坐标真值本身是弱的：深度用 Depth Anything V2-Small 的逆深度，水平/垂直用图像平面坐标且明确不解透视（footnote 2），因此 S-Space 编码的是 viewer-centered 的 2.5D 关系，把它包装成 mental workspace 并类比人类心理旋转，修辞跑在证据前面。
  - 若干结论只有图没有表：持久性（Fig 5）、CoT 逐步变换（Fig 9）、动作训练让 part-whole 深度几何变准（Fig 14，只有 3 个 checkpoint）都是定性曲线；"S-Space 源于预训练时预测空间语言"是作者自己标注的 hypothesis，没有任何训练期干预支撑，引用时不能当结论。
  - 与已有工作的本质区别站得住：比 [[2606-Thinkwith3D]] 那种训出显式几何中间态的路线便宜得多也更可诊断，比 [[2601-VisualProjectionSpace]] 那种只做相关性的 projector 几何分析多了编辑写回的因果闭环。真正的增量不是"发现了空间方向"，而是把"VLM 空间推理差"拆成可分别测量的 perception 和 computation 两段。
- **Rating**: `2` 👀 ，诊断框架和 89.36 对 73.60 这个读出反超 Direct 的发现值得借鉴，但"瓶颈在变换"这个真正会改变研究方向的 claim 建在 oracle 旋转、146 题 benchmark 和单模型干预上，离 Foundation 还差一组非 oracle 的验证。

### Taming VLAs
- **Title**: Taming VLAs under Robot Execution Errors: Self-Compensation and Stress Testing
- **Institutes**: POSTECH, MBZUAI
- **Source**: [link](https://arxiv.org/abs/2609.37334)  📰 HF Daily ⬆️ 45   **📒 论文笔记**: [[2609-SelfCompVLA]]
- **核心**: VLA 发出的 delta-pose 指令和机器人真正执行出来的位姿变化并不一致，作者用 proprioception 直接测这个残差 η = Δx − a^policy，把 a^policy − η 当 pseudo-target，在线用 flow-matching 损失更新挂在 action expert 上的 rank-4 LoRA（lr 1e-6，带 anchor 正则），让后续 chunk 预先补偿误差，不需要 reward、label 或误差来源知识，低层控制器不动。配套的 RoboStress 把文献里四个关节级误差模型（Stribeck friction、gravity-compensation error、backlash deadband、二阶 compliance）经 OSC 注入 LIBERO，拼成 7 个部署场景。仿真上 π0.5 平均 49.1→56.6、π0 41.7→44.2；真机两台 AgileX Piper 上 π0.5 为 43→76 和 43→74，π0 为 40→72 和 38→71。Clean 设置下 π0.5 从 97.0 掉到 95.8。
- **锐评**:
  - Framing 切得对，设计也便宜。把"命令被执行之后产生的误差"从"命令之前注入的合成 action 噪声"里分出来，并指出前者依赖当前状态与近期运动历史，这确实是 DR / RobustVLA 那一类工作没覆盖的面。Table 4 的两个消融有真信息量：把残差当固定偏置直接减掉只有 23.6%（Base 41.7），把 η 置零只保留在线更新是 40.8%，两者都低于 Base，说明增益来自"残差 + 参数更新"的组合而不是"在线微调"本身。这个分解值得借用。
  - 最亮的数字恰好是消融最缺的地方。+30pp 以上的增益全在真机，而 η=0 这个唯一能排除"随便做点在线适配也行"的对照只在仿真跑过，差距还只有 3.4pp，主表又没有误差棒（附录才说 3 seed 取平均）。真机侧一个组件消融都没有，所以"真机 +33pp 来自残差信号"这条因果链目前是空的。
  - 仿真和真机的增益差一个数量级，论文没解释。π0 在仿真上只涨 2.5pp（40 任务 × 20 episodes 下单次 SE 约 1.7pp，也就是 1.5 个 SE 量级），π0.5 涨 7.5pp，同一方法在两个 backbone 上差三倍也没有分析；换到真机直接变成 +30pp 以上。更朴素的解释是真机上补的不是"磨损导致的执行误差"，而是 teleop 采数据与策略自主回放之间的整体分布失配，即一次普通的 test-time adaptation。
  - 作者自己的两个数字在拆自己的动机。全文前提是"误差随机器人个体而异、必须部署时适配"，可实测新机器人平均归一化残差 32.9%、用了一年的 35.0%，几乎一样，Base 在两台机器人上的平均也都是 43。fleet 异质性这个前提在本文数据里就没立起来。更要命的是未见物体实验：改的是物体外观，方法补的是动力学，结果 Ours 64% vs Base 16%。这 48pp 只能说明在线更新把策略拉回了这台机器人的状态分布，和"执行误差补偿"的机制叙事对不上，论文对此没有任何干预分析。
  - Baseline 选错了档位。真机只对了 base 和 RobustVLA，后者是冲着 adversarial 视觉/动作扰动设计的，不是执行误差的对手；该对的 test-time adaptation 方法、经典 adaptive control、residual RL 一个没有。唯一的 controller-level 对照 DOB 只跑了 Robot A Task 1，而且 DOB+Ours（80）低于 Ours alone（84），这个诚实报告的数字其实在提示两条路径功能重叠，而 RoboStress 里干脆没放 DOB。于是"policy-level 补偿优于 controller-level 补偿"只有单任务支撑。
  - Benchmark 的真实性只验了七分之一。只有 Heavy Payload 用 1 kg 真实负载回放做了 DTW 对照，其余 6 个场景的 per-joint severity 是作者手设；四个噪声模型都是文献现成的（作者自己写明了），本文贡献是打包而非建模。全部仿真只跑 LIBERO，代码承诺发布但还没有。
  - 长期稳定性完全没评。Clean 下 π0.5 掉 1.2pp、去掉 anchor 掉 2.4pp，都在说在线 LoRA 对 drift 敏感，而最长的评测单元就是一个 episode，连续跑几百次会不会累积漂移没有数据。另外残差只能修下一个 chunk，对抓取瞬间负载冲击这类一次性误差天然滞后，这个结构性滞后也没量化。
- **Rating**: `2` 👀 ，"用 proprioception 残差做零标签 test-time adaptation"是个干净可复用的设计，Table 4 的消融也排除了平凡解释，但 +33pp 的真机主结果既没有对应消融也没有 TTA baseline，机制叙事还被作者自己的 32.9% vs 35.0% 和未见物体结果反驳，仿真增益在 π0 上只有 1.5 个 SE，撑不到 Foundation。
