### Macaron-V1
- **Title**: Macaron-V1: Towards Open Continual Learning with Self-Improvement and Mixture-of-LoRA
- **Institutes**: Mind Lab (Mindverse)
- **Source**: [link](https://arxiv.org/abs/2608.09819)  📰 HF Daily ⬆️ 294   **📒 论文笔记**: [[2608-MacaronV1]]
- **核心**: Mindverse 的开放 agent 模型技术报告:在 frozen 744B GLM-5.2 base 上挂四个 rank-16 LoRA specialist(Chat/Agent/Coding/GenUI),由 Chat adapter 兼任 per-turn router,配套三件套 harness 工程(UI4A GenUI、REPL agent harness、版本化 HCP contract)和 MindForge 递归自改进循环。主结果:自建 UI4A-Bench 87.8 大幅领先 Opus 4.8 的 75.9;最有信息量的实验是 Section 3.2.5——122 个 frozen base 全挂的 TerminalBench 派生任务,零权重更新、纯 harness/配置搜索累计覆盖 122/122,而最好单配置只过 11/122。harness 代码与权重均开放(CC BY 4.0)。
- **锐评**: 先说难得的:这份报告的 evidence discipline 在厂商技术报告里属于稀有物种——routing accuracy 主动声明非 held-out、748B 明说是 label 不是 stored count、基建数字标明来自 companion report,连 BFCL v4 上 REPL 反而输 function calling(49.5 vs 54.0)的负面结果都照登。但硬伤同样清楚:**标题承诺的两件事一件都没证明**——continual learning 的跨代复利(RSI 的 Update 阶段没跑通测量)和 collective intelligence 全被作者自己列为 open question,这是一份"快照+执行检查",不是 compounding 的证据;MoL 的核心动机 cross-task interference 压根没量化(C10,作者自认是 design motivation 而非实证),等于整个架构选择建在一个未验证假设上;主表优势集中在自建 benchmark,而 ChatBench 的 judge 是与 base 同族的 GLM-5.2(作者自认可能偏袒),外部 VitaBench/ClawGym/DeepSWE 全部不是第一。真正值钱的是 3.2.5:它把大量 benchmark failure 定性为 **elicitation failure 而非 capability failure**,是 harness 归因方向(我们 [[Topics/AgentHarness-Design]] 主线)迄今最强的公开数据点之一——尽管 adaptive search 的 122/122 是 coverage ceiling,不代表任何单配置的能力。config search(language space)与 weight update(parameter space)在 π_φ(a|o;θ,c) 里的因子化,也是对 self-evolving 文献里两条常被混谈路径的干净形式化,可与 [[2608-ZerothOrderSelfEvolve]] 直接对照。
- **Rating**: `3` 🔥 ,continual learning 叙事是期票,但 3.2.5 的 0/122→122/122 配置搜索结果 + HCP 可审计化 + 开源 harness,对我们 harness 归因主线是必读级数据点。

### Ouroboros
- **Title**: Ouroboros: A Self-Developing Frontier Coding Agent with Reviewed Core Evolution
- **Institutes**: Lomonosov Moscow State University, Skolkovo Institute of Science and Technology, Joi Lab, FusionBrain Lab AIRI, HSE University
- **Source**: [link](https://arxiv.org/abs/2608.08311)  📰 HF Daily ⬆️ 69   **📒 论文笔记**: [[2608-Ouroboros]]
- **核心**: 把 agent harness 本身当演化对象:tools、prompts、context assembly 乃至核心实现全部经 blocking diff-review panel 走 reviewed commit 落地,改完的代码直接成为下一轮 runtime。安全靠结构而非 prompt——盘上重读的 protected constitution(P0–P4 不可删改)、launcher/repo 进程边界、agent 自己调不高的 spend cap、/panic 终止链。frozen seed 评测报 Terminal-Bench 2.1 audited 86.74%、OSWorld-Verified 90.69%、CL-Bench 0.2301,另附 161 天真实部署实验 "Hope":1,085 次 self-commit(94.2% agent-authored)、\$110.6K spend、63.5% review block rate。代码 MIT 开源。
- **锐评**: 这篇最值钱的不是分数,是纪律和数据。评测操作干净得在系统论文里近乎异类:frozen seed + evolution off + 逐 benchmark 配置披露 + trajectory audit,还主动请维护者把一个 shortcut trial 记零、对 SWE-bench Pro 污染做对称过滤——这套流程比 SOTA 本身更值得抄。Hope 的 161 天部署是 self-evolution 领域第一份公开的长期生态学数据,63.5% review block rate 直接量化了"agent 自提改进的质量分布",此前无人给过。但 SOTA 叙事要打折:按论文自报的 ±1.7pp binomial SE,Terminal-Bench 领先 2.94pp 在双系统噪声下仅约一个 SE 量级;OSWorld 领先 0.5pp 无显著性检验;SWE-bench Pro(p=0.40)和 GAIA 干脆是 parity——headline 强于统计证据。更致命的硬伤是**归因缺失**:没有 day-0 seed vs day-161 seed 同模型对照,1,085 次 self-commit 和分数之间的因果链完全没建立,你无法排除"分数全来自作者的人工初始设计、演化只是昂贵的装饰"。加上不同 benchmark 挑不同 base model 报最好成绩、review quorum 构成不披露(把关强度不可复核)、单 lineage 不能外推安全性质——"self-development 有效"这个核心 claim 其实还悬着。与 DGM 的本质区别倒是真的:DGM 拿 benchmark 分数当 fitness 刷循环,这里演化压力来自 review + 真实部署经验,benchmark 只是冻结快照的度量,这个 formulation 更接近生产现实。
- **Rating**: `3` 🔥 ,正中 vault 的 harness 设计与归因主线:评测纪律与 161 天部署数据是稀缺资产,而它缺的 day-0 vs day-N 归因实验恰好是我们该做的题;repo 已开源,值得 repo-digest 跟进。

### SWE-Bench ProMax
- **Title**: SWE-Bench ProMax: Benchmarking Agents on Large-Scale Multilingual Code Refactoring
- **Institutes**: 未渲染/推测中国大陆+香港团队
- **Source**: [link](https://arxiv.org/abs/2608.09802)  📰 HF Daily ⬆️ 122   **📒 论文笔记**: [[2608-SWEBenchProMax]]
- **核心**: SWE-bench Verified 双重失效——frontier agent 已到 75%+ 区分度耗尽，且论文转引 OpenAI 审计称近 60% 未解决实例含缺陷测试（35.5% 过窄/18.8% 过宽；此数字为对 OpenAI note 的转引，笔记未独核原文）——于是作者换任务形态：170 个专家策展的多语言 refactoring 实例（七语言、70 仓库，29,782 候选筛到 170，接收率 0.57%），gold patch 平均改 11.4 个文件/261.6 行，要求行为保持的跨文件协调修改。6 个 frontier 模型 × 2 个 scaffold 评测，最好成绩 GPT-5.2 + OpenHands 仅 41.2%。附带一个扎眼发现：换 scaffold 同一模型 resolve rate 可差近 2 倍（GPT-5.2 21.8%→41.2%），Gemini-3-Pro 甚至反向下跌（26.5%→19.4%）。
- **锐评**: 这是 benchmark 论文里少见的正确姿势——不靠堆难度续命，而是换任务形态测 Verified 根本测不到的能力（sustained cross-file coordination），86% 单文件 vs 平均 11.4 文件的对比给足了硬理由；策展也是逐条对着 OpenAI 审计的具体失效模式打（从零重写 spec、人工删过窄/过宽测试、2025-01 后 commit 防泄漏），不是泛泛"更严格"。失败模式分析同样值钱：agent 文件覆盖 CDF 在 ~10 个文件就到 90% 而 gold patch 要 ~20 个，把 41.2% 分解成了可操作的瓶颈（incomplete refactoring + 空转探索）。但硬伤也很实：判定天花板是测试套件——"通过全部测试"≠行为保持，测试没覆盖到的行为漂移检不出来，resolve rate 系统性高估真实正确率，且论文未量化测试覆盖与判定可靠性；笔记标注全文未见 formal equivalence checking（absence-based 判断，论文未显式否认）。每语言仅约 20-29 个实例，"C 最容易 75%"这种逐语言结论建在 ~20 样本上纯属噪声敏感区。scaffold 效应差 2 倍是全文最有信息量的数字，却停在 bundle 级归因——"richer runtime tooling 有利"是猜测不是消融，OpenHands 的 sandbox/编辑工具/prompt 到底哪个贡献增益答不上来，Gemini 反向数据点更暴露 scaffold×backbone 交互没人管。另外泄漏缓解有保质期：2025-01 时间线只防得住当前一代模型，论文没谈刷新机制。
- **Rating**: `3` 🔥 ，直击 agent benchmark 兴趣点：任务形态创新 + 未饱和区分度 + scaffold 敏感性实锤，是"排行榜数字里 harness 方差被低估"论断的又一关键数据点，尽管测试套件判定上限和 bundle 级归因留了明显尾巴。

### Business Arena
- **Title**: Business Arena: Benchmarking LLM Agents in a Realistic Marketplace
- **Institutes**: Accio Team, Alibaba Group; Yale University
- **Source**: [link](https://arxiv.org/abs/2608.08621)  📰 HF Daily ⬆️ 12   **📒 论文笔记**: [[2608-BusinessArena]]
- **核心**: 让单个 LLM agent 在 30 个模拟经营日里自主运营一家 cross-border B2B 店铺，sourcing 侧用真实 Alibaba listings、关税用 WITS、季节需求用美/欧/中官方零售统计校准。15 个 frontier 模型 10-run 平均终局净资产从 \$20,856 到 \$188,488（9.0×），51% 的 run 相对 \$80k 本金亏损，最强 expert 策略 \$436,195 超最佳模型均值两倍。真正的卖点不是又一个商业沙盒，而是它把"分数是否真在测目标能力"当成实验命题：9 组 mechanism ablation 系统构造 neglect/shortcut 对照证明二者都被惩罚，再叠加 expert 机会上界、skill-level metrics、action-level attribution、save-fork-load 反事实评测。
- **锐评**: 方法学是这篇的硬通货——ablation 直接堵住"高分=simulator hacking"的质疑，ICC(1,10)=0.944 且诚实报告单 run 只有 0.626、split-half ρ=0.898，这种方差纪律在 agent benchmark 里罕见地规范；"保本率"与均值并列、客服榜（Opus 4.8 84% 转化第一但整体经济弱）与利润榜解耦，都实打实证明单一 leaderboard 数字会骗人。但绝对数字别当真：整套 grounding 全在输入侧，"决策→利润"的映射（买家选择、价格弹性、NPC 竞争）是设计出来的，从未与真实商家结果对照——9× 差距和 \$436k headroom 只在模拟内成立。demand inference 那个漂亮的 ρ=0.972 更要打折：Google Trends 信号被后处理到与 oracle demand 相关，它证明的是"环境里的信号确实可用"，不能读成"真实公开信号有这么高信息量"。另外两处结构性弱点：所有模型跑在同一 OpenClaw harness 上，榜单是 model×harness 联合效应，而非纯模型能力；全员开最大 thinking effort 却零 cost 口径，cost-accuracy Pareto 缺位；expert 上界由知道机制结构的人设计，headroom 可能偏高。跟 MerchantBench 比，它补上了后者"n=3 无显著性"的短板，但产出侧不 grounded 是两家的共同原罪。
- **Rating**: `3` 🔥 ，evaluation-validity 当命题做的诊断四件套 + 可靠性纪律值得任何开放环境 benchmark 抄，与 AI Agent / harness 归因兴趣线正中；扣分项是模拟内经济结论不可外推、单 seed、无 cost 维度。

### GHD
- **Title**: The Next Screenshot Knows: Gated Hindsight Distillation for Mobile GUI Agents
- **Institutes**: 未提供
- **Source**: [link](https://arxiv.org/abs/2608.06065)  📰 HF Daily ⬆️ 6   **📒 论文笔记**: [[2608-GatedHindsight]]
- **核心**: 离线训练 mobile GUI agent 把成功轨迹拆成 prefix-action pair 时，动作之后的 next screenshot o_{t+1} 被丢弃——而"这个动作为何正确"的证据往往恰恰只出现在那一帧上。GHD 让一个与 student 共享参数、唯一多看 o_{t+1} 的 hindsight teacher，对 student 的 on-policy rollout 做逐 token teacher-forcing re-score，并只在"prefix-only student 失败、但 teacher 能凭未来帧恢复 demonstrated action"时才施加 JS 蒸馏。部署时 teacher、未来帧、gate 全部丢弃，零推理开销。AndroidWorld/AndroidLab 上对 Qwen2.5-VL-7B 与 Qwen3-VL-8B 两个 backbone 均稳定超 GRPO（AW 47.1→52.7 / 61.4→66.5，AL 31.9→43.1 / 37.4→54.1）。
- **锐评**: 少见的问题定位干净、方法克制的 GUI-RL 工作。"What should I do?（不确定的 prior）变成 What must I have done?（近乎确定的 posterior）"一句话就把动机压到底，且真做到了 simple——不加模型、不预测未来、不付推理成本，只是把数据里被扔掉的一帧重新塞回训练信号。最有信息量的不是主表而是 Table 4：只喂 reference action 反而掉分（-0.43），只喂 next screenshot（+7.42）反超把答案全给的 Full（+5.62）——"给答案"不等于"给证据"，screenshot-only gate 还顺手过滤掉合成轨迹里能抄 reference 骗过 gate 的冗余步骤，这个反直觉结果给足了 mechanism。gate 自洽性也是真设计：蒸馏用的 teacher 分布（Eq.5）与 gate 检验的 top-1 动作（Eq.8）同源同 prefix，检验的就是将被蒸馏的信号本身，不是代理指标。但别被标题的"hindsight/test-time"误导：这不是 test-time 机制，就是在 OpenMobile 的 hard subset（~6-7k 样本、200 steps）上的离线 RL 增强层。硬伤也清楚：gate 通过率、假阳/假阴率一个没报，τ_succ=1.45、δ=20 的敏感性因此是隐藏面；gate 只锚单一 demonstrated action，多解步骤会误拒/误纳；只用 t+1 一帧，延迟反馈/跨屏事务机制上够不着；验证面窄到只有 mobile + 只有 Qwen 系。GRPO baseline 在 AndroidLab-8B 上竟退化到低于 SFT（37.43<39.13），部分相对增幅难免有 baseline 欠调的成分——所幸同预算对照（Table 5，+2.29/+14.50）和 7B 结果把这担忧压了一半。还要说清：Table 1 里 UI-Venus-1.5-8B 73.7 等 open-weight 更高，GHD 系统绝对分并非 SOTA，作者自己也只说 competitiveness——这东西的正确读法是"可叠加在任意 offline RL recipe 上的训练信号"，不是新 SOTA 系统。（顺带：全文并无 "Contrastive Calibration" 之类组件，别被外部传言带偏。）
- **Rating**: `3` 🔥 ，问题提得干净、方法克制、Table 4 的 screenshot>答案是真 insight——尽管 gate 统计缺失、验证面窄、绝对分非 SOTA，作为可移植的离线 RL 监督信号仍值得跟进。

### PointWorld
- **Title**: PointWorld: Scaling 3D World Models for In-The-Wild Robotic Manipulation
- **Institutes**: Stanford University, NVIDIA
- **Source**: [link](https://openaccess.thecvf.com/content/CVPR2026/html/Huang_PointWorld_Scaling_3D_World_Models_for_In-The-Wild_Robotic_Manipulation_CVPR_2026_paper.html)  🎓 CVPR2026   **📒 论文笔记**: [[2606-PointWorld]]
- **核心**: 把 state 与 action 统一成 3D point flow：scene 用 RGB-D 反投影的点云，action 用 URDF+FK 前向推演出的 embodiment-agnostic dense point flow，喂进 PTv3 backbone 预测 full-scene 逐点位移。单一预训练 checkpoint 接 MPPI-MPC，无需 demo 或 post-training 就能 zero-shot 驱动真实 Franka 做推/变形/articulated/工具操作。配套自建 ~2M 轨迹/500 小时数据集和一条无标注 3D 标注管线（Stereo + 相机位姿优化 + CoTracker3），号称最大 3D dynamics 数据集。
- **锐评**: 表示层的 unification 是真 taste——把 action 变成"想象出来的、完整可见的" robot point flow，一举解决 video world model 缺 action conditioning、遮挡接触无法表达、跨 embodiment 不好迁移三件事，比"给视频塞 action token"干净得多，多轴 scaling ablation 也比刷单点 SOTA 有信息量得多。但别被 log-linear 曲线晃花眼：主指标是一秒 horizon 的逐点 ℓ2 flow 误差，而 ℓ2 到任务成功率的映射作者自己都承认没量化——模型层面的漂亮 scaling 不等于下游成功率同步 scaling。真机数字更是当场自曝：Drawer 90% 但 Book 20%、Microwave 30%、Pillow 40%，每类就几次试验方差巨大，且 task point 与 target 还得人工 GUI 或 VLM 指定，这是"world model + MPC 可行性演示"，不是稳健策略。所谓"统一表示"也没抹平 sim-real gap——D→B zero-shot 直接烂到 0.1460，靠 finetune 才救回来（虽然 20× 更少迭代就超 specialist 确实亮眼）。整套还硬绑精确 URDF/FK 与 FoundationStereo 深度质量，无 URDF 的柔性/欠驱动 embodiment 一律没验证。至于"最大数据集""全部开源"目前仍是 will-be 未来式，兑现前只能算 claim。
- **Rating**: `3` 🔥 ，表示选择有 first-principles 高度、scaling 证据扎实、直接命中 world model / embodied 兴趣核心；真机成功率和 ℓ2 代理指标是明显软肋，但方向价值足够高。

### StealReasoning
- **Title**: Stealing Reasoning Traces from Proprietary LLM APIs
- **Institutes**: ELLIS Institute Tübingen, Max Planck Institute for Intelligent Systems, University of Tübingen, Tübingen AI Center, MATS Research, Snyk
- **Source**: [link](https://arxiv.org/abs/2608.09867)  📰 HF Daily ⬆️ 55   **📒 论文笔记**: [[2608-StealReasoning]]
- **核心**: 各大厂商为多轮对话连续性，把隐藏的完整 CoT 以**加密块**回传客户端。本文的关键发现：这些加密块在同一 provider 生态内跨 session、跨用户、甚至跨模型完全兼容可互换。攻击者只需普通 API 权限，就能把强模型（如 Opus 4.8）的加密 reasoning prefill 进同生态的弱模型（如 Haiku 4.5），再用 jailbreak 逼其逐 token 明文转写，把本应隐藏的推理提取出来。据此在三家生产模型上演示了蒸馏、隐私窃取、隐蔽注入、越狱四类攻击，并从 6,708 条公开 agent 轨迹里恢复出 367 项 PII 和 182 项 credential。
- **锐评**: 这是一篇罕见的"威胁模型弱到令人不适"的安全论文——纯 API 访问就把厂商引以为傲的"隐藏 CoT 防蒸馏"防线连根拔起，切中 reasoning-model 商业化的核心保密假设，问题选得极准。真正的贡献不是单点越狱，而是 Sec 2.3 那句"跨模型可互换"：它把 Green 2026 的本地解码问题升级成可规模化的窃取通道，315,320 条重建 trace + 62 个 API key/33 个密码 的 in-the-wild 战果说明危害已经发生而非纸上谈兵，这比任何 attack success rate 表格都有说服力。但硬伤也不小：**faithfulness 的证据是间接的**——全篇用 thinking-token 计数当保真度代理，没有对"提取内容 == 真实 CoT"做 ground-truth 语义比对，也没有一个显式成功率数字，token 数贴近顶多证明"长度对得上"，不等于"内容对得上"。防御一节（Sec 5.5/Appendix A）更是清一色提案、零实证，修复到底是堵死还是仅仅抬高成本，读者无从判断。加上结果依赖 2026-08 前的实现、披露后 Fig 1 已不可复现，外部复核窗口彻底关闭，机制虽在披露时点自洽，但可验证性天然打折。对我的 GUI/VLM/Agent/Embodied 主线关联偏弱，最大迁移价值是那条冷峻的提醒：agent trajectory 数据集发布前必须做泄露审计，靠隐藏 CoT 防蒸馏的假设已经不成立。
- **Rating**: `3` 🔥 ，问题重要、威胁模型极弱、in-the-wild 危害量化到位的高影响安全工作，尽管 faithfulness 用 token 计数代理、防御纯属提案未实证。

### AgentMemoryDistill
- **Title**: Agent Memory Distillation: Empowering Small LLM Agents with Hierarchical Teacher Memory
- **Institutes**: KAIST, DeepAuto.ai
- **Source**: [link](https://arxiv.org/abs/2608.07169)  📰 HF Daily ⬆️ 39   **📒 论文笔记**: [[2608-AgentMemoryDistill]]
- **核心**: Training-free 的 agent memory 蒸馏:让 GPT-5-mini teacher 先在任务集上跑出成功轨迹,提炼成 Workflow(NL insight)/ Subtask(code 示例)/ Function(error 触发 hint)三层 memory,供 4B-8B student 检索。AppWorld / BFCL V3 / ToolSandbox 上四个 student 平均相对 zero-shot +27.2 / +11.2 / +3.4 个百分点,Gemma4-E4B 和 Qwen3-8B 在 AppWorld 上反超 teacher 本身。核心发现是"消化"三要素:粒度分层、表示匹配(高层 prose、低层 code,49.40 vs 23.21)、注入时机(proactive vs error-reactive)。
- **锐评**: 组件全是旧的——workflow memory 承自 AWM、subtask 检索、error-triggered hint 都见过,但这篇把"teacher 经验怎样才能被小模型咽下去"的三个自由度 ablation 答齐了,这是它比一堆 memory 灌水文强的地方。真正值钱的三个数字:Subtask memory 单项 +25%p(Table 2)、k=1→5 时精度从 49.40% 单调掉到 33.34%(小模型经不起检索噪声,与 vault 内多篇 memory 论文互证)、以及 teacher compatibility 的负结果——DeepSeek V4 Pro(teacher acc 81.55%)教 Qwen3-4B 反而不如 GPT-5-mini(50%),作者没藏这个反直觉发现,诚实加分。但三处硬伤必须点名:其一,memory 构建集与评测集就是同一 benchmark,disjoint 协议(self-excluded 46.43%)只排除了任务级泄漏,cross-benchmark / cross-domain 迁移完全没测——现在这更像"同环境程序性经验转移"而非广义 distillation,标题有点大。其二,claim-evidence 缺口:"consistently outperforms all baselines in every model" 覆盖四个 student,Table 1 的 baseline 数字却只列了两个,另两个全凭正文断言(Ledger C5 已标注)。其三,MemP / SASM 本是 same-model self-evolution 方法,强改到 transfer setting 后被吊打,这个对比的公平性存疑;ToolSandbox 上仅 +3.4%p 且 ablation 未覆盖,对话式场景为何失灵一字未解剖。Compatibility 现象也止于描述,没有可操作的 teacher 选择判据。
- **Rating**: `2` 👀 ,ablation 纪律扎实、三个 actionable 发现直接喂给我们的 memory/harness 主线,但方法是组合式、通用性证据止步于同 benchmark,离"重要工作"还差 cross-domain 那一步。

### R-OPSD
- **Title**: Test-Time Self-Evolving GUI Visual Grounding via Reflection-Guided On-Policy Self-Distillation
- **Institutes**: 未提供
- **Source**: [link](https://arxiv.org/abs/2608.11191)  📄 arXiv   **📒 论文笔记**: [[2608-ROPSD]]
- **核心**: 让 GUI grounding 模型部署后在无 GT 的界面数据上自我改进：一个先用带 GT 数据训好的 MLLM Reflector 对每次坐标预测输出二值评估 S 和一段文本反思 R，再由 R-OPSD 把 pi_G 自身条件化在 (S, R) 上当 self-teacher，取条件化 teacher 与无条件 policy 的逐坐标-token log-ratio 作为稠密监督，把自由文本反思翻译成 policy gradient 能吃的信号。Contrastive Calibration 用被反向告知"预测正确"的 inverse-prompted student 做对比分母，抑制失败探索里错误前缀对监督的污染。Qwen2.5-VL-3B 在六个 grounding benchmark 上 adapt-on-MMG 平均 50.2→57.6（+7.4），较 TTRL 基线 GUI-RCPO 最高 +7.7（对方在同设置负迁移 -0.3）。
- **锐评**: 这篇难得地回答了一个真问题而不是刷点——"标量 reward 只说成败、文本反思信息量更大，但怎么把自由文本变成 policy 能优化的信号"一直缺解，conditioned self-teacher + log-ratio advantage 是 simple & generalizable 的转译方案，还顺手证明了能当无监督训练算法用。消融也硬：无 reflection 或无 CC 都不是掉几个点而是直接 policy collapse，说明组件是结构必需；Table 3 又系统排除了"增益来自 OPSD 本身"（GUI-SD 崩）和"增益只来自 Reflector 的 S"（binary-S GRPO 仍差 4+ 点）两个替代解释，CC 的两段行为还有 Fig. 4 的 token 级定量兜底（初始错 token -0.97 vs -0.39、漂移末端 0.0033 vs 1.34），不是纯 story。但硬伤在包装：所谓"test-time adaptation"实为 transductive 离线设置——adaptation 数据就是 benchmark 自身去标签、训完再评，in-domain 数字（adapt SSv2→eval SSv2 88.8）含 transductive 成分，跟"部署后遇到未见界面流式自进化"的动机叙事有明显距离，别当成流式部署已验证。更要命的是整个闭环压在 Reflector 上，而它恰恰是用带 GT 的 GroundCUA 训出来的——"无需人工标注"只对 test-time 那一半成立；论文只给了 89.5-91.7% 一个工作点，没做"Reflector 掉到多少框架失效"的压力测试，而分布外 UI 风格下 Reflector 大概率先退化，那正是最需要 adaptation 的场景。此外增益随基座变强快速收窄（Qwen3-VL-8B 只 +1.4~2.0），价值集中在中小基座，却要付 1.73× GRPO 训练开销；只测单步 grounding，没验证能否传导到 agent 端到端成功率；附录 Table 7 把 91.7 归到 Qwen2.5-VL-3B 名下并据此算"超 zero-shot 15.2%"，与 Table 4 的归属（91.7 属 Qwen3-VL-2B）自相矛盾，读数时留神。
- **Rating**: `2` 👀 机制干净、消融诚实、CC 是对 incorrect-prefix 问题的巧解，值得进 CUA-Survey 的 test-time adaptation 线；但 transductive 设置被叙述成流式 TTA、Reflector 依赖 GT 却无失效边界、只测单步 grounding，压住了它的上限。
