### EnvHarness
- **Title**: EnvHarness: Awakening Static Worlds for Agent Learning
- **Institutes**: Google Cloud AI Research, Google Cloud, University of North Carolina at Chapel Hill, Washington University in St. Louis
- **Source**: [link](https://arxiv.org/abs/2608.19880)  🔥 HF Trending ⬆️ 259   **📒 论文笔记**: [[2608-EnvHarness]]
- **核心**: 把"造环境"降级成"包环境"：只在 `reset`/`step` 接口层套一层 decorator，用 Stage（replay 动作序列改初始状态）、Contract（改写动作/转移/观测三个 hook）、Chain（串接两个环境，复合 verdict 取合取）三类组件改造冻结的静态 benchmark，底层 simulator 和人工 verifier 一行不动。EnvRigger 把 policy 当黑盒，跑 5 次 rollout 诊断弱点 → 让 designer 直接 emit Python 组件源码 → 再用 5 次 rollout 判接受/拒绝/重写。五个 benchmark 上 skill-based learning 最高 +9.0（ALFWorld OOD 70.4 vs 61.4），SWE-bench Verified SR 52.58 vs 49.88、平均步数从 55.01 降到 49.61。真正的杀手锏是 Figure 5 的 scaling 曲线：同预算下原始环境和生成环境在 300 个环境处已平掉（52.13 / 50.37），EnvHarness 还在往上爬到 54.79。
- **锐评**: 抽象层次选对了，这是全篇最硬的东西——生成式环境路线为了造新任务必须伸进环境内部自造 verifier，正确性成本全从这来；EnvHarness 不造新任务、只改暴露面，一句"接口层变换"同时把 domain-agnostic、verifier 保真、可组合性三样一起买下。Appendix C 那条 `get_env_state()` 只暴露纯数据视图、组件 hook 只准读它的约束，加上生成代码在每 episode 独立子进程里跑，是任何想让模型自己写环境侧代码的系统都该直接照抄的地基，价值高于主表任何一个数字。最有信息量的一行也不是 EnvHarness 那行，而是 Original Envs：WebArena 38.5 和 SpreadsheetBench 45.88 都**低于完全不给 skill** 的 38.7 / 46.44，SWE-bench 上还把轨迹拉长——静态环境让 agent 反复练已经会的事，抽出来的是负资产，这个反例比正面增益更能立论。

  但 claim 和证据之间有几处明显的松动。第一，那两个 headline 数字（9.0 点 / 9.8% 步数）分属不同 benchmark，9.8% 还是相对 Original Envs 而非 No Skills baseline，摘要读起来像同一套设定的双赢，实际不是。第二，除 ALFWorld OOD 外增益全是个位数点，全文没有任何显著性检验；笔记的独立核查还把"主表皆为三次独立运行均值"降级为 unsupported——只有 Table 2 caption 这么写，Table 3 只给了 std 没交代重复次数，而 OfficeQA EM 的 +1.80 同时小于两侧 std（1.84/2.34），这一个点基本可以当噪声看。第三，效率提升的机制归因是解释不是消融：原文措辞是 "directly correlates with"，Table 5 只把 Chain 和 Stage/Contract 当两整组比，没有任何实验隔离"打断循环"或"过滤冗长观测"这两条具体机制，这条在笔记里同样被判为 unsupported，别拿它当结论用。第四也是最要命的，主表的因果链上挂着一层 ReasoningBank skill extraction，测的其实是"从改造环境抽出的 skill 更好"，而不是"改造环境本身更好"；共享抽取 pipeline 只排除了 pipeline 差异，排不掉"轨迹分布变了导致抽取器表现变了"这条通路。唯一绕开 skill 层的 RL 实验只有两个环境四个指标，还输掉一个（ALFWorld OOD 88.8 vs 89.6，被作者一句 negligible 带过）。固定 skill bank 只换环境、固定环境只换抽取器的 2×2 是最该做的实验，作者没做。

  剩下两处硬伤：三个组件里最"新"的 Chain 恰恰是唯一没进自动化闭环的（笔记指出原文是"难以观察"内部状态，不是"无法"，别夸大），且单独用时 SR 反而略降到 49.63。跨 backbone 增益一律 2.7–3.7 点、几乎不随 policy 强度变化（no-skill SR 从 30.7 到 67.2），反直觉——如果诊断质量真随 designer 变强，增益不该这么平；作者的解释没有任何交叉配对实验支撑。对我们最直接的一刀：`reset` 是 binding constraint，Stage 靠 replay 动作序列构造初始状态，这在真实浏览器和 OS 上根本不成立（副作用不可逆、转移非确定），作者自己把 visual / GUI / embodied 列进 future work。所以这套结论**不能**外推到 GUI agent 环境——想搬过去，Stage 得换成快照/VM checkpoint 之类不依赖 replay 的状态构造机制，那本身是另一个独立问题。
- **Rating**: `3` 🔥 ，reframe 本身（authoring → wrapping，verifier 免费继承）比任何数字都值钱，Appendix C 的三层协议可直接照搬到我们的环境侧工作；扣分项是效应量小、机制归因未消融、主结果被 skill extraction 中介，且接口假设正好卡死 GUI/embodied 方向。

### TRACE
- **Title**: TRACE: A Self-Evolving Skill Bank for Consistent, Limit-Aware LLM Agents
- **Institutes**: Xiaomi Inc., Nanjing University, Beijing University of Posts and Telecommunications, Tsinghua University
- **Source**: [link](https://arxiv.org/abs/2608.22793)  📄 arXiv   **📒 论文笔记**: [[2608-TRACE]]
- **核心**: 针对"部署可靠性 = consistency + limit-awareness 而非峰值能力"这一设定，TRACE 不改权重，只演化一个外部 markdown Skill Bank：Curator 按被调用的 skill 给评测轨迹分组、对比成败轨迹重写 skill body，Actor 在部署时每一轮根据当前对话状态重新决定激活哪些 skill、几个、什么顺序。评测在 CAR-bench（Kirmayr et al. ACL 2026，非本文提出，58 工具 + 19 条 policy + LLM 模拟用户）上进行。主表 GPT-5.5 的 Pass^3 从 59.9% 升到 94.5%，Pass@3−Pass^3 gap 收到 4.0 点；官方 hidden set（GPT-5.6-Sol，30 任务 × 3 trial）Pass^3 50.0%→70.0%，作者自述取得第一名。代价是 token +72.4%、成本 +58.8%、延迟 +22.0%。
- **锐评**: 问题设定和 metric 比方法值钱，但摘要的卖点站不住。§3.1 白纸黑字写着演化循环先用 training split bootstrap、再用 **test split** 拓宽覆盖，而 Table 1 的 94.5% 报在 train+test 合并集上——在优化过的数据上报 gap closure，这是把一个好 metric 用坏的教科书示例。笔记的推算把折扣量化得很清楚：域内 gap 27.8→4.0 收窄 23.8 点，hidden set 上 16.7→13.3 只收窄 3.4 点。也就是说"把潜力转成稳定行为"这个 claim 在真正 held-out 数据上基本没兑现，剩下的 Pass^3 +20 点更像整体能力上移。引用请用 50.0→70.0，别碰 94.5。第二刀：Pass^3 里混着 LLM 模拟用户的随机性，论文自己的 Figure 4/5 就显示两次 trial 的用户开场白措辞不同，却没报 temperature/seed，也没做固定用户回放的对照——一篇把 consistency 当核心 claim 的论文，居然没把"agent 变稳"和"用户恰好这么说"拆开。第三刀：标题写着 Self-Evolving，全文零 component ablation、零轮数 R 曲线、零 misevolution/退化检查，唯一护栏是 LLM 自己跑的 de-hardcoding 校验且未度量。limit-awareness 也缺 false-refusal 反面指标，token +72.4% 恰好和"多追问几轮"的行为一致（笔记反推 Base 类没塌，只排除了粗暴全面拒答）。方法层面，层级抽象 + 对比重写 + 检索编排都有先例，真正新的 Deployment-Faithful Reconstruction 信息隔离和 per-turn 无状态重编排恰恰一个 ablation 都没有。
- **Rating**: `2` 👀 ，framing 与 Pass^k/Pass@k gap 这个 metric 对我们的 harness / self-evolving agent 线有直接价值，但主表污染 + 零 ablation 让方法本身的证据强度撑不起 Foundation。

### Graph Engineering
- **Title**: Graph Engineering in the Era of LLM Agents: From Individual Intelligence to System Intelligence
- **Institutes**: 原文未列出
- **Source**: [link](https://arxiv.org/abs/2608.21156)  📰 HF Daily ⬆️ 35   **📒 论文笔记**: [[2608-GraphEngineering]]
- **核心**: 35 作者、461 条引用的 survey，把 Prompt → Context → Harness → Loop 的工程演进接上一个新阶段 Graph Engineering：主张单 agent（Individual Intelligence）在并行依赖、独立验证、可回滚 state 三处存在结构性上限，需用显式图结构在 Task Organization / Agent Coordination / Runtime State Management 三个系统层视图上组织，才能得到 System Intelligence，并以 System Evolution 横切三者。全文无实验，novelty 依据是附录 Table 4 的自评覆盖矩阵，"Ours" 八维度全 ✓。两处实质产出在框架之外：§9.7 区分 graph-structured 与 graph-engineered（结构若是人工选定且执行前固定，就只是前者），§6.1/§7.4 要求 benchmark 提供 matched execution budgets、versioned graph artifacts、完整 trace 与受控结构扰动。
- **锐评**: 分类学不可判定就等于修辞。给一个组件，这套框架答不出它归 Harness 还是 Loop——§3 通篇散文定义加引用清单，无指标、无判定流程（C5）；一个自动重试的 harness 同时落在两边。全文支点"单 agent 存在固有上限"只有引用加假想例子、无作者自有测量（C6），是 position 不是 finding：论证止步于"当前单 agent 做得不好"，没排除这是模型能力与 harness 成熟度的函数——而排除办法它自己在 §6.1 写了，只拿去量别人。Novelty 全押 Table 4 的自评自打分（C1）；逐列做算术推论（非原文断言）会发现唯一无前作拿 ✓ 的列是 Ontology，而 §6 标题写着 Future Direction——增量 ≈ 已有覆盖的并集 + 一节未来工作。对早三天的最近竞品，切割也只到"提问角度与系统范围不同"（C3）。图被断言为 natural 而非论证为 necessary，全节不与关系表 / event log / HTN 作任何对比（C7）。值钱的两处都不在 taxonomy 里：§9.7 的 graph-engineered 判据是全文唯一近乎可证伪的东西，§6.1+§7.4 的算力对齐与结构消融要求来自图/MAS 社群，构成归因缺口的跨社群独立信号。35 作者、461 引用，广度替代了论点。
- **Rating**: `2` 👀 ，taxonomy 不做可证伪预测也不改变任何人会 build 什么，但 461 条引用是 harness 方向可用的覆盖度体检，§9.7 判据与 §6.1 评测纪律值得单独引用。

### MobilePA-Bench
- **Title**: MobilePA-Bench: Benchmarking Mobile Planner Agents on Complex Real-World Tasks
- **Institutes**: MAI Team Alibaba Token Foundry
- **Source**: [link](https://arxiv.org/abs/2608.23035)  📄 arXiv   **📒 论文笔记**: [[2608-MobilePABench]]
- **核心**: 把 mobile agent 评测从「GUI 像素操作」与「离线 API 字符串匹配」之间的空档接起来：一个带持久化数据库、会返回结构化运行时反馈的模拟 sandbox，1,705 任务 / 212 工具 / 13 domain，只考中枢 planner 的 Basic Tool Use、Sub-agent、Memory、Skill 四项。评测设计按「什么证据最能证明完成」把每个任务固定路由到三个 bucket（工具序列匹配 / 终态 DB delta / 行为 rubric），memory 检索与 gold skill 加载则做成主 checker 之上的合取 gate。13 模型横评中最好的 Claude-Opus-5 加权总分 75.52%（Table 3 里 Overall 在第二列，不是末列），Memory 维度 13 模型均值仅 50.98%，7 个模型总分不到 70%。
- **锐评**: verification 分层是真本事——主 checker 按证据类型固定路由、memory/skill 做正交 gate，比把一切塞进单个 success flag 的同行干净一个档次。可惜最关键处失声：全文没说 Bucket 3 的 rubric 谁执行，唯一痕迹是 Table 3 caption 里那句「judge outputs」；而占总分 10% 的 Sub-agent 维度全部走 Bucket 3 且只有 89 题，作者自己的重跑就显示两题翻转值 2.25 点。所谓稳定性实验测的是模型采样方差，不是 checker 正确率，标注协议与一致率零报告。归因同样脏：召回固定 N=15 却不报 recall@15，T_max=15 对它自己强调的 long-horizon 任务偏紧，步数耗尽与规划失败在分数上分不开——「前沿模型只有 75%」里有多少是 harness 的账，作者没算。标题的 Complex Real-World 实为 human seed 合成扩展加合成 user profile world，摘要许诺的「foundation for agentic RL」全文零 RL 实验。最省事也最有诊断力的消融（gate 过/checker 挂 的三分解）没做。另据笔记作者 08-25 的外部实测（非论文内证据），承诺的开源仓库当时仍为 404。
- **Rating**: `2` 👀 ，bucket routing 的评测切分值得抄进我们自己的 agent benchmark，但 checker 可靠性与 harness 归因都没落地、代码也没放出，75.52 只能当参考数字，更不能和 OSWorld/AndroidWorld 的分数并列——最难的感知部分被它设计性地剥离了。

### GSAR
- **Title**: GSAR: Goal-State-Anchor Rewards for Mobile GUI Agents with Self-Evolving Data Synthesis
- **Institutes**: Wuhan University, Xiaomi Inc.
- **Source**: [link](https://arxiv.org/abs/2608.22847)  📄 arXiv   **📒 论文笔记**: [[2608-GSAR]]
- **核心**: 给 mobile GUI agent 的 VLM judge 多喂一张"任务完成后长什么样"的参考截图，并按 a11y tree 在上面画出任务相关元素的 bbox，judge 据此对当前屏出二值 reward。goal state 来自 self-evolving 数据合成 pipeline——在真机上反复执行任务让 app 状态自然变复杂，并保存可复现的初始环境快照，取成功轨迹终止帧作参考答案。离线 315 条轨迹上四个 judge 平均 91.5% Acc / 91.8% F1，把 StepCritic 的 77.6/81.8 拉开一大截。但在 AndroidWorld 同 backbone 的 online RL 头对头里，GSAR 训出的 UI-TARS-7B-DPO 只到 30.2%（+3.5），低于 rule-based reward 的 32.8%（+6.1）。
- **锐评**: 这篇最值钱的东西恰恰是它自己输掉的那个实验。绝大多数 model-based reward 论文只报 offline agreement 就宣布胜利，这篇老实做了同 backbone、同训练子集的 rule-vs-model 对照，并如实写下自己低 2.6 点——那 2.6 点就是残余奖励噪声的实测标价，比 91.5% 那个 headline 有信息量得多。附带的 rollout 墙钟数据（GSAR 2342 s/step vs rule-based 2755 s/step，笔记标注低约 15% 系本人计算）也反直觉且有用：rule-based 反复走 ADB 查设备，比跑一遍 judge 推理还慢，"模型奖励=昂贵选项"这个默认假设该改了。但方法本身的硬伤很清楚：91.5% 是在 315 条**离策略**轨迹上测的，那是 GUI-Owl-7B / Qwen2.5-VL-7B 评测记录构成的、从未承受过优化压力的固定分布；而 GSAR 的判据本质就是"当前屏是否视觉匹配这张画框的图"，最直接的攻击面——策略学会到达像素上对上 anchor、实质没完成任务的屏幕——全文一个测试都没有（笔记明确记录检索 collapse/hack/gaming/Goodhart 零命中）。论文证明的是 reward 与成功相关，不是 reward 可以安全被优化，而 C5 那 2.6 点正是这个 gap 的账单。Ablation 更是把牌摊开了：w/o reference 掉 26 点，w/o anchor 只掉 3 点不到——真正干活的是"多给一张参考图"这个平庸操作，论文标题里的 anchor 只是配菜，而且 Table 3 的 w/o reference 与 Table 2 的 StepCritic 逐位相同、w/o history 与 GSA-Only 逐位相同，anchor 的贡献全程只有一次独立测量。Delete 类任务上 GSA-Only（88.1）反而低于 GS-Only（91.5），框太大把注意力引偏——这暴露了 anchor 是像素高亮而非符号谓词的本质局限，也是作者自陈"单终态判据 + 完成态须有视觉表达"天花板的同一个病根。另外两处该扣分：online RL 的主打数字（+23.2% / +8.1%）跑在自建 86 query benchmark 上，半数是 training split，且成功率"由人工与 GSAR 双重核验"却不给一致率——用被评估的 reward model 去评估它自己训出的策略，循环性摆在那；而唯一外部定义的 AndroidWorld 只给出 +3.5。self-evolving 那半边更虚：从没在固定数据预算下与非演化合成对照，"多迭代"和"多数据"完全不可分离，Table 9 里 edge density 0.0240→0.0295、UI 元素 22.68→24.56，作者自己都只敢写 "slightly"。换到 UI-TARS-7B-SFT 这种 GUI 特化 backbone，AC-Low EM 91.52→91.53，增益直接归零——这套 pipeline 是把通用 VLM 拉到特化模型的水平线，不是推过去。"human-free" 也有例外：采集阶段做不出来的困难任务靠人工补 goal state，且 91.5% 的标注准确率意味着约每 12 份参考错一份，而一份错参考会污染该任务的**每一步** reward，误差传导没测。无代码发布。
- **Rating**: `2` 👀 ，方法本身平庸且核心 claim 没跨过"相关"到"可被安全优化"的那道坎，但同 backbone 的 rule-vs-model 头对头和 rollout 成本实测是稀缺的一手对照数据，值得进 GUI reward 的 survey 存档。

### Hydra-0
- **Title**: Hydra-0: Action Flow for Generalist World Modeling and Control
- **Institutes**: NVIDIA, Brown University, Columbia University, Harvard University
- **Source**: [link](https://arxiv.org/abs/2608.18077)  📰 HF Daily ⬆️ 5   **📒 论文笔记**: [[2608-Hydra0]]
- **核心**: 把机器人动作重新表示成图像平面上的稀疏点轨迹（action flow），用像素运动这一共享接口替掉 embodiment 相关的关节/末端指令，让同一个 video world model 跨形态、跨任务、跨 backbone 训练。这套表示有正反两条构造路线：有 URDF 与标定时走 Isaac Lab rollout + 相机投影，只有视频时走 AllTracker + grounded mask 反解，因此 DROID/EgoDex 这类无标定语料也能进多形态混训。反向使用同一接口即 world action model：只喂期望的 object flow，模型生成兼容的机器人运动并由 action head 读出指令。主要结果是 Table 2 的条件表示对比、IWS 上 0% 任务数据的迁移优势，以及 RoboLab 上 replay 成功率相关 r=0.96。
- **锐评**: reformulation 是干净的——video model 的输出空间是像素，那就把动作也放进像素空间，这一层 embodiment 相关的隐式映射直接消掉；正反双向构造 + 三个 backbone 复现，证据类型比单点 SOTA 值钱。但摘要在自毁信誉。头条的 90.40% / 60.16% 同时换了动作表示、backbone（Cosmos 2.5 2B → Wan2.2 A14B）和 4-step 蒸馏三样东西，受控口径只有 59.7% / 52.6%。更难堪的是 gripper EPE 这个指标本身：零样本、零 mid-training 的 ATI/Wan-Move 在这列拿 4.62/4.67，把作者精调的 baseline（34.28）碾了一个数量级——它度量的是"有没有照抄像素条件"，不是动力学预测，跨表示比较结构性偏袒 flow。object EPE 才是有信息量的那列。r=0.96 是 achieved-trajectory replay，policy 从不在生成观测上被 query，这是 policy evaluation 的必要非充分条件；且相关系数的 n 全文不自洽（正文读作 30、摘要读作 5），每点仅 10 rollout，成功率量化步长 10% 大于 MAE 5.7pp。"emergent inverse mode" 更是过度措辞：Object 条件以 0.40 概率训过，还额外 post-train 了 rank-32 LoRA 与 action/state head，真机只有单个 flexible-pipe-bending 的定性演示，作者自己写 proof-of-concept。摘要的 "zero-shot composition" 全文只在摘要与引言各出现一次，无任何对应实验。另外 4-step student 在 Average 全部七项上优于自己的 50-step teacher，论文一句不提，这个反常最该做 ablation。
- **Rating**: `2` 👀 ，接口设计对 world model 解绑训练数据是实质贡献，但 headline 数字、"emergent"、policy evaluation 三处 claim 都明显跑在证据前面。

### InstructMove
- **Title**: InstructMove: A Text-Indispensable Benchmark for Instruction-Following Manipulation
- **Institutes**: Horizon Robotics, WuwenAI, Southeast University, Huazhong University of Science and Technology
- **Source**: [link](https://arxiv.org/abs/2608.22990)  📄 arXiv   **📒 论文笔记**: [[2608-InstructMove]]
- **核心**: 论点是 manipulation benchmark 里语义可行的目标物往往只有一个，指令因此退化成 task identifier，于是提出 text-indispensable 判据：每个 episode 至少两个物理可执行候选、只有一个与语言一致。据此在 Isaac Lab 上造了 pick-and-place benchmark——1,757 个筛选后的 asset、四个任务族（category / attribute / spatial / compositional）、脚本合成示范（有效合成率约 70%），指标是 instruction-conditioned 的分阶段 Reach/Lift，Reach 相对指令一致目标定义，抓错物体即判失败。四个 VLA 每任务 100 条 demo 微调后普遍"定位对了但抓不起来"，最强的 π0.5 在 pick_category seen 上 Reach 0.82 / Lift 0.57，pick_spatial 全表最低（Reach 0.46–0.51）。counterfactual 诊断显示换指令能重定向目标（Alternative target 0.72/0.53 对 Normal 0.74/0.48），但撤掉指令后策略仍以 0.99–1.00 的比例去抓某个物体。
- **锐评**: 一个正确的判据，配一套没去验证它的实验。全篇最该有的那格是空的：按论文自己的定义，text-indispensable 的决定性证据应是撤掉/打乱语言后 **target-conditioned** Reach 掉到 6 选 1 的 chance 附近，而 Table 4 在 Generic/Empty/Absent 三行的 Target 列全是"–"，只报了 any-object 比例——作者自己也承认这两种口径不可比。所以"文本不可或缺"在这篇里是**构造保证的，不是测出来的**。真正有效的只有 Alternative target 一格，且只覆盖 π0.5 一个模型、一个 split；π0 和 Motus 的 Lift 全线 0.01–0.17，究竟是没听指令还是根本没适配 action space，无从分离。对既有 benchmark 的指控同样只有 Table 1 的 ✓/▲/✗ 打分加转引 LIBERO-CF，没跑过一次空指令对照——这种自评表格恰是 benchmark 论文最容易自利的部分。每任务 100 条 demo + 5,000 步 + 各不相同的适配方式（LoRA-only vs 更新 projector/diffusion vs 冻 Qwen3-VL），使绝对分数不可解释、排名混进适配质量；稳定性只声明 ±5pp，而 GR00T 与 Motus 在 pick_spatial 差 0.01，纯噪声。真机 Table 5 是 n=50：笔记作者按二项比例推算，19/50 对 26/50 的差（SE≈0.10）与 26/50→28/50 的"扩数据增益"都撑不起作者的两条结论；作者自己在 Limitations 承认 sim 排名与真机相关性尚未建立。值得留下的是那个指标决定和 Appendix B 的失败分析——18 次 Reach 失败里 15 次抓的干扰物与目标共享显著线索，给出"响应单个显著属性、不做完整 referent binding"这个可检验假设——以及开源的 asset/layout/validator 基建，复用价值大概高于 benchmark 本身。
- **Rating**: `2` 👀 ，问题提得准、指标设计可直接借用，但核心性质靠构造断言而非实测，缺的只是一个成本极低的 target-conditioned 无语言对照。

### Grounding Isn't Knowing
- **Title**: Grounding Isn't Knowing: Do VLMs Need Object Localization for Spatial Reasoning?
- **Institutes**: MBZUAI, The Chinese University of Hong Kong, University of Liverpool
- **Source**: [link](https://arxiv.org/abs/2608.23074)  📄 arXiv   **📒 论文笔记**: [[2608-GroundingIsntKnowing]]
- **核心**: 论文问的是机制而非榜单：VLM 判断"A 在 B 左边"时，是否必须先精确定位两个物体。做法是把 segmentation mask 命中的 visual token 替换成一个常量全局平均 embedding（干预点在 multimodal projection 之后、position encoding 之前），配等量随机 token 对照与 LaMa 抹除物体的 object-removed 对照集，再叠 position probe + logit lens、attention knockout、CMA 与累积 head ablation 四层干预。结果是 target ablation 把 Loc-T 打掉 5.37 / 27.90 / 64.93 点（LLaVA-1.5-7B / 13B / Qwen2.5-VL-7B），relation 最多只掉 1.32 点；而 mask 向外膨胀 1 格吃进周边 context 时 relation 才塌（13B 掉 12.38、Qwen 掉 6.37）。全层 knockout 在 LLaVA-1.5-13B 上把定位打到接近零、关系压到 chance 附近，作为 positive control 排除了"关系判断纯靠语言先验"。作者的限定结论是：需要 object grounding，但不需要 precise localization。
- **锐评**: 问题拆得漂亮——把 precise localization / relational grounding / spatial reasoning 三件常被混用的事分开，并且只给限定回答，比"VLM 根本没在看图"那类标题党克制得多。侵蚀伤定位、膨胀才伤关系的不对称，是全文唯一一个方向性可证伪的预测，值钱。但支撑面比宣称的窄：LLaVA-1.5-7B 的 relation baseline 是 24.82%，four-way 多选的 chance 约 25%（笔记作者依协议推算，论文全文未写出任何 chance 数值），它所有 Rel. 变化 ≤0.40 点是地板效应而非稳健性；13B 的 40.23% 也只是略高于 chance。真正承载结论的是 Qwen 一个模型，而它 96.11% 贴天花板，−1.32 点同样难与噪声区分，且没有任何 delta 报显著性。更要命的是对照设计：被替换的是按 mask 选出的连通区域 + 常量 embedding，外观身份没了，"此处有一块统计异常区域"及其精确位置完好保留——那恰恰就是论文说的 coarse anchor。随机对照打散全图，形状与位置都不匹配，排不掉"干预压根没触及关系推理所依赖的线索"这个同样融贯的解释。要 shape-matched 或 position-shifted 对照，论文没做。另外 abstract 说少量 head "mediates both"，正文是 top-10 只重叠 2–3 个、结论写 largely distinct——自己打自己脸，引用请以正文为准；probe 解码的也是每个 image token 的 grid 坐标（在 ImageNet 上训），不是被问物体的位置，"staged" 在正文是 hedge，到 abstract 升级成断言，而 7B 上 logit lens 全程近 chance，阶段边界在那个模型上无从检验。attention knockout 还缺 7B，±2 padding 与 prompt 都在 v1 未放出的 Supplement 里，无代码。
- **Rating**: `2` 👀 ，实验设计可直接迁移到 GUI grounding 的证据依赖性测量，但结论受地板/天花板与形状未匹配对照拖累，当方法论范本读、别当结论采信。
