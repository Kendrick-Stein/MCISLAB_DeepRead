# 🔪 今日总结

28 篇候选里精读 11 篇，最值得追的一条线是 **harness 本身正在变成可训练对象**：JIT-Agent 给 agent scaffold 定了 $(\mathbf{M},\mathbf{P},\mathbf{A},\mathbf{F})$ 四模块类型签名，把 13 个已有 scaffold 压到同一坐标系上，再训一个 27B 模型现场生成一次性 harness——这是今天唯一可能是 foundation 级的形式化，尽管它的效率数字连"含不含自己那次生成 pass"都没交代。

另一条线是**证据纪律的集体塌方**，而且几乎都塌在自家表格里。SenseSearch 的 Table 1 四条线俱全，任何人都能算出 RL 只值 +4.37（约 15%）、而 training-free 的 RAG workflow 对每个模型都打赢 agentic workflow——正文一字未提；ZonUI-3B 宣称的两阶段 desktop +3.3% / web +1.8% 换成等数据量对照后腰斩为 +3.0 / +0.9；VoiceMem 摘要里"top-5 打 Mem0 的 top-200"从未跑过 K=200；Visual Projection Space 的 regime 划分核心数字（67.9% / 68.8%）被它自己的 Figure 2（约 0.24 / 0.445）推翻。今天 11 篇里唯一一条 15/15 全 source-verified 的是 PanoEnv，而它的问题恰恰相反——数字全对，但缺 SFT 对照、训练 reward 与评测 accuracy 共用同一套 parser，对得上的数字撑不起它想讲的故事。

真正值得抄走的是三个方法学动作，都与结论无关：BDH-CQ 冻结模型后才生成、每次只动一个复杂度维度、换 context 而保持 test pair 逐字节相同的 controlled ladder；GRWM 冻结三个 dynamics backbone 只换表示模块的单变量替换；H3-World 把 "frozen backbone + 朴素 prompt" 抬成强制对照——这条几乎零成本，却让它自己的 constant-action 结果打成 301.8 vs 300.5 的平手，作者照实写了出来。

### JIT-Agent
- **Title**: JIT-Agent: Scaling Harness Intelligence via Just-in-Time Harness Evolution
- **Institutes**: National University of Singapore, EverMind AI, Nanyang Technological University
- **Source**: [link](https://arxiv.org/abs/2608.25593)  🔥 HF Trending ⬆️ 117   **📒 论文笔记**: [[2608-JITAgent]]
- **核心**: 把 agent harness 从"人写好、长期复用的工件"改成"拿到任务现场生成的一次性产物"。做法是先用 $(\mathbf{M},\mathbf{P},\mathbf{A},\mathbf{F})$ 四模块协议给 harness 定一个固定类型签名，把开放式代码生成压成受约束的结构化合成，再用 13 个统一重实现的 scaffold 当 seed bank，三阶段训一个 Qwen3.6-27B 的 harness 生成器（SFT+DPO 学定制、teacher-forced 学两轮内修复、Evo-GDPO 学超越 archive frontier）。九个 benchmark 上换掉默认 scaffold，18 个 backbone–benchmark 配对全部提升（GLM-5.2 均分 74.1→81.8，DSV4-Flash 66.7→75.5）；固定 backbone 的受控对比里 token 和成本 6/6 全场最低（相对最便宜的固定 harness 平均降 36.0%），但性能只有 4/6 居首。
- **锐评**: 形式化是真贡献，实证纪律是真塌方。先说好的：给 harness 一个类型签名并让 13 个已有 scaffold 落在同一 kernel 上，是这个文献族第一次有了可比坐标系；Evo-GDPO 用 $\mathbb{I}[r_i\ge b_r]$ 门控效率通道、堵住"生成一个什么都不干的廉价 harness"这条退化路径，是多目标 agentic RL 该有的默认值；DSV4-Flash 在 xBench-DS 上 527K→212K token、\$0.075→\$0.039、分数还从 78.0 涨到 82.0，这一格干净得可以直接引。然后说硬伤，而且都压在 headline 上。**第一，效率结论的口径是空的**：Evidence Ledger 全文检索确认，Table 3 和 §5.3/§5.4 从未说明报告的 token 与 \$ 是否包含 JIT-Agent-27B 自己那次生成 pass——static 模式还要并行生成 $N$ 份、外加最多两轮修复。也就是说 36.0% 这个数到底是"系统总成本"还是"executor 单侧"，论文没交代，不能当系统级降本读。讽刺的是 Stage-III 训练期作者明确把 repair 的 latency/cost 计进效率，评测期反而闭嘴了。**第二，reliability 这条被写进"harness intelligence"定义的性质，一个数字都没有**：协议合法率、生成失败率、修复成功率——Ledger 确认全文皆无。而 Stage II 的全部存在理由就是"生成会失败、失败能在两轮内修好"，$K^\star\le2$ 这个截断到底够不够、部署时多大比例任务要走修复循环，读者一概不知道。**第三，标题里的范式主张没有实验**：Appendix A 自陈 AOT-vs-JIT "is structural rather than a ranking of empirical performance"，Harness-R1/AHE/AutoHarness 一个都没在同 benchmark 同 backbone 上跑过；Table 3 的对照全是 Claude Code / Codex / OpenCode 这类人工生产 runtime，证的是"生成的 harness 打得过手写 runtime"，不是"JIT 打得过 AOT"。附带一提，摘要那句"first model purpose-built for just-in-time harness generation"和 Table 4 那张四项能力全勾的分类表，Ledger 只核实了"论文确实这么写"，分类判定本身没有被独立验证——自己划的赛道自己第一，别当结论看。**第四，零 ablation**：三阶段以 bundle 形式打包报告，24/24 击败 ReAct 里有多少只是 Stage I 的 teacher 蒸馏、Evo-GDPO 的三通道解耦相对普通 GRPO 是否必要，全是黑箱；teacher 连名字都没给，若是前沿闭源模型，"训出一个 27B 生成器"这个叙事得改写成"蒸馏出一个 harness 写手"。**第五，Table 2 的对照口径明显弱于 Figure 4**：从没说明 GPT-5.6、Gemini 3.5 Flash 这些 vanilla 行跑在什么 scaffold 下，而 BC+ 78.0 vs 76.9、Odyssey 78.7 vs 78.0、Shop 83.9 vs 83.7 这种量级的领先，一个 scaffold 差异就能吞掉；全文无 seed、无方差、无置信区间，Figure 4 用的还是 50–100 题子集，Table 2 题量干脆没报。最后一个值得追的裂缝：[[2609-HarnessDev]] 测出 harness 自演化增益基本落在 ±4.75 噪声带内、用可见反馈选版本的同向率只有 53.1%（接近抛硬币），而本文 Appendix B.1 的 streaming 演化正向结论压根没做噪声带估计——两篇必有一篇的噪声口径是错的。
- **Rating**: `3` 🔥 ，值得精读的是那份类型签名协议和 Evo-GDPO 的效率门控配方，不是它的排行榜——把 harness 变成可训练输出空间这件事可能是 foundation 级的，但它自己给出的证据撑不起标题里的范式宣言。

### BDH-CQ
- **Title**: BDH-CQ: In-Context Learning with Recurrent Latent Reasoning
- **Institutes**: Pathway, Bielik AI, New York University
- **Source**: [link](https://arxiv.org/abs/2608.09888)  🔥 HF Trending ⬆️ 772   **📒 论文笔记**: [[2608-BDHCQ]]
- **核心**: 把 in-context learning 和 latent reasoning 压进同一套前向计算——demonstration 顺序写进 recurrent state `S_t`，query 在 latent workspace 里迭代 `H_{r+1}=F_θ(H_r,S_K)`，不 decode 中间 token，也不像 HRM/TRM 那样在评测任务的 demonstration 上跑一轮反传。150M 模型在 public ARC-AGI-1 上 pass@2 118/400（29.5%），论文按 0.85 H200 GPU-秒 × 自设 3 美元/H200-小时折算出 0.00070 美元/task，据此宣称打破 cost–accuracy Pareto frontier。但真正值钱的是模型冻结之后才生成的 controlled ladder：dense color binding 96/96 全对，conditional rule selection 却掉 43.3 点（100.0% → 56.7%，Fisher p=9e-9），demonstration 未覆盖的参数值 0/120，color swap ∘ relocation 0/72，160 个 ConceptARC 任务里 52 个"部分对但规则没跨 test input 一致应用"。结论很干脆：latent workspace 学到的是 demonstration 条件下的 operator binding，不是可组合的规则归纳。
- **锐评**: 一篇好实验被一个烂 headline 拖累的典型。先说硬伤——**成本这条主线基本站不住**。(1) 内部账目自相矛盾：§5 的 headline 是 0.00070 美元/task，§6.6 描述同一次 standard 运行（同样是 118/400）时写的是 0.00265246 美元/task，差 3.8x，全文没有一个字对账（Ledger C12）；effort 叙事也是两套互不衔接的档位命名（LOW/MEDIUM/HIGH vs MIN/STANDARD），Table 5 的 "Cost reduction" 连基准和单位都没定义（C15）。(2) 跨系统比较根本不可比：自家分子是 measured GPU-seconds 乘一个自己挑的电价，对手分子是 leaderboard 上"可能是硬件估算也可能是含利润的 API 报价"——论文自己在 Figure 2 caption 里写明了这点，然后照样把 Pareto SOTA 写进 Abstract、§1、§5、§9、§10 五个地方。(3) 那个 57x 的对照系统 GPT 5.6 Luna (Low) 得分 34.2%，**比 BDH-CQ 高 4.7 点**，而且论文同段就承认 7 月 30 日降价后只剩 11x。用一个精度更高的系统当"我便宜 57 倍"的锚点，这不是 Pareto，这是选点。
  更要命的是可检验性归零：所谓 "independent black-box audit" 的执行者是本文署名作者（Bielik AI + NYU 两位，C6）；维度、更新规则、实现细节、训练配方全部 proprietary，开源的只有一个 MIT 的 ARC 任务生成器，没有权重也没有模型代码（C7）。一篇核心主张是"我在成本轴上是 SOTA"的论文，外界既复现不了这个数，也审计不了这个折算。ConceptARC 同时躺在训练混合和评测集里（C5），§6.5 的 opaque-identifier 复现只排除了 request 侧的 identifier 泄漏，论文自己承认"不能排除训练或 checkpoint 选择带来的暴露"——那 59.38% 就只能读作训练分布内的能力画像，不能当泛化证据。
  **两处需要点名的证据缺口**：§9.2 那句 "Early experiments confirm Transformer-like scaling laws apply during pretraining at scales from 1B to 600B parameters"（C11），Evidence Ledger 的核查结论是全文**没有任何数据、表格、图或引用**支撑它，同段还顺手断言架构"particularly easy to train at 1T scale"——用 150M 的实测撑正文、用零证据的 600B 撑展望，这是把新闻稿塞进 arXiv，读者不该把它当作 BDH 架构可 scale 的依据。另一处是 §1 的 "no parameters are updated at inference time / 评测任务的 identifier 与 demonstration pair 不参与训练"（C14），这是全文对 HRM/TRM 那条 transductive 路线的整个对比赖以成立的前提，但它是**裸声明，没有任何实验或审计证实**——在权重不公开的前提下，这条也无从外部验证。同理 §A.2 的 mechanic 难度表（68.6% → 2.9%）也别当真：论文自己披露手写 gravity 任务 80–100%、生成版 2.9%，公开集与生成集 mechanic 排名相关只有 ρ=0.300（C13），这张表刻画的是它自己的生成器，不是操作本身的难度。
  值得夸的部分同样具体：controlled ladder 的设计比 99% 刷榜论文有信息量——冻结模型后才生成任务、每次只动一个复杂度维度、**换 context 而保持 test pair 逐字节相同**，靠这一招把"外推失败"和"执行失败"分开：depth-5 nesting 给个匹配深度的 demonstration 就从 19/24 回到 24/24（纯外推问题，输出维度 36/36 全对、cell 精度 >99.9%），length-8 ordering 给了支持也只从 0/24 到 13/24（还压着执行瓶颈，3/24 连输出维度都不对）。dense binding 96/96 全对配上 conditional selection −43.3 点、参数外推 0/120、复合 0/72，四条证据锁死同一个结论：记住一个规则容易，选规则、参数化规则、复合规则是三堵墙。另外论文诚实地指出 color swap 单独就只有 26/72 且几乎全来自固定色布局，所以 0/72 不能单独归因于 composition——这种自我拆台在当下很稀缺。最后一个结构性遗憾：`S_t`/`H_r` 的二分是全文的 system-level 卖点，却没有一个实验直接检验它（比如冻 `S_K` 改迭代步数、或跨任务迁移 `S_K`），目前只是设计意图不是被验证的机制。
- **Rating**: `2` 👀 ，ladder 那套干预式评测方法值得原样搬到 GUI/agent 轨迹上（"按屏幕状态在两条已演示规则间选择"和 conditional rule selection 是同构问题），但 headline 的 cost SOTA 建在不可比口径与不可复现的闭源系统上，且离团队主线方向较远，读方法论、忽略结论。

### VoiceMem
- **Title**: VoiceMem: Streaming Dual-Brain Memory for Real-Time Interaction
- **Institutes**: Nanyang Technological University, National University of Singapore, Tsinghua University, The Chinese University of Hong Kong, Open Interaction Lab
- **Source**: [link](https://arxiv.org/abs/2608.26005)  🔥 HF Trending ⬆️ 177   **📒 论文笔记**: [[2608-VoiceMem]]
- **核心**: 在 Mem0 之上加两层上层索引——"左脑"是 schema–entity 两级语义图，"右脑"是 persona/情感节点图（区分稳定人格与针对某 entity 的情境情感）；检索时先按 schema 把候选池路由收窄，后端只在收窄后的池子里做 top-K，目标是把注入预算从 top-100 压到 top-5 而不掉分，并把整条检索塞进 VAD 的 500 ms 静音窗（自报 134 ms / 430 memory tokens）。三个 information benchmark 均分 76.39，比自家后端 Mem0 的 52.27 高 24.12；同一索引层换到 LangMem / Zep 也分别涨 15.76 / 22.92。真正被单独隔离出来的机制主张是"小 K 时决定成败的是候选池语义密度而非 ranking 精巧度"——只关掉 schema routing，K=3 掉 4.53 分、K=5 就收敛到 0.05 分以内，作者自己也写明它"lowers the budget needed to reach the ceiling, not raises it"。
- **锐评**: 这篇最硬的证据不在 abstract 里，在 Table 4：VoiceMem 本质就是"Mem0 + 索引层"，bare 61.68 → 91.20 是存储介质固定下的层级消融，比任何跨系统横比都可信；三个后端齐涨 15.8–29.5 分说明收益不绑定某个 store，这条完全可以脱离语音场景搬到文本 agent memory。cluster emergence 的对照也做得规矩——random_split 被强制拆同样次数仍差 2.00 分，直接掐死了"拆本身有益"的平凡解释。可惜头条叙事几乎条条挂红牌。（1）abstract 的"top-5 打 Mem0 的 top-200，高近 30 分"是 **abstract-only**：正文压根没跑过 K=200，扫描区间只到 K=100，最接近的依据是"任何预算下 Mem0/Zep 都不过 63"——用一句上界陈述冒充一次对照实验。（2）baseline 在三张主表用的 K **全文未声明**（Ledger 判 unsupported），所以"同等预算对比"在记录上根本不可判定，整套 +24.12 悬在空中。（3）"三个 persona benchmark 全 SOTA"同样 **unsupported**：按能在 Table 1 精确复现三个 baseline 的同一口径重算，ES-MemEval 输给 Emotional RAG（73.30 vs 75.10，主要输在 conflict detection 69.10 vs 77.30），PersonaLens 输给 MemOS（82.10 vs 82.31），只有 pooled 均分成立——把聚合层级的胜利写成逐 benchmark 的胜利，而 +1.89 在 LLM-judge 上本就接近噪声，全文零 seed 方差零置信区间。（4）更难看的是 **contradicted** 那条：同一口径下 Table 1 的 VoiceMem LoCoMo 均值是 90.40，而 Fig. 5/6、Table 4/5 与结论一律用 91.20（微调行 91.25 也不等），论文从头到尾不说这几处用的是哪个应答模型——于是 Mem0 的 +29.52 里有 0.80 分是 Table 1 支撑不了的，"+8.1 vs EverMemOS"也存在拿微调应答模型对 GPT-4o-mini baseline 的嫌疑。最致命的是写侧成本 **完全缺席**：fact 抽取、schema 分配、emergence 的 LLM judge、persona consolidate 全是 LLM 驱动，论文一次调用、一个 token、一毫秒都没报，还在 §3.1 白纸黑字承诺"细节见附录"——附录里根本没这一节。异步不消灭成本，只是把账挪出关键路径；而"top-5 / 430 tokens"衡量的是**上下文预算**不是**检索代价**，Table 5 自己写着进入最终 ranking 的候选池 LoCoMo 平均 292 项。134 ms 也没有硬件、向量库、测量协议；实验里的 store 只有左脑 510 + 右脑 251 项，在几百条规模上论证"路由降本"约等于没论证——收益究竟来自去噪还是降本，没有 store 规模扫描就分不开。另有一个作者自己都没提的负结果：为 memory 蒸馏的 VoiceMem‡ 在 persona 上 74.16→76.56，却在 information 上 76.39→75.65、ChatMem-Bench 上 68.73→66.96，自家蒸馏模型在自家 benchmark 上打不过 GPT-4o-mini。至于 ChatMem-Bench，与训练集同出一条人工精修流水线、细节推迟到"后续技术报告"、三个声学子类结构性保证纯文本 baseline 必输（它们只拿到转写）——这能说明"存音频有用"，不能当作 memory 架构之间的公平对比。
- **Rating**: `2` 👀 ，一条可迁移的机制结论加一个真正受控的后端消融值得读，但 abstract 级 claim 里有 abstract-only / unsupported / contradicted 五处、写侧成本整块缺失，工程参考价值明显大于证据价值。

### WeMM-Embedding
- **Title**: WeMM-Embedding: WeChat Multi-Modal Embedding Technical Report
- **Institutes**: WeChat Vision, Tencent Inc.
- **Source**: [link](https://arxiv.org/abs/2608.24053)  🔥 HF Trending ⬆️ 70   **📒 论文笔记**: [[2608-WeMMEmbedding]]
- **核心**: 把 classification / QA / retrieval 全部改写成 (instruction, source, target, hard negatives, graded relevance) 的统一配对格式，在 Qwen3.5 backbone 后缀一个 `<embedding>` token 取 hidden state 做向量，靠 causal attention 可以在序列多处插 token 一次 forward 出多粒度表示（video-only 与 video+ASR）。训练分两段：Stage-1 用数亿配对跑 InfoNCE，加 task-consistent batching（每个 batch 只采一个数据集）与 duplicate-aware masking 压 false negative；Stage-2 在约 1/10 规模的 curated 数据上加 reranker 排序监督与 9B→4B/2B 蒸馏，9B 因为没有更大的 teacher 改用 model merging。结果是 MMEB-v2 overall 9B 80.6 / 4B 79.2 / 2B 77.9，MMEB-v3 的 190 任务上 9B 59.5 对最强 baseline Qwen3-VL-Embedding-8B 53.5，另称 14 次线上 A/B 全正。MRL 支持 64–2,048 维截断，2B 在 256 维保留 2,048 维 98.7% 的 image/video 性能。

### H3-World
- **Title**: H3-World: Turning Language Understanding into World Control
- **Institutes**: Tencent, National University of Singapore, The Hong Kong Polytechnic University
- **Source**: [link](https://arxiv.org/abs/2609.01560)  🔥 HF Trending ⬆️ 49   **📒 论文笔记**: [[2609-H3World]]
- **核心**: 不给 33B 的 MiniMax-H3 新建 action 通路，而是把 8 键 + 1 个 speed flag 的控制状态查表渲染成英文短句，每个 video latent 区间独占一条，再用 single-egress attention mask 把每条指令锁死在自己的时间窗里，只训 rank-32 LoRA、0.199% 参数、7,872 段 clip、10,000 步。全文唯一的定量手段是 Farneback 光流的累计水平分量：在"前 15 latent 左转、后 22 latent 右转"的切换 schedule 下，H3-World 给出 +52.7 / −106.0，冻结底座配单条全局 prompt 给出 0.0 / −17.3，接口齐全但 LoRA 置零则几乎不响应。最有信息量的是 constant-action 对照——冻结底座和 H3-World 打成 301.8 vs 300.5。作者没藏这个对自己不利的等号，这比论文里任何"我们更好"都值钱。
- **锐评**: 先说证据边界，因为它直接掏空了标题级 claim。第一，abstract 里的 "preserving strong generation quality" 在正文没有任何指标对应：Ledger 的 C7 明确核过全文零 FVD / PSNR / LPIPS / VBench、零 human eval、零表格，唯一定量工具就是那把光流尺子——所以"保住了生成质量"目前是一句没被测过的话，不能当事实转述。第二，被反复引用的 301.8 vs 300.5，数字 verbatim 无误，但 `directional separation` 这个量的定义、样本数、seed 全文都没有，Ledger 直接判定"不构成可复现的测量"；这个近乎打平的结论恰恰是全文最重要的科学发现，却建在一个未定义的指标上。第三，"语言接口优于 dedicated action module" 这条 C6 只有一张单条 held-out clip 的定性图撑着，additive-bias 和 FiLM 两个 baseline 都是作者自实现，训练步数、可训参数、算力预算一概不报，C12 又确认没有任何外部已发表的 action-conditioned world model（Matrix-Game、GameFactory、Genie，甚至提供数据的 ABot-World-0）在同数据上跑过——所以这条 claim 最多只能读作"在 8k 样本 + LoRA 预算下从头学 action embedding 打不过复用预训练文本通路"，而低预算下从头学的模块表现差本来就是预期内的。硬伤还有两处：temporal attention routing 被列为独立贡献并宣称 "reduces control leakage"，但从没做过"训好的 LoRA + latent-aligned prompt，去掉 mask"这一组——Sec 4.2 的 zero-LoRA 组是带 routing 的，只证明了 LoRA 必要，routing 一次都没被单独 ablate，而这个实验只是改一个 mask，代码还开源了，没做很难解释；时间 grounding 的有效样本量近乎 N=1，一条手工 schedule 加它的反转，切换点还刻意对齐 latent block 边界，而边界内切换——真实交互里最常见的情况——完全没测，128 条 held-out clip 摆在那儿只用了 5 条出图。再说标题：接口本质是 135 路离散动作空间 + 全数据集同构的模板句，所谓 compositional generalization 是 9×16 笛卡尔积上的外推，没有同义改写、否定、程度副词、未见动词任何一项测试，"Turning Language Understanding into World Control" 严重过度。笔记里提的那个反证实验很干净：把模板换成随机但一致的无意义 token 串，若性能不降，方法就退化成"给离散动作找了组恰好落在文本 embedding 空间里的编码"。真正的贡献不在方法而在它抬对了 baseline——frozen backbone + 朴素 prompt 这条几乎零成本的对照，应该成为所有声称自己 action interface 有效的 world model 工作的强制项。
- **Rating**: `2` 👀 ，问题重述干净、frozen-baseline 对照是可继承的方法学纪律，但零质量指标、核心贡献未 ablate、N≈1 的时间评测让它离标题 claim 差得很远。

### ZonUI-3B
- **Title**: ZonUI-3B: Competitive GUI Grounding with a 3B VLM Trained on a Single Consumer GPU
- **Institutes**: DeepCAT Lab, National Yang Ming Chiao Tung University
- **Source**: [link](https://openaccess.thecvf.com/content/WACV2026/html/Hsieh_ZonUI-3B_Competitive_GUI_Grounding_with_a_3B_VLM_Trained_on_WACV_2026_paper.html)  🎓 WACV2026   **📒 论文笔记**: [[2601-ZonUI3B]]
- **核心**: 把 GUI grounding 的改进变量从模型规模挪到数据构成：Qwen2.5-VL-3B 冻结、只训 LoRA（rank 8、α=16），用 ShowUI / UGround-WebHybrid / AMEX 四源合并抽稀出的 24.1K 跨平台多分辨率样本做两阶段微调（Stage 1 跨平台 1:1:1 balanced，Stage 2 高分辨率专门化），单张 RTX 4090 上 48 小时训完。结果是 ScreenSpot 84.9、ScreenSpot-v2 86.4、GroundUI-1K 82.4、ScreenSpot-Pro 28.7。全程零架构改动，不用 HTML / accessibility tree / OCR。最有信息量的其实是数据消融：ShowUI-Web 的 16.1K 子集与 119.4K 全集在 ScreenSpot 上只差 0.1 个点（82.8 vs 82.9），而换个数据源后 24.1K 就到 83.5。

- **Rating**: `2` 👀 ，数据冗余消融是个可复用的真发现，但两阶段增益的对照锚点被证伪、"rivals 7B" 建在残缺的 baseline 行上、SS-Pro 领先只靠两个类别，够格当 recipe-only 的轻量 SFT 基线，够不上前沿。

- **Source**: [link](https://openaccess.thecvf.com/content/CVPR2026/html/Xia_Cloning_Deterministic_Worlds_The_Critical_Role_of_Latent_Geometry_in_CVPR_2026_paper.html)  🎓 CVPR2026   **📒 论文笔记**: [[2606-GRWM]]
- **核心**: 论文只问一个问题：deterministic 环境里 long-horizon rollout 崩坏，锅在 dynamics model 还是在 representation？作者先做诊断——同架构下把 latent 换成 ground-truth agent pose (x, y, θ) 的 oracle 长程近零误差，VAE-WM 误差迅速累积——据此把矛头指向 autoencoder，然后在带 causal Transformer 时序聚合的 VAE 上加两项正则：轨迹内全帧对拉近的 `L_slow` 和跨轨迹超球面均匀的 `L_uniform`。dynamics 侧完全不动，直接插进 SD (DIAMOND) / VD / DF 三个 backbone。结果是 M3x3-DET / M9x9-DET / MC-DET 三数据集 × 三 backbone 共 9 组，63 步 frame-wise pixel MSE 全胜；latent probing 回归 MSE 从 0.082/0.106/0.137 降到 0.031/0.058/0.081。
- **锐评**: 先说值得偷的：dynamics 三个 backbone 保持不变、只换表示模块，这是真 intervention 而不是事后相关性；latent dim 16/32/64/128 每档 GRWM 都赢，干净地杀死了"无非是 latent 容量更大"这个平凡解释，而顺带那个负面发现——vanilla VAE 维度越大长程误差反而累积越快——比正面结果更有信息量。现在说硬伤。**第一，标题里那个 "Critical Role of Latent Geometry" 的因果归属没有完成识别。** 撑起它的 Sec. 4 诊断实验换掉的是**信息含量**而不是几何：oracle 吃的是全局坐标，图像只有局部观测，论文自己在 5.1 节承认这一点。一个信息严格更多、天生消歧的 oracle 赢了，跟它 latent 长什么形状无关；这个实验最多支持"瓶颈在 dynamics 上游"。**第二，GRWM 相对 baseline 同时改了 encoder 架构（causal Transformer 聚合滑窗历史）和两项 loss，而消融只做了"去掉其中一项 loss"（两个变体直接发散成 NaN），从未跑"保留时序架构、正则全去掉"这一格。**于是"时序上下文解决 perceptual aliasing"和"contrastive 修正流形几何"这两个解释无法分离——偏偏 5.1 节的 aliasing 论证本身是个信息论证。**第三，"long-horizon" 的量化上限是 63 步。**旗舰的 10,000 帧结果只有可视化，用的是随机采样动作序列，且没有 ground-truth 对照行，判据实际上退化成"GRWM 的画面更多样、更连贯"——在一篇以"plausible 不等于 faithful"立论的论文里用视觉观感评判长程保真，这是它自己要批的那种推理。**第四，全文与附录零 downstream control / planning / task-success 评测**，指标只有 MSE / SSIM / rFID / PSNR 和对 (x, y, θ) 的回归探针，而引言是拿"给 RL agent 当 simulator"和"机器人任务规划"立的动机；对照 [[2506-VJEPA2]] 一路做到 zero-shot robot planning，这里的实用性主张纯属未检验。**最后一条最需要标出来：训练预算是否对齐，无法核实。**正文与附录 A 把超参、轮数、数据预算整体推给代码库，Evidence Ledger 对"GRWM 与 baseline 是否在对齐 compute/data 预算下训练"这条给的状态是 **not-checkable**——从一手来源查不出来。而这不是无关细节：论文自陈 GRWM 因时序聚合与几何正则带来额外计算开销（C7，已核实），那么"9 组全胜"这个头条结论，究竟有多少来自几何正则、多少来自更大的表示侧预算，读者没有依据判断，笔记也没有把它当成已知事实来写——引用时不能默认这是等预算比较。另加两笔：表示侧的对照只有 vanilla VAE，Related Work 里引的 DINO-WM、denoised MDP、CLTT 一个都没进实验，所以结论是"强于不加正则"而非"强于别的表示学习目标"；全文无 seed 与方差报告，附录 Table 4 的 VAE-WM probing MSE 记为 0.136 且未注明数据集，与正文三个值都不精确吻合。附录那两个 Atari 数字（Asterix PSNR 28.57→29.04、Breakout 34.23→37.76）作者自己标了"非完整 benchmark"，撑不起引言那句无限定的 plug-and-play 推广。
- **Rating**: `2` 👀 ，实验设计的姿势（oracle 诊断台 + dynamics 冻结的单变量替换）值得偷，但标题的因果措辞跑在证据前面、缺关键消融、无 downstream 评测、预算对齐不可核实——方法论可借鉴，结论不宜直接引用。

### PanoEnv
- **Title**: PanoEnv: Exploring 3D Spatial Intelligence in Panoramic Environments with Reinforcement Learning
- **Institutes**: University of Glasgow, HKUST(GZ)
- **Source**: [link](https://openaccess.thecvf.com/content/CVPR2026/html/Lin_PanoEnv_Exploring_3D_Spatial_Intelligence_in_Panoramic_Environments_with_Reinforcement_CVPR_2026_paper.html)  🎓 CVPR2026   **📒 论文笔记**: [[2606-PanoEnv]]
- **核心**: 从 TartanAir 的 depth / semantic segmentation / 3D bounding box 出发，把 360° ERP panorama 的空间推理程序化展开成五类共 14,827 条 QA（595 张 ERP 图、60 个虚拟环境），同一套几何 ground truth 既当答案也当 GRPO 的 rule-based reward，绕开 LLM judge 和人工 CoT。Reward 按题型路由到五个 parser：distance 用相对误差容忍带（≤10% 给 1.0、≤20% 给 0.5），spatial 按三条轴的正确占比给部分分。在 Qwen2.5-VL-7B 上只对 language decoder 加 LoRA 跑 GRPO，配 structured→mixed 两阶段 curriculum，total accuracy 49.34%→52.93%，open-ended 6.39%→14.83%。Benchmark 侧 14 个 SOTA VLM 零样本平均 total 只有 36.72%、OE 4.26%。
- **锐评**: 先说清楚证据边界：这篇笔记的 Evidence Ledger 15 条高风险 claim 逐条比对 CVF 正文与 supplementary，**全部 source-verified**，没有 unsupported / contradicted / abstract-only。也就是说这篇的问题不是数字造假，而是**核对无误的数字撑不起它想讲的故事**。三处 Ledger 亲手挖出来的硬伤：（1）C11 是条否定性事实——Table 2/3/4 里所有非 GRPO 模型全是零样本，正文与 supplementary 都没有在 PanoEnv-QA 上做 SFT 的对照。于是 49.34→52.93 这 3.59 个百分点（论文写成 "+3.59%"，实为百分点差，相对增幅 7.3%）根本拆不开"GRPO 的功劳"和"在同分布数据上训过"的功劳，而全篇的核心主张恰恰是前者；顺带那句"7B 超过 32B"，比的是 in-domain 训过的 7B 和零样本的 32B，不成立。（2）C14：abstract 里 "49.34% overall and 8.36% open-ended" 是两个不同模型的分列最优（前者 Qwen2.5-VL-7B，后者 DeepSeek-VL2-Base / Qwen2.5-VL-32B），正文 §1 用 "best…best" 说清了，abstract 没有——这种含糊只有一个方向的收益。（3）C12：supp Table 2 把 60 记为 Scenes、595 记为 Images，与正文 §4.1 的命名完全相反，自己的数据卡都没对齐。更要命的是训练 reward 与评测 accuracy 共用同一套 routed parser，OE 翻倍这件事里有多少是"更会 3D 推理"、多少是"更会写 parser 认的措辞"，表格区分不了；旁证很硬：独立 judge 的 Q-Score 只从 5.60 爬到 6.24、P-Score 5.48→5.95，约 +0.6/+0.5 分，和"OE +132% relative"完全不成比例。Ablation 是全文最诚实也最有信息量的部分——Structured-only 的 T/F 69.5、MCQ 60.9 是全表最高，都压过 Balanced 的 68.8/58.9，Stage 2 实质是拿 −0.7 T/F 和 −2.0 MCQ 换 +9.1 OE；abstract 那句 "maintaining structured-task performance" 只相对 base 成立，相对自己的变体不成立。跨域证据只有 supplementary 里三行数：OSR-Bench 上 Object Counting / Relative Distance 领先 72B 的幅度是 0.030 和 0.046（近似噪声量级），而 Relative Direction 0.105 vs 0.181 被 72B 按在地上，作者归因于"OSR-Bench 缺垂直维度"纯属事后叙事，没有配套 ablation。最后是题目本身的通胀：物体的 2D bounding box 是以文本写进 prompt 的（"focus on the specific objects mentioned in bounding boxes"），模型不检测、不定位，只做几何反演——这叫 "3D spatial intelligence" 属实撑得太满。真正可复用的是那条 insight：环境状态可程序化验证时，几何 reward 比 LLM judge 更可控、也不会把 judge 的偏差回灌进策略；但 595 张图、5 个固定模板，模板过拟合排除不了，且全篇没有任何 navigation / manipulation 闭环实验，别拿它去声称能提 agent 成功率。
- **Rating**: `2` 👀 ，reward 可程序化验证的思路值得抄，但缺 SFT 对照 + 训练/评测共用 parser 让核心增益无法归因，跨域证据只有 supplementary 里三个数字。

### VisualProjectionSpace
- **Title**: Understanding the Visual Projection Space of Multimodal LLMs
- **Institutes**: UC Irvine, Soonchunhyang University, Changwon National University
- **Source**: [link](https://openaccess.thecvf.com/content/WACV2026/html/Jeong_Understanding_the_Visual_Projection_Space_of_Multimodal_LLMs_WACV_2026_paper.html)  🎓 WACV2026   **📒 论文笔记**: [[2601-VisualProjectionSpace]]
- **核心**: 把 MLLM 的 projection 输出 `z` 当几何对象来探针：SVD 测 effective dimensionality、`cos(z, top-k token embedding 质心)` 测 latent–token alignment、正交扰动后 output token subspace 的 Grassmann 距离斜率 `κ_t` 测 perturbation sensitivity。在 frozen 的 BLIP-2 / LLaVA / Kosmos-2 上宣称存在三种 operating regime（BLIP-2 刚性低秩、LLaVA 高维高响应、Kosmos-2 居中），并把这些几何量与 SQA correctness、VQAv2 hallucination 等级做分组 t 检验，得出"欠敏感 → grounding 弱、过敏感 → 放大幻觉"的双向解释。全文纯诊断，不提任何 projector 改动、训练目标或修复，也没有一个 benchmark 增益实验。选题方向对——projector 确实是 MLLM 里最少被当研究对象的组件——但交付的是一堆读数，不是一个可用的诊断工具。
- **锐评**: 硬伤在证据链本身，而且伤在最要命的位置。**头条 regime 划分的 vision-latent 那一侧是空的**：正文写 BLIP-2 首个主成分在 COCO 解释 67.9%、Flickr 68.8%，Evidence Ledger 把这条标为 **contradicted**——它引用的 Figure 2 上对应值约为 0.24 / 0.445，而 67.9% / 68.8% 全文再无第二处出处；紧接着同一段落把 Table 1 的 output-subspace 数字（19.1 / 26.6 / 6.6 / 16.8 / 19.7）当成 Figure 2 的 vision-latent 数字来叙述，实为串表。也就是说 abstract 里 "BLIP-2 rigid low-rank vs LLaVA flexible high-dimensional" 这个对比，在 vision latent 一侧不存在可引用的数值支撑，"LLaVA 高维"实际建立在另一个量上。三条 regime 轴的第二条同样悬空：latent–token alignment 的 BLIP-2 众数 0.68、LLaVA/Kosmos-2 中心 0.15–0.20 在 Ledger 里是 **not-checkable**（直方图读数，论文未给表格值，本轮未独立复核），不能当事实用。第三条轴自己打自己：Table 2 说 LLaVA 在 COCO 上 `κ_t` = 1.1895，4.5.2 节换一档 `ε` 重做同一实验说所有模型 `κ_t` 都 "centered around zero"（LLaVA COCO −0.0183 ± 0.3290）——差 65 倍且符号相反，斜率本该对扰动尺度近似不变，论文既未察觉也未调和；顺带 `ε` 取值在全文三处互不相同（`{0.01,0.05,0.10}·‖z‖` / `{0.1,0.2,0.3}` / `{0.01,0.03,0.05}`）。统计层面同样经不起看：Table 3 里 BLIP-2 VQAv2 的 Hallu0（1.9608 ± 0.1579）与 Hallu2（1.9532 ± 0.1554）相差 0.0076、不到组内 std 的 5%，却报 t = 10.213、p = 0.0000，全表无 effect size、无样本量、无多重比较校正、无多 seed；Table 2 的 Kosmos-2 (VQAv2) 一行用它自己的三个 `Δ_t` 最小二乘拟合出 3.506，表里印的却是 0.9324（其余十一行误差都在 ±0.0003 内）。因果层级也被抬高了一档：扰动实验只证明"改 `z` 会改 output subspace 几何"——对一个把 `z` 前置进序列的模型这近乎恒真；撑起 abstract 的"敏感度预测 unreliable grounding"那一步全是既有标签的分组比较，且 SQA 上 BLIP-2 p = 0.983、Kosmos-2 p = 0.9801，三分之二的模型上关联根本不存在，"过敏感 → 幻觉"更是只有 LLaVA 一个点。最后是实验身份不清：无 checkpoint、无 LLM backbone、无 vision encoder、无代码；数据集 "SQA" 引用的文献实为 RecipeQA，缩写全文未展开，4.2 节称其 "constrained answer spaces"、4.5.2 节称其 "open-ended questions"；而 4.2 节说所有实验都用固定 prompt "Describe this image."，那 exact-match correctness 到底怎么产生的全文没交代——这一句就能让 4.4 节整节的解读失效。probe 的 k = 10 / top-k = 100 / rank-r = 10 / 128-D PCA / 用 static embedding 而非 contextual hidden state，每一个都会实质改变 anisotropy 与子空间距离的读数，零 ablation 零理由。参考文献 [33] 是未填的 BibTeX 占位符且被正文引用，Kosmos-2 与 LLaVA 各重复列两次且作者列表不实。跟已有工作的本质区别本可以是"从 attention map 换到 embedding 几何"，但论文没引 Verma et al. (ACL 2024)、Yu & Ananiadou、Venhoff et al. 这批最贴近的先行工作，连自己站在哪都没说清。唯一值得捞的残留观察是笔记的推测：BLIP-2 的 `Δ_t` 绝对值（约 1.8–2.4）远大于 LLaVA（约 0.24）却斜率近零，这更像 output subspace 已进入饱和区，而非论文说的 "locked"——饱和与不敏感是两回事，甚至可能意味着 BLIP-2 的 `z` 影响更大。要立住这篇，最小补实验很清楚：沿几何量方向直接干预 `z`（强抬/压 `α_t`，或人为压缩 effective rank）看幻觉率是否随动，把观察变成干预。在那之前，"geometry as a diagnostic lens" 只是一个提法。
- **Rating**: `1` 💤 ，视角选得对但证据自相矛盾——regime 划分的核心数字被自家 Figure 2 推翻、主结论在两档 `ε` 间符号翻转、下游关联全是无干预的 t 检验，只适合当"观察冒充干预"的反面教材归档。
