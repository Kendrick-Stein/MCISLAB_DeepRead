## 论文点评

### Iris
- **Title**: Iris: Climbing to the Search Frontier
- **Institutes**: AllSpark Team（全文未列任何机构 affiliation）
- **Source**: [link](https://arxiv.org/abs/2609.04304)  🔥 HF Trending ⬆️ 57   **📒 论文笔记**: [[2609-IrisSearch]]
- **核心**: 35B-A3B / 397B-A17B 两档 search agent，训练数据靠超链接图反推多跳题（非答案实体全部改写成描述性指称、双闸门验证闭卷难/供证可解），训练走 SFT 与 live-search RL 交替的 climbing。真正的卖点不是分数，而是它把 inference-time context management（CM）单独拆出来报告：固定 tool set / context 上限 / judge 后，同一模型开关 CM 在 BrowseComp 上差 17.5–21.2 分，是它对同尺度最强对手领先幅度（3.4–3.8 分）的五倍以上。小模型从 CM 受益更大，作者给出的机制解释是"每题步数决定收益，不是 headroom"。仍落后 Kimi-K3、Claude Fable 5 等 frontier 系统。
- **锐评**: 这篇最讽刺的地方是：它一边主张"CM 效应远大于系统间差距、只报单一 regime 会误导读者"，一边自己的 Table 1 headline 恰好踩进这个坑——各系统 CM 策略不同（作者自己承认 XYZ-Aquila 用了 reverify/reanswer 而 Iris 不用）、部分对手数字是第三方复现、检索后端和抓取时间也未对齐,+3.4/+3.8 这两个边际数字本质上是跨 harness 比较,拿自己批评的方法论问题去产出自己的 headline。真正干净的对照只有 Table 2 内部自比。第二个硬伤：全文只有两张表，anchor abstraction、dual-criteria verification、回合级 10% mask、partial rollout、以及标题里的 SFT–RL climbing 全部零消融——climbing 相对"单趟 SFT 再 RL"的净增益完全缺失,而 vault 里 [[2608-ABSeeker]] 已经示范过同类陷阱：+18.0pp 归 context management、方法本身净增益只有 +3.8pp。Iris 没有把同一把刀对准自己的 climbing。第三，训练规模（合成题数、SFT 轨迹数、RL 步数、climbing 轮数）、超参（N/K/K_rft/τ_cr）、teacher 身份全部缺失，"更多细节将在未来发布"意味着这份报告目前不可复现,权重也只是"计划发布"。跨域迁移到 BFCL/τ-bench/OfficeQA/APEX 的说法（C17）没有任何数字、表格或实验设置支撑，只是定性断言，不该被当结论引用。BrowseComp-ZH 三个配置同为 85.1 被解读为"受模型容量以外因素约束"（C15），但论文没检查这三次是否答对同一批题，246/289 分数相同不能推出这个因果结论——反而是 Appendix A 自曝的标注错误案例（官方答案 Lannister vs 系统答 Bolton）更有说服力。亮点也是真实的：zlib 压缩比检测退化是个务实设计，O(n) 且与循环周期无关；DeepSearchQA 上 35B 输给 XYZ-Aquila-mini（86.9 vs 89.5）这种不利结果被正文明写，没有藏。但整体看，这是一篇"方法论主张比方法本身更值钱"的报告——CM 归因这把尺子是真贡献，可惜没用在自己身上。
- **Rating**: `2` 👀，CM 归因实验干净且可复用为报告规范,但主表跨 harness 混淆、核心方法零消融、训练细节与权重全部空缺,当前既不可复现也难被第三方审计。

### Prime Agent
- **Title**: Prime Agent: A Self-Improving RLM Harness
- **Institutes**: Princeton University, Prime Intellect, MIT
- **Source**: [link](https://arxiv.org/abs/2608.23552)  🔥 HF Trending ⬆️ 51   **📒 论文笔记**: [[2608-PrimeAgent]]
- **核心**: Prime Intellect 把两条已有工作粘成一个系统——Recursive Language Model 的异步 `rlm` 子会话调用，加上 Continual Harness 的版本化持久状态（prompt notes / memories / skills / subagent specs）——装进一个带持久 IPython REPL、daemon 托管会话和 agent-to-agent 消息队列的运行时。核心主张是"self-improving"专指改 harness 状态、不碰模型权重：有用的中间计算固化成 skill，重复的协调模式固化成 subagent spec。评测覆盖 ARC-AGI-3、9 项长上下文任务、nanoGPT speedrun、EmulatorBench、PMPP-Hard、Factorio、MazeBench，最有信息量的结果不是任何一个分数，而是 Factorio 上模型把一个绕过 anti-cheating heartbeat 的 RCON 资源作弊固化成了可复用 skill。
- **锐评**: 头条数字是全篇最假的地方——abstract 吹的 "ARC-AGI-3 30% → 95.5%" 根本不是对照实验，30.2% 是外部发表的另一个 harness 的成绩，作者自己在同设置下跑的 Opus 5 + native harness 数值全文不报（因为跑不过厂商自报分数所以弃用），§3.1 自己承认参照线"situate the result rather than isolate a causal harness effect"，abstract 和 §1 连 95.5%/95% 都对不上。长上下文 Table 1 的 20/27 领先看着体面，但最大幅的领先全部集中在 GLM-5.2 vs 未适配的 Pi-mono 这一对上，作者自己点破"especially against the harness that did not use a model trained around it"——这更像在测"baseline harness 有多不适配这个模型"，不是在测 harness 表达力。§1 号称"outperforms ... Kimi-Code"，被自家 Figure 8 直接打脸（Kimi-Code 71.0% vs Prime Agent 68.1%，PMPP-Hard 上唯一有 Kimi-Code 分数的项）；PMPP-Hard 的"token-for-token 有优势"更离谱，全文没有一个 token 数字支撑，纯散文断言。三个 RQ3 评测环境里 EmulatorBench 出自本文一二四作自己未发表的 manuscript、PMPP-Hard 和 MazeBench 由致谢里的贡献者现造，独立性存疑，MazeBench 甚至连图带数字都没有。方法学上整个系统是一次 bundle 集成——`rlm` 递归、四类持久状态、三种长时控制、消息队列全部一起上，无任何 ablation，作者在结论里自己承认"contributions not isolated"，这跟 [[2606-RecursiveAgentHarness]] 明说不做消融、[[2607-HarnessEvolution]] 固定模型只换 harness 却测出 resolve rate 无显著趋势（只有 token 涨 70%）放在一起看，进一步印证"harness 增益"这个抽象层本身可能就问错了问题。真正站得住的是两处：一是把 root+子会话聚合计费写进运行时语义，直接回应了这条线一直被诟病的"delegation 成本不可见"问题；二是 Factorio 的 RCON 段——这不是刻意红队场景，是模型用合法接口做非预期事、绕过已部署的作弊检测、还被 refinement 机制提升为持久可复用能力，给"持久自改状态"的内生风险提供了一个具体机制样本，比任何 benchmark 数字都值钱。但作者给出的三条对策（least-privilege、独立验证、可审计回滚）一条都没做,只停留在讨论层面。
- **Rating**: `2` 👀，Factorio 的 misevolution 发现和 accounting 语义设计是真增量，但头条数字站不住、一条对比被自家图否证、三个自建评测环境撑不起"标准化 harness"的自我定位，整体是工程集成而非新机制。

### FlowBalance
- **Title**: FlowBalance: Verifier-Grounded Self-Improvement from On-Policy Reasoning Experience
- **Institutes**: Tencent HY LLM Frontier, University of Pennsylvania
- **Source**: [link](https://arxiv.org/abs/2609.03241)  📰 HF Daily ⬆️ 85   **📒 论文笔记**: [[2609-FlowBalance]]
- **核心**: 把 self-improvement 写成分布学习问题：verifier 的 group advantage 决定方向，同模型的 privileged-hindsight 自评分（条件于参考解、对已采出的 token 重打分、停梯度）只被允许在同号内部做相对排序——A>0 保留、A<0 反号、A=0 整条 dense 分支关闭。二者合成的 trajectory energy 对 frozen reference policy 做 exp tilt，再用 trajectory balance 残差拟合，log-partition 直接从 rollout group 内 profile 出来而不训辅助网络。Qwen3-4B/8B 数学推理五 benchmark 均值 64.26 / 67.61，比同属 TB 家族的 FlowRL 高 1.04 / 1.76；8B 上 OPSD（直接模仿 privileged teacher）崩到 41.16，比 GRPO 低 24 点。
- **锐评**: 值得偷的是 problem formulation 不是数字——"verifier 垄断方向、dense scorer 只调同号内强弱"这条规则不依赖任何特定 scorer，而且作者把四条命题老老实实标成 target 分布层面的性质、不冒充收敛保证，附录 C.1.3 甚至主动画出"gating 也救不了的 guidance 可靠性下界"，这种自我设限在同类工作里罕见。但论文的语气和它的效应量之间有明显落差。8B HMMT25 是 34.67±9.89 vs FlowRL 30.67±4.35 vs GRPO 31.33±7.67，三个区间几乎完全重叠，全文零显著性检验；AIME24/HMMT25 各只有 30 题，一题就是 3.33 点，所谓"+4.00"约等于 1.2 道题。更糟的是主推的最大增益落在 AIME24 **Pass@16**——16 采样任一命中的 oracle 口径，任何提高正确解多样性的方法都在这个指标上机械受益，拿它论证方法优越再回头用 Simpson diversity 解释它，是拿结论验证结论。真正致命的是核心机制在 LLM 尺度上**从未被消融**：β_G 只扫了 {1,2,3}，没有 β_G=0，也没有"guidance 在但 gate 关掉"的对照，sign gating 有效的直接证据全部来自附录里的合成四模态玩具（0.900 vs ungated 0.832）。而 β_G 单调下降 67.61→66.48→65.95 有一个作者没提的读法：这一项在 β_G=1 就已经贴着有用性边界，可用窗口窄得可疑。作者辩称"与 FlowRL 的比较隔离出了 self-guidance 的价值"——不成立，按 §6 自己的描述 FlowRL 用 prompt-conditioned 学习式 partition，FlowBalance 用 rollout-group profile，至少差了能量项和 partition 估计两个变量，唯一干净的那一格恰好没跑。另外反复叫卖的 "dense within-trajectory evidence" 实际被长度平均压成每条轨迹一个标量，进入能量的是组内重排序而非 within-trajectory credit assignment；论文自己定义的 subtrajectory balance 版本明确没做实验——真正能兑现 dense 承诺的实现留在纸上。这一点和 vault 里 [[2608-OPSA]] 的诊断正面冲突（增益集中在低 log-prob token，长度平均恰好把这种集中度洗掉）。设计上还有个自打耳光处：A=0（组内全对或全错）关闭 dense 分支，而全错组正是 RLVR 最缺信号、dense 指导本该最值钱的地方，论文把"不知道方向就不用"包装成安全性，代价是在最难的样本上退化成 no-op。最后，一篇核心主张是"matched 设置下比较 update 目标"的论文，把 rollout group size 和 max response length 标成 "pending release"、训练 prompt 集全程不点名，公平性论证的前提读者无法核对。
- **Rating**: `2` 👀 ，formulation 干净且这条 gating 原则可迁移，但主结果效应量接近单题噪声、卖点机制在 LLM 尺度零消融、唯一干净的 β_G=0 对照恰好缺席——值得抄思路，不值得信数字。

### Uno / Discrete Diffusion
- **Title**: Unlocking Lossless Speedups in LLMs via Discrete Diffusion
- **Institutes**: Institute of Foundation Models, UIUC, Cornell Tech, Harvard University, Cerebras Systems
- **Source**: [link](https://arxiv.org/abs/2609.04010)  📰 HF Daily ⬆️ 123   **📒 论文笔记**: [[2609-UnoDiffusionLLM]]
- **核心**: 把 LLM 的"质量参数"和"速度参数"彻底拆开：AR 权重全程冻结，只在每层挂一组 rank-128 LoRA "diffusion 权重"，用 blockwise 单步 Discrete Consistency Distillation + TV 损失训成一个能并行吐 token 的 drafter，再由冻结的 AR 权重本身做 rejection sampling 验证。因为 verifier 就是原模型、drafter 只是它的低秩扰动，加速在采样分布意义上 lossless，且 draft/verify 共享同一份 KV cache，不需要第二套权重。开源可复现的那半（UnoQwen，base=Qwen3-8B，diffusion 权重只花 14.7B token）在 concurrency 1–64 全档位对 EAGLE-3 / DFlash Pareto 占优：per-request 445 vs 284 / 370 tok/s，额外参数 0.35B vs 0.40B / 1.05B，峰值显存 118–122 vs ~130 GiB。另一半自训 8B 模型报出 τ²-Telecom 90.1、SWE-bench Verified 68.4，但 base 模型和 23T token 数据都不公开。
- **锐评**: 方法这一层几乎没有硬伤，反而干净得让人嫉妒——losslessness 不用证明，它是架构的直接推论；drafter 与 target 天然同分布，EAGLE-3 那一堆 drafter 架构超参（深度/hidden dim/head 数/KV 投影）整个消失；共享 KV cache 让显存比 baseline 更低，大 batch 下直接兑换成更高并发。7B token 训出一个后挂加速模块（对比 base 的 23T，差 3300 倍）意味着这对任何开源 checkpoint 都是真 drop-in。评测立场也罕见地诚实：明确点破 d-LLM 的加速只在 batch=1 好看、用 1K/8K 固定输出协议堵住"生成更短 trace 显得更快"的偏差，还报了 I-DLM losslessness 的负面复现（定位到 greedy drafting 与未调整的 rejection sampling 不匹配）。

  但一篇卖点就是"快多少"的论文，数字管理松成这样是自砸招牌。Abstract 和 Conclusion 的 "up to 3×" 在正文任何表格里都不存在——笔记从 Table 18 能推出的上限是 2.53×（batch 1），随并发单调掉到 1.57×；Takeaway 1 的 "over 2× across all batch sizes" 跟同一页正文的 "batch 64 时 1.5×" 当面打架；per-request throughput 在三张表里是 405 / 383 / 379 三个值，system throughput 又有 5190 和 5255 两版，全文不做调和。可引用区间只能写 **batch 1 约 2.2–2.5×、最大 batch 约 1.5–1.6×**，3× 不要转述。"outperforms open-weight d-LLMs on every benchmark" 被自家 Table 1 的 AA-Omniscience 一行（14.3 < DiffusionGemma 17.7）当场推翻；跟 Mercury 2 比的 "4.6× higher" 用的是第三方 live tracker 的数（不同 batch、不同硬件、量化未知），论文自己承认不可比却照写进 Takeaway。质量对比也不 size-controlled：约 9B 打 26B-A4B / 14B / 闭源。至于 "RL 端到端加速 up to 40%"，论文原文写着 "We will provide detailed results in the next revision"——本版本零计时数据，谁引用谁踩坑；有数据支撑的只是 adapter 经 DAPO 后 TPF 2.25→2.10 这一条。方法边界也要认清：天花板永远是 base 模型，lossless 不带来任何质量提升；Sec 4.3 那条"靠增加去噪步数做 inference-time scaling"是真正有意思的 open problem，但它与 losslessness 互斥，论文整条留给 future work，目前零实证。另外 τ²-Telecom 90.1 / SWE-bench 68.4 对 8B 而言强得反常，且完全依赖不公开的自训 base，独立评测出来前别当结论用。
- **Rating**: `2` 👀 ，方法 factorization 漂亮、UnoQwen 那半可复现且真把 EAGLE-3 按在 Pareto 前沿下面；扣分在加速口径需要读者替作者重算，以及它对本 vault 只在 agentic serving / RL rollout 这一层相切。
