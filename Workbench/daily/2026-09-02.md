### OPSA
- **Title**: Does On-Policy Distillation Really Distill? From Noisy Teacher to Self-Improvement
- **Institutes**: Purdue University
- **Source**: [link](https://arxiv.org/abs/2608.31046)  📰 HF Daily ⬆️100   **📒 论文笔记**: [[2608-OPSA]]
- **核心**: 系统解构 on-policy distillation 的增益来源：teacher 对 student 轨迹的 advantage 监督噪声率 30.6%-50.6% 且随 teacher 规模**增大**（235B 对 97.8% 的正确答案 token 给负 advantage），但 student 对噪声完全不敏感；进一步归因发现增益集中在低 log-prob token，且用一个固定 -0.5 的 advantage 就能复现 OPD 性能。据此提出零监督（无 teacher/reward/hint）的 OPSA：只对每条 rollout 中 logp 最低 20% 的 token 施加随熵增大的负 advantage。Qwen3-1.7B AIME24 Avg@32 从 13.44 升至 48.85，超 OPD 16.77 点，训练还比 OPD/GRPO 快。
- **锐评**: 今年少见的"分析产出方法"范本：噪声量化→噪声不敏感→token 归因→符号归因，每步受控实验，最后 OPSA 只是分析的自然推论——对比之下多数 self-improvement 论文是先有方法再编故事。"固定 -0.5 即可匹配 OPD"这一刀直接砍向 OPD 的 knowledge-transfer 叙事，且"teacher 越大监督越 noisy"对正在堆大 teacher 做 OPD 的人是可操作的警告。机制验证也没偷懒：fork-token masking 和 token-budget 对照（续写 "wait" 到 23K token 不涨分）分别排除了两个最顺手的替代解释，Jaccard+Pass@32 双证据回应多样性坍缩。但三个硬伤要压住兴奋：一，全程 Qwen 家族 + 数学域，263% 相对增益的分母是 non-thinking 模式的 13.44，OOD 上 MBPP+ 仅 +1.20——这更像"把 Qwen 预训练里已有的数学能力挤出来"而非 self-improvement，作者自己也承认 thinking 模式下 Pass@k 提升有限、方法本质是重分配已有概率质量；二，"OPD 不蒸馏"的强结论只在 K1-estimator 反向 KL 版 OPD 上成立，对 GKD 等混合采样变体未验证，标题问句的答案其实是"这一种 OPD 不太蒸馏"；三，噪声定义只看 \boxed{} 答案 token 的 advantage 符号，是作者自认的 proxy，覆盖不了中间步监督质量。另外 OPSA 本质是训练时的"压 tail 匀 head"温度整形，与 inference-time min-p/top-p 的增益重叠没有对照——这是全文最该补却没补的实验。跟 TTRL/TTPO 一系的本质区别在于连伪标签都不要：TTRL 的 Pass@32 从 40 掉到 30 而 OPSA 翻到 80，是"负向 token 级信号不坍缩、正向 trajectory 级自奖励坍缩"谱系里最干净的证据点。
- **Rating**: `3` 🔥 ，即便 OPSA 本身可能只在"分布还没 sharp 的 Qwen 数学域"好使，"OPD 增益可无 teacher 复现 + teacher 越大打分越不可靠"这两个诊断结论对整个 on-policy distillation 范式是必读级警钟。

### Lucida
- **Title**: Lucida: Parse, Generate, and Place for Composable Real-to-Sim Scene Modeling
- **Institutes**: ByteDance Seed, Peking University, Zhejiang University
- **Source**: [link](https://arxiv.org/abs/2608.30821)  📰 HF Daily ⬆️74   **📒 论文笔记**: [[2608-Lucida]]
- **核心**: 把真实室内拍摄恢复成可单独编辑的 object assets（composable real-to-sim），保留 parse→generate→place 三段式但重新分配各段职责：parse 只产出真实拍摄可靠提供的 evidence bundle，精度收敛推迟到最后的 placement。招牌是 GizmoAct——把 9-DoF object placement 重构成 multi-turn gizmo 界面交互的 VLM policy（SFT on privileged expert 轨迹 + GRPO），增量编辑 pose、24 离散 reorientation 处理大旋转、正交视图切换消歧。自建 R2S-Scene 上检测 mAP 0.351→0.592、重建 F-Score 0.924 vs SAM 3D 的 0.794；pose 估计在 CA-1M/R2S-Object/ADT 三个数据集一致压过 RecGen（ADD-SB 0.046→0.021）。
- **锐评**: GizmoAct 是这篇真正值钱的部分：局部增量编辑消掉绝对 metric scale 估计、相对尺寸表达消掉单位歧义、permute_axis 离散化绕开大旋转的 gimbal lock——三个设计各杀一个具体难点，这是把 computer-use 的"渲染观测+结构化动作语法+multi-turn RL"范式移植到 3D 空间任务的干净样本，且单一 policy 免 retraining 适配三种 initializer 的泛化证据（Table 3）比一般 pose refinement 工作扎实；RL 把 hard subset 旋转误差从 45.19° 砍到 20.98° 也是实打实的 ablation。但账要算清楚：最唬人的 +69% mAP 发生在自建、仅百余物体规模的 R2S-Scene 上——运动员兼裁判；换到第三方 CA-1M，检测提升缩水到 0.171→0.180，几乎贴地。"闭环收敛"的哲学只兑现在最后一步，parse/generate 仍是开环，作者自认漏检物体下游找不回来。最要命的是复现性：base VLM 名字和参数量全文不披露、资产生成绑闭源 Seed3D 2.0、截至今日无代码——核心贡献外界摸不到。另外"simulation-ready"目前只在几何摆放意义上成立，物理属性（碰撞体/质量/摩擦）零评估。
- **Rating**: `2` 👀 ，GizmoAct 的 GUI-agent-式 3D grounding 重构值得整个 embodied 社区抄作业，但自建 benchmark 撑门面、第三方增益贴地加上零复现性，够 Frontier 不够 Foundation。

### LightNav-0
- **Title**: LightNav-0: Eliciting VLM Spatial Intelligence for Generalist Embodied Navigation
- **Institutes**: Light Origins Team
- **Source**: [link](https://arxiv.org/abs/2608.30935)  📰 HF Daily ⬆️24   **📒 论文笔记**: [[2608-LightNav0]]
- **核心**: 把 Qwen3-VL-4B 原封不动拿来做 generalist 导航：不加 waypoint head、不加 action expert，只扩词表——dual-channel pointing token（affordance + object）先显式化空间决策，3 个 residual-VQ token 编码 10 步 SE(2) waypoint（复原误差 0.72 cm），全程单一 CE loss。ER mid-training → SFT → GRPO 三阶段后，在 10 个公开仿真设定上拿下 monocular success rate SOTA：R2R SR 68.5、HM3D-OVON unseen 47.0（前开源最好 Uni-NaVid 39.5）、自建 INSIGHT-Bench 43.7 vs JanusVLN 27.4。代码权重开源，4090 上 4 ms/token。
- **锐评**: 这篇的价值在 formulation 洁癖：同期 ABot-N1（[[2607-ABotN1]]）也用 affordance pixel + target pixel 接口，但要 4B reasoner + 2B action expert + QFormer 的 slow-fast 双系统才能出连续 waypoint；LightNav-0 证明一个 4B 单模型、纯词表扩展就够——"actions-as-tokens 打败 action head" 这条路线上它是目前最干净的证据点，RVQ 对比 VADv2 式单层量化（0.72 vs 2.48 cm）的数字也扎实。所以 pointing 接口本身不新，新的是把它和动作压进同一个自回归序列且不掉精度。但三处硬伤不能放过：其一，INSIGHT-Bench 训练场景和评测场景出自同一 Molmo2 预标注 pipeline，拿它对 zero-shot 的 JanusVLN 吹 +16.3 SR 是既当运动员又当裁判，分布内优势占多少论文没拆；其二，SOTA 限定词是 "monocular success rates"——RxR nDTW 67.4 输给 DualVLN 的 70.0，说明它擅长"到终点"而非"按指令走"，路径保真度这个维度没赢；其三，GRPO 阶段的逐 benchmark 增量笔记未查到独立报告，三阶段里 Stage 3 必要性的证据链最弱，真机 zero-shot 数字也未经逐表核对，跨 embodiment claim 目前只能算展示不算量化证据。INSIGHT-Bench 按指令类型的分解倒是全文最诚实的部分：ordinal/extremum 掉到 ~33%，自曝关系性空间语言仍是 VLM 短板，与 vault 内跨论文 pattern 一致。
- **Rating**: `2` 👀 ，接口设计干净、开源开权重、数字大面积过硬，是 actions-in-vocabulary 路线的最强样本；但 pointing 思想有先例、自建 benchmark 对比对手偏严、RL 与真机证据未闭环，够前沿必读，不够改写认知。

### Zero-WAM
- **Title**: Zero-WAM: In-Context World-Action Modeling from Human Videos for Open-Ended Task Generalization
- **Institutes**: Robbyant, HKUST(GZ), HKUST
- **Source**: [link](https://arxiv.org/abs/2608.26103)  🔥 HF Trending ⬆️20   **📒 论文笔记**: [[2608-ZeroWAM]]
- **核心**: 把 zero-shot cross-task manipulation 重述为 in-context 问题：拿一段 human video 当任务说明，causal video-action 模型（LingBot-VA 框架、Wan-2.2-TI2V-5B 底座）照着预测未来 robot video 并反解 action。paired 数据不靠人采，用 VLM+图像编辑+视频生成的 pipeline 把已有 robot 轨迹自动改写成 human video（HumanGen，74.2K 对 / 8.6K 任务）；再加 IFP 辅助目标压制"只看 robot history 外推"的 shortcut。RoboTwin 2.0 七个 unseen 任务平均 46.95%，比 LingBot-VA 高 29.50 pp，实机三个 task family 也全胜。
- **锐评**: 先说好的：这篇的 ablation 诚实得罕见——诚实到把自己的 headline 拆穿了。text-only 变体（mask 掉 human video）就有 39.44%，也就是 +29.50 pp 里约 22 pp 来自 task-balanced 数据重采样，标题主打的 human-video ICL + IFP 净贡献约 7.5 pp。全文叙事以 ICL 接口为中心，真正的大头却是一个数据配比技巧，这个错位论文自己不点破。真金是 IFP：机制假设明确（teacher forcing 下 seen task 可绕过 ICL 视频的结构性 shortcut）、设计有讲究（辅助分支只经主干特征间接看视频，防旁路）、单项 +18.4 pp 且推理零开销，还把 stack blocks three 从 0% 破到 9%——这是全文最值得抄的一件事。硬伤有三：仿真评测的 human video prompt 是训练同一 pipeline 生成的，等于用自家生成分布考自家模型，真人 in-the-wild 视频的 domain gap 只有实机每 family 30 trials 撑着；实机对比接口不对等（自己吃视频、baseline 吃文本，caption 有标注但不可读作同条件胜出）；"open-ended" 措辞远超证据——7 个 unseen 任务和 43 个训练任务同属 RoboTwin 桌面双臂家族，这叫 held-out split，不叫 open-ended。跟 DreamZero 的本质区别站得住：DreamZero 做 visual-domain shift 的 zero-shot，这篇做 cross-task 的 in-context 规约，且比 AGNOSTOS 测试时不需要 unseen-task robot 轨迹。另外 pipeline 挂着 Gemini/Nano Banana/Kling 一串闭源商用模型，过滤通过率不报，复现基本别想。
- **Rating**: `2` 👀 ，IFP 是有机制、有增益、零开销的真设计，HumanGen 把 paired 数据稀缺翻转成合成问题也算路线贡献，但 headline 增益七成来自数据配比、评测又困在同分布生成视频里，够 Frontier，不够 Foundation。

### MNIST-PRO
- **Title**: MNIST-PRO: MNIST is Back as a Partially Observable World for AI Agents
- **Institutes**: Nanyang Technological University, A*STAR
- **Source**: [link](https://arxiv.org/abs/2608.31022)  📰 HF Daily ⬆️7   **📒 论文笔记**: [[2608-MNISTPro]]
- **核心**: 把 MNIST 改造成 glimpse 式 POMDP：agent 每步只看 224×224/224×448 画布上一个 64×64 窗口，靠上下左右移动主动收集证据后报出 digit，在剥离 low-level control 的最小视觉域里单独测 multimodal agent 的 perceptual state construction。10 模型 × 4 种 memory 表示的结果很惨烈：full observability 下 94-99% 的识别率在 partial observability 下崩到 0-75%（Claude-5-Sonnet 双 digit 直接归零）。最关键的反事实：把同一条探索轨迹的 glimpse 事后拼成 offline canvas 再判读，Claude-5-Opus L1 41→76、L2 13→67——错不在采集证据，而在组织和解释已采到的证据。三类失败模式（early stopping / belief rigidity / spatial drift）均有量化：323 个单 digit 预测里 238 个压根没探索过另一个 digit 的任何像素。
- **锐评**: offline canvas 反事实是全文最聪明的一招——同一轨迹只换证据呈现方式就 +35~54 个点，这种"采集 vs 解释"的归因粒度是 ALFRED、ActiView 这类 benchmark 给不出来的，也是它跟一般 active vision 评测的本质区别。覆盖率-准确率脱节（覆盖 >75% 时 accuracy 也才 26%）进一步钉死结论：瓶颈在 working memory 不在 exploration。harness 实验有实践含金量：给 Gemini-3.7-Flash 配可写代码的 MCP，模型自己写 stitch.py 做 visual stitching，L1 冲到 88%，而加 persistent memory 反而不增益——短期内外置工具化记忆比模型内生记忆更可行，这对 agent memory 方向是个不客气的信号。硬伤也明摆着：标题喊 "World"，实际是个动作语义已知、完全确定性的 2D active perception 探针，谈不上 world model；"canvas 拼接即恢复"依赖 glimpse 可无损坐标对齐，自然场景的视角/遮挡/光照下根本没有这个便利，结论外推是最大问号；每任务 100 episode、无 error bar，模型间几个点的排序别当真；glimpse 从 32×32 放大到 128×128 时 L2 从 3% 飙到 74%，说明整个难度曲面对窗口尺寸极端敏感，benchmark 数字的绝对值意义有限。另外代码没放，纯 evaluation 无训练侧干预，belief rigidity 能否被 RL 修正只能留白。
- **Rating**: `2` 👀 ，诊断设计和反事实归因是教科书级的干净，但 toy 域外推性存疑且只测不治——是把好手术刀，不是新大陆。

### VisLens
- **Title**: VisLens: Single-Pass Interpretable Visual Search for Multimodal LLMs
- **Institutes**: Technical University of Munich, Helmholtz Munich, Munich Center for Machine Learning
- **Source**: [link](https://arxiv.org/abs/2608.30705)  📄 arXiv   **📒 论文笔记**: [[2608-VisLens]]
- **核心**: 高分辨率图里找小目标时，MLLM 的信号被固定 token budget 稀释，现有方案要么多轮搜索烧推理成本、要么 RL 训出不可解释的裁剪策略。VisLens 训一个 tuned-lens 残差 MLP translator（自蒸馏 KL、无任何 box 标注、仅 0.05% 参数、base 全冻结），把早期 visual token 的 hidden state 解码成逐空间位置的语义热图，与 query 名词匹配、连通分量聚类出 crop，连同原图回喂出答案。三个 7-8B backbone 在 V\*Bench / HR-Bench 上 +5.6~+10.1 点，比 RL 方法 Thyme 快 8.5-9.9x（74.30 @ 0.98s vs 72.25 @ 8.78s），通用 VQA 基本无损。
- **锐评**: 这篇的灵魂不在 crop 流程，而在两个消融。其一，source layer 消融 spread ≤0.010——定位语义在 pre-layer 1（projector 刚出来、还没进任何 LM 层）就已经齐了，说明"模型内部早就知道目标在哪"其实该读成"projector 特征本来就是开放词表语义的"，故事没那么玄，但把它用 LM head 免标注解码出来确实是干净的工程。其二，SAM3 替换消融是全文最硬的证据（+1.0 vs +8.4）：换上更强的外部分割器增益反而崩掉，说明关键是 crop 选择与模型自身语义表示对齐，这是对一切 crop-and-reprompt 启发式的机制性区分。但精度维度上 comparison set 挑得很讨巧：只比 Thyme 和外推的 ZoomEye；同为 Qwen2.5-VL-7B，vault 里的 FaithEyes（SFT+GRPO agentic）在 V\*/HR-4K/8K 报 87.4/77.8/72.9，VisLens 是 74.3/70.6/65.1，差 8~13 点——它赢的是成本轴不是精度轴，"精度相当或更高"只在自选 baseline 内成立。流程层面 WordNet POS 抽名词 + "短语中任一词匹配即算"是十年前的 NLP 手艺：属性词直接丢弃，多个同类实例（红车 vs 蓝车）如何分辨没有交代；single-pass 换来的是匹配错了零纠错机会，且错误类型未细分。"single forward pass"的措辞也偏营销——crop 终究要回喂，0.98s 才是诚实的数字。OCR/chart/diagram/全局布局是作者自认的失效区；无代码。Evidence Ledger 12 条全部 source-verified，笔记本身干净；笔记末段对 GUI grounding 的移植设想是标注了的推测——GUI 元素恰是文本/图标，正踩在自认弱区上，别当结论用。
- **Rating**: `2` 👀 ，把 interpretability 工具变成推理期能力的干净示范、SAM3 消融有真正的机制信息量，但精度天花板离 agentic RL 同侪差 8-13 点、名词-only 的适用域窄，是一件好工具而非新范式。

### Zeva
- **Title**: Zeva: In-Context Causal Learning for Generalizable Embodied Manipulation
- **Institutes**: Institute for AI Industry Research (AIR), Tsinghua University; Z-Trans AI
- **Source**: [link](https://arxiv.org/abs/2608.30880)  📄 arXiv   **📒 论文笔记**: [[2608-Zeva]]
- **核心**: 提出 In-Context Causal Learning：用 gated recurrent encoder 把机器人自身的 (action → state change) 因果对编码为 causal signal，存入双时间尺度记忆（attempt 内滑窗 BIT + 跨 attempt 合并的 PIM），按任务 phase 检索后作为 causal prompt 注入**全程冻结**的 Cosmos3 backbone policy——部署期零梯度更新，只更新记忆。真机 ChemLab-Evo 三级难度 83.3 / 70.0 / 57.32，仿真 Atomic5 76.8%（超 Fast-WAM 4.4 点）；最硬的证据是 cumulative success rate 随交互从 26% 爬到 73%（4 次 attempt 内，权重全冻结）。等价于把 LLM 的 in-context learning 搬进物理交互域，context 里装的是编码过的动力学证据而非文本。
- **锐评**: Problem formulation 是真干净——把 continual learning 的稳定性问题转化为 memory 管理问题，这一步值得尊重。而且作者知道什么实验有说服力：CSR 曲线和 cross-task signal 替换（最近邻替换 100→95% 几乎无损、random 替换跌到 55%/45%）比主表任何数字都硬，说明 signal 空间确实按物理效应组织而非任务表面特征；BIT 比 PIM 更关键这个反直觉 ablation 也诚实报了。但硬伤同样明确：**主表归因是脏的**——Zeva 用 Cosmos3 backbone，baseline 里只有 Cosmos3-Nano，规模是否可比论文不说，+4.4 点里多少来自 memory、多少来自 backbone 白送，读者无从判断；且三项真机指标的"最强 baseline"是三个不同方法，没有稳定压制任何单一对手。"first framework" 的 novelty claim 只在"物理交互 + latent 注入"的窄口径下成立——frozen model + 可检索经验记忆在 LLM/GUI agent 域早是通用配方，这里的增量是编码对象换成了动力学。CTE 训练要 task identity 标签，泛化证据全部来自 7 任务小集合内部，标题里的 "Generalizable" 是预支的。评测规模小（真机 20 episodes/任务、evolve 曲线只跑到 4 次 attempt），PIM 长期膨胀与错误因果污染记忆完全没测，注入机制细节（哪些层、prefix 还是 cross-attn）和 latency 也不报。另有一处 abstract 与正文的 warm-up 数字不一致（"up-to 15%" vs 正文按任务最高 20 点）——小事，但审稿人看到会皱眉。
- **Rating**: `2` 👀 ，机制实验（CSR 曲线 + signal 替换）设计得漂亮、formulation 有品位，但 backbone confound 未清、任务集太小、"first" 与 "generalizable" 都是预支的 claim——等更大 backbone 与开放任务集上的复现，成立即升 3。

### PRACTICE
- **Title**: Practice: From Experience to Expertise in Self-Evolving Embodied Agents
- **Institutes**: BAAI; Institute of Software, CAS; University of Chinese Academy of Sciences
- **Source**: [link](https://arxiv.org/abs/2608.30760)  📄 arXiv   **📒 论文笔记**: [[2608-PRACTICE]]
- **核心**: 现有 skill library 方法的内容在演化、维护逻辑却是写死的 prompt workflow，Practice 把 update policy 本身变成可训练对象：冻结 executor，训一个 8B skill learner 输出 ADD/REVISE/MERGE/REMOVE 结构化批量编辑，走 oracle SFT → failure-aware SFT →对 32B teacher 的 top-K forward-KL on-policy 蒸馏三阶段课程。EB-ALFRED 上 49.7% 超最强 experience-augmented baseline 9.7pp，同一套流程对 4 个异构 executor 均有提升（GPT-5.2 +30.3、Qwen3-VL-32B +25.4），全程仅 71 GPU hours。
- **锐评**: Formulation 是这批 skill-library 工作里最有 taste 的——"library 演化但 update policy 不演化"这个观察打得准，failure-aware 阶段用多 executor 同任务成败轨迹做受控对比也比随机混轨迹的同行干净，Table 4 证明失败轨迹给了成功样本给不了的信号（Long split 8→14）。但方法与自己的动机拧着：口号是从 execution outcome 学 update policy，实际三个 stage 的监督**全部来自更强 teacher**（Qwen3.7-Max 造 SFT 目标、通用 32B 给 OPD soft target），没有一比特 task reward 进优化目标——所谓 "learning how to evolve" 是模仿强模型的 edit 分布，而且为什么一个没为 skill editing 训过的通用 32B 的 edit 分布值得对齐，论文只有 +4.4pp 的间接证据、零机制解释。数字上更诚实的读法是：BPE 初始库一步 +16.4pp，三个学习阶段加起来 +9.0——标题里的"学习"贡献不到无学习启发式的六成。绝对性能也不体面：49.7 仍低于裸 GPT-5.4 的 65.3 和 post-training 的 ELITE 70.8，EB-Habitat 只赢 2.6pp 且 Base/Long 反而输。终库 29/15 张 card 的规模下 consolidation 可靠性无从谈起，离散 primitive action pattern 也出不了 EmbodiedBench 这类高层动作空间。附录 C.2 还把 49.7% 串写成 40.0%（笔记 C14 已核实原文如此），校对粗糙。附录的 paired 分析、bootstrap CI、失败归因倒是难得的诚实，值得同行抄作业。
- **Rating**: `2` 👀 ，问题问对了、监督设计干净，但"学 update policy"实际是蒸馏 teacher 而非从下游结果学习，最大增益来自无学习的 BPE 初始化——铺好了 RL 那一步却没走。

### CAER
- **Title**: CAER: Causal Action Effect Reweighting for World Model Training
- **Institutes**: Tsinghua University, Manifold AI, University of Science and Technology of China
- **Source**: [link](https://arxiv.org/abs/2608.30897)  📄 arXiv   **📒 论文笔记**: [[2608-CAER]]
- **核心**: Action-conditioned world model 用 uniform MSE 训练时，海量静态背景 token 主导梯度，稀疏的物理交互反而欠监督。CAER 让模型自己在线对比真实 action 与 null action 两条件下的预测差（借 CFG 式 action dropout 训出 null 分支），把差异大的 token 认定为"承载 action 后果"，在总权重 mass 不变的前提下把监督预算重新分配过去——无外部模型、无预处理、两次 no-gradient forward 的开销。同一 Wan 2.2 5B backbone 上四个异构 setting（LIBERO/RoboTwin/camera control/PoseAnything）aggregate 一致优于 uniform baseline，且附带一阶理论刻画"何时赢"（Cov(ρ,a)>0）。
- **锐评**: 方法品味是真好：把 CFG 的 conditional contrast 从推理时引导挪到训练时 loss 分配，budget-neutral 归一化免调 loss scale，比 SAM/RAFT 外部标注管道干净一个量级；理论部分给条件而非无条件保证、明说"causal"只是 operational contrast 不冒充 do-calculus，这份诚实在灌水区罕见。但证据链有三处硬伤。其一，全文只跟 uniform MSE 一个 baseline 打，与 MotiF 等外部监督 reweighting 零实证对照——"在线自算更好"目前只是效率论证。其二，也是最刺眼的：一个卖点是"学会 action 如何改变世界"的方法，controllability 单项集体退步——camera Trajectory Accuracy 0.6211→0.5474（相对掉 12%，作者措辞 "slightly decrease" 属于粉饰），RoboTwin 的 Instruction Following/Trajectory Accuracy 也在跌；aggregate 是靠 consistency/dynamic 类指标拉起来的，而 LIBERO Background Consistency 0.628→0.792 的暴涨本身就反直觉——背景 token 被抽走监督预算，背景一致性反而大涨，这个机制论文没解释。其三，5,000/1,000 步的训练预算太短，crossover 曲线只在此窗口内成立，且 RoboTwin 增益仅 +0.78（vault 内 FlowWAM 同 backbone 报 63.71，绝对值上 CAER 的 63.13 并不出挑）。RQ 里自己立的"增益应体现在 task-level success"最后完全没做，policy/planning 闭环缺席。
- **Rating**: `2` 👀 ，idea 干净且跨四 setting 可复制，是训练目标层少见的 tasteful 改动；但单 baseline、轨迹跟随指标退步与"因果"卖点自相矛盾、无下游闭环，证据撑不起 Foundation。

### SkillZip Pro
- **Title**: SkillZip Pro: Execution-Aware Dynamic Compression of Progressively Loaded Skills for Self-Evolving Agents
- **Institutes**: Alibaba Group, Zhejiang University
- **Source**: [link](https://arxiv.org/abs/2608.30785)  📄 arXiv   **📒 论文笔记**: [[2608-SkillZipPro]]
- **核心**: SkillZip 续作，把 evaluation-free 压缩对象从单个 SKILL.md 升级为 production agent 实际用的渐进加载 skill bundle 目录（root + references + subskills + scripts）。核心论点是单一压缩率在此 setting 下系统性误导：catalog / activation / path / deployment 四层成本必须分开记账并联合优化，删除必须携带 witness（字面包含 ≻ 确定性 coverage ≻ 冻结 checker entailment），routing 表锁为一等单元、发布前独立 disk audit 验证可达性。三 benchmark 上它是唯一四层全降且 pooled 配对检验保质量的压缩器（102 任务，+0.010，CI [−0.029, +0.059]）；真实内容审核服务上 witnessed 压缩去 38.1% deployed / 10.4% per-run tokens，而无保护压缩 71.4%/75.8% 让 accuracy 从 88% 跌到 70%/62%（FP 10→29–35，损失集中在 exemption rules）。
- **锐评**: 这篇最值钱的不是压缩器本身，而是三组测量。第一，它把"压缩率游戏"逐一拆穿：flat-concat 报 63.8% 节省但真实库只留 0.2% 的 instruction lines（所谓节省就是删除）；root-only 看似无害但 routing 保留 0.000——分支在盘上却永远选不中。这对任何报单一 ratio 的 context/skill 压缩工作都是打脸。第二，VI-P 的机制测量：自进化每轮新增内容 55%±3% 是重复、可移除份额随库龄 29%→53% 单调上爬——压缩对进化库是报酬递增，这个结论对所有 skill-accumulating 系统可迁移，价值超出本文方法。第三，production 消融把每个 safeguard 的载荷量化到位：witness 强度直接决定安全压缩上限（13.8%→32.7%→38.1%），去掉 audit 就 rename public entry、discoverability 归零。但毛病也不小：abstract 的 "no quality loss" 是包装——production v3 accuracy 89.00 对同 session 未压缩 92.00/91.00，低 2–3 个点，正文只敢说 "within the observed variation"；主表的 SkillReducer 被禁用了 evaluation-based selection，拿削弱版对照撑"唯一保质量"的头衔不够体面；pooled 才 102 任务（BFCL 仅 21 题）配 5 分宽 margin，真实库只有 3 个且全出自同一 project 的 SkillOpt 运行。kimi-k2.6 迁移直接翻车（成功率 0.611→0.574，irrelevant load 近 4 倍）说明把 inline 冗余改写成 shared-file routing 不是免费的。最扎眼的口径问题：Table XII 报 0 model calls，而 production 附录证实 benchmark 路径是纯 lexical 抽取——English marker set 在中文 bundle 上只认出 7/264 个 required units，faithfulness 保证依旧是 parser-relative 的，正文 V-E "one structured extraction" 的说法与 0 model calls 对不上，需查代码才能定论。
- **Rating**: `2` 👀 ，四层成本记账 + 55% 每轮重复率 + witness-上限曲线三组测量扎实且可迁移，但削弱版 baseline、小样本和 "no quality loss" 的包装让它停在优秀工程续作，不到必读。

### NavForesee
- **Title**: NavForesee: A Unified Vision-Language World Model for Hierarchical Planning and Dual-Horizon Navigation Prediction
- **Institutes**: AMAP, Alibaba Group
- **Source**: [link](https://arxiv.org/abs/2512.01550)  🎓 CVPR2026   **📒 论文笔记**: [[2512-NavForesee]]
- **核心**: 用单个 Qwen2.5-VL-3B 同时做两件事：显式的 hierarchical language planning（Gemini 2.5 Pro 标注 ~1.5M 样本，summary→plan→actions）和隐式的 dual-horizon world model 预测——短期固定 k 步、长期自适应外推到下一 milestone，预测目标是 depth/DINOv2/SAM 特征而非像素，经 MLP 头输出 K=5 连续 waypoint。仅用公开 R2R-CE/RxR-CE 数据，R2R-CE Val-Unseen 拿到 SR 66.2 / OSR 78.4 / NE 3.94，但 SPL 59.7 落后 CorrectNav 的 62.3；RxR-CE 上全面不敌 SOTA。
- **锐评**: 全文最值钱的是作者自己没点破的一行数据：Table 2 里去掉 language planning 但保留双 horizon 预测，SR 掉到 48.8，比三模块全关的 52.6 还低——world model 预测没有语言意图 condition 时是**负资产**。这是"预测信号必须被 plan 引导"的少见直接证据，恰好印证了他们自己动机里的 semantic drift 假设，比 leaderboard 位置有价值得多。但 SOTA claim 是挑着报的：SR/OSR/NE 领先、SPL 落后 2.6 pts（OSR +10.9 配 SPL 下降，大概率是"探索得多、走得绕"）；更难看的是正文吹 "highest OSR across both datasets"，而 Table 1 的 RxR-CE 部分压根没有 OSR 列，这话在论文内不可核对，属于 overclaim。RxR-CE SPL 差 10 pts，归因"别人数据多"却零 controlled 实验——也可能是 30° 粗转角 + 79° 窄 FOV 下 dual-horizon 预测本身失效，论文不区分。planning 的 ground truth 是 Gemini 蒸馏来的，上限被教师锁死；纯 Habitat 仿真、无真机、无 code、训练细节全塞 supplementary。跟 concurrent 的 PROSPECT（latent 监督）的"latent vs explicit 预测目标"之争，两边都没做对照，仍是 open question。最尴尬的是同组后续的 ABot-N1 在 R2R-CE 上已全面碾过它（SR 70.9 / SPL 67.5，仅 OSR 除外）——它的 leaderboard 生命周期在发表前就结束了。
- **Rating**: `2` 👀 ，机制 ablation（尤其"无 planning 时预测反成负资产"）是真 insight，但 SOTA claim 挑着报、RxR 归因无对照、已被同组后作超越，是值得追踪的 frontier 而非 foundation。
