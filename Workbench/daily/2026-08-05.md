## 论文点评

### Screenshots or Tools
- **Title**: Screenshots or Tools? Eliciting Tool Use and Managing Multimodal Context in Hybrid GUI-MCP Computer-Use Agents
- **Institutes**: University of Electronic Science and Technology of China · AI Platform, Xiaohongshu Inc. · Gaoling School of AI, Renmin University of China · School of Electronic and Computer Engineering, Peking University
- **Source**: [link](https://arxiv.org/abs/2608.03327)  📄 arXiv   **📒 论文笔记**: [[2608-ScreenshotsOrTools]]
- **核心**: 同一 8B backbone 的 Thinking / Instruct 两个 checkpoint，harness、retriever、prompt、toolset 全锁死，扔进 OSWorld-MCP 309 个任务：同一批 MCP 工具让前者 +4.0pp（30.5→34.5）、让后者 −5.9pp（25.4→19.5）。挂 MCP 的净效应符号不是工具的属性，是模型 tool-decision 行为的属性。即便受益一侧也只在 55/309 任务上真调过工具（tool-reachable 口径 23.9%），VLC 暴露 12 个原生工具、16/17 任务可达，两个模型一次没碰。RL probe 把病因劈开：dense tool bonus 23 步内把 spreadsheet adoption 从 0.03 拉到 0.33 并迁移到 greedy，held-out 精度一动不动——因为 API 执行成功率 98–100%、语义成功率 0/23（regex 替换）和 0/16（格式转换），server 对零效果调用照返 `success:true`。
- **锐评**: 这篇的价值全在它敢做减法。**最硬的一条是 adoption 与 competence 的解耦**：三条机制上完全不相干的干预（outcome-independent bonus、positive-advantage cloning、推理期塞工具文档）齐刷刷抬 adoption、齐刷刷不动精度，再加上 0/23 和 0/16 这两个刺眼的分母，"这是监督数据问题不是 reward-design 问题"这个判断被顶得很死。任何还想在 GUI↔tool routing 上做 reward shaping 的组，看完这段可以直接省一轮实验——奖励信号是干净，但它够不到瓶颈。诚实度也罕见：预登记 DiD 门槛 15pp 没达标（step-30 只有 12.8pp）就写 failed 而不是改阈值重述；+4.8pp 里 4.1pp 来自 74 个训练任务自己拆出来；rich-observation 对照在训练带学得快近两倍（+20.5 vs +11.5）、说明压缩其实是训练期障碍而非红利，照写不误。当下 agent RL 圈这是稀缺品。
  但主 claim 的地基没有它看起来那么稳。**zero-adoption 域的方向性是个真问题**：gimp / thunderbird / vlc / chrome 四域 adoption 全为 0，Thinking 侧四域全涨（vlc 24.7→40.0 是全表最大跳变），Instruct 侧四域全跌（gimp 57.7→34.6）。作者以"无调用、变化只是 prompt 扰动"为由把它们从 per-domain 统计里剔了，却原样留在 ±4.0 / −5.9 这两个 headline 里，且全文没给剔除后的 all 行。零工具调用的域能整体被推向与 headline 同号，那"符号由 tool-decision 决定"至少有一部分是"system prompt 里多一个 `<tools>` 块"对两个模型的相反扰动，这不是同一个 claim。这一条是笔记作者读 Table 2 的推断、未进本轮核查集，但它落在主张的正中心，作者本该自己跑一行数字堵掉。
  Context 那半篇要打折看。"37.8% vs 33.0%（+4.8pp）、53% 输入成本"这个 headline 用的是同期 greedy×3 anchor，而 Table 2 里同一 window-4 operating point 的 5 次均值是 34.5%——换个锚就只剩 +3.3pp，论文全程没并排提示口径不同，摘要只带 33.0。更要命的是 235 个未训练任务上只有 +0.8pp 且不显著，作者自己判定全套数字 in-distribution。**能外推的结论只有"等精度、半成本"，摘要的写法比正文松一档**。另外 drop rule 的 "nearly free" 也悬：Table 2 上 window-4 → +drop 是 34.5→32.3（−2.2pp），逐格 SE 没给，而 §4.2 配对分析的 SE 约 ±1.0——这个"免费"依赖一个没展示的方差估计。
  机制归因作者自己只敢写 association，是对的：两个 checkpoint 差的不止 reasoning trace，单 backbone 单尺度（8B），标题里的结论目前 n=1，要 within-model thinking toggle 才能定论。还有个不该原谅的：一篇核心贡献就是"同一 harness 下的受控对比"的论文，**零代码释出**，harness、retriever、74 任务 gradient band 清单全不可复现——别人没法在"同一 harness"下接着做，等于自己废掉了自己最大的复用价值。真正最有意思的线索作者提了没做：`succ_mcp` 只是执行级成功，零效果调用照返 success，这同时喂出 33.0% 的 false-success prior、又让 drop-on-success 精准丢掉那次失败的唯一视觉证据——两个机制叠起来是让 agent 系统性看不见自己失败。把 succ 判据换成带廉价状态 diff 的语义校验，比再加一项 reward 离问题近得多。
- **Rating**: `3` 🔥 ，符号反转 + adoption/competence 解耦是能改变 hybrid GUI-MCP 研究重心的负面结果，控制变量干净、失败照写；headline 口径偏松和 zero-adoption 域的污染扣分，但不影响它作为本方向必读。

### LongHorizon-Harness
- **Title**: LongHorizon-Harness: Advancing Long-Horizon Agents for Real-World Tasks
- **Institutes**: DreamX Team, Alibaba Group
- **Source**: [link](https://arxiv.org/abs/2608.01964)  📰 HF Daily ⬆️ 128   **📒 论文笔记**: [[2608-LongHorizonHarness]]
- **核心**: 把 long-horizon 执行拆成三个权限互不重叠的角色：manager 持有结构化 task state 但碰不到环境，executor 每轮 fresh context、是唯一能改环境的角色，auditor read-only、从看不到 executor 轨迹的干净上下文里自己去环境取证。硬规则只有一条——executor 说"做完了"不算数，一条记录只有拿到 clean audit evidence 才能标 completed，审计期间检出任何 mutation 直接判 integrity violation。Qwen 3.7-Plus 上 WeaveBench PassRate 51.8→80.7、Terminal-Bench 2.1 69.7→77.2、OSWorld 2.0 binary 2.8→8.3。AgentAdapter 把 Claude Code / Codex CLI 等现成 agent 当作一次 bounded episode 拉起，不动其原生 loop。
- **锐评**: 问题 formulation 站得住——不赖模型能力、不赖 context 长度，而是赖 harness 的权限分配（谁能改环境、谁能判完成、什么被允许跨轮持久化），这是个可证伪的机制假设，比一堆"我们又加了个 memory 模块"高一个层级。真正撑起可信度的是 Terminal-Bench：纯 CLI、无 GUI/CLI 路由、同 backbone 同 Claude Code 自跑对照，收益还在而且 **token 少用 24%**——一刀砍掉了"收益来自多给工具"和"多验证必然更贵"两种怀疑。Table 4 的分布也漂亮：Qwen 基线 ≤0.04 的 6 个任务全回到 0.30–0.92，增益的形状是抬失败地板；Opus token 反降、Qwen token 暴涨这对反向走势，是"弱模型要烧更多 audit-replan 轮"留下的机制指纹，比均分有信息量得多。
  然后是硬伤。**全文没有任何 role-level ablation，"ablation"一词根本不出现**——外置 state、fresh-context executor、read-only auditor 三者的净贡献一笔糊涂账。而 fresh-context executor 本身就是个极强的 context-management baseline：只做每轮 context 重置加结构化交接、把 auditor 整个删掉，能拿多少？这实验便宜到没有任何不做的理由，不做就等于本文最核心的主张——"独立核验是关键"——完全没有直接证据，只有一个自洽的故事。更尴尬的是主实验里 auditor 和 executor 是同一个 backbone，只是 context 不同，所谓 exogenous verification 究竟 exogenous 到什么程度，论文自己也答不上来。
  OSWorld 那个"3.0×"是全文最不该被引用的数字：2.8 的 baseline 是官方 GUI-only 结果，实验组多了一整套 shell，附录 A.2 白纸黑字承认 hybrid tool pool。在 median 1.6 小时的桌面 workflow 上给 agent 加 CLI 本身就是重大能力变更，MEA 贡献几分、CLI 贡献几分无从谈起；何况 8.3% binary 的绝对水平低得可怜，小基数上做倍率修辞是标准的包装动作。而且笔记也点明，"全集 baseline 完全无 CLI"这一条论文只用了 hedged 的"typically rely only on GUI actions"，unhedged 版本只出现在 34 任务子集——连这个被污染的对照本身都没被逐任务确认。那个唯一的 Opus 结果所依赖的 34 任务子集**没给任何筛选准则**，34/108 凭什么外推？Abstract/Intro 写 20.0→34.3、Table 3 和 B.1 写 20.6→35.3，两者不可能同时为真，偏偏错在最容易被二手引用的位置；PassRate 定义正文说"fully passed"、附录说"score ≥ 0.8"，也对不上。三个 benchmark 用三个不同 Claude Code 版本（2.1.76 / 2.1.176 / 2.1.211），WeaveBench 还额外塞了个 save_screenshot——作者辩称不增加环境控制能力，可它恰好服务于"截图作为评分 artifact"那类任务的得分条件，这话我不买。
  最有价值的其实是作者自己在附录 B.2 承认的边界：增益集中在"progress 能被表示为可核验环境状态"的任务，隐藏阈值、排序语义、时序定位类任务上系统性回退（mteb、data-science、video-processing 全是负 tag），并且写下了"a misinterpreted contract can still lead to a confidently verified wrong answer"。这句话该进 abstract 而不是被埋在附录第二层——MEA 提升的是"把已达成的进展锁住"，完全不提升"判断什么才算达成"；当 acceptance criteria 本身被误解时，独立审计只会把错误固化得更自信。与 StateAct 换 observation interface 的路线是正交的两条腿，共同指向同一个判断：当前 CUA 的瓶颈在长程状态维护与验证，不在单步 GUI 能力。
- **Rating**: `2` 👀 ，formulation 和 Terminal-Bench 那组 matched 对照是真货，但零 ablation 让核心机制主张悬空、OSWorld 的招牌数字被工具变更污染，够看不够信。

### WorldExam
- **Title**: WorldExam: Benchmarking World Models from Apparent Appearance to Inherent Reactivity
- **Institutes**: CASIA, SLAI, CUHK, AMAP, THU
- **Source**: [link](https://arxiv.org/abs/2608.02603)  📰 HF Daily ⬆️ 30   **📒 论文笔记**: [[2608-WorldExam]]
- **核心**: 把可控视频生成的评测拆成 Visual Quality / Control Adherence / Spatial Consistency / World Reactivity 四层，1,474 case、8 任务、20 个模型。真正的新东西只有一条：reactivity 类任务的输入只给触发控制（或高层目标），刻意不写明场景应当如何回应，逼模型自己从初始状态推断后果——区别于 Omni-WorldBench / WBench 那批"把期待结果写进指令再检查是否实现"的做法。同一控制意图被适配成 SE(3) 轨迹 / 离散动作 / 自然语言，从而让三类接口跑同一批 case。结论是能力沿接口分裂：action 接口主体控制更准（Subject Control 55.47 vs 37.28），却常让世界纹丝不动（Terrain 27.49 vs 64.39、Object 33.75 vs 75.96），language 接口反过来。
- **锐评**: 概念切分是干净的，"给触发、留空后果"落到实现上是可操作的、而且能直接搬去别的模态——这是本文唯一活得比排行榜久的东西。工程也有几处真功夫：Terrain Interaction 用 Subject Control 做 gate，而 action-driven 的 Subject Control 更高，等于这个 gate 系统性偏袒 action 一方，它们还是只有 27.49，这条结论因此比表面数字硬；两条 track 不合并总榜，拒绝把"接口不支持"记成"做得差"，是正确取舍；backend swap（VGGT-Ω→DA3）和 human alignment 都做了，还老实报了分任务最差项（Social Interaction ρ=0.7019）和最敏感范式（language-driven 5.36%），这种披露密度在 benchmark 里少见。
  但招牌结论站不住。dynamic-interaction track 上 action-driven 只剩 WorldPlay 和 LingBot-World 两个本地模型，language-driven 是全部 7 个 API 商用系统（Table 8）——"action 接口 → 世界不反应"和"这两个特定开源模型 → 世界不反应"在这份数据里根本分不开，作者自己都承认闭源系统的 proprietary prompt enhancement 可能在替它们做场景 grounding，却没把这条列进 limitation。更打脸的是范式内方差：language-driven 的 Task 均值从 39.85 铺到 65.02，跨度 25 分，而垫底的 Kling 2.5（39.85）还低于 action-driven 的 LingBot-World（39.91）。所谓"language 更会反应"其实是 Veo 3.1 / Vidu Q3 / Hailuo 2.3 三个最强系统撑起来的，写成接口属性是过度概括。要拆这条共线得同一底座接两种接口，本文没做。
  第二处硬伤在 ground truth：四个 checklist 任务的正确答案由未具名的 LLM case composer 起草、refiner 改写后定稿，人工只筛了初始图，**checklist 本身从未被人审过**。§5.6 那 5,793 条标注验证的是"judge 按给定 checklist 打分与人一致"，不是"checklist 抓对了该发生的物理/社会反应"——两件事的失效模式完全不同，Conclusion 里却合成一句话讲了。再加上 125–192 帧的视频被压成 10 帧丢给 GPT-5.5，而 Social Interaction / Physical Reaction 要判的恰恰是 timely adjustment、premature onset 这类纯时序量，10 这个数还没做敏感性分析——一致性最低的正是 Social Interaction，不意外。另外每个 case 只生成一次、无重复采样，对随机生成模型来说方差完全没量化。
  最值得引用的反而不是主结论，是 Visual Quality 与其余三层的解耦：language 范式 General 均值挤在 79.64–81.04 的 1.4 分窄带里，Task 均值却铺到 39.85–65.02；ReCamMaster General 80.97 / Camera Control 38.64；Kling 2.5 General 最高 81.04 / Goal Completion 48.25。三个证据分布在不同范式和不同层级上，是一条现成的、打"拿 FVD/aesthetic score 论证 world model 质量"的弹药。有一点得留神：论文对解耦的直接证据里只有 Kling 那条落在 checklist 任务上——"画质差导致 judge 无法核实、按规则记 0，于是画质从后门漏进 reactivity 分数"这条路径论文没做分析，属于未验证假设，别拿去当结论。最后，引用"20 个模型"时必须说清那是 static track 的规模，reactivity 层实际只有 9 个、Goal Completion 只有 7 个；数据与 toolkit 写的是 will release，现在只有项目主页，无法复现。
- **Rating**: `2` 👀 ，切分和"画质≠能力"那组数字值得抄，但招牌的"接口能力互补"被模型档次共线彻底污染、checklist 无人审核、benchmark 还没放出来——离我们四个方向也隔了一层，值得读不值得等。

### GUI-Lens
- **Title**: GUI-Lens: Coarse-to-Fine Cropping for GUI Grounding with General-Purpose VLMs
- **Institutes**: Tencent（v1 作者块只有数字标记 1/2/3，正文未展开机构名，唯一线索是"internship at Tencent"脚注，另两家未知）
- **Source**: [link](https://arxiv.org/abs/2608.03270)  📄 arXiv   **📒 论文笔记**: [[2608-GUILens]]
- **核心**: Training-free 的 GUI grounding 脚手架：先用 EasyOCR + 一个开源 UI detector 抽一批带原屏坐标的参考塞进 prompt，然后让 VLM 自己决定每轮裁哪块、放多大，每个 crop/click 提议再由同一模型做一次 accept/reject 视觉校验，拒了就回退全屏重开。与 ZoomClick 那类 click-centered zoom 的关键差别是新视图不以上一次点击预测为中心，避免早期误差把后续观察锁死。ScreenSpot-Pro 上 GPT-5.5 74.8→87.9、Claude Opus 4.7 57.4→82.3（摘要的 +24.9 出处）、MiniMax-M3 26.4→47.4；OSWorld 三域 Overall 86.8。
- **锐评**: 全文最有价值的证据被作者自己埋在 Introduction：Figure 2 那张 coarse-to-fine vs. click-centered 的受控对比，才是唯一说明"这个方法为什么不是又一个 zoom 变体"的东西——多步 refinement 的收益来自不把点估计当锚，而不是"看得更细"。可惜 headline 卖的是 SOTA，而那个 SOTA 是全文最脏的一个数。Table 1 跨行 backbone 完全不受控（KV-Ground、AdaZoom-GUI 跑在小开源模型上，本文用 GPT-5.5），而 GPT-5.5 光单次调用的 74.8 就已经压过表里所有 specialized GUI model 的最好成绩 70.6——87.9 里框架占多少、基座占多少，从表里根本读不出来。更硬的伤是算力没解耦：baseline 是 1 次调用，Quality 配置最多 8 轮裁剪、每轮外加独立的 proposal 与 verification 调用、校验重试上限 6，全文没有任何等调用数或等 token 预算的对照（连最朴素的"单次调用多采样投票"都没做）。所以 +13.1 / +24.9 不是方法净收益，是"十几次调用 vs. 一次调用"的收益。§3.4 的效率分析（Efficient 1.27× 延迟 +10.34）是全文对这一点唯一像样的辩护，但它对照的是延迟不是预算，而且 headline 用的偏偏是高预算档。OSWorld 那个 86.8 同样要打折：论文自己写明只测 Chrome / Multi-Apps / OS 三域、15 步上限，但没说 leaderboard 上别人的 Overall 是不是同口径——笔记明确把这条列为本文无法核实的开放项，那这一列就不该跨行读，唯一站得住的是与 Pointer Agent 的同 backbone 对比。方法本身是 OCR 参考 + 迭代裁剪 + 自校验的组装，概念增量有限，超参一堆（8 轮 / 5×/8× 放大 / 60-80 条参考 / 8% padding / 6 次重试）却零敏感性分析；没有 Limitations 节，没有失败分析，verification 误拒要整轮回退全屏，代价统计一个字没有；所有数字单次运行不做重复，配上 McNemar 显著性更像是用一个测不了运行间方差的检验来给一个每样本发十几次 API 的 pipeline 背书。真正亮眼的反而是消融里那条被作者低估的规律：priming 的收益随 backbone 变弱而暴涨（−1.0 / −2.0 / −7.3），verification 同向，唯独 cropping 在最强的 GPT-5.5 上仍值 10.4 分。这暗示 cropping 补的是高分辨率输入的信息瓶颈（架构约束，不会随基座变强而消失），另两个补的是模型能力缺口（会蒸发）——这个判据比论文的 SOTA 更有引用价值，也顺带说明这条技术路线的另外三分之二正在贬值。Appendix 的坦诚（自认 Table 1 不受控、OSWorld 表不是受控对比、未做重复运行、token 成本不可得只能数调用次数）值得给分，但坦诚不能替代缺失的对照实验。
- **Rating**: `2` 👀 ，工程实用、代码已放、消融给出可迁移规律，但 SOTA 被基座和算力双重污染，核心 claim 撑不起 headline；值得读 Figure 2 和 Table 4，不值得信 87.9。

### AgentStream
- **Title**: AgentStream: How Well Do Self-Evolving LLM Agents Perform Under Streaming Tasks?
- **Institutes**: University of Chinese Academy of Sciences, Microsoft, Institute of Automation CAS, Nanjing University
- **Source**: [link](https://arxiv.org/abs/2608.00155)  📰 HF Daily ⬆️ 3   **📒 论文笔记**: [[2608-AgentStream]]
- **核心**: 把 6 个 agentic benchmark（AppWorld / BFCL / BrowseComp-Plus / HLE / SWE-bench Verified / Tau2）编排成可配置任务流，用 Isolated / Sequential / Interleaved 三种流式场景，对 5 个 self-evolving 方法 × 3 个闭源 frontier 模型做受控析因，测量 evolution gain = 有 state 减无 state。测试时无 ground-truth，演化只靠自生成反馈。结论三条：Isolated 最可靠（34/45 跑赢 vanilla，+1.37），Interleaved 反而优于 Sequential（15 配置里 10:5）；收益被 base model gate 住且非单调——GPT-5.4 三场景 gain 全负，vanilla 更弱的 Gemini（56.6）反而比更强的 Claude（63.9）多赚 +2.37% vs +1.23%；没有方法能跨模型占优，A-Mem 在 GPT-5.4 第一、在 Gemini 垫底。最有价值的抽象是 context-integrated（ACE/Harness，吃 Isolated）vs retrieval-based（ReasoningBank/AutoSkill/A-Mem，吃 Interleaved）的二分。
- **锐评**: 问题选得比方法好——把"自进化有没有用"从各家自报一个数变成三因子析因，这个 formulation 是这个方向真正缺的，Table 5 里两族方法在 Isolated/Interleaved 上的**符号翻转**（ACE +2.28 → −1.26）是全文最干净的证据，也是唯一一条噪声压不住的。但除此之外，效应量和噪声的比例是灾难：头条结论建在 0.6–1.6% 的均值差上，而 Table 1 单元格的 seed 标准差常在 3–6%，Tau2 上到 ±36.2——附录 C 逐 seed 显示同一 model+method+scenario 仅换任务到达顺序就能从 12.0 跳到 84.0。全文零显著性检验、零置信区间，Table 2 自己给的 +1.37±0.80 vs +0.90±0.34 区间大幅重叠，"Isolated 最可靠"顶多是趋势。更要命的是"model capability"这个核心自变量被单列绑架：GPT-5.4 被定为最弱模型靠的是 vanilla 均分 45.8，而它在 HLE 上只有 2.0（Gemini 52.0 / Claude 38.0）——2.0% 这种分数通常是 harness 或解析失败的味道，论文一句诊断都没有，于是"capability gating"和"非单调"两条结论的能力刻度都吊在这一列上。作者给的 bootstrap loop 机制（solve rate 低 → 经验流被失败轨迹主导）是个好假设，但论文措辞就是 "These results suggest"，全文没有任何操纵经验质量的 ablation，附录 B 只统计了 state 的大小和更新频率、没把经验**质量**和 gain 连起来——这是最该补而没补的一刀。Sequential 只跑了一个固定顺序（AppWorld→…→Tau2），顺序效应和跨域干扰完全混杂，"Interleaved > Sequential"也可以只是说这条 curriculum 排得烂。"per-model 选方法"的建议同样虚：Gemini 上五法 spread 只有 2.0%、Claude 上 0.9%，这个量级的排名基本是掷骰子。真正扎实的数字反倒在附录：A-Mem 在 GPT-5.4 上换来 +3.2% 却烧掉 577% baseline 成本，Claude 在 Harness 下 96% 任务都改 skill（460 次编辑）而 GPT-5.4 300 个任务只编辑 5 次、从不动 system prompt——这种行为级差异比主表任何一个 1% 都有信息量。另外全是闭源模型的特定档位（-medium / -high），几个月后不可复现，跟"统一 harness 让方法可比"的卖点直接打架；论文正文印的 code 链接 404，canonical 路径下（2026-08-05 实测）只有一个写着 "Code is under preparation" 的 README——一篇核心贡献是评测基建的论文，当下零可复用物。对我们的价值：这是 AI Agent 方向 test-time self-evolution 的一次系统性证伪压力测试，"45 个计数单元里有 11–17 个跑输 vanilla" 的量级感值得内化；耦合强度（而非"演化哪个组件"）作为一级分类轴的观察，可能比论文自己的结论更耐久。
- **Rating**: `2` 👀 ，formulation 和两族二分值得吸收、量级感有用，但统计功效撑不起头条结论、机制假设无对照实验、代码未发布，当 hypothesis generator 读而非当结论引。

### VLA-Proprioception
- **Title**: How Should Vision-Language-Action Models Use Proprioceptive State?
- **Institutes**: The Hong Kong University of Science and Technology (Guangzhou), MMLab, The Chinese University of Hong Kong, AI2 Robotics X-Lab
- **Source**: [link](https://arxiv.org/abs/2608.03052)  📄 arXiv   **📒 论文笔记**: [[2608-VLAProprioception]]
- **核心**: 把"VLA 里 proprioceptive state 怎么接"这个一直靠惯例决定的问题拆成三条轴——离散 token 化还是连续投影、历史多长、注入到 VLM 侧还是 action expert 侧——固定 π0.5 基座、数据、action 表示和评测协议，只动 state 这一个自由度，在 RoboCasa365 的 45 个 atomic + 20 个 composite 任务上闭环跑五种接口。结论有三条：当前帧 state 的平均收益很小（no-state 54.6% → 各接口 55.7–57.7%）且不存在任务无关的最优接口，族内排名会直接翻转；短历史有界有益、长 raw 历史有害，且在小工作空间高精度任务上退化最重；注入位置的偏好随时间预算翻转——单帧时 VLM prefix 占优，K=8 时 action prefix 在所有 panel 变成最强。关键控制实验是 slot-matched 对照：把 8 个 slot 全填当前帧副本只有 30.8%，真实有序历史 39.0%，说明收益来自时序内容而非多出来的 conditioning 容量。
- **锐评**: 先说值钱的：slot-matched repeat-current 对照是这篇最好的一个设计决定，它把"多给几个 conditioning slot"和"真的有时序信息"这两个在无数 memory/history 论文里被混为一谈的因素干净地分开了（+8.2，配对区间排除 0）；任务族按控制语义**事前**划分而不是按模型表现事后聚类，否则"族内排名翻转"就是循环论证；每个 claim 建立在独立训练的系统之间而不是对单个 checkpoint 做扰动。这套协议可以直接拿去审计任何一篇声称"我加了 X 记忆所以变好了"的 VLA 工作，方法论比结论值钱得多。
  然后是站不住的地方。**RQ1 的诚实表述是一个负结果**：五个接口的 atomic macro 全挤在 2 个点的带子里，只有 sp 的 [0.2, 6.1] 排除 0，作者克制地只认这一个效应——那就该把标题写成"当前帧 state 基本无关紧要"，而不是留给读者一个"state 有用"的印象。**+10.8 这个 headline 数字的基准是烂的**：composite 上 ap1 = 28.2%，no-state baseline 28.4%，也就是单帧走 action prefix 等于自残；+10.8 大半是在填自己挖的坑。跨设计的公平比较应该是 ap8（39.0%）对最好的单帧设计 vp1（34.4%），+4.6 点，幅度砍掉一半以上，方向不变但"决定性"三个字要收回。**最要命的是标题里的 "proprioceptive" 掺了水**：16 维 state 里 7 维是 world frame 下的 mobile-base 位姿，那是全局定位不是本体感受；而 sp 增益最大的 A 族恰恰是大范围重定位 + 移动底盘的任务（+7.0）。"把全局位置离散化塞进语言空间有用"和"proprioception 帮助运动控制"是两个完全不同的机制，去掉 base pose 重跑 A 族是唯一能区分它们的实验，论文点出了这个边界却没做——这是我最想看而没看到的一个 ablation。sp 的处境也很尴尬且被回避了：它是唯一拿到区间支持的接口，训练侧却比连续接口贵两个数量级，还因为构造上只支持当前帧被整体排除在历史实验之外；最终"单帧进 VLM"这半条设计规则的最强证据来自 sp，作者却在 RQ3 里主要用 vp 代表 VLM 侧——而 sp 和 vp 同属 VLM 侧却在族内排名上互相打架（A 族 sp 赢，C 族 vp 是唯一低于 baseline 的接口），说明"注入位置"这一根轴根本不足以刻画二者差别，离散化 vs 连续投影这条表示轴在三轴框架里没被干净分离。
  证据强度也要打折：多数对比是单 seed，bootstrap 区间量的是评测与任务采样的不确定性、不是优化方差，interface×depth 的整片 sweep 属 exploratory 且未做多重比较校正；se/fm 因硬件分配样本曝光偏低（作者主动披露，态度可嘉，但意味着它们**没赢**的地方一律不能读成"不行"）。Appendix 的注意力重分配和 flow 轨迹 probe 作者自己声明是 descriptive 关联而非 mediation，所以"VLM 侧有早期上下文化路径、action 侧没有"目前只是数据流层面的观察，不能当作机制已被证实。最后，无真机验证、state 纯 kinematic 无 force/tactile，而 ap 的优势建立在"每个 denoising step 都能重读 state"上——换成单步回归式 action head 这条机制根本不存在，这套 design guideline 更应被当作 RoboCasa365 + π0.5 + flow-matching 这一组合下的先验，而不是可以搬去真机的规则。
- **Rating**: `2` 👀 ，协议设计和"接口偏好随时间预算翻转"这一条值得抄，但效应量小、单 seed、纯仿真，加上 "proprioception" 被 mobile-base 全局位姿污染却没做关键 ablation，结论强度撑不起 must-read；且只命中我们四个方向里的 Embodied AI 一条。

### Zero-Mem
- **Title**: Zero-Mem: Zero-Token Memory Operations for LLM Agents
- **Institutes**: The Hong Kong Polytechnic University, Southwestern University of Finance and Economics, Jilin University
- **Source**: [link](https://arxiv.org/abs/2607.29377)  📰 HF Daily ⬆️ 5   **📒 论文笔记**: [[2607-ZeroMem]]
- **核心**: 把 agent memory 的构建、组织、路由、检索、校准全部换成不调 LLM 的确定性流程，只在最后一步 QA 调一次 reader。做法是不生成 abstraction 替换原始 trace，而是在 trace 之上叠两个非生成式视图——spaCy NER 建的 entity–context 共现图（走 Personalized PageRank）和 turn/window/episode/local 四级时间层级——按 query 结构信号决定二者融合权重。LoCoMo 与 HotpotQA 上平均 F1 最高（59.15 / 相对最强 baseline 平均 +5.52），memory-operation token 归零，耗时比最快 baseline LightMem 降 57.6%。
- **锐评**: 这篇的价值几乎全在负面结果，不在方法。方法本身是一套组装得很干净的 pre-LLM IR 流水线——NER + BM25 + BGE-M3 + PPR + 手写 query 启发式——真正的"新意"是把它重新记账成一个可证伪的 operating regime。而 PPR-over-entity-graph 正是 HippoRAG 的核心，偏偏 HippoRAG 只在 Table 1 里出现了一行，Baselines 段落从头到尾没介绍它，Table 3 也不含它（C21），被引用的 Appendix 在 v1 里根本不存在（C22）。最该说清楚的那条对照，恰恰是文档最缺的一条，这不是巧合。"零 token"更是个会计选择而非免费午餐：成本转移到了对全部 trace 跑 NER 与 BGE-M3 的 encoder 推理，以及那套 φ(q) 五字段规则——后者全文只给了字段名，没有规则集、没有抽取器、没有跨 benchmark 迁移测试，如果它是照着 LoCoMo/HotpotQA 的题型手调出来的，那换 domain 就要重做，而这笔人力成本永远不会进 Table 2。更要命的是 C20：正文和表注都没说一次性建图/建索引是否计入那 334.77 s，而这正是一个无 LLM 系统唯一会付大钱的地方——57.6% 这个数字的可比性因此是悬空的。数据里最诚实的信号有两个：一是 GPT-4o-mini 下 multi-hop 41.61 输给 GAM 的 42.29（C3），偏偏是最需要跨 trace 组合而非定位证据的那一类，论文用"remaining competitive"轻轻带过；二是 C18——A-Mem/Mem0/MemoryOS/LightMem 在 HotpotQA 全部六个设置上都输给 memory-free 的 LONG-LLM 和朴素 RAG（LightMem 峰值 40.93，对手列内最低 43.17/46.72）。这才是全文最有杀伤力的一张表，作者却没展开：它说明这个子领域一大批"记忆模块有效"的结论压根没控成本轴。作者把 C19（zero-token ≠ 零计算）主动写进正文值得加分，但结论段那句 "effective agent memory does not require generated intermediate representations" 的覆盖面远超两个证据可定位型 QA benchmark 能支撑的范围——记忆价值在于归纳（偏好漂移、失败模式总结）而非定位原句时，完全没测。另外两个 backbone 都不是强推理模型，代码要等 peer review 之后才放（C15），当前不可复现。
- **Rating**: `2` 👀 ，"删掉生成式 memory 质量不降"这个反 convention 的证据对 AI Agent memory 方向值得记一笔，但整套 substrate 建在文本实体和显式指称上，GUI/Embodied 的截图与动作轨迹里没有 spaCy 能抽的实体，迁移性接近零。

### MissClick
- **Title**: MissClick: Exploiting Digit-Serialized Coordinates to Attack GUI Grounding Models
- **Institutes**: 未标注
- **Source**: [link](https://arxiv.org/abs/2608.03740)  📄 arXiv   **📒 论文笔记**: [[2608-MissClick]]
- **核心**: GUI grounding 模型把点击坐标以 digit token 逐位吐出，解析时每位带十进制位权——百位翻一次就是 100 个坐标单位的位移，而 token-level 的交叉熵对所有位一视同仁。MissClick 据此拆成两个目标：untargeted 用期望 digit 值重建可微 soft coordinate、最大化与 GT 点击的距离；targeted 直接对 target digit 做交叉熵并按 10^(m−j) 加权。白盒 PGD（ε=16/255，α=1/255，100 iter）打 OS-Atlas-Base-7B 与 UGround-V1-7B，ScreenSpot-v2 上 untargeted ASR 75.07% / 72.93%，targeted 44.86% / 62.67%，比 representation attack 和 token CE baseline 高出 16.6–47.1 pp。最有价值的其实是 Table 2 的交叉验证：soft-coordinate 目标在 untargeted 最优、换到 targeted 反而输给朴素 Digit CE，因为期望值命中目标不等于 argmax 命中目标（p(1)=.48, p(8)=.16, p(9)=.36 期望恰为 5 而 argmax 为 1）。
- **锐评**: 观察是对的，推导也干净——增量不过是给交叉熵乘一个位权，不训练不改模型，targeted 上 +31.7/+47.1 pp 的幅度不可能是噪声，10 步迭代追平 baseline 的 100 步这个成本数字也有实际意义。带机制解释的负结果（soft-coordinate 在 targeted 失效）比主表多出的那几十个百分点信息量高得多，这是我愿意给它分的唯一理由。但威胁模型是塌的：全程没有说这个 ±16/255 的全屏逐像素扰动经由什么通道进入 agent 看到的截图——能任意改写整张截图的每个像素，攻击者已经站在渲染/截屏管线里了，那时候直接改写模型输出比跑 100 步 PGD 便宜得多；真正对应现实的受限区域扰动（广告位、自托管页面、上传图）+ 浏览器缩放 + 模型自己的 resize/patchify，一个都没测。论文把这推给"transferability 是 future work"是偷换问题：迁移性问换个模型灵不灵，扰动通道问这个攻击面存不存在。数字也要打折——untargeted 的 75.07% 被评测协议抬高（解析失败直接计为成功），而且 untargeted 的成功条件只要求"点击离开 GT box"，把小按钮挤偏 5 像素和跳出 300 个单位在指标上完全等价，这恰恰不检验全文赖以立论的"高位带来大位移"；真正相关的是 targeted，OS-Atlas 上 44.86% 连一半都不到，且对预算敏感（targeted ASR ε=16 的 46.47% → ε=4 的 24.91%）。机制证据全是端到端 ASR 消融，没有一张位移直方图、没有逐位翻转率——"位权加权有效"完全可以有平凡解释：它把梯度预算集中到更少、更易优化的位置上，与十进制语义无关，一张图就能解掉这个歧义，作者没画。覆盖面也窄：两个 7B victim、一个 benchmark、零防御评测（JPEG 重编码、随机缩放这种最便宜的检查一个没做），使用特殊坐标 token 而非 per-digit 十进制的模型未涉及——而那恰恰是判断"这是接口固有缺陷还是实现偶然"的关键对照。targeted 的目标元素是从零-IoU 元素里均匀采样的，不按攻击者收益挑，也没有 ASR-对-距离曲线，所以 62.67% 度量的是"能否命中一个随机的别的元素"，不是危害。最后，作者自己承认 digit 位权结构在训练侧（NTL、Phi-Ground、DIST2Loss）早被研究过（C18），本文是把已知观察搬到攻击侧——扎实，但增量；且未放出代码（C16），复现只能靠自己重写。对我们的价值不在攻击本身，而在它暴露的接口性质：per-digit 序列化制造了一个非均匀误差曲面，一个 token 管 100 个单位——这对量化、采样温度、解码扰动同样成立，也直接指向一个现有 CUA 栈普遍缺失的廉价防线：动作语义与执行坐标的一致性校验。
- **Rating**: `2` 👀 ，观察和那个 targeted 负结果值得记住，但纯白盒全屏扰动 + 零防御 + 两模型单 benchmark 的证据撑不起威胁叙事，对我们更像一条关于 grounding 接口脆弱性的线索而非可用结论。
