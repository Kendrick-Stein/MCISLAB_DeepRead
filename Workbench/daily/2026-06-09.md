## 论文点评

### SWE-Explore
- **Title**: SWE-Explore: Benchmarking How Coding Agents Explore Repositories
- **Institutes**: 无（作者未在 arXiv 页面列出机构信息）
- **Source**: [link](https://arxiv.org/abs/2606.07297)  📰 HF Daily ⬆️ 98
- **核心**: 把 coding agent 的"找代码"能力单独拎出来做 benchmark——给 issue 和 repo，让 agent 在固定行数预算下返回 ranked 相关代码区域。数据构建很聪明：从 5 个强 agent 的成功轨迹中提取 read actions，取交集作为 ground truth（所有 agent 都读过 = 大概率必要），再用 LLM refinement + 人工审计校准。848 个 instances 跨 10 种语言 203 个 repos。结果很戏剧：agentic explorers 吊打传统检索（CoSIL 59.3% vs BM25 12.7% 下游 resolve rate），但所有 agent 的行级 recall 都惨不忍睹（0.14-0.19），文件级定位倒是还行（0.5-0.68）。换更强 LLM 也没用，GPT-5.4 和 Sonnet-4.5 的 recall 都卡在 0.11-0.19。
- **锐评**: **问题切得准，数据构建有想法，但 ground truth 的保守性藏了定时炸弹**。轨迹交集生成标注的逻辑是"所有成功 agent 都读过 → 必要证据"，但反过来不成立："没被所有 agent 都读 ≠ 不必要"。作者用 LLM refinement 补漏，然后说"这是经验近似，不是唯一有效证据集"——这不是谦虚，这是硬伤。如果某个 agent 用了完全不同但同样有效的路径（比如从 test 反推 implementation 而非从 issue 顺推），那它需要的 regions 根本不会进入 ground truth，然后 benchmark 会错误地惩罚这条路径。更致命的是 **只测试能解决的 instances**——这不是 exploration benchmark，这是"已知解法的覆盖率测试"。文章对此的辩护是"我们要评估的是 agent 能否复现成功路径"，但这跟 title 承诺的"benchmarking how agents explore"是两回事。真正的 exploration 应该包括"在未知地形中找路"，而非"在已知路线上打卡"。下游验证 n=150 太小，Pearson r=0.950 虽然亮眼但可能是 overfitting 到这 150 个样本的 artifact。行级 recall 全线低（0.14-0.19）确实是有价值的发现，但"换 LLM 无用"这个结论站不住脚——Table 5 里 GPT-5.4 的 HitFile 0.655 vs Gemini-3-Pro 0.369，差了快一倍，只是 recall 指标对模型不敏感不代表模型本身不重要。最大的讽刺是 CoSIL（iterative code-graph search）的 recall 0.788 吊打所有通用 agent，证明方法比模型重要，但文章把它埋在一张表里轻描淡写带过，没有深挖为什么 code-graph 有效、其他 agent 为什么学不到。
- **Rating**: `2` 👀，benchmark 设计有新意但 ground truth 构建的保守性和 coverage bias 限制了它的适用范围，更像是"成功路径覆盖率测试"而非真正的 exploration benchmark，低 recall 的发现有价值但分析不够深。

### Agents' Last Exam
- **Title**: Agents' Last Exam
- **Institutes**: UC Berkeley (lead), Stanford, MIT, Johns Hopkins, UW, Caltech, NYU, Brown + 80+ institutions
- **Source**: [link](https://arxiv.org/abs/2606.05405)  📰 HF Daily ⬆️ 79
- **核心**: 308 位作者联合构建的经济价值导向 benchmark，覆盖 SOC 2018 全部 55 个数字化行业子领域（制造、金融、生物、视觉艺术、医疗等），1490 个真实专家任务实例，从业者提交自己已完成的数日-数周级项目。要求 agent 同时操作 GUI + CLI + 代码 + 文件，输出可确定性验证的交付物（CAD 文件、审计报表、3D 模型、MIDI 乐谱等）。当前最强配置（Codex + GPT-5.5）在最难档 Last-Exam 通过率仅 8.6%，完整平均 26.2%。
- **锐评**: **硬伤**：308 作者、1490 任务的工程量震撼，但 benchmark 本身不 open-source（仅公开 10% 任务防污染），无法复现 evaluation pipeline，实质是个 leaderboard service 而非 research artifact。**方法论断层**：claim "economically valuable" 但未给出单个任务与 GDP 的因果链，SOC 2018 映射是分类学而非价值量化。**数据质量存疑**：专家提交的"已完成项目"如何标准化成可自动评分的 rubric？任务卡显示很多 partial credit 来自"部分文件存在"而非真实质量，LLM-as-judge 被刻意回避但 vision judge 又悄悄混入（Task Card 3）。**benchmark 设计的根本矛盾**：真实专业工作的评价 *inherently* 需要人类专家 judge（GDPval 和 RLI 诚实承认了），ALE 用 deterministic scripts 强行自动化，结果是要么 oversimplify 任务要么 overfitting 到可脚本化的 corner cases。**唯一亮点**：task 覆盖面确实广，GUI+CLI 混合操作比纯 terminal 或纯 GUI benchmark 更接近真实工作流，但这不足以支撑 "agents pass → GDP impact" 的 grand claim。
- **Rating**: `2` 👀，benchmark-as-a-service 的工程价值 > 科学洞察，评估协议不透明 + 经济价值 claim 过度 + 自动评分 vs 真实质量的 gap 未解决

### LatentSkill
- **Title**: LatentSkill: From In-Context Textual Skills to In-Weight Latent Skills for LLM Agents
- **Institutes**: 未明确标注（从作者阵容看疑似国内团队）
- **Source**: [link](https://arxiv.org/abs/2606.06087)  📰 HF Daily ⬆️ 50
- **核心**: 把 agent 的文本 skill 通过 hypernetwork 编译成 LoRA adapter，塞进权重里而不是每次都往 prompt 里灌。ALFWorld 上 seen/unseen split 分别涨 21.4/13.4 个点，prefill token 砍掉 64%。生成的 LoRA 权重空间有结构（不同 domain 的 skill 自动聚类）、可控（α 系数调节强度）、可组合（skill 算术）。
- **锐评**: Idea 够清爽——skill 从 context 搬到 weight 确实省 token，hypernetwork 一次性生成 LoRA 也比反复微调灵活。但评估太保守：只测了 ALFWorld 和 Search-QA 两个玩具 benchmark，都是文本 agent，skill 全来自同一个 library（SkillRL）。这 skill compiler 见过复杂 web agent、多模态 agent 吗？Component-level composition 号称能合并语义组件，却没解释训练时怎么保证 "semantic alignment"——不同 skill 的共享部分凭什么在权重空间自动对齐？看起来更像是 pretraining 的副产品而非设计结果。训练成本避而不谈，171K documents pretraining + trajectory SFT 的开销对小团队不友好。ALFWorld +21 pts 看着唬人，但 unseen split 只涨 13 pts，泛化性存疑。Weight space 的 low stable rank（~2.2）倒是个有意思的发现，暗示 skill knowledge 可能本质就是低秩的——但这结论能推广到更复杂 skill 吗？对比 baseline 也不够狠：RAG 没针对 skill retrieval 优化，in-context baseline 被 prompt attack 打趴下（52.9%→8.57%）证明它脆弱，但 LatentSkill 也只剩 38.6%，并没硬到哪去。
- **Rating**: `2` 👀，技术方向有新意但评估太窄，泛化性和实用性打问号，暂时只适合跟进不值得复现

### Harness-1
- **Title**: Harness-1: Reinforcement Learning for Search Agents with State-Externalizing Harnesses
- **Institutes**: UIUC (Jiawei Han lab)
- **Source**: [link](https://arxiv.org/abs/2606.02373)  🔥 HF Trending ⬆️ 51
- **核心**: 把检索 agent 的状态管理（candidate pool、证据链、去重、budget）外置到环境 harness 里，policy 只管语义决策（搜什么、留什么、何时停）。20B 模型在 8 个检索 benchmark 上平均 curated recall 0.730，比次强开源 agent 高 +11.4 points，在 held-out transfer 任务上泛化强。
- **锐评**: idea 清晰：把 RL policy 从簿记杂活中解放出来。但 0.730 recall 在检索任务上算不上惊艳，"competitive with frontier models" 没给具体数字是糊弄人——到底差多少？+11.4 points 的 baseline 是谁也不说清楚，开源里谁是"次强"？held-out 泛化好听，但 8 个 benchmark 都是什么分布、是不是真的 diverse 没交代。harness 设计像工程经验总结，novelty 有限，更像"把 retrieval 做对了"而非"新范式"。代码开源加一分。
- **Rating**: `2` 👀 — 工程扎实但 insight 单薄，数字遮遮掩掩，等全文看 ablation 和 failure case

### SpatialWorld
- **Title**: SpatialWorld: Benchmarking Interactive Spatial Reasoning of Multimodal Agents in Real-World Tasks
- **Institutes**: 未披露（20 位作者，包含 Nan Duan、Yinpeng Dong 等知名学者）
- **Source**: [link](https://arxiv.org/abs/2606.09669)  📰 HF Daily ⬆️ 37
- **核心**: 整合 8 个异构仿真器（AI2-THOR、CARLA、魔方游戏等）构建统一 benchmark，强制 agent 纯视觉观察 + 文本 action，760 个人工标注任务横跨室内操作、城市导航、抽象几何推理。GPT-5 平均任务成功率仅 17.4%，物理环境更低至 14.4%；Navigation-Interaction 混合任务成功率暴跌至 4.2%（纯交互 50.2%），揭示 MLLM 在长时序物理推理上的复合瓶颈。
- **锐评**: 典型的"benchmark 大乱炖"——8 个仿真器拼在一起，看起来覆盖全面，实则缺乏系统性能力分解。最致命的问题：**只展示 MLLM 不行，但不告诉你为什么不行**。17.4% 的惨淡数字背后，agent 是视觉 grounding 崩了、探索策略瞎了还是规划逻辑断了？论文一概不提，连定性失败案例都没几个。更要命的是 baseline 缺失——没跟任何专门的具身方法（spatial memory、world model、hierarchical planner）对比，无法判断差距来自模型架构还是预训练数据。SE 指标（效率）倒是有点意思，能区分"蒙对的"和"真懂的"，但论文浅尝辄止。数字游戏（魔方、Block3D）的加入更像是凑数——跟真实具身任务能力相关性存疑，isolated geometric reasoning 真能迁移到物理交互？存疑。整篇论文像是个"MLLM 打脸展"，适合刷 citation 但对推进领域价值有限。
- **Rating**: `2` 👀，benchmark 统一协议有工程价值，但分析深度不足以指导下一步改进方向

### OpenSkill
- **Title**: OpenSkill: Open-World Self-Evolution for LLM Agents
- **Institutes**: 无法从摘要页提取（需访问完整 PDF）
- **Source**: [link](https://arxiv.org/abs/2606.06741)  🔥 HF Trending ⬆️ 24
- **核心**: 在开放世界中让 agent 自我进化，不依赖人工标注的 skill 或验证信号。从文档、代码库、网页中提取 grounded knowledge，构建虚拟任务和自建 verifier 来练习和筛选 skill。Skills 可跨模型迁移，verifier 不接触真实答案却能对齐真实结果。在三个 benchmark 和两个 agent 上达到 no-supervision 约束下的最佳 pass rate。
- **锐评**: Idea 有意思——用开放资源自举出 skill + verifier 的闭环，但魔鬼在细节：(1) "grounded knowledge" 和 "verification anchors" 到底怎么抽？如果靠 LLM 从文档里提，噪声和幻觉怎么办？(2) "virtual tasks grounded in anchors" 听起来是自己给自己出题，容易 overfitting 到自己的 anchor 分布上，泛化性存疑。(3) 摘要只说 "best automated pass rate under no-supervision"，没给具体数字，也没说跟 supervised 方法差多少——如果差 20% 那这个 trade-off 不值。(4) "Skills transfer across models without adaptation" 这个 claim 需要看是什么 skill、什么模型，抽象度高的 skill 当然能迁移，这不是贡献。需要看完整实验才能判断是否真有硬核突破。
- **Rating**: `2` 👀 — 方向对（自举很重要），但摘要信息不足以判断方法是否 work，需确认 verifier 质量和 skill 泛化性的实证

### Bayesian-Agent
- **Title**: Bayesian-Agent: Posterior-Guided Skill Evolution for LLM Agent Harnesses
- **Institutes**: Not available from accessible content (authors: Xiaojun Wu, Cehao Yang, Honghao Liu, Xueyuan Lin, Wenjie Zhang, Zhichao Shi, Xuhui Jiang, Chengjin Xu, Jia Li, Jian Guo)
- **Source**: [link](https://arxiv.org/abs/2606.08348) | [code](https://github.com/DataArcTech/Bayesian-Agent)  📰 HF Daily ⬆️ 12
- **核心**: 把 agent 的 skill 和 SOP 当成贝叶斯假设，不再靠 naive 计数决定是否复用，而是基于验证过的轨迹维护 feature-conditioned posterior，然后通过后验状态触发 patch/split/compress/retire/explore 等操作。在 SOP-Bench 上从 80%→95%，Lifelong AgentBench 从 90%→100%，RealFin-Bench 从 45%→65%（用的 DeepSeek-v4-Flash）。声称跨 harness 通用（GenericAgent、mini-swe-agent、Claude Code）。
- **锐评**: **核心 idea 合理但细节成疑**。Bayesian posterior over skills 听起来优雅，但"feature-conditioned categorical posterior"到底 condition 在什么 feature 上？prompt embedding？task 类型？还是简单的 success/failure count + Dirichlet？如果后者，披着贝叶斯外衣的启发式而已。**数字可疑**：Lifelong AgentBench 90%→100% 太完美，SOP-Bench +15% 也很夸张，需要看 baseline 是什么——如果是裸 few-shot 那不算本事。**跨 harness 通用性是亮点**，但没看到在不同 harness 上的 breakdown，可能只是接口层抽象。方法复杂度（12 个公式）vs 收益是否匹配？如果只是 skill selection 优化，为什么不直接 RL 或 BO？
- **Rating**: `2` 👀 — 问题切得准（skill evolution 确实需要 principled 方法），但从摘要看不出比 heuristic reflection + experience replay 本质强在哪，数字好到可疑，需要细读方法和 ablation 才能判断是真 insight 还是工程拼凑

### Hi-VLA
- **Title**: What Matters in Orchestrating Robot Policies: A Systematic Study of Hierarchical VLA Agents
- **Institutes**: Google DeepMind
- **Source**: [link](https://arxiv.org/abs/2606.10267)  📄 arXiv
- **核心**: 用 options framework 统一了层次化 VLA 系统的设计空间，系统性地 ablate 了 VLM planner、VLA controller、终止条件、观测表示、记忆模块。核心发现：VLM 的推理能力（thinking）比尺寸重要，VLA 的可引导性（steerability）比专精化重要，success detector 比 VLM 自判断鲁棒，bounding box 描述能让 VLM 重新看图，跨 episode 记忆有用但 episode 内记忆无用。最佳配置在 long-horizon 任务上比 flat VLA 高 42%，真机 ALOHA 上 12/15 vs 3/15。
- **锐评**: **方法论扎实但缺乏理论深度**。系统性 ablation 做得很工整，但只是 "什么 work" 的实验报告，缺少 "为什么 work" 的洞察——比如 thinking 为何有效、bounding box 为何让 VLM 重新关注图像、in-episode memory 为何反而有害，都只是现象描述。Sim-fine-tuned VLA 在 long-horizon 暴跌到 7.5% 暴露了一个关键问题：专精化会牺牲可引导性，但论文没追问这个 trade-off 的边界在哪、能否通过训练方式缓解。真机实验只有 15 个任务的成功率统计，没有 failure case 分析、没有 latency 数据、没有对 static environment 假设的讨论——作者自己都承认这些是局限但实验里完全没碰。最大的问题是 **novelty claim 不清晰**：options framework 是 2019 年的老框架，把现有系统往里套不算贡献；各个 component 的 ablation 结论（thinking 好、fine-tuning 坏、success detector 鲁棒）在各自子领域都不新鲜，只是第一次在 Hi-VLA 这个组合场景下验证了一遍。78% vs 69% 的提升更多是 "选对了 component" 而非 "设计了新方法"。适合作为 engineering guideline，但作为 research paper 缺少 surprising insight。
- **Rating**: `2` 👀 — 系统性 ablation 有工程价值，但理论深度和 novelty 不足，更像 tech report 而非 insight-driven research

### AgenticNav
- **Title**: AgenticNav: Zero-Shot Vision-and-Language Navigation as a Tool-Calling Harness
- **Institutes**: Shanghai Jiao Tong University, Huawei Technologies Ltd.
- **Source**: [link](https://arxiv.org/abs/2606.10577)  📄 arXiv
- **核心**: 把 zero-shot VLN-CE 重新建模为 VLM 调用工具的过程，抛弃学习的 waypoint predictor，用三个工具暴露能力：(1) Action Tool 让 VLM 直接选图像像素作为目标点，转成可执行动作；(2) Depth Tool 按需查询指定像素的深度值，而非丢整张深度图；(3) Memory Tool 提供轨迹 map image + 选择性召回历史观测，避免塞满 prompt。R2R-CE 上 GPT-5.5 达到 55% SR / 48.41% SPL，比同 backbone 的 SmartWay 高 11/13.37 个点；真机实验 SR 翻倍（46.7% vs 23.3%）。
- **锐评**: **亮点**：Waypoint predictor 确实是个硬瓶颈——学出来的候选点限制 action space，真机 sim-to-real 还会失效。直接选像素 + 安全检查的设计干净，ablation 证明 Action Tool 单独贡献 +5 SR。Depth Tool 的"按需查询"也比喂整张深度图聪明（+13 SR）。真机实验设计诚实，outdoor yard 场景确实比 sim 难，而且明确标注 71.4% 失败来自 VLM 决策错误，不甩锅。**硬伤**：(1) **核心 idea 不够 fundamental**——本质是把 VLM 的 tool-use 能力照搬到 VLN-CE，工程 contribution 大于 insight。Pixel-based action 在 robotics 中不新（PaLM-E、Code-as-Policy 都用过），这里只是把它拿到 VLN-CE benchmark 上刷分。(2) **对比实验有水分**——EvoNav 被标记为"非 episodic zero-shot"排除在外，但它 43% SR 其实比本文的 Gemini-2.5 版本（49%）只差 6 个点，而 EvoNav 用的跨 episode memory 在真机部署时完全可用。把它踢出 leaderboard 显得 defensive。(3) **真机 30 episodes 样本量太小**，SR 从 33.3% 到 46.7% 的提升在统计上不够稳健（单个 episode 占 3.3%），而且没报置信区间。(4) Memory 的 "compact map image" 没细说怎么渲染、VLM 能不能真的看懂，ablation 显示去掉 Recall Tool 只掉 4 个点（51→55），说明这个"选择性召回"的增益有限。**本质问题**：这是个 harness 工程，不是方法论突破。Waypoint predictor 的问题已经在 SmartWay/OpenNav 中被讨论过，AgenticNav 只是换了个更直接的实现，但没回答"为什么 VLM 选像素就比选 waypoint 本质上更优"。失败分析暴露真相：88.9% sim 失败 + 71.4% 真机失败都是 VLM 决策错（不是 harness 的错），说明瓶颈还是在模型推理能力，tool interface 只是把天花板稍微抬高了一点。
- **Rating**: `2` 👀 — 工程扎实，真机实验加分，但 insight 浅，contribution 主要是"把 VLM 的 API 设计得更合理"，不是"理解 VLN-CE 为什么难"或"发现新的导航范式"。发 top-tier 有点勉强，但对实际部署有参考价值。

### SlimSearcher
- **Title**: SlimSearcher: Training Efficiency-Aware Web Agents via Adaptive Reward Gating
- **Institutes**: 未能提取（PDF 解析失败）
- **Source**: [link](https://arxiv.org/abs/2606.07074)  📰 HF Daily ⬆️ 8
- **核心**: 针对 deep research agent 的"暴力搜索"问题（盲目调工具、performative reasoning、冗余轨迹），在 SFT 阶段用 Pareto-efficient filtration 筛选成功且经济的轨迹，在 RL 阶段用 Adaptive Reward Gating 动态评估 cohort 内的相对效率（工具调用数、token 消耗），配合严格的 correctness gate 避免 brevity bias 和 reward hacking。在 GAIA、BrowseComp、XBenchDeepSearch 上减少 17%-58% 的工具调用，同时保持或提升准确率。
- **锐评**: 方向实用——效率是 agent 部署的真问题，但摘要信息太少无法深度评估。Adaptive Reward Gating 的"相对效率"设计理论上能避免绝对惩罚的 brevity trap，但"cohort 内比较"的稳定性存疑：如果 batch 里都是低效样本，相对最优也可能绝对低效。Pareto-efficient filtration 在 SFT 阶段有用，但如果训练数据本身缺乏高效样本，筛选再精也白搭。17%-58% 的 tool-call 减少范围太宽，暗示不同任务的增益差异大，但没细说哪类任务受益最多。最关键的问题：**准确率"保持或提升"是模糊说法**——到底是平均涨了还是某些 benchmark 涨某些跌？如果 GAIA 准确率从 45% 涨到 48%、tool call 少 50%，那是真突破；如果准确率持平、tool call 少 20%，价值就打折扣。
- **Rating**: `2` 👀 — 问题切得对（agent 效率优化被忽视太久），方法听起来合理，但信息不足无法判断实际效果和适用范围

### WebChallenger
- **Title**: WebChallenger: A Reliable and Efficient Generalist Web Agent
- **Institutes**: 未披露（仅 arXiv 预印本，无机构信息）
- **Source**: [link](https://arxiv.org/abs/2606.10423)  📄 arXiv
- **核心**: 提出 PageMem 结构化页面表示 + 三个机制：(1) divide-and-conquer 让 agent 只看相关区域，(2) exploration 系统预遍历网站建地图，(3) compound action 把多步操作封装成一个动作。用开源模型在 WebArena 56.3%、VisualWebArena 48.7%、Mind2Web 51.0%、WorkArena 70.9%，声称逼近闭源系统但成本低得多。
- **锐评**: **数字亮眼但故事可疑**。WebArena 56% 如果用的是 Llama-3 级别开源模型确实不错，但 abstract 连用的什么模型都不说，"off-the-shelf open-weight" 太模糊——是 Qwen2.5-72B 还是 Llama-3.1-8B？成本对比更是空口无凭。PageMem "deterministically constructed from DOM" 听起来就是规则解析 HTML，divide-and-conquer 本质是 hierarchical summarization，exploration 系统要"预遍历网站"——这在真实场景怎么 scale？用户任务来了先花几分钟爬全站？compound action 是把 heuristic 写死，泛化性存疑。最大问题：**没 baseline 对比、没 ablation、没 cost breakdown，全是 claim 没 evidence**。如果全文有扎实实验另说，但 abstract 这么写就是耍流氓。
- **Rating**: `2` 👀 — 数字够格但方法论存疑，等全文 ablation 和 cost 数据再判生死
