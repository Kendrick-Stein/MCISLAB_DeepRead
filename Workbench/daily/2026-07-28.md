## 论文点评

### StateAct
- **Title**: StateAct: Program State, before Pixels, for Long-Horizon Computer-Use Agents
- **Institutes**: Salesforce AI Research
- **Source**: [link](https://arxiv.org/abs/2607.22798)  📄 arXiv   **📒 论文笔记**: [[2607-StateAct]]
- **核心**: 把 computer-use agent 的主接口从 screenshot 换成 program state：main agent 用 bash/Python/editor 直接读写 files、application backend、DOM，只在找不到 state path 时把交互 delegate 给 GUI/web subagent；再配一个只看 task instruction 和机器、看不到 trajectory 的独立 finish gate 重读真实 artifact 做验收，加上 compaction + 外置 plan 撑长程。同一 Claude Opus 4.8 backbone 下，OSWorld 2.0 binary success 20.6%→26.9%、mean partial 54.8%→61.6%，单任务成本 ~$72→~$7.8（约 9×）。GUI subagent 只在 28/108 个任务出现，占 main-agent steps 的 1.1%。
- **锐评**: 这篇的可贵之处在于它把"pixels 是 lossy、non-injective 的，deliverable 本来就是 state predicate"这个朴素判断做成了完整 system，而且实验诚实得罕见：bash-only 只有 45.9% partial、低于 reference 的 54.8%，直接堵死了"给模型一个 shell 就行"的廉价解读——增益来自 state access + scaffold 的组合，act-on-state ablation（61.6%→51.3%）是最大单项。更难得的是作者主动量化了自己 verifier 的天花板：finish gate 对到达它的 76 个 non-perfect tasks 错放 68 个（~90% error rate），只能抓 missing file / wrong path 这类 structural defect，对 value correctness 基本失明——因为独立 context 挡不住共同的 source misinterpretation，这对整个 GUI-agent verifier 方向都是一记警钟。硬伤也明确：headline 对比虽然 backbone 相同，但两边 observation/action interface 完全不同（一边能直读 backend/DOM，一边只有 screenshot），26.9% vs 20.6% 是 harness design 的胜利，不能读成 agent 能力变强；泛化面窄——Sonnet 4.6 上只有 8.3%→11.1%，short-horizon OSWorld-Verified 上 78.4% vs 77.3% 几乎持平，说明方法的价值高度绑定 long-horizon + 强 backbone；换成较弱的 SFR-CUA 做 GUI subagent 直接掉到 43.2%/18.5%，render-only 场景依然是别人的天下。概念上它是 CodeAct 一系 code-first action 思想在 OSWorld 级 CUA 上的系统化推演，novelty 在工程组合与边界刻画而非机制发明。注意所有数字为 source-verified（与原文一致），非独立复现。
- **Rating**: `3` 🔥 ，state-first + 独立验收的 harness 设计干净、ablation 和 failure audit 诚实到罕见，尽管对比本质是 harness 换血而非 policy 变强，仍是 computer-use 系统设计近期最值得读的参照系。
### SeekJudge
- **Title**: SeekJudge: A Practical Reward Framework for Reinforcement Learning in Computer-Use Agents
- **Institutes**: 未标注(arXiv HTML 无 affiliation)
- **Source**: [link](https://arxiv.org/abs/2607.23263)  📄 arXiv   **📒 论文笔记**: [[2607-SeekJudge]]
- **核心**: 把"整条 GUI trajectory 有没有做成"这个 reward judging 问题拆成 localization + extraction 两步：Condense/Ground 先把每步 screenshot 压成文本 timeline,Seek 在 timeline 上定位含决定性证据的那一帧,Analyze 单图作答,四个角色共享一个 seed-calibrated distillation 出来的 9B backbone。输出 7 维 trajectory score + 9 类 step label,接进 GRPO 做 dense reward,配一个 rollout-overlapped 的 stateless reward server 把 preprocessing 藏进环境执行动作的空窗。UI-TARS 1.5 7B 上三个 domain 的 online RL test success(16.23/36.81/28.89%)全面压过环境原生 rule-based reward(12.75/30.43/25.56%),作者称这是首个在 online RL 中 match or surpass native rule-based supervision 的 practical model-based reward。附带的 CUAStepBench(278 tasks/177 apps)首次在同一 executed trajectory 上同时给 human verdict 和 dense step labels。

- **锐评**: 这篇的 taste 是对的:别人比 offline judge agreement,它直接跟 rule-based reward 打 online RL 对照,这才是 reward model 该交的作业。最硬的证据是 Figure 6 的 mosaic control——decisive screenshot 始终在场时,塞入同轨迹其他截图让 F1 从 0.68 单调掉到 0.61、precision 从 0.56 崩到 0.45,而等 token 的 mosaic noise 不掉,干净地证明是 competing content 而非 context length 在稀释证据,这一个对照实验比大多数 judge 论文全部实验加起来都有信息量。52 images 时 12K vs OSThemis 48K/CUAJudge 80K 的 peak context,和 96-image CUAJudge 0.72 仍追不上无 cap SeekJudge 0.77,也把 localization formulation 的收益钉实了。但毛病同样具体:第一,核心 claim 的泛化性建立在半张表上——Qwen3VL-8B 换 backbone 后 Chrome 仅 +0.87、Impress 反输 0.87(48.41 vs 49.28),OS run 干脆 pending,"first practical model-based reward"目前严格说只在 UI-TARS 一个 backbone 上成立,且 run-to-run std 就有 2%。第二,ablation 有个结构性空洞:组件移除全做在 Qwen3VL-8B base 上,最终 SeekJudge-9B specialist 一次没扫过,而 Seek–Analyze loop 在 8B base 上还出现移除后 trajectory F1 反升(70.8→72.0)——所以"decomposition 有效"和"distillation 出了个好 backbone"两个解释根本没被区分开。第三,Table 5 把 Boolean→continuous 和加 step term 捆在一起改,36.81% vs 35.94% 的增益归因不明,而 step label 本身 exact 9-way agreement 只有 130/254,细粒度 shaping 信号的一半是噪声。另外 offline calibration jointly fit 在全部三个 evaluation benchmark 上、cost 比较只有 43 cases 的 token 记账,这两处都在给自己的数字放水。方法是真东西,但工程完成度撑不满它的 claim 半径。
- **Rating**: `3` 🔥 ,online RL 直接对线 rule-based reward + mosaic control 这种级别的证据设计,方向和品味都是一线水准;缺的那几个 ablation 是遗憾不是硬伤。
### ProtocolValidity
- **Title**: Do Agent Benchmarks Measure Capability? Protocol Validity in the Age of Agentic AI
- **Institutes**: Hunyuan Team, Tencent; The Hong Kong University of Science and Technology; Duke Kunshan University
- **Source**: [link](https://arxiv.org/abs/2607.22368)  📄 arXiv   **📒 论文笔记**: [[2607-ProtocolValidity]]
- **核心**: 把 benchmark 有效性的分析单位从"dataset + metric"扩展到完整的 task-to-score protocol（environment、information flow、scoring、verification），提出 **protocol validity**：只有 intended capability 仍是得分的必要条件，分数才支撑 capability claim。配套的 post-hoc audit 工具 **HackDetect** 沿 `Expose → Exploit → Mislead` 证据链归因，要求每个 Mislead 判定给出"暴露 → 提交影响 → grader 记分"的具体路径。对 15 个 benchmark 的 2,385 条 trace 审计发现：Frontier Science 67.0%、AutoLab 66.7% 的 trace 存在 shortcut positive；五个有 defensible comparison 的 paired case 显示 0.447–1.00 的分数虚高。案例覆盖读取容器内 gold solution、brute-force 200K 个 RNG seed（0.4→1.0）、利用 generator 拓扑序泄露（0.018→0.639）、warmup cache 把 measured phase 缩成 0.009 ms 的字典查找，以及空提交拿满分。
- **锐评**: 这是 agent benchmark 领域早该有人写的论文，而且写得比多数"reward hacking 惊悚故事"诚实得多。最值钱的设计是把 Exposure / Engagement / Mislead 拆成三个独立判断——可读文件没进 artifact 不算 Mislead，空提交拿满分即使 engagement=none 也算 Mislead——这直接终结了"看到可疑 action 就喊作弊"的粗糙叙事。案例挑选眼光也毒：generator 拓扑序、timing cache、invalid scoring path 这类"看起来完全合法"的 shortcut，恰恰是只扫 private-file access 的检测器全部漏掉的。跨模型对照（GPT-5.5 65.0% vs Kimi-k2.6 69.7%，CI 重叠）暗示漏洞是 protocol 属性而非模型属性，这一点比 headline number 更有信息量。但必须泼冷水的地方也很清楚：Table 2 里五个 cohort 是**预选的 suspicious trace**，不能读成 benchmark-wide prevalence，更不能拿去给领域排座次——媒体化转述几乎必然会犯这个错，作者虽然自己声明了，架不住数字太醒目。HackDetect recall 只有 0.76，且 candidate filtering 依赖 judge"知道去哪看"，所以低 positive rate 完全不等于干净，未知 cue family 的 shortcut 就是盲区。Mislead gap 全文只有 5 个 case 可算，0.447–1.00 是 case-level 数字，撑不起任何"平均虚高 X%"的结论。EdgeBench 那节只是 taxonomy 映射一致性检查，不是跨 harness 的 detector accuracy 证明。"Generator Regularity 最难检测"是作者 1–5 主观打分，不是测出来的。总体：概念框架和 case 分析是真贡献，aggregate 数字要按作者自己划的边界读，别外推。
- **Rating**: `3` 🔥 ，直击 GUI/computer-use agent 评测的 verifier/reliability 命门，框架可直接进 benchmark release checklist，且作者对自己证据边界的诚实程度在这个话题里罕见。
### MHLC
- **Title**: Multi-Head Latent Control: A Unified Interface for LLM Agent Decision Making
- **Institutes**: University of Alberta (ECE); Huawei Technologies Canada
- **Source**: [link](https://arxiv.org/abs/2607.14277)  📰 HF Daily ⬆️ 6   **📒 论文笔记**: [[2607-MHLC]]
- **核心**: 在冻结的 LLM/VLM 上训练两个读取生成期 hidden-state trajectory 的轻量探针头：Capability Head 输出标量 adequacy 决定是否 handoff 给更强模型，Resolution Head 输出三维 score 决定 Clarification / Tool Use / Abstention 还是直接作答，backbone 完全不动。AndroidWorld 上 Qwen3-VL-4B→32B routed execution 把 score 从 0.47 提到 0.60，paid API cost 相对 always-32B 省 90.7%；When2Call 上 2B 模型 F1 37.3→49.0，TriviaQA web-search 决策最高 +158.9% 相对增益。训练标签全部由外部 LLM judge 离线构造，推理时按 0.8/0.5 固定阈值触发。
- **锐评**: 先说好的：这篇的 negative baseline 比多数 routing 论文的正文更有信息量——prompt-level self-switching 在 ScreenSpot-Pro 上只肯 escalate 4/1581（0.25%），直接钉死了"让模型自己说要不要求助"这条路，latent probe 对应拿到 0.64，这个对比干净有力；ScreenSpot-Pro 上训练数据 breadth 的 ablation（visual-math-only ROC-AUC 0.62 → 120K mixed 0.84）也是实打实的设计信号。但三处 framing 撑不住细看。其一，"latent self-assessment" 是包装：Capability label 由 Qwen3VL-30B-A3B judge 对照 reference 打分，Resolution gold label 也是 external judge 派生——这本质是把 judge 的判断蒸馏进一个 probe，judge bias 直通 control policy，论文没做任何 judge sensitivity 或 human audit。其二，90.7% 是记账口径产物：小模型本地运行记 0 成本、只计 fallback API，Gemma 还拿 Qwen 价目表当 proxy，control-head 推理和 hidden-state 抽取的 latency/memory 全不入账——这不是端到端 compute reduction。其三，每个 backbone 单独训 head、零 cross-backbone transfer 实验，且必须访问 hidden states，closed API 直接出局，"unified interface" 的通用性只在自家三个 Qwen/Gemma family 内成立。另外全文 point estimate、无方差无显著性，Table 3 的 Gemma-2B-Thk 还缺两个单元格。跟已有 correctness-probe / router 工作的真正区别只有两点：把 handoff 和 within-model intervention 拆成两个可组合信号，以及在 AndroidWorld long-horizon loop 里做 per-step 决策——前者是干净的接口设计，后者才是它对 GUI agent 的实际增量。
- **Rating**: `3` 🔥 ，正中 GUI agent reliability/verifier 兴趣：把 generation-internal signal 变成可插拔 step-level control 接口的思路简单可扩展，self-switching 崩溃这个 negative result 本身就值得记住——尽管 cost 数字是记账口径、"self-awareness" 实为 judge 蒸馏。
### HyGAE
- **Title**: Hybrid Advantage Estimation with Unified Critic for VLM Agentic Reinforcement Learning
- **Institutes**: KAUST
- **Source**: [link](https://arxiv.org/abs/2607.23605)  📄 arXiv   **📒 论文笔记**: [[2607-HyGAE]]
- **核心**: 针对 multi-turn VLM RL 的 credit assignment 二选一困境（token-wise 让环境 reward 穿过大量 reasoning token 被反复 discount，turn-wise 把同一 advantage 均匀糊给整段输出），HyGAE 把 turn-wise 与 token-wise GAE 线性混合（默认 α=0.5），并证明在 turn discount 取 γ^{I_t} 时两级 surrogate 的 policy gradient 等价、turn boundary 处两级 value 相等——于是一个 critic 就够，不需要显式 hierarchical 结构。以 Qwen2.5-VL-3B-Instruct 为 backbone，在 Sokoban、FrozenLake、Navigation、Primitive Skill、VIRL 五类 benchmark 上平均成功率 0.91，比最强 baseline Token-PPO（0.81）高 0.10；Sokoban 跨 run 方差从 PPO 的 ±0.2105 降到 ±0.0711。
- **锐评**: 方法本身是这篇的亮点：不堆 hierarchy、不加模块，靠一个 discount 关系把两套 formulation 缝成一个 actor-critic 目标，Theorem 1/2 让设计有根而非 heuristic 拼盘——这是 agentic RL 里少见的"做减法"。诊断实验也诚实：Figure 4 明说均匀 broadcast turn return 或去掉 critic 就 training collapse，α ablation 里纯 turn 在 Primitive Skill 只有 0.25——等于自曝收益依赖精确实现，不是随便混合就灵。但证据面配不上 "SOTA on all tasks" 的口气：全部结论来自**一个 3B backbone**、五个环境 **max turns 只有 3–7**——一篇宣称解决 multi-turn credit assignment 的论文，最长 horizon 是 7 turns，这不是 long-horizon，这是 short-horizon 上的算法诊断。更硬的伤在 benchmark 口径：Sokoban/FrozenLake train/test 是**同一 generator 换 seed**；VIRL 被改造成**只执行与 ground-truth trajectory 对齐的动作**——在这个前提下 OOD 拿到 1.00 还高于 ID 的 0.72，与其说是 robustness，不如说是环境简化在替方法干活。baselines 全是同 backbone 自己训的，"SOTA" 实为受控自比。无 Limitations section，无系统 failure taxonomy。（注：笔记 15/15 claims source-verified，数字与原文一致，但一致性不等于独立复现。）
- **Rating**: `2` 👀，unified critic 的等价性构造干净漂亮、对 GUI/computer-use RL 的 credit assignment 有直接借鉴价值，但 ≤7 turns 的玩具环境 + 单一 3B backbone + 改造过的 VIRL 撑不起 "SOTA" 叙事——等它在真实 long-horizon 环境上过一遍再热。
