# 🔪 今日总结

VLA 领域迎来密集发布季：边缘部署（RhinoVLA 11.69 Hz）、action-token planning（Coarse-to-Control）、LAM-VLA 联合优化（LARA）、自适应多模态推理（AdaWAM）齐头并进，NVIDIA 的 Cosmos 3 则试图用单一 omnimodal 框架统一 Physical AI 全栈。GRAIL 展示了 3D assets + VFM 生成 humanoid 数据的新路径。方法上各有巧思，但普遍存在真机验证薄弱、failure case 分析缺失的问题——研究节奏快过验证深度。

## 论文点评

### Cosmos 3
- **Title**: Cosmos 3: Omnimodal World Models for Physical AI
- **Institutes**: NVIDIA
- **Source**: [link](https://arxiv.org/abs/2606.02800)  🔥 HF Trending ⬆️ 93   **📒 论文笔记**: 2606-Cosmos3
- **核心**: NVIDIA 用 mixture-of-transformers 架构做全模态世界模型，统一语言/图像/视频/音频/动作五种模态，把 VLM、视频生成、world simulator 和 world-action model 塞进一个框架。在开源 Text-to-Image/Image-to-Video 上拿下 Artificial Analysis 榜首，RoboArena policy 性能也是开源最佳。
- **锐评**: 291 位作者，这规模已经不是做研究而是堆工程了。"统一架构"听着美好，但 MoT 如何设计 expert routing、各模态怎么共享参数、推理效率几何，abstract 里一个字没提——典型的大厂 paper：结果亮眼，细节藏着掖着。RoboArena 是单一仿真 benchmark，sim-to-real gap 怎么解决？真实机器人上跑过吗？没说。跟 Sora、Runway 这些顶级生成模型对比了吗？没有。跟 OpenVLA、π0 这些开源 VLA 的细粒度对比呢？也没有。只说"开源最佳"，但不说跟闭源差多少、在哪些场景会崩。工程价值认可，但科学价值存疑——这更像是 NVIDIA 的产品发布而非研究突破。
- **Rating**: `2` 👀 工程完整度高、开源诚意足，但缺少关键技术细节和 failure case 分析，更像产品 demo 而非可复现的研究

### GRAIL
- **Title**: GRAIL: Generating Humanoid Loco-Manipulation from 3D Assets and Video Priors
- **Institutes**: NVIDIA Research, University of Toronto, UC Los Angeles, University of Texas at Austin
- **Source**: [link](https://arxiv.org/abs/2606.05160)  🔥 HF Trending ⬆️ 7   **📒 论文笔记**: [[2606-GRAIL]]
- **核心**: 先构建完整 3D 场景配置（物体几何、相机参数、metric scale 全已知），再调用 video foundation model 生成 human-object 交互视频，通过 metric-aware 重建（MoGe-2 深度 + VLM 接触标签联合优化）恢复 4D 交互轨迹，retarget 到 Unitree G1 humanoid 训练 object-aware latent adaptor 和 scene-aware tracker，最终在真机上实现 84% 物体抓取成功率和 90% 爬楼梯成功率。生成 20,000+ 序列，tracking success rate 88.9% 完爆 baseline 的 24.0%。
- **锐评**: 核心 insight "先 3D 后 video" 设计精巧，彻底绕过野外视频重建的深度歧义死结，这是真正解决问题而非打补丁。工程完整度高，L_depth、L_cont、relative observations 等细节都有 ablation 支撑，不是堆砌黑盒。但依赖性是硬伤：需要 3D assets、simulator-ready scenes、cooperative VFM 三样缺一不可，failure filtering 丢了多少数据语焉不详（"non-trivial fraction" 是多少？30%？50%？）。更致命的是 "task-general" 名不副实——移除 SONIC 预训练 controller 后 SR 从 81.4% 暴跌到 45%，"motion family 变化显著时仍需 training/fine-tuning" 说明根本没做到真正的 generalist policy，只是在预训练基座上微调特定任务族。Real-world 评估偷懒：whole-body manipulation 和 sitting 都没真机结果，只测了 pick-up 和 stair-climbing 各 10 个物体，这点评估量配不上 20,000+ 序列的数据规模。VFM 是黑盒赌博，user study 显示 25.3% 的人觉得 affordance realism 不如 baseline，说明生成质量天花板被 Kling 锁死。
- **Rating**: `3` 🔥，方法有洞察、工程扎实、真机效果不错，但 task generality 过度宣传 + 依赖性强 + 评估不够全面，限制了实际影响力

### RhinoVLA
- **Title**: RhinoVLA Technical Report
- **Institutes**: Huixi Intelligence
- **Source**: [link](http://arxiv.org/abs/2606.07383v1)  📄 arXiv   **📒 论文笔记**: [[2606-RhinoVLA]]
- **核心**: 边缘芯片实时 VLA 部署的首次完整实现。用 token-efficient Qwen3-VL backbone（64 vs 256 visual tokens，4× 减少）+ 72D 统一物理槽位空间（通过二值掩码对齐异构机器人）+ robot-instance LoRA（可合并部署）实现跨机器人学习，配合 Huixi R1 芯片的算法-硬件协同优化（W8A16 混合精度、算子融合、并行视觉编码）达到 11.69 Hz 端到端推理（85.54 ms），LIBERO 平均 90.0%，Long suite 82.4% 超越 π₀ 9.4 个点。
- **锐评**: 这是边缘 VLA 的第一个能打的 baseline，算法-系统协同设计清晰：roofline analysis 找到 MLP projection 占 74.7% 延迟 → token reduction 降 4× → 混合精度和算子融合拿到 2× 加速，每步都有性能拆解支撑。72D 槽位空间 + instance LoRA 的设计优雅，LoRA 可合并是工程实用细节。但硬伤也明显：（1）真机实验弱到可疑——AgiBot G2 三步序列 seen 设定下仅 58% SR 暴露严重问题却不分析，Galbot G1 的红包任务过于简单（single-arm pick-and-place）撑不起 cross-embodiment 泛化的 claim；（2）与 π₀.₅ 的 6.9 个点差距来自哪里？token reduction 的代价、训练数据差异、还是 flow-matching vs diffusion？没有 controlled ablation；（3）72D 固定槽位对 humanoid + parallel gripper 友好，但如何扩展到 soft manipulator、quadruped 等非标形态？预留 11 个辅助槽位够吗？论文不讨论；（4）深度绑定 Huixi R1（SPM tiling、SIMT 调度）的优化迁移到 Jetson、Rockchip 成本未知——这是 technical report 而非 generalizable method。LIBERO 90.0% 和 11.69 Hz 的数字亮眼，但真机 58% SR 和缺失的 ablation 暴露这更像 "能跑的 demo" 而非 "理解清楚的方法"。
- **Rating**: `3` 🔥，边缘 VLA 部署的首个完整实现，11.69 Hz + LIBERO 90.0% 证明可行性，算法-硬件协同设计对后续工作有参考价值，但真机实验薄弱、关键 ablation 缺失、硬件绑定风险限制了方法的 generalizability

### Coarse-to-Control
- **Title**: Coarse-to-Control: Action-Token Planning for Vision-Language-Action Models
- **Institutes**: 未披露（12 位作者来自多个机构）
- **Source**: [link](http://arxiv.org/abs/2606.07107v1)  📄 arXiv   **📒 论文笔记**: [[2606-CoarseToControl]]
- **核心**: 把 planning 原生嵌入 action token space——先预测粗粒度的 coarse action tokens 作为未来轨迹计划，再基于该计划生成可执行 tokens。Planning 和 execution 共享统一的离散词表，通过 dual-granularity joint tokenizer 实现。LIBERO 达到 97.9%，SimplerEnv 83.3%，真实机器人 62.5%，长时域任务提升显著且比 visual CoT 快 3 倍。
- **锐评**: 这个 idea 漂亮——直接在 motor space 做规划，绕过了 textual/visual CoT 那套 semantic-to-motor 转换的损耗，joint tokenizer 让 plan 真正"说机器人听得懂的话"。Ablation 扎实，从 planning horizon 到 tokenizer 设计到跨域迁移都有数据支撑，joint-mode 比 separate 多赚 1.3% 说明共享词表不是玄学。但坦白讲，这更像是打开了一扇门而非走完了全程：coarse action 就是粗暴求和+末态 gripper，螺旋运动、多段式操作怎么压缩？没说。Plan 是 one-shot 吐出来的，执行失败了能 re-plan 吗？不能。真实世界 62.5% 勉强及格，单阶段任务反而输给不带 plan 的 baseline，说明 planning overhead 在简单场景是负担。SimplerEnv 的 Put Eggplant 只有 58.3%，论文连个 failure case 分析都没给——要么是 object property 特殊，要么是 demo 分布有坑，总之这种选择性失明让人不爽。Insight 值 4 分，但离"解决问题"还远着。
- **Rating**: `3` 🔥，核心 insight（action-space planning + joint tokenizer）足够 sharp，但方法实现和真实世界泛化都还在起点

### LARA
- **Title**: LARA: Latent Action Representation Alignment for Vision-Language-Action Models
- **Institutes**: (未在 arXiv 页面列出)
- **Source**: [link](http://arxiv.org/abs/2606.07100v1)  📄 arXiv   **📒 论文笔记**: [[2606-LARA]]
- **核心**: 通过表示对齐联合优化 Latent Action Model 和 VLA，让 LAM 从真实动作轨迹中学到控制相关的视觉变化（而非背景光照），同时用 LAM 的 forward dynamics 约束 VLA，避免生成"运动学合理但功能错误"的动作幻觉。在 LIBERO 上比 OpenVLA 提升 12.1%，长时序任务（LIBERO-Long）暴涨 32.3%，真实 G1 人形机器人上达到 76% 成功率。
- **锐评**: 双向正则化机制清晰有说服力，实验覆盖 4 个 benchmark + 真实机器人且一致有效，即插即用设计实用性强。但实验规模受限于"计算限制"仅用 OXE 子集，与 full-scale 预训练模型（UniVLA 95.2%）仍有 gap——这不是方法问题，是资源问题，但论文标题和 claim 没有强调这一点，容易让人误以为已做充分验证。最优对齐深度因架构而异（GR00T 用 L−2，π0.5 用 L）却无启发式规则，ablation 只测了 4 个深度就收手。LAM refinement 那 +15.7% 很亮眼，但对比基线只有 baseline LAM，缺少其他 VQ-based 方法对比，说服力打折。另外完全没报告失败案例——哪些任务 LARA 反而变差？对齐失败时 LAM 表示会不会崩塌？这些关键问题被回避了。方法本身是好的，但验证不够狠，像是"concept 验证"而非"production-ready"。
- **Rating**: `3` 🔥 思路扎实、即插即用有价值，但实验规模受限、失败分析缺失，属于"好的起点"而非"决定性进展"

### AdaWAM
- **Title**: Dreaming when Necessary: Advancing World Action Models with Adaptive Multi-Modal Reasoning
- **Institutes**: 未明确标注（从作者名推测可能是清华/字节等国内团队）
- **Source**: [link](http://arxiv.org/abs/2606.07089v1)  📄 arXiv   **📒 论文笔记**: [[2606-AdaWAM]]
- **核心**: 用轻量级动态路由器按需触发文本推理（任务转换时）或视觉推理（精细操作时），而非全程生成视频或全程语言 CoT。LIBERO-Long 99.1%，RoboTwin hard 任务 88.43%，组合泛化 61% vs. Fast-WAM 0%，真实 ALOHA 上 Clean Up Trash 70%。
- **锐评**: 动机站得住——不同阶段确实该用不同推理模式，动态路由比"一刀切"聪明。**但路由器监督靠启发式规则（任务阶段+接触密集指标）打标签，这是工程 workaround 不是 principled solution**。作者提 RL 优化但没做，说明也知道这是坑。HangingMug 59% vs. 58% 这种"改进"在误差范围内，StackBowlsThree 100 vs. 80 亮眼但缺少置信区间。**组合泛化 61% 是真亮点**，证明文本推理不只是装饰。真实世界 70%/60% 有说服力，但**没展示失败案例、没细粒度推理延迟分析、RGB-only 的空间推理瓶颈作者自己都承认**。整体思路对，但实现还是半自动化——路由器学不会自己找推理边界，scaling 到更多任务类型时标注成本会爆炸。
- **Rating**: `3` 🔥，动机清晰、组合泛化和真实验证加分，但路由器监督依赖人工规则是硬伤，离"自适应推理"的理想态还有距离
