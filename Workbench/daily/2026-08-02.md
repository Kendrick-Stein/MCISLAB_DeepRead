# 🔪 今日总结

今天最值得读的两篇都在讲"测量"而不是"提升"：Kimi K3 把 3T-class 开放权重推到第三方榜单可验证的位置，OSReward 则用 1019 条 fresh human-gold 轨迹证明 CUA 的 VLM judge 系统性偏宽松、且视觉输入的影响低于重采样噪声地板——后者直接否掉了"多塞截图 + 多模型投票"这套 reward 设计默认。另一条主线是三篇不同方向的"删中枢"尝试（TurboVLA 删 LLM、PhiZero 用离散码替像素、AAPT 把 decode 挪出 critical path），三篇的问题重构都比它们的证据强：决定性 ablation 集体缺席，主战场多为自建 benchmark。今日无一篇给出"同数据同算力对照"，这本身就是个信号。

### Kimi K3
- **Title**: Kimi K3: Open Frontier Intelligence
- **Institutes**: Moonshot AI
- **Source**: [link](https://arxiv.org/abs/2607.24653)  🔥 HF Trending ⬆️ 427   **📒 论文笔记**: [[2607-KimiK3]]
- **核心**: 首个开放权重的 3T-class 模型——2.8T 总参 / 104B 激活的 native multimodal MoE，1M context。架构在序列、深度、宽度三个维度各做一件事：KDA 线性注意力（3:1 混合 Gated MLA，全程 NoPE）、Attention Residuals（层间用 attention 取代均匀残差累加）、Stable LatentMoE（896 routed expert 激活 16，sparsity 56）。Post-training 在 3 域 × 3 档 reasoning effort 上训 9 个 teacher，再用 Multi-Teacher On-Policy Distillation 合回单模型，全程 MXFP4/MXFP8 QAT 让 rollout 与 training 共享量化方案。结果是整体落后 Claude Fable 5 与 GPT-5.6 Sol、稳定压过其余开闭源；第三方侧 Artificial Analysis Index 57.1 排 580 中第 4，WebDev Arena 1,678 Elo 第 1/99，是首个登顶该榜的开放模型。
- **锐评**: 这是一份罕见地"该被认真读"的技术报告，也是一份该被逐条打折扣的技术报告。**先说真货**：KDA 的 lower-bounded decay 是全篇最漂亮的一处——把 log-decay 从无界 negative-Softplus 换成 scaled sigmoid（$g_{\min}=-5$），只为让 16-token tile 的累积 decay 落进 BF16 动态范围，于是对角 tile 也能吃 Tensor Core，一行公式改动消掉 intra-chunk 瓶颈。这才叫 simple & scalable。MoonEP 的 $E/R$ 冗余专家上界（存在性 + 基本紧）把负载均衡从调参变成有保证的规划，静态 shape 顺带消掉逐层 host 同步；KCP 用一次固定 all-gather + prefix scan 绕过 delta-rule 不可直接求和的障碍；hybrid prefix cache 把 hash 粒度与物理块粒度解耦。这几块都开源了，价值在实现里，比正文有用。**再说该骂的**：那个"2.5× scaling efficiency"是全文最响的数字，也是最不可核验的数字——作者自己写明是 architecture + data + training 一起变出来的，零逐组件 ablation，而全文（Ledger C26 明确核过）不披露预训练 token 总量、总 FLOPs、GPU-hours，Fig. 7 两条拟合曲线也没给拟合区间与方法。这只是厂商自报的聚合指标，谁都别拿它去指导自己的架构选择。主表的可比性有三道裂缝：每个模型跑各自 harness（K3/Kimi Code、GPT/Codex、Claude/Claude Code），harness 与模型耦合根本拆不开；最亮眼的"SWE-Marathon 42.0 领先 Fable 5 七分"，对手在 35% 的任务上触发了 fallback——对照组自己瘸着；SWE-Marathon 还是作者按 H20 自己重标定的分支，不是官方 v1.1。更讽刺的是 BrowseComp 91.2 用了 300K 触发的 context compaction，而真用满 1M、不做 context 管理时掉到 90.4——论文的头号卖点是 1M context，可在自己的旗舰 agentic 榜上，1M 是靠砍掉才拿的分，这个对比被放在配置说明里而不是正文。内部 bench 承担了过多结论：Swarm Bench / Deep Research Bench / Kimi Webdev Bench 全是 in-house 且"frequently refreshed"，而 RL 环境里恰好就有 web development、deep research、personal assistant 任务，训练-评测同源风险摆在明面上；Webdev Bench 那个 +31.0 盲评净胜是打 Opus 4.8 而不是 Fable 5，挑对手挑得很有分寸。薄弱面倒是诚实报了（CritPt 23.4 vs GPT-5.6 Sol 32.3、HLE 有无工具全落后、Agent Behavior Bench 65.0 vs 76.4），但一句"research-level reasoning remains a key direction"就完事，没有 failure mode 分析——反倒是 cyber 那节给出了四类长程失效模式（收尾无法从 primitive 完成 exploit chain、mitigation 下策略选择差、无效 debug 死循环、提交前验证不足），这四条明显是通用的 long-horizon agent 病症，作者却没把它接回 coding/agentic 的分析。**最该展开却最短的是 cyber**：开放权重的模型在真实代码库上找出 16 个此前未知漏洞（含 Linux kernel 远程可触发堆越界写、RDMA 子系统的 Dirty-COW 类提权原语），Tier 2 exploit 14/36 vs GLM-5.2 8/36——唯一基线是 GLM-5.2，因为 Anthropic/OpenAI 模型拒答；缓和证据是 UK AISI + NIST CAISI 联评在 41 个任务上任意代码执行 0 次。但 47 页里 case study 独占一节（"48 小时自主设计推理芯片"这类零对照展示），却没有一节 Limitations、没有一段 release 决策论证，这是实质性缺口而不是排版问题。另外 AttnRes 是全篇最可能被别人复用的想法（把 Transformer 替代序列 recurrence 的方法论搬到深度维，Block 版把 $O(Ld)$ 压到 $O(Nd)$），但它的完整 ablation 在一篇只标"Kimi Team, Preprint 2026"、无 arXiv 编号的引用里——本文里这条贡献同样不可审计。同一团队两代之间推翻 SigLIP 初始化（K2.5 的 MoonViT-3D 正是 SigLIP-SO-400M init）是有价值的信号，但证据只有一条梯度范数曲线加一句"matches across vision evaluations"，没给对照分数，结论强度大于证据强度。**对我们的方向**：K2.5 的 OSWorld-Verified 63.3 到 K3 的 84.8（Fable 5 85.0）只隔了几个月，可 OSWorld 2.0 上 58.3 vs 66.1 差距反而拉开——开放模型在"短程可验证 computer-use"上已经追平，瓶颈整体迁移到长程、状态依赖强的真实桌面任务，这是 GUI Agent 该重新对焦的地方。
- **Rating**: `3` 🔥 ，2.5× 与主表都该打折，但"3T-class 开放权重 + 可复用的 KDA/MoonEP/AgentENV 实现 + 第三方独立榜单佐证"这三件事共同抬高了整个开源生态的天花板，是会改变别人做什么的那类工作。

### OSReward
- **Title**: OSReward: Instituting Standardized Evaluation for Cross-Platform Computer-Use Reward Models
- **Institutes**: The University of Hong Kong, Nanjing University, National University of Singapore, USTC, Xi'an Jiaotong University, University of Oxford, Fudan University
- **Source**: [link](http://arxiv.org/abs/2607.28609)  📄 arXiv   **📒 论文笔记**: [[2607-OSReward]]
- **核心**: 作者拒绝复用现成 benchmark 的轨迹，从环境层重建了四平台（web/Windows/Ubuntu/Android）的指令与 rollout，用 3 人独立标注 + senior 审议裁定产出 1019 条 gold trajectory（Krippendorff α=0.797），专门去量化「VLM-as-judge 到底可不可靠」。结论是天花板比业界默认低得多：全集最高 Claude-Opus-4-8 89.7%，困难子集 OSReward-Hard 上最佳只剩 69.7%、均值 52%，且几乎所有 judge 共享同一个错误方向——把 agent 自称完成实则失败的 run 判成 success，over-accept 占全部错误约三分之二且是每个 judge 的首要错误模式。最有价值的是机制归因：去掉每步 thought+action 文本掉 7.2pp、翻转 22.7% 判定，而三种视觉侧改动（少给帧、去点击 marker）accuracy 变化都在 0.5pp 以内——judge 其实主要在读 agent 的自述，不是在读屏。作者据此训了开源 OS-Shepherd-9B/35B，9B 达全集 86.1% / Hard 60.2%，判完全集一次 \$1.36 对 Opus-4-8 的 \$86.04。
- **锐评**: 先说好的，因为这篇的好是硬的。**证据链是闭合的，不是靠叙述串起来的**：「judge 偏宽松」有错误分类支撑（2/3 占比、每个模型 ≥48%），「因为它读文本多于读屏」有 ablation 支撑，而且作者聪明地测了判决噪声地板——同一 judge 同一输入在 T=0.7 重采样已翻转 6–9% 判定，视觉 ablation 的 <0.5pp 抖动**落在噪声地板之内**。也就是说不是「视觉贡献小」，是「视觉贡献测不出来」。这个数字应该让所有还在往 judge 里塞更多截图的人停一停。第二条负面结论同样值钱：top judge 之间 Cohen's κ≈0.71，同家族 0.731 vs 跨家族 0.709，**家族先验几乎不起作用**，所以 top-3 majority vote 只买到约 1pp 而成本翻倍——「多模型投票提升 reward 可靠性」这个业界标配做法在 CUA 上基本无效。但 oracle 能到 99.2%，池子里几乎总有正确答案，缺的是路由。这是把「集成」问题干净地重述成「选择」问题，比排行榜有用得多。
  **最大的硬伤：全篇没有一个下游实验。** 没有把 OS-Shepherd 真接进 RL 或 rejection sampling 去训一个 policy，「30–60× 降本」是一次假想 51,200 次调用的 API 等价外推，不是实测收益。放在半年前这还能算领域惯例，但同月的 InteractiveRewardAgent（2607.25904）已经用自家 reward 训到 OSWorld 34.0% 对 script reward 34.9%，SeekJudge（2607.23263）在三个 domain 的 online RL 上都压过 rule-based——这条线已经有人跑通了，OSReward 停在 offline agreement 就显得是主动回避。更刺眼的是**它自己刨出了 reward hacking 的完美靶子却不去打**：一个被证明系统性偏宽松、且主要读 agent 自述的 judge 拿去做 RL reward，policy 最省力的梯度方向就是「把成功宣言写得更可信」。这个实验是论文第 5 节亲手递到作者面前的，没做。
  **循环论证：benchmark 层面基本干净，训练标签层面不干净且未被讨论。** 干净的证据很实在——OS-Shepherd 与 27 个 baseline 跑完全相同协议，训练指令与 benchmark 指令做了 cosine>0.8 污染筛，最关键是**它压根没夺冠**：86.1% 中游，落后 Opus-4-8 三点六，主张的是性价比不是最强；三个外部 benchmark 完全没参与训练而去偏依然迁移（OSWorld fail recall 0.46 vs Qwen 系中位数 0.24）。不干净的地方在供应链：OS-Shepherd-100K 的标签来自「多个强 judge 高一致性」筛选，而这些强 judge**正是本 benchmark 证明共享同一 leniency 方向的那批模型**。作者靠「只留近乎无异议的、丢掉模糊带」规避，但被一致接受的 false success 恰恰是这种筛选最抓不住的一类——它们看起来就像 success。RL 阶段用「greedy 判错、重采样能判对」挖 false success 算是部分对冲，但那仍受限于 SFT 模型已有的潜在能力，变不出标注者才有的判据。**OS-Shepherd 的上限被它的标注 ensemble 的上限锁住，论文对此一字未提。**
  另外三个引用时必须留神的边界。其一，**协议过窄导致结论被过度泛化**：全场 27 个 judge 统一吃 last-5 帧 + 无工具 + 无 step 监督，论文自己在 §7 给出 OSWorld 超过 16 步 accuracy 0.76→0.57、假阳率 0.20→0.37 的数据——这直接说明窗口而非模型是绑定约束。所以标题级 claim 应该是「被动、定窗、无工具的 judge 不可靠」，不是「VLM-as-judge 不可靠」；IRA 的 environment-state 主动核验路线正好证明这个瓶颈可绕。其二，**从未与同名同类的专用 reward model 打过分**：Web-Shepherd / GUI-Shepherd / OS-Themis / CUARewardBench 只在 Table 10 里比了数据来源和发布物。取名 OS-Shepherd 却全程不和 Web-Shepherd 跑同一条轨迹，这个选择很难说是无意的。其三，「Hard 最佳 69.7% 恰好等于恒判 fail 的常数判别器」这句 punchline 修辞冲击力满分但是构造出来的——30/70 分布是作者刻意选来放大 leniency 的，作者在 §4.4 自己就点破 raw accuracy 是陷阱、要看 BalAcc（Opus-4-8 69.7 vs 常数 50.0 仍有差距），引用时别只搬那半句。最后，一篇立论是「诚实测量」的论文**没有 Limitations 章节**，有点讽刺。
- **Rating**: `3` 🔥 ，下游实验缺席是真缺口，但「视觉输入的影响低于重采样噪声地板」和「judge 同质导致 ensembling 无效」这两条负面结论足以改变 CUA reward 的设计默认，且 benchmark + 100K 语料 + checkpoint 全开放，大概率成为该方向的默认基座。

### Frontis-MA1
- **Title**: Frontis-MA1: Training an AI4AI Model towards Recursive Self-Improvement in Machine Learning Engineering
- **Institutes**: Frontis.AI (Horizon Research), Tsinghua University, Zhejiang University, Shanghai Jiao Tong University, Georgia Institute of Technology
- **Source**: [link](https://arxiv.org/abs/2607.28568)  🔥 HF Trending ⬆️ 162   **📒 论文笔记**: [[2607-FrontisMA1]]
- **核心**: 把 MLE agent 的三层——可执行任务环境（OpenMLE-Gym，5,758 个 quality-gated 任务）、算子级 post-training（SFT 26,259 例 + GSPO RL，训 Draft/Improve/Debug/Crossover 四个原子 program-transformation）、长程演化搜索（OpenMLE-Evo）——串成一个栈，训出 35B 的 Frontis-MA1。同一 harness 下 MLE-Bench Lite Medal Average 从 base 的 39.39% 提到 60.61%，叠加 Evo-Max 到 71.21%，30B backbone 上复现同样趋势（34.85→53.03→66.67）。搜索侧同 checkpoint 同 seed 对比原版 AIRA-Evo，总 token 降 41.7% 而评估节点只降 12.4%，每百万 token 的 new-best 从 1.77 升到 3.27。预算是 12h / 单卡 4090 限 12GB VRAM，比榜上多数 24h × A100/H200 的对照苛刻得多。标题里的 recursive self-improvement 是纲领不是结果——作者在 Related Work 和 Limitations 里明说不 claim 实现了 RSI，演化系统本身"largely fixed"，全文只到 generation 1。
- **锐评**: 先说真货：把监督单位从整条 trajectory 下沉到四个可复用算子，是这篇唯一能跨域搬走的设计——训完整轨迹等于把模型焊死在某个 controller 的搜索策略上，训算子则让 post-training 和 inference-time search 共享同一个接口，这个抽象层次的选择跟 MLE 本身没关系，GUI agent 和 long-horizon tool use 该直接抄。reward 侧的 adaptive bounds + entropic advantage 同样是针对"指标异构、绝大多数候选无效、只有最好那个算数"这一类问题结构的正经设计，不是刷分补丁。两条正交对照（固定 harness 换模型 / 固定模型换 harness）都跑了，MLE-Bench 重叠竞赛在建库期就排除、Evo-Max 先验蒸馏前也排除 MLE-Bench 来源，污染控制是显式的，比同类技术报告干净。
  然后是账要算清楚的部分。**标题欠债**：真正的递归意味着产物反过来改进产生它的过程，这里的闭环只到"用第一轮演化搜索的轨迹离线训一次模型，再把模型放回同一个搜索器"，是单次 meta-evolution。需要说明的是，"搜索期不更新权重"是笔记从 RL initialization 配置与"同一个 Frontis-MA1-35B checkpoint"的实验标注**推出的间接结论，作者并未直接陈述**；但"演化系统本身 largely fixed"和"不 claim 实现 RSI"是作者原文，边界他自己划了——所以这笔账该记在标题和 abstract 的措辞上，HF 上那 162 的热度里有相当一部分是标题红利，不是内容红利。
  **真正的硬伤是归因**：SFT teacher 是 GLM-4.7，evolutionary path 的轨迹也是 GLM-4.7 跑 AIRA-Evo 产的，trajectory-step 筛选还靠 DeepSeek-V4-Pro 标注。那 21.22 个点里"执行反馈接地的学习"和"蒸馏一个更强模型的 MLE 习惯"完全没分开，论文里没有任何实验能回答。语料结构还在自己拆自己台：Draft 占 74.0%，撑起整个"演化"叙事的 Improve+Crossover 加起来才 9.4%（Crossover 2.8%）。配上全文**没有 SFT vs RL 的拆解、没有单算子 ablation、Evo 三个组件也没逐项拆**（笔记确认为全文检索无 ablation 章节），"是什么在起作用"这个问题在这篇里是空的。Evo-Max 更是把跨任务经验先验和异步多卡并行两件事打包上线，最后 10.6 个点无法归因——这是最容易补也最不该省的对照。机制主张同样脆：那个"Improve+Crossover 贡献 85.0% validation gain"来自 leaf-classification 单任务轨迹，91.9% 来自 mlsp-2013-birds 单任务，n=1，不是聚合证据，不能当结论引用。
  **基准判别力撑不起 abstract 的口气**：22 任务 × 3 run，一块奖牌约 4.5 个百分点，71.21% ± 8.57% 和 GPT-5.6 Sol 的 72.73%（且对方只跑一次，是点估计）区间高度重叠，"approaching"严格讲只是"不可区分"。NatureBench Lite 那个"+20 点 All M"实打实就是 2 个任务的差别，而 NatureBench 还是作者自家 benchmark，held-out 的独立性天然打折。另外 71.21% 根本不是 MLE-Bench Lite 最好成绩——作者自己的 Table 11 就摆着 75.76%–80.30% 的既有系统（预算更大，比较口径确实不同，这点作者诚实），但 abstract 很容易被读成 frontier SOTA。值得单独表扬的是主动汇报 RL 期的 reward hacking（打乱 sample submission 提交）并上 o3-mini pre-execution judge 给 −0.5，以及把分数高于自己的系统列进同一张表——技术报告里罕见的自曝。
  跟 [[2510-HuxleyGodelMachine]] 摆一起看更清楚：HGM 已经把 RSI 的瓶颈论证到"parent selection 信号质量"（clade-level CMP 与真实改进相关 0.778 vs 即时信号 0.285），本文的三因子 parent 效用（quality/gain/novelty，权重 1.0/0.6/0.3 手工固定不学）打的是同一个靶，但解法退了半步。最后，那个"六项 artifact 全勾、全表唯一"的卖点目前是**承诺不是事实**——§1 用的还是将来时"We will release…"，链接可达性未经独立核查，这一条兑现与否直接决定这篇的最终价值。
- **Rating**: `2` 👀 ，算子级监督的抽象和 reward 设计值得抄，但"自我改进"与"蒸馏更强 teacher"没分离、零 ablation、机制证据 n=1，让它更像一个（尚未验证可用的）开放实验台而非结论；artifact 真落地并有人补上 ablation 的话可以升到 3。

### TurboVLA
- **Title**: TurboVLA: Real-Time Vision-Language-Action Model at 32 Hz on an RTX 4090 with <1 GB VRAM
- **Institutes**: Huazhong University of Science and Technology, Huawei Technologies
- **Source**: [link](https://arxiv.org/abs/2607.27205)  🔥 HF Trending ⬆️ 127   **📒 论文笔记**: [[2607-TurboVLA]]
- **核心**: 把 VLA 的 V→L→A 串行通路改成 V+L→A：DINOv3 编视觉、BERT 编指令（保留完整 token 序列而非 pooled embedding），经 6 层双向 cross-attention 直接交互，再由 ACT 式 decoder 并行解出 action chunk，执行层完全不经过 LLM。机器人 state 旁路交互模块直入 decoder，纯 ℓ1 behavior cloning，无辅助语言目标。0.2B 参数在 LIBERO 拿 97.7% 平均成功率，同机 batch=1 下 31.2 ms / 0.9 GB，对比 π0.5 的 3.4B / 12.8 GB / 93.6 ms。RoboTwin 2.0 双臂 60.2% / 43.4 ms，真机 AgileX Piper 四任务 92.5/80/90/87.5%。
- **锐评**: 问题问得好，答案是删而不是加——整篇没有新 loss、新 tokenizer、新蒸馏，就是把 LLM 换成 BERT + 6 层 cross-attn，这种"减法论文"值得鼓励。效率口径也是全文最硬的部分：论文明确声明所有 runnable baseline 的 params/VRAM/latency 都在同一张 4090、batch=1、官方 checkpoint 下测得，而不是把各家自报数字拼一张表（vault 里的 EfficientVLASurvey 正好把"latency 数字口径不齐、chunk-level 和 token-level 混着比"列为行业通病），这一点本文没滑。0.2B/0.9 GB/31.2 ms 对 3.4B/12.8 GB/93.6 ms 也不是 +0.3% 式改进，是把部署门槛从服务器 GPU 挪到单张消费卡。
  但**论文用自己的 Table 3 打死了自己的标题**。把语义指令换成可学习的 closed-set task-ID embedding，只掉 2.3 个点（95.4 vs 97.7）。翻译一下：在 LIBERO 上，"语言"的全部作用约等于"告诉 policy 这是 40 个任务里的哪一个"。那么"轻量文本编码器足以替代 LLM"这个 paradigm 级主张，就是在一个几乎不考语言理解的 benchmark 上得出的——它和"这里语言本来就不重要"根本无法区分。要立住这个 claim，唯一需要的证据恰恰是 benchmark 之外的语言泛化，而全文**零 unseen object / 零改写指令 / 零新任务组合 / 零 OOD**，也没有 failure case 分析。Conclusion 里那句"不具备高层规划所需的复杂语义理解"是自我豁免，但"同义改写一句指令还能不能执行"是执行层能力，不在豁免范围内，这一层被整个跳过了。
  第二个硬伤：**该做的消融偏偏没做**。交互模块是从 Grounding DINO 的 grounding-pretrained feature-enhancement 权重初始化的，也就是说取代 LLM 的那点 V-L 对齐能力是从 open-vocabulary detector 继承来的。论文做了文本编码器、交互方向、层数 N、horizon H 六张消融表，唯独没有随机初始化对照——而这个实验才决定结论是"轻量交互结构本身够用"还是"open-vocab grounding 先验可以顶替 LLM"。同理 Table 1 的 "Emb. PT. ✗" 只表示没在 LIBERO 之外的机器人数据上预训练，读成"从零训到 97.7%"是错的。
  数字层面还有几处需要打折：(1) 97.7 只是**这张表里**的第一，不是 LIBERO 上的最好——vault 里 Xiaomi-Robotics-0 是 98.7 avg / 97.2 Long（同样 RTX 4090、80 ms），EO-1 是 98.2，都早于本文；TurboVLA 是效率轴上的 Pareto 点，不是精度轴上的。(2) 平均分掩盖分项：99.2/99.8 来自两个已饱和的 suite，Goal 97.4 低于 π0.5 的 98.0，最难的 Long 只有 94.2，在自家表里排第六——长时序恰恰是"删掉 LLM 会不会丢表征"最该被检验的地方。(3) 标题的 32 Hz 是量级最优的那个配置（LIBERO 单臂 ViT-B），双臂 RoboTwin 是 43.4 ms ≈ 23 Hz；latency 只算"收到观测→吐出 chunk"，不含相机采集、预处理、通信与执行器往返，且 chunk 内 12 步动作怎么消费（全执行还是执行首步重规划）论文没写，所以"32 Hz 闭环控制"这个读法论文并没有直接支持。(4) 把硬件型号和 Hz 写进标题，却不报输入分辨率、数值精度和是否用 torch.compile/TensorRT——这些在 30 ms 量级足以造成两倍差异。(5) 全文单点成功率、无种子无方差，而 97.4 与 97.7 的差本来就在噪声里。(6) AR baseline 的 latency 定义为"一个 chunk **或等量的自回归 action token**"，"等量"怎么换算没说，OpenVLA 系的数字因此留了一个未公开的自由度。
  真机部分只能定性读：π0.5 的逐任务成功率仅以 Fig. 4 柱状图给出、y 轴从 70 截断且无数值标注，除了"consistently outperforming"这句定性表述外，**差距幅度在论文中不可核实**。何况 4×65 = 260 条演示、4 个已见任务、40 trials，正是小模型专精化最占便宜、大模型泛化预训练完全用不上的区间——它能说明"窄任务上小模型够用"，不能说明真机上整体优于 π0.5。最后，related work 提了 TinyVLA、RoboMamba 却没进对比表，而这两个恰恰是延迟量级最接近的直接对手，"最快"的位置缺了最该有的对照。
  一句话：一个诚实的工程结果，配了一个证据不足的范式主张。它真正的价值不是新 SOTA，而是把"执行层必须以 LLM 为中枢"从默认假设变成了可证伪的问题——但证伪工作留给了别人。
- **Rating**: `2` 👀 ，减法方向和效率口径都对，但核心 claim 只在一个"语言≈任务索引"的饱和 benchmark 上验证、决定性消融（随机初始化交互模块）缺席，值得跟进复现而不值得当结论用。

### PhiZero
- **Title**: PhiZero: A World Model Built Around Physical Language
- **Institutes**: NLPR, Institute of Automation, Chinese Academy of Sciences (CASIA)（三位作者标注为 Independent Researcher，非全员同机构）
- **Source**: [link](https://arxiv.org/abs/2607.28624)  🔥 HF Trending ⬆️ 156   **📒 论文笔记**: [[2607-PhiZero]]
- **核心**: 把 world model 的预测目标从像素换成一套自监督学出来的离散码：对每一对相邻 video latent 用共享 Q-Former 抽 transition 特征，FSQ 量化成 25K 词表，4 秒视频压成 256 个符号，作者管它叫 physical language。然后 Qwen3-VL-4B 扩词表后自回归预测这 256 个符号，再由 Wan2.2-5B diffusion decoder（LoRA rank 32，把 text condition 换成这串符号、首帧单独供外观）渲染成视频。整套表示只靠 flow-matching 视频重建监督，不用 action 标注、不用仿真器导出的物理量。结果是 5B decoder + 4B reasoner 在 6 个第三方 benchmark 上综合压过 14B 级 pixel-space 模型：Physics-IQ Verified IQ-Score 41.2 vs Cosmos3-Super 39.5 / Wan2.2-14B 32.2，WorldModelBench Total 8.19 全表最优。附带展示了动作条件驾驶/机器人仿真与 human→G1 的跨形态迁移。
- **锐评**: 最值钱的地方是中间量**学出来**而不是**定出来**——FSQ 词表是量化级数的 Cartesian product，连码本都不用训，这跟 FlowWAM 那类手工指定 optical flow 当中间量的路线形成了一个干净的对照实验入口；pure-noise warm-up 直接堵住"预训练 decoder 靠自身 denoising prior 抄近路、无视新 condition"这个真实失效模式，是很懂行的工程细节；六个 benchmark 全第三方、全官方 evaluator，在这个人人自定义 physical consistency 指标的方向上算难得的克制。但**最该做的那个消融，全文加附录一个都没有**：论文从头到尾没有"控制数据与算力、去掉离散中间层直接渲染"的对照。Table 9 里唯一的非中间层参照是 Wan2.2-5B 21.2 和它的 prompt enhancement 版 26.6（这两行是否在 PhiZero 语料上训过，论文没明说，笔记那句"未训练"是推得的，不能当事实）；而 PhiZero 的 decoder 在 10K 小时 + 5M clip curated 语料上微调过、reasoner 又另训 5M + 1M clip。于是 21.2→41.2 这 20 分里，中间表示、额外数据、训练配方三者完全糊在一起，作者亲手剥的只有仿真数据（值 3.5 分）。Table 8 补不上——它只报重建 PSNR，测的是 decoder/Q-Former/warm-up 三个设计选择，不是离散 bottleneck 本身该不该存在。就现有证据，只能说"这条 pipeline 好用"，说不了"因为有 physical language 所以好用"。更要命的是掉队的分项全部指向同一个物理解释：Physics-IQ 上 S-IoU 58.2、ST-IoU 36.8 双第一，唯独 WS-IoU 27.6 被 Grok-Video 35.7 甩开——8 个 transition 区间 × 32 符号的时间粒度就是这么粗；LikePhys 刚体误差 29.14 全表最低，流体 53.15 全表倒数第三；IntPhys2 Hard 52.38（pairwise 随机基线 50），被 V-JEPA 的 57.42 反超。离散化不是免费的，"physical language 优于 pixel prediction"在刚体和物体级交互上成立，在连续介质和长尾困难样例上直接不成立。Table 7 更是把代价量化了：256 token PSNR 28.9 确实优于 Video-LaVIT 270 token 的 23.6，但对着 Wan2.2 VAE 44,800 token 的 37.7 就是断崖，这笔账原样反映在 PhyGround General Quality 2.93 落后 Veo3.1 3.01。至于摘要和 Fig 1 主打的三大应用——交互式 rollout、动作条件驾驶/机器人、跨形态迁移——Sec 4.5 加整个 Appendix C **零数字零 baseline**，全是定性图；而 nuScenes 轨迹跟随误差、RealRobot gripper 位姿一致性都是现成可测的，不测就只能记成 demo。"zero-shot"的口径也得收紧：每个 source domain 要先 brief fine-tune tokenizer，首帧还得 GPT-Image 2.0 编辑，driving/robotics 更是 tokenizer 与 reasoner 双双在目标域微调——所谓通用接口，实际是每域一套适配后的接口。理解那三个 benchmark 还有个没人讨论的可比性问题：PhiZero 走的是自建的 physical-language likelihood ranking（判别式），同表的 GPT-4o / Gemini 是生成式 QA，两者直接排名论文没有辩护；IntPhys2 的 caption 还是作者自己用 VLM 生成的（防护做得合理：只看首帧、四条视频共用一条 caption，但协议自由度终究更大）。训练语料含 Physion / CLEVRER / ComPhy / Phyco 等合成物理 clip 是否与 LikePhys / IntPhys2 场景分布过近——数据集本身不重叠，这条属于该追问的方向，笔记里也明确标成推测，**不是已证实的污染**。最后一个结构性问题：4 秒固定 horizon + "末帧当下一窗口首帧"的滑窗，凡是单帧恢复不了的状态（速度、已完成进度、被遮挡物体）在每个窗口边界都会丢——对一个自称 world model 的系统，这是设计问题不是 future work。无代码仓库、无开源承诺，128×A100 + 50K 小时视频池，复现门槛基本封死。
- **Rating**: `2` 👀 ，方向和中间表示的设计是真有想法、参数效率的现象值得记录，但支撑核心 claim 的那个同数据对照实验缺席、旗舰应用全程无数字，够跟进不够当结论。

### AAPT
- **Title**: Why Are GUI Agents Correct but Late? Decode on the Decision-Time Critical Path, Tested with Pre-Compiled Policy Trees
- **Institutes**: Georgia Institute of Technology, Fudan University, Marquette University, UNC Chapel Hill, National University of Singapore, Southeast University
- **Source**: [link](http://arxiv.org/abs/2607.28399)  📄 arXiv   **📒 论文笔记**: [[2607-AAPT]]
- **核心**: 把 computer-use agent 在 transient GUI 事件上的失败重新归因为调度失败——动作算对了，但 autoregressive decoding 占着 decision-time critical path，等生成完窗口已经关了。方法 AAPT 是在空闲期用同一个 frozen 模型预编译一棵扁平 policy tree（每个节点带 observable guard、pre-authorized 动作、per-branch deadline），事件发生时只跑一次低 token 的 observer 做分支路由，critical path 上零生成。核心定量断言是 latency-coverage 规则 $T_{cover} \geq L_{p95}+M$，它从独立测量量预测收益出现的临界点，实测 crossover 落在 2.4 s。自建的 `key_prompt` 计时 benchmark 上，650 ms 窗口成功率 0.50 → 0.79（exact McNemar p=1.8e-3）；唯一的外部 benchmark DynaCU-Bench 上 7/39 vs 6/39，p=1.0，平局。
- **锐评**: 先说好的——这篇的实验纪律在 GUI agent 圈里属于稀有物种：预注册端点、per-seed 配对 exact McNemar、seed 区间用完即烧、两个失败的预测（700 ms 主端点打成 n.s.、oracle 探针直接推翻作者自己的假设）原样留在 ledger 里、归零的 arm 逐字报告而不打补丁重跑。最强的一击是 R1/P1 双双 0/42：open-loop 和 predict-and-replan 都"提早行动"了却颗粒无收，per-decision 路径 411/459/484 ms vs observer 273 ms，干净地杀死了"只要预判就行"这个替代解释——anticipation 只有在把生成搬出 critical path 时才兑现成延迟收益。顺带那条 `torch.compile` cache key 把 tree validity 从 88.1% 打到 18.3% 的证据，对整个 thresholded agent 评测领域都该是条警报。但骂点同样硬。第一，问题前提根本没量化：全文（笔记明确记为经全文检索确认的缺失）没有一个数字回答"现有 CUA 的失败里 timing 失败占多少"，作者用 19 个真实响应窗口的调研替代论证——那只证明亚秒窗口存在，不证明它在任务分布里重要，而 DynaCU 上可预枚举的 deadline 任务只占 9/39，恰恰是这个隐忧的实证。第二，主证据链是一个自建的三按键微 benchmark，唯一外部检验是平局，分类学 dissociation 建在 4 vs 5 个 discordant 任务上——机制被证明了，实用性没有。第三，也是最要命的：$K_{max}$ 是个手工设的**正确性**参数，而"这一步有几个可能结果"正是真实 GUI 里事先不知道的量；预算设小 planner 写泛化 guard、设大就用 catch-all 填槽，两侧都把 miss 变成按错键（k=1 时 13/42、k=2 时 12/42、k=7 时 15/42，只有匹配的 k=5 才 0/42）。所谓"零错误动作"是预算配平的副产品，不是安全性质，作者自己也这么写。$\tau_c,\tau_r,\rho$ 压根不做 runtime 强制、只是写进 planner prompt 的"设计规则"，这套软 contract 的代价立刻兑现：不均匀先验那条 arm 因为 planner 把 outcome prior 抄进 `confidence` 字段、撞上 $\tau_m=0.45$ 下限，T2 0/42 vs R0 39/42，回放显示 40/42 本来能按对。两个语义不同的量共用一个 schema 字段就能让整条 arm 归零——这个 bug 比 AAPT 本身更有普适性。适用带还窄得可怜：必须 ≥2.4 s 静默期、必须是 MoE 快解码模型（dense 的 EvoCUA-32B 上 T2 0/43 vs R0 22/43，UI-Ins-32B 0/50，方法不是无效而是有害）、guard 必须事件前可绑定（late-revealed 坐标和多步序列直接违约，`click_target` 场景压根没跑成配对）；代价是 3.2× completion tokens、2× 墙钟，算力是搬走了而且变多了。跟已有工作的本质区别，作者自己在 §2 就交代了——contingency planning、behavior tree、speculative execution 没一个是新的；真正新的是问题重构和那条从独立测量量预测收益边界的规则。跟 vault 里 [[2604-DynamicGUI]] 正交（那边改的是 agent 看到什么，这边改的是看到之后多快能动），跟 [[2411-WebDreamer]] 系 world model 的区别也清楚（那边的"想象未来"是决策时消费一次的 deliberative context，没有 observer 把实时帧路由进预备好的树）。最后一刀：一篇核心贡献是"给 GUI agent 评测加上 deadline 维度"+"compile-cache key 是必要 provenance"的论文，全文没有任何代码、数据或 benchmark 的开源链接与释出承诺——你要求全领域改评测协议，却不放出唯一能测这件事的 benchmark，这是自己拆自己的台。六作者六个单位这件事也不太像一个长期扎在这个问题上的组。
- **Rating**: `2` 👀 ，实验纪律和"correct but late"的问题重构值得学，但主证据全在自建微 benchmark、外部评测打平、分支预算是手设的正确性参数且不开源——机制成立，方法本身还不到能跟的程度。

### Qwen-UI-Agent
- **Title**: Qwen-UI-Agent Technical Report: Toward Next-Generation Real-World Centric Foundation GUI Agents
- **Institutes**: Alibaba Token Hub, Alibaba Group
- **Source**: [link](http://arxiv.org/abs/2607.28227)  📄 arXiv   **📒 论文笔记**: [[2607-QwenUIAgent]]
- **核心**: 主张 GUI agent 的瓶颈已从模型转到环境，于是把 100+ 台真机、150+ app 做成可调度资源池（virtual display 让单机并发多 session，总 rollout 吞吐约 20×），配 GUI+CLI+API 的统一动作空间（一个决策步可输出有序动作序列）、agent 驱动的数据飞轮、以及约 10,000 并发环境 + 约 10,000 组自动合成 task-verifier 的 online RL。分数：自建 MobileWorld-Real 92.2%、MobileWorld 82.1%、OSWorld-Verified 79.5%（第二）、WebArena 73.6%、ScreenSpot-Pro 81.5%（zoom-in）。全文没有一个新学习算法——GRPO、model merging、sliding window 都是现成件。真正新的东西在 §4：混合执行的实测画像与 online RL 涌现的行为分工。
- **锐评**: 先说好的：**§4 是这篇报告唯一不可替代的部分，也是全场最诚实的一段**。CLI 占全部动作的 40.7% / 55.1%、出现在 92.0% / 98.2% 的 OSWorld 任务中，batched 动作占 39.6% / 41.6%、平均每批 3.1 个 primitive——这是第一次有人把"给了终端之后模型到底用不用"量化到这个粒度，而 UI-TARS-2 早就把 SDK/终端塞进动作空间却只给了个 BrowseComp 7.0→29.6 的端到端跳变。更值钱的是 "Bash as hands, GUI as eyes"：在**没有任何显式模态协调目标**的情况下，execution→verification 转移从 40.2% 升到 52.4%，含验证动作的轨迹 +14.7%、false-stop rate −11.2%。这句话的潜台词比作者写出来的更狠——SFT policy 的典型病是"执行完就宣告成功"，RL 学到的核心增量其实是"回头看一眼"，那么外挂 verifier/critic 那条路线的价值边界在哪，值得被认真追问。恐龙游戏那个 case 同理：模型用 CLI 把自己的策略编译成本地控制器，绕开了"每步截图-推理-动作"的循环延迟——它不是证明 GUI agent 更强了，是证明这个 paradigm 在某些任务上本身就是错的抽象。
  然后说硬伤，而且是大的。**中心 claim 一次都没被 ablate。**全篇论点是"真机训练消除 sim-to-real gap"，但据 Evidence Ledger 核实，全文不存在任何"同一模型加/不加真机数据"的受控对比；唯二的 before/after 是 Action RL 和 online RL，跟真机没关系。现有证据只是"我们用了真机 + 我们在真机上分高"，这叫相关性。对照组就在隔壁：SCALECUA 的三个组件全给了独立增量消融（去 VeriGen 68.7→43.9），Xiaomi-GUI-0 一个月前就跑了真机为主的闭环——所以"真机"既不是首创，规模也没被证明是必需品而非过渡方案（作者自己在 Limitations 里承认高保真合成环境已建但没用上，正好回避了最该做的那个对照）。**更讽刺的是 §4.1 那份细致的失败画像拆的是 Qwen 3.7 Plus 的轨迹，不是自己的**——一篇以真机可靠性立论的报告，从头到尾没展示过自己那 7.8% 的失败长什么样。
  三个主力数字全建在作者可控的评测条件上：MobileWorld-Real 是自建 benchmark + 自建 5-judge AutoJudge + env_error 不入分母；WebArena 是作者自行修正官方参考答案与评测脚本、baseline 还是自跑的；Table 9 全部自测且把官方 judge 换成了 GPT-5.5/GPT-5.2。单看每项都有说法，叠起来就是最亮的几个领先都没法被第三方复算。最要命的一处：**MobileWorld-Real 上对 Seed 2.1 Pro 的 3.5pp 领先，小于 AutoJudge 自身 7.2pp 的人工不一致率**——这个"SOTA"在测量噪声里。Abstract 那句 "competitive or superior against Opus 4.8 / Gemini 3.1 Pro / GPT-5.6 Sol" 在 mobile 和 grounding 上成立，在 computer-use 和 DeepSearch 上根本不成立：OSWorld-v2 partial 40.0 vs Opus 54.8、BrowseComp 64.1 vs GPT-5.5 90.1，"competitive" 这个词在这句话里干了太多活。Intro 的"少用 58.4% / 21.7% 步数"更是选择性对比——那是跟 Single 模式 baseline 比的，同为 Batched 的 Opus 4.8 只要 103.0 步，比它的 135.8 少，这个对比论文没做。
  剩下的：**27B dense 在 MobileWorld 上比 35B-A3B MoE 高 17.1pp（82.1 vs 65.0）**，同一 pipeline 下 MoE 变体退化成这样，论文一句"部署效率更高"带过就不管了——GUI agent 的真实部署压力恰恰在端侧，这个 gap 比它拿到的篇幅重要得多（论文只说 35B-A3B 的 CUA/DeepSearch 训练没跑完，解释不了 mobile 上的崩盘）。权重和代码零释出，只承诺"未来开源环境合成方法"。文内 six vs five transitions、Conclusion 的 40.2% vs Table 5 的 40.0%、`ask_user` 写成 `call_user`——赶工痕迹写在脸上。加分项是 Limitations 确实老实（承认全自动 pipeline 行不通、仍需大量人工监督），比一堆把 limitation 写成 future work 广告的技术报告强。
- **Rating**: `2` 👀 ，读 §4 的混合执行统计与涌现行为分析，那部分是真货；leaderboard 部分自建 benchmark + 自评 judge + 自修脚本三件套齐全、核心 claim 无消融、权重不放，当营销材料看。
