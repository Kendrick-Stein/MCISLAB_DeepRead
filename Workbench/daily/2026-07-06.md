## 论文点评

### DataComp-VLM
- **Title**: DataComp-VLM: Improved Open Datasets for Vision-Language Models
- **Institutes**: University of Tübingen, MPI Informatics, Google DeepMind, Stanford, ETH Zürich, LAION, UW 等
- **Source**: [link](https://arxiv.org/abs/2606.28551)  📰 HF Daily ⬆️ 27   **📒 论文笔记**: [[2606-DataCompVLM]]
- **核心**: DataComp/DCLM 原班人马（Schmidt、Jitsev、LAION 系）把"固定训练配方、比拼数据 curation"的范式搬到自回归 VLM：汇集 160 个公开数据集、6T 多模态 token 的数据池，在 1B-8B 四档规模（6.25B-200B token 预算）上用 52 个 benchmark 系统比较 filtering 与 mixing。核心发现是所有 quality filter 相对 no-filter 都无稳健收益（最好的 SigLIP-2 也只 +0.8pp），而 instruction-heavy 的 mixing 配比才是主杠杆且随 scale 越来越好。产出的 DCVLM-Baseline 在 33 任务 Core 套件上达 63.6%，超 FineVision +5.4pp——4B/100B token 就能打赢 FineVision 的 8B/200B token，等效 4× compute 节省。
- **锐评**: 这是数据侧论文该有的样子——不发明花哨方法，而是用严谨的受控实验校准整个社区的先验。"filtering 无效"直接打脸从 DataComp/DCLM 继承来的 "filter harder" 惯性，而且给了机制解释：现代 VLM 数据池早被上游 curated 过，二次过滤边际收益从 +2.4pp（25% pre-filtered）衰减到 +0.6pp（100% pre-filtered），这一条就能让 daily feed 里一半 "更好的 VLM data filter" 论文原地贬值。实验设计诚意足：30× 固定 pool ratio、benchmark 经稳定性/单调性筛选、pretraining→post-SFT 排序 r=0.99 的迁移验证，重复容忍实验（instruction 数据重复 2-4× 仍优于换差配比）还有直接可抄的实用价值。但要警惕两点被过度泛化：其一，"filtering 无效"只对已 curated 的公开池成立，raw crawl curation 作者自己都承认没碰；其二，70% instruction-heavy 这个"最优配比"建立在 instruction 数据集稀缺、中等预算就得大量重复的现实上，它可能是数据可得性的产物而非 scaling 本质规律。架构也钉死在 InternViT + Qwen2.5 一套上，vision encoder 从没换过。另外别被 +5.4pp 冲昏头：对照闭源数据的 InternVL-3-8B（68.5%）还差着 5pp，开源数据的天花板问题没解决，只是把地板垫高了。
- **Rating**: `3` 🔥 ，VLM 数据研究的标准试验台候选——"mixing over filtering" 是少数能改变社区资源分配方向的结论，基础设施贡献远超单点 SOTA。

### MIPU：优化训练策略是海市蜃楼
- **Title**: The Mirage of Optimizing Training Policies: Monotonic Inference Policies as the Real Objective for LLM Reinforcement Learning
- **Institutes**: Tianjin University, Alibaba
- **Source**: [link](https://arxiv.org/abs/2606.29526)  📰 HF Daily ⬆️ 147   **📒 论文笔记**: [[2606-MIPU]]
- **核心**: LLM RL 用分离的 inference/training engine，两侧对同一 trajectory 概率不一致；本文的关键论点是这不只是 off-policy 修正问题，而是 objective misalignment——你优化的 training policy π 根本不是部署时跑的 inference policy μ。据此把 J(μ) 的提升分解为 pre-update gap + training update + post-update gap 三项，提出 MIPU：Step 1 用 sampler-referenced 截断重要性权重修正 pre-update 失配（clip 只作用于当前更新比值），Step 2 同步后用 inference-side gap proxy 决定接受还是回滚。FP8 rollout 高失配设定下，Qwen3-4B 平均 66.71%（GRPO 64.42%）、Qwen3-1.7B 53.97%（GRPO 50.86%），且 baseline 全崩、MIPU 稳住。
- **锐评**: Problem formulation 是真贡献——TIS/MIS 一族都在 token 级修修补补，这篇把问题抬到 objective 层，三项分解干净地点破 GRPO 只管中间项的盲区，比方法本身更值钱。实验设计里最硬的一手是 random rollback 对照：随机拒绝 67% 更新照样崩，MIPU 拒 53.5% 却稳，直接堵死"Step 2 只是少更新"的平凡解释；Step 1/2 单独用分别 +0.94 / −1.61、合用 +2.29 的互补 ablation 也自洽。但硬伤同样明显：全部主实验建立在 FP8 rollout 这个**人为放大的失配**上，BF16 常规设定下 mismatch 小一个量级，MIPU 的收益减去 validation rollout 开销（论文压根没量化）还剩多少，只字未提——这是 claim 与证据之间最大的缝。标题里的 "Monotonic" 也是广告词：Step 2 基于 proxy 接受，没有任何正式单调性保证，且容忍度 c 敏感、调严了直接滞留 stale policy。1.7B/4B + 纯数学域的验证范围，撑不起 "the Real Objective for LLM RL" 这么大的帽子。
- **Rating**: `2` 👀 ，视角转换（优化 μ 而非 π）值得记住，但收益目前只在人为高失配设定下成立，常规设定的性价比未被回答。

### Unlimited OCR
- **Title**: Unlimited OCR Works
- **Institutes**: Baidu Inc.
- **Source**: [link](https://arxiv.org/abs/2606.23050)  🔥 HF Trending ⬆️ 51   **📒 论文笔记**: [[2606-UnlimitedOCR]]
- **核心**: LLM-based OCR decoder 解析多页文档时 KV cache 随输出线性膨胀，只能逐页 for-loop。Baidu 提出 Reference Sliding Window Attention (R-SWA)：视觉 token 作为静态 "reference" 全程可见，生成侧只留 128-token 滑窗，KV cache 全程恒定。在 DeepSeek OCR 基座上只改 attention mask + 4K steps 微调，OmniDocBench v1.5 拿到 93.23%（超基座 6.22 分），长序列 TPS +35%，32K context 内单次 forward 解析 40 页文档（edit distance 0.107）。
- **锐评**: 问题选得极准——OCR 输出几乎完全由输入图像决定，对远距离已生成文本的依赖天生就弱，sliding window 假设在这里是免费午餐，这是"任务结构决定 attention 结构"的教科书案例；恒定延迟曲线也是比平均 TPS 更硬的证据。但硬伤同样明显：**零 ablation**——n=128 怎么定的、reference 段砍掉会怎样，全靠信仰；更致命的是没有 "基座 + 同样 2M 数据全 attention 微调" 的对照，v1.5 上 +6.22 的精度提升到底归功于 R-SWA 还是那 2M 训练样本，论文自己都说不清，这是把 efficiency 贡献和 accuracy 贡献混着卖。"Unlimited" 纯属标题党：prefill 侧视觉 token 照样线性涨，40 页就顶到 32K 天花板。ASR/translation 泛化是零实验的口头支票——translation 的长程一致性依赖远强于 OCR，128 窗口大概率不够。机制本身是 StreamingLLM/attention-sink 的任务特化版，新颖性在适配不在发明。
- **Rating**: `2` 👀 ，工程上干净实用、假设选得聪明，但缺关键对照实验且标题 overclaim，是好产品报告而非严谨论文。

### VLA-Corrector
- **Title**: VLA-Corrector: Lightweight Detect-and-Correct Inference for Adaptive Action Horizon
- **Institutes**: Zhejiang University, Alibaba DAMO Academy
- **Source**: [link](https://arxiv.org/abs/2607.01804)  📰 HF Daily ⬆️ 24   **📒 论文笔记**: [[2607-VLACorrector]]
- **核心**: Action chunking 让 VLA 一次预测多步动作开环执行，扰动在盲区内滚雪球成 compounding error。本文不动 backbone 权重，外挂一个 ~40M 的 Latent-space Vision Monitor 在线比对"预期 vs 实际"视觉 latent 演化，持续偏差（MAD 双阈值 + 连续 5 步确认）就截断剩余 chunk，并用 LVM 的梯度对下一次 flow-matching 去噪做 Online Gradient Guidance 引导重规划——等效于把固定 action horizon 变成事件触发的自适应量。MetaWorld 上 π0.5 从 48.70% 提到 64.35%（+15.65），LIBERO few-shot 97.8% 反超 fully fine-tuned 的 96.95%，真机 disturbance recovery +28.3 pts，且平均 policy calls 不升反降（5.15→4.98）。
- **锐评**: 问题选得准——"何时 replan"是所有 chunked VLA 的真实痛点，把 horizon 从静态超参变成 drift 事件驱动是干净的 formulation；跨 π0.5/SmolVLA/X-VLA 三个 backbone 均有收益、ablation 诚实（truncation 贡献 +11.65 大头，OGG 只再 +4），这些都值得表扬。但硬伤同样明显：**通篇没有和 H=1 每步 replan 或 Real-Time Chunking 这类 async replanning 方法的定量对比**，"缓解 horizon trade-off"的 claim 只打了静态 horizon 这个稻草人。OGG 更是性价比存疑——+4 pts 换 ×1.62–1.68 推理开销，X-VLA 每任务触发 ~120 次 OGG event 暴露检测器触发过密；而且它只能在 frozen backbone 已会的行为里挑，造不出新的 recovery 行为（作者自己承认）。"无需 retrain backbone"是真的，但 LVM 要 domain-matched demo 训练且跨域掉分明显（域内 +10.0 vs 跨域 +3.1），plug-and-play 打了折扣。数字里最硬的是真机扰动恢复 +28.3 和 success-per-call +24.6%，最虚的是把 monitor 训练成本从"training-free"叙事里悄悄剥离。
- **Rating**: `2` 👀 ，问题真实、模板可复用（monitor 触发 + guidance 修正），但缺关键 baseline 对比且 OGG 收益/开销比难看，离标准组件还差一轮硬实验。

### Embodied.cpp
- **Title**: Embodied.cpp: A Portable Inference Runtime of Embodied AI Models on Heterogeneous Robots
- **Institutes**: Southeast University, Nanjing University, Microsoft Research, Tsinghua AIR
- **Source**: [link](https://arxiv.org/abs/2607.02501)  📰 HF Daily ⬆️ 41   **📒 论文笔记**: [[2607-EmbodiedCpp]]
- **核心**: 想做"具身界的 llama.cpp"：一个 C++ 推理 runtime，把 VLA 和 World-Action Model 的执行统一拆成五层（input adapter / sequence builder / 共享 backbone / 可插拔 head / deployment adapter），主打多速率闭环执行和 batch-1 低延迟，声称覆盖 CPU/GPU/NPU 异构硬件。实测两个 VLA 闭环跑通——HY-VLA 在 RoboTwin place_empty_cup 上 100% 成功率、pi0.5 91% 且 step latency 仅 56.85 ms；WAM 侧用 Q4_K 量化把 LingBot-VA 单个 transformer block 内存从 312.2 MiB 压到 88.1 MiB（-71.8%），精度漂移可忽略。代码已开源。
- **锐评**: 问题诊断是对的——多速率闭环、latency-first batch-1、异构具身 I/O 确实是 vLLM/SGLang 这类 serving 框架管不到的空白，这个卡位值得占。但 evaluation 和 claim 的落差大到离谱：capability matrix 里画了 4 类 VLA + 4 类 WAM 全覆盖，实际只有 2 个 VLA 跑通；WAM 是核心差异化卖点（vla.cpp 不支持），结果完整模型自己承认"在 edge 上跑不稳"，只交了个单 block 微基准——而那个 -71.8% 内存基本是 Q4_K 量化的功劳，跟 runtime 架构半毛钱关系没有。全文没有一个与 PyTorch 部署的端到端对比数字，零 ablation，graph replay / buffer 复用 / 算子融合各贡献多少全靠信仰；标题写 "heterogeneous robots"，实验里连硬件型号都没写，更没有真机。HY-VLA 1340 ms 的 inference latency 还顺手打脸了 "latency-first" 的核心卖点。这是一篇自称 "current revision" 的抢跑 draft，系统骨架搭好了，实验是占位符。
- **Rating**: `2` 👀，方向真实且工程卡位聪明，但当前版本是"愿景 + 微基准"，等 repo 和完整 WAM 结果落地再认真对待。

### DSWAM
- **Title**: DSWAM: A Dual-System World Action Foundation Model for Fine-Grained Robot Manipulation
- **Institutes**: AIRC Midea Group, Tongji University
- **Source**: [link](https://arxiv.org/abs/2607.04927)  📄 arXiv   **📒 论文笔记**: [[2607-DSWAM]]
- **核心**: 美的家电研究院的双系统机器人操作框架：System 1 是 WAM 执行器，把多视角 RGB + 指令 + 本体感知编码成 latent world features，用 conditional flow matching 直接出 action chunk（训练时 video co-training 当辅助损失，推理不生成视频）；System 2 是可选的 Rynnbrain4B 规划器，每 2 秒把高层指令切成 subtask。RoboTwin 2.0 上 50 个双臂任务平均 92.38%（clean）/ 91.90%（randomized），真机叠衣服在与 DeMaVLA 同数据、同本体、同协议下做到 96.3% SR、平均 1′44″，比 DeMaVLA 快 34 秒；TensorRT BF16 把 policy latency 压到 73.8ms（2.69×）。
- **锐评**: 一篇包装成 "Foundation Model" 的工业部署报告——backbone 是哪个 video model、参数量多少、预训练数据多大，一概不说，谈何 foundation。最致命的是核心 claim 零消融：video co-training 和 world latent 到底贡献了什么完全没有 isolate，而对最强 WAM baseline Fast-WAM 的增益是 clean +0.50 pt、randomized +0.12 pt——这是噪声，不是方法优势。标题里的 "Dual-System" 更虚：主 folding benchmark 全程关着 System 2，只在一个 sorting 任务上演示（75.7%→100%），且 "VLM planner 分解 subtask 有用" 是 Hi Robot、π₀.₅ 早就确立的结论。真正值得肯定的有两点：一是 matched-condition 的 VLA vs WAM 对比协议，直击该领域真机对比被数据/本体/协议 confound 的通病；二是完成时间全面碾压（towel 1′27″ vs 2′26″），这不是 20-trial 噪声能解释的，说明 WAM 执行确实更果断。但成功率上 +3.8 pt 的均值几乎全靠 pants 单项（90 vs 75，即 3 次 trial 的差距），且 DeMaVLA 是同组前作，左手对比右手。
- **Rating**: `1` 💤 ，部署工程扎实但方法零新意、核心 claim 零消融、"Foundation" 与 "Dual-System" 双双名不副实，价值只剩那套 matched 对比协议。
