# 🔪 今日总结

今天两篇 world action model 撞上了同一个结论，而且都是作者自己的消融给出的：world model 对控制的贡献主要来自训练期的辅助监督，不来自推理时"想象后果再行动"。WAVE-0 只把 world model 当训练 loss 就让 RoboTwin 从 80.38 涨到 89.51，推理时显式用预测未来做条件只再多约 2 点；UNITAS 的 policy 模式直接跳过 flow 分支，scene-flow loss 只贡献 +0.73 pp。标题里的 "world model" 在这两篇里起作用的方式，更像一个 action-grounded 的表示正则。

另一条主线是"诊断比方法值钱"。Bifocal 用 GT-oracle 递进实验说明 visual token pruning 的瓶颈在表示被拆碎而非打分不准，general VQA 近无损、grounding 只剩一成，是今天唯一的 3 分；ExpActivator 把 GUI memory 的增益拆成首步与轨迹内，四种 baseline 的轨迹内增益 95% CI 全部跨零；AgentSWE 实锤了 coding agent 的"自报完成"不可信和 hollow runtime。三篇方法部分都偏弱或证据不足，诊断却都可以直接拿来审视已有工作。PR-OPD 的 token→hidden 通道替换消融干净，但单 seed、缺"无关 skill"对照，机制叙事撑不住。

## 论文点评

### Bifocal
- **Title**: Bifocal: Training-Free Mixed Granularity Visual Token Pruning for Multimodal LLMs
- **Institutes**: Eastern Institute of Technology, Ningbo; Shanghai Jiao Tong University; Uppsala University; University of Science and Technology of China
- **Source**: [link](https://arxiv.org/abs/2610.18399)  📄 arXiv   **📒 论文笔记**: [[2610-Bifocal]]
- **核心**: 作者用 10 个方法、14 个 benchmark 把 training-free visual token pruning 重测了一遍，发现 general VQA 上"近乎无损"的结论只是因为测得太宽松。LLaVA-1.5-7B 在 192 tokens 下，HiPrune/EADP/SID 的 general 能保住 93.9–98.1%，grounding 却只剩 9.5–14.0%。原因归结为两点：单一重要性排序让保留下来的证据同质化；稀疏 patch 子集破坏了位置和内容的完整性（RefCOCO testA 上只保留 GT 框内 144 个 patch 仅 39.1，补上 64 个 block-pooled token 就到 63.0，不剪枝是 64.5）。方法把 Stage-1 预算拆成三份：query-focused patch、image-intrinsic patch（加权 facility location 贪心）、剩余 patch 的 block pooling coarse token；Stage-2 是 FastV 乘局部密度先验。三个 7B 模型、9 个 model–budget 设置下 general 和 grounding 平均都排第一，Qwen2.5-VL 15% 预算时 REC 67.9%，所有 baseline 都不到 60%。
- **锐评**: 这篇最值钱的是诊断，不是方法。Fig. 3 那组递进实验（GT oracle → 补位置 → 补 pooled 内容）把"选不准"和"表示被拆碎"干净地分开了：oracle 选择都只有 39.1，说明整个领域在打分器上卷错了方向。Appendix B 更说明问题：把 HiPrune/VisionZip/EADP 塞进三分预算框架，grounding 就涨 9.7–20.6 点，收益主要来自预算结构，跟 Bifocal 自己的打分关系不大。也正因为如此，query-focused 分数里叠的五个部件（平滑、norm 回归去偏、Pearson 词权重、几何平均 soft AND、背景惩罚）显得很臃肿。Table 4 只消融了 C/I/Q 三类预算的配比，一个打分部件都没单独拆，这些部件各自贡献多少目前**不知道**。另外 Table 4 的 REC 只算了 RefCOCO+ 两个 split，跟 Table 2 的 8-split 口径对不上。数字上有三处要打折。一是预算按 layer-averaged 计：128 档实际先送 224 tokens 进 LLM 前几层，跟单阶段方法比本来就占便宜；FLOPs 拉平了，TTFT 1.27× 仍慢于 VisionZip 1.37× 和 HiPrune 1.38×。二是 OCRBench 192 档 284，输给 HiPrune 316 和 VisionZip 312，"每个能力组 >90%"是按组平均算出来的，query 预算挤掉 image 预算的代价藏在了平均数里。三是 grounding 111.0% 比不剪枝还高，作者没解释，更像 REC 输出格式被扰动后的偶然收益，不像真正的能力提升。可复现性也有缺口：Stage-2 层号 L、pooling block 尺寸、各档 K 都没给数值（笔记原先写"平滑核也未给出"，ledger C18 已判 contradicted，平滑其实只在 Appendix C 的分析里以 3×3 mean filter 出现），复现只能看代码。评测范围只到 7B、单图、单轮，没有多轮、视频和高分辨率 GUI 截图。多轮恰恰是 query-focused 预算最容易出问题的地方，[[2606-RethinkingTokenReduction]] 已经指出过 prompt-dependent pruning 在后续轮次会失效。
- **Rating**: `3` 🔥 ，诊断揭穿 pruning 评测偏差，pooled 底图对 GUI grounding 直接可借鉴

### ExpActivator
- **Title**: Relevance Does Not Imply Applicability: Experience Activation for Personal GUI Agents
- **Institutes**: NTU, Alibaba
- **Source**: [link](https://arxiv.org/abs/2609.33304)  📰 HF Daily ⬆️ 29   **📒 论文笔记**: [[2609-ExpActivator]]
- **核心**: 个性化 GUI agent 的常见做法是按任务检索用户历史，再把整段历史塞进 context。作者在 AndroidIntent 上把 SSR 拆成"首步"和"轨迹内"两段来打分，发现 Recent、Retrieve、LLM-UM、HIM-Agent 四种 memory baseline 的收益几乎全落在首步（选 app）：在 7,140 个轨迹内动作上，它们与无历史基线的差只有 −0.80 到 −0.07 pp，95% CI 全部跨零。ExpActivator 不做任何训练：每一步用冻结视觉塔的分块特征，在历史中找最像的那一屏，只把那一屏上的动作作为 reference 交给 policy。Qwen3-VL-8B 上 SSR 从 22.6 升到 30.9，轨迹内 +8.24 pp，每步历史 token 144.6，baseline 是 418–844。主动建议部分用时间核加场景一致性做门控，决定建议还是 abstain，MCC 约为 HIM-Agent 的 2.3 倍。
- **锐评**: 这篇最值钱的是诊断，方法本身没多少新意。首步/轨迹内拆分做起来很便宜，结论却挺伤人：包括 PersonalAlign 自家的 HIM-Agent 在内，"memory 有用"的提升在这里基本只是把 app 选对了。16 个 baseline×backbone 组合中，轨迹内增益没有一个超过 2.4 pp，12 个与零无法区分。今后谁再报 GUI memory 的增益而不做这个拆分，结论都要打个问号。$K_\xi=1$ 的对照也做得干净：同一条轨迹，整条追加得 18.47，只给匹配那一步得 23.84，信息量相同、只改呈现方式。方法上，所谓"step-level activation"就是同一用户、同一任务的屏幕最近邻动作复制。论文自己的案例也承认被激活的历史屏与当前屏"nearly duplicates"。换成新任务、新 app 版本或跨用户，它还能不能 work，论文一个证据都没给。硬伤有三处。(1) 执行评测全部离线逐步打分，policy 看到的是真实前序动作。错误 reference 把 agent 带偏后的错误累积根本没测，policy 实际 reject reference 的比例也没报告。(2) backbone 越强，增益越小。GUI-Owl-1.5-8B 上 SSR 只比 Retrieve 高 0.7（28.2→28.9），轨迹内 +2.38，HIM-Agent 是 +1.92，几乎打平。"平均 +20%"主要靠弱 backbone 撑起来，看起来更像是在补弱模型的 grounding，而不是 memory 机制本身的胜利。(3) 首步 70.06 对 baseline 约 62 的优势，来自另一个 app 投票器，跟核心的视觉匹配无关，也会把 CSR 抬高。主动建议部分有 6 个手工常数，敏感性扫描直接在 315 个评测状态上做。MCC 约 0.4、误报率约 37%，离"能放心主动打扰用户"还远。好在作者指出了"总是建议"就能把 F1 刷到 81.1，还揭穿了 MAI-UI 上三个 baseline 实际上 recall 和误报率都是 100%，这对 proactive 评测算是一次有用的纠偏。整篇只有一个 benchmark，最好的 SSR 只有 30.9%，结论都是相对改进。
- **Rating**: `2` 👀 ，首步/轨迹内拆分直击 GUI memory 评测盲区，值得一读；方法实为近重复屏动作复制，强 backbone 上增益接近消失，且只做了离线评测。

### AgentSWE
- **Title**: AgentSWE: Can Coding Agents Build the Agent You Actually Want?
- **Institutes**: Beijing Academy of Artificial Intelligence; Institute of Automation, Chinese Academy of Sciences; Renmin University of China
- **Source**: [link](https://arxiv.org/abs/2610.13361)  📰 HF Daily ⬆️ 203   **📒 论文笔记**: [[2610-AgentSWE]]
- **核心**: 这篇 benchmark 测的是"让 coding agent 按自然语言需求给你造一个 agent"这件事。25 个任务分三类：10 个 Creation（从零造）、10 个 Editing（给 OpenHands/Aider 等生产代码库加功能且不破坏原有行为）、5 个 Optimization（把 starter agent 往 BrowseComp/OSWorld 等 benchmark 上推）。builder 每个任务只能看到 2 个开发 case，交付物冻结后在 6 个 held-out case 上由 validity gate 加 rubric LLM judge 打分，runtime model 经统一 gateway 固定。Codex harness 配五个 backbone，最好成绩只有 Creation 19.1、Editing 31.6，Optimization 没有一个 builder 的平均 gap closure 超过 5%。开发分 ≥90 的 11 个 Creation run，held-out 平均只有 9.9。
- **锐评**: 最值钱的不是主表，是失败分析。一是静态代码评审分不出能跑和不能跑的交付（0 分交付 44.2，非 0 交付 45.8），"看代码打分"这条评测路线基本可以判死刑。二是 58.1% 的 held-out 执行连 validity gate 都没过，"看着完整、根本跑不起来"的 hollow runtime 被实锤。三是 9 份与轨迹矛盾的完成报告全部声称"已完成"，21 份承认失败的报告没有一份被反驳，"自报完成"不可信这一点因此很干净，也很容易用起来。Optimization 被选候选开发集 +13.1、held-out 只有 +1.8，和 [[2609-HarnessDev]] 指向同一个结论：用少量可见反馈做 selection，会系统性地选中过拟合候选。这对 DGM 一类 self-improving 工作是直接警告。硬伤同样明显。第一，"过拟合"有一部分是构造出来的：held-out 被有意设计成覆盖开发 case 没演示的条款，开发 case 又只有 2 个，dev≫held-out 几乎是必然结果。builder 习惯问题和需求文档没写清楚的问题没有被拆开，开发 case 数量实验也只做了 2 个任务、各 3 run，4 个 case 时 PPTX 还从 33.5 掉到 15.2，得不出规律。第二，主表排名不可信：每个配对只跑一次，而同配对重复构建能出现 32.8/33.3/90.5；PinchBench 上 starter 重复评测的标准差就有 20.8，比多数 Δ 还大。比较 DS-V4-Pro 和 GPT-5.6 Sol 谁更强没有意义，Table 1 只能支撑"大家都很差"。第三，评测存在闭环：GPT-5.6 Sol 同时负责起草任务材料，又在 Creation 里当 builder、runtime 和 judge，论文没有做 judge 替换，也没有人工一致性校验。第四，gap closure 统一取 J*=100，对远未饱和的 BrowseComp、OSWorld 来说分母过大，"<5%"有一部分是指标定义造成的。另外，related work 漏掉了最相近的同期工作 HarnessDev（v1 参考文献中未检索到）。正文的 Table/Figure 交叉引用也有多处错误。
- **Rating**: `2` 👀 ，失败分析（静态评审失效、完成声明不可信）值得看，但主表单次运行、方差压过差距，不能用来排序

### WAVE-0
- **Title**: WAVE-0: Bridging VLA Policies and WAMs with Lightweight Latent Future Prediction
- **Institutes**: Shanghai Jiao Tong University, Awaken Robotics, Baidu AI Cloud, Zhejiang University
- **Source**: [link](https://arxiv.org/abs/2610.18568)  📄 arXiv   **📒 论文笔记**: [[2610-WAVE0]]
- **核心**: 在 pretrained π0.5 上外挂一个 257M 的 latent world model。Stage 1 只用带 GT action 的 demo，在 frozen SigLIP 特征空间里学"给定动作、预测未来表示的残差"，没有视频预训练，也不重建像素，另加一个 counterfactual ranking loss，逼模型真正依赖 action。Stage 2 冻结 world model：VLM 先产出 latent action plan，world model 据此预测未来，再压成 12 个 future tokens 条件化 action expert。plan 只能经由"预测的后果"影响动作。结果：LIBERO 98.7、RoboTwin 2.0 91.47（π0.5 为 80.38）、LIBERO-Plus/Pro 88.0/61.4，真机 3 任务从 38.3 提到 73.3，延迟只多 18.8 ms。
- **锐评**: 全文最值钱的是作者自己给的 π0.5 + WM 对照，可惜它削弱了标题的卖点。同一个 frozen world model 只当辅助训练 loss、推理路径不改，RoboTwin 就从 80.38 涨到 89.51（+9.1）；"推理时显式用预测未来做条件"只再多约 2 个点（clean/rand +1.98/+1.94）。这说明大头收益来自训练期 action-grounded dynamics 监督，"想象未来再行动"只是边际增量，正文却在强调后者。这个关键对照只在 RoboTwin 上做了，LIBERO-Plus/Pro 没报，同样基于 π0.5 的 JEPA 辅助监督也没纳入同表。
  Counterfactual ranking 的诊断做得干净：去掉它，错动作与对动作的预测误差差距只有 0.0020，margin 满足率 0%，也就是 world model 基本无视 action。这点值得整个 latent WAM 圈子拿去自查。
  硬伤主要在真机实验。正文写"same data"，附录却承认 WAVE-0 的 Stage-1 world model 用了 3 个任务共 600 条 demo，baselines 每个任务只用 200 条；chunk 长度和执行步数也不一致，每个任务又只有 20 trials。73.3 vs 38.3 这个最亮眼的数字因此混杂严重，不能当干净证据看。"SOTA"说法也得按 benchmark 拆开：LIBERO 只比 LaWAM 高 0.1，已在饱和区；RoboTwin 上 ImageWAM、AHA-WAM、LingBot-VA、Fast-WAM 都比它高。真正站得住的领先只有 LIBERO-Plus/Pro 的 OOD 分数，而且 Noise 类掉了 3.7。"无需大规模预训练"的效率叙事没把 π0.5 本身的预训练成本算进去，Table 4 只数 examples、不数 FLOPs，比较口径偏向自己。
- **Rating**: `2` 👀 ，π0.5+WM 对照揭示收益主要来自训练期监督，值得一读；真机对照混杂，RoboTwin 也非 SOTA

### UNITAS
- **Title**: UNITAS: A 3D-Native World Action Model for Embodied Manipulation
- **Institutes**: The Chinese University of Hong Kong, Shenzhen; DexForce Technology; Foshan University; Sun Yat-sen University; South China University of Technology
- **Source**: [link](https://arxiv.org/abs/2610.12099)  📰 HF Daily ⬆️ 2   **📒 论文笔记**: [[2610-UNITAS]]
- **核心**: 把 world action model 的预测对象从视频 latent 换成 metric 3D 点轨迹：观测 token 加 world-aligned 3D position embedding（无深度时沿射线采 64 个候选深度做 attention），夹爪（20 个 URDF 点）、人手（21 个 MANO 点）和场景变化统一成点轨迹，再用按秒编码的 tokenizer 把每条轨迹压成一个 token。1.7B 的 MoT 双专家同时输出 action chunk、action flow 和 scene flow。结果：LIBERO 99.8%，LIBERO-Plus 89.1%（camera 扰动 82.1%，Cosmos Policy 为 75.8%），RoboTwin 2.0 92.94/93.04；action-conditioned scene prediction 的 Moving ADE 比 PointWorld 低 35%；policy mode 推理 55.77 ms/chunk。
- **锐评**: 标题写的是 "World Action Model"，自家消融却说明 world model 在控制里基本没用上。action chunk 和 action flow 并行生成、互不条件，纯 policy 推理直接跳过两个 flow 分支；scene-flow loss 在 LIBERO-Plus 上只带来 +0.73 pp（85.74→86.47），没报 seed 方差，这点增益落在噪声范围里。真正起作用的是 3D PE（去掉后 camera 79.11→66.73）、action-flow 辅助损失（-6.9 pp）和 history tokens（-9.8 pp），三者全去掉跌到 67.58%。所以准确说法是"world-frame grounding + 点轨迹辅助监督的 VLA"，"想象后果再行动"没有得到证据支持。这部分消融本身做得干净，3D PE 对应 camera 鲁棒性、history 对应初始状态鲁棒性，机制归因能对上；无深度 routed PE 84.43% vs GT depth 84.68%，推理时可以不要深度，这是实打实的工程价值（但标定照样要提供）。数字包装要扒一下：摘要里 "up to 49% lower" 来自 Static ADE（背景漂移），运动点只低 35%/21%，而且 PointWorld 是否在 RoboTwin 上重训正文没交代。Table 4/13 对视频 WAM 的大幅领先里混着 SpatialTrackerV2 + 深度估计的 lifting 误差，不能读成"3D 世界模型比视频世界模型更懂物理"。RoboTwin Clean 92.94 vs LingBot-VA 92.93 就是持平。预训练有负迁移，作者没讨论：noise 扰动 89.8→84.5，VLABench IS 71.2→69.3。真机只有 2 个任务 × 20 trials，Pack the Ball 在 Intro 写 65%、Table 2 写 80%，自相矛盾。scene flow 只有仿真监督，真实场景只有定性图、没有 GT，仿真可视化还用的是训练 clip，世界模型在真实场景的定量能力完全是空白。Table 1 的基线数字是自己复现还是直接引用，笔记无法确认。
- **Rating**: `2` 👀 ，3D grounding 加点轨迹接口值得借鉴，但 world model 对控制的贡献只有 +0.73 pp，没有证据撑住

### PR-OPD
- **Title**: PR-OPD: Privileged Representation On-policy Self-Distillation for Agentic Reinforcement Learning
- **Institutes**: University of Florida, University of Illinois at Chicago, Case Western Reserve University, Vanderbilt University, Weill Cornell Medicine
- **Source**: [link](https://arxiv.org/abs/2609.36642)  📰 HF Daily ⬆️ 29   **📒 论文笔记**: [[2609-PROPD]]
- **核心**: SDAR / Skill-SD 这类 privileged self-distillation 的做法是：同一 policy 在上下文里带上 skill 当 teacher，把 token log-prob 蒸馏回不带 skill 的 student。作者先做诊断：skill 让 3B WebShop success 从 42.2% 升到 56.2%，可加上 skill 后不到 1/4 的 response token 概率变了，hidden state 却有 80% 以上变了。于是换掉蒸馏通道：GRPO warm start 之后，policy 给每条轨迹写一段 hindsight skill，student 的各层 hidden state 经 per-layer projector 投影后，对齐到"带 skill 重读同一 response"的 stop-gradient 自身。整个方法不含 output 蒸馏项，推理时也没有额外开销。step 150 时，WebShop acc 比 GRPO 高 11.7（3B）/ 14.0（1.7B）；ALFWorld 两个 backbone 都只比 Skill-SD 高 1.6。
- **锐评**: 全文最值钱的是 Table 2 这个受控消融：同一个 step-100 checkpoint、同一批自生成 skill，只改读 teacher 的通道，token OPD 掉 8.6，hidden alignment 涨 6.3。"同权重所以层层天然对齐、不需要 layer mapping"这个观察也确实干净。问题出在证据撑不起叙事：
  (1) 所有数字都是单 seed、128 episode 评测。ALFWorld 每个 task type 只有约 20 个 episode，领先 1.6 点基本落在噪声里，真正可信的只有 WebShop 3B 上对 Skill-SD 的 +7.8。
  (2) 主表混了两个变量。baseline 用 SDAR 手写 skill（每个 task type 一条），PR-OPD 用每条轨迹自生成的 skill。OPSD 在 ALFWorld 上跌到和 Vanilla 一样的 23.4，明显没调好，却被拿来代表 token 路线。
  (3) warm start 的 N 按环境分别设定。WebShop 取 N=120 时 acc 57.0，取 N=100 时只有 49.5，已经低于 Skill-SD 的 54.7。论文没说明 N 是在独立 validation 上选的，有在评测集上调参的嫌疑。
  (4) projector 号称核心组件，可在 3B 上去掉它反而更好（72.7 vs 71.1），默认配置在主力 backbone 上并不是最优。
  (5) "传递 advantage"的机制叙事站不住。probe 能分辨 own skill 和 other skill，只说明 hidden state 读到了 prompt，这几乎是必然的。不加 projector 时 alignment loss 和初值相差 ≤0.01，却在 3B 上换来 +6.3，更像通用的 representation 正则。训练时缺一组关键对照：把 teacher context 换成 unrelated text、他人 skill 或 shuffled skill。缺了它，"hindsight 内容被迁移"就是推测，不是结论。
  (6) token OPD 掉 8.6 还有一个没排除的解释：自生成 skill 里带着 outcome，teacher 的 token 概率会把轨迹结局泄漏给 student，不一定是 token 通道"带宽不够"。
  另外，实验只覆盖 text-only、≤3B 模型、150 步训练，GUI 和多模态都没碰。
- **Rating**: `2` 👀 ，通道替换的消融干净、值得关注，但单 seed 加上缺 context 对照，机制叙事撑不住
