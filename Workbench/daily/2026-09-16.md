今天最该带走的是两条**作者自己没当回事的对照**，它们说的是同一件事。RSIAgent 的 GameCraft-Bench 是全文唯一干净的受控实验：同底座同起点，harness 贡献 +5.07 / +11.33 / +14.18 / +12.52，被命名为"自我改进"的那部分只贡献 +3.44 / +3.76 / +3.99 / +3.64，稳定钉在 harness 的三分之一到四分之一。Real-Time EXPO-FT 的 Table I 更狠：delay-unaware 的 RL fine-tuning 拿 18.8/30，和完全不做 RL、只加了 RTC 的 SFT（18.0/30）打平——头条那条 12.5 → 29 里只有约四分之一归本文新机制。两条证据的方向一致：**交付增益的是外围工程，被写进标题的那个机制是小项**。第三条值得单独记的是 Dream-RSI §5.1 的负面消融——把历史压缩成 prompt 里的方向性建议，在等预算下对两种范式**都**更差；历史的价值在于它是可重新检索、重新排序的结构，一旦被总结成语义先验就只剩损失掉的多样性。

## 论文点评

### Atria Dawn
- **Title**: Atria Dawn: The Dawn of Agentic Superintelligence
- **Institutes**: Fudan University, East China Normal University, Harbin Institute of Technology, Institute of Automation CAS, Institute of Software CAS, Renmin University of China, Shanghai AI Laboratory（原文按 "Atria Team" 署名、无逐作者 affiliation，机构列表系据标题区 logo 与通讯邮箱推断）
- **Source**: [link](https://arxiv.org/abs/2609.15818)  🔥 HF Trending ⬆️ 429   **📒 论文笔记**: [[2609-AtriaDawn]]
- **核心**: 在一个 744B MoE 基座（论文引用指向 Z.ai GLM-5.2）上做 agentic post-training，配方叫 Verifiable Experience Pipeline——任务接真实可执行环境，产出用外部信号核验，只有"任务—轨迹—产物—验证证据"链条完整的经验才入训。16 个 benchmark 中 5 项拿到所报最高分，但强项集中在 search/tool-call，SWE-bench Pro、JobBench、Terminal-Bench、GDPval 全面落后 Claude Opus 5。论文真正独有的东西不在模型，而在把自己的研发过程仪器化：56 名参与者的 769 条任务记录加 agent 日志，量化出"agent 提方案、人做决定"的分工——方法/参数决策上人握有 85.5% 最终选择权，目标/范围 93.4%。标题喊 superintelligence，§3.2 与 §5 却在系统性论证 RSI 尚未闭合。
- **锐评**: 这是两篇论文被订在一起：前半篇是 release note，后半篇是一份有真价值的人机协作田野调查。先说前半篇——§2.1 全节三段散文，**零量化**：不给训练数据规模、不给 RL 算法、不给 compute、不给超参、全文零 ablation。更要命的是基座对照彻底缺席：论文引用 GLM-5.2 作基座却从头到尾不报它的分数。也就是说，Verifiable Experience Pipeline 这个全文唯一的方法贡献，**买来了多少增益在表里根本读不出来**。笔记作者自己拿同门 GLM 5.3 做了逐行差值（9 项领先 6 项落后，增益集中在 search/tool-call、terminal 与长程交付反而更弱）——但这是笔记的推算、不是论文断言，且 5.3 ≠ 5.2，只能当弱信号，不能当消融。一个把"经验必须可核验"写进标题性口号的 pipeline，自己的效果却完全不可核验，这个反讽有点大。

  "16 项里 5 项最高分"经不起两分钟的细读。这 5 行里**只有 AutomationBench 七个模型全部有数**（53.8 领先亚军 Qwen 3.8 Max 4.1 分，也是唯一一个在完整对照下的明确胜出）；BFCL v4 缺 3 个竞品、DeepSearchQA 缺 3 个、BrowseComp 缺 2 个、CyberGym 缺 Claude Opus 5，而论文自己写明 "missing results are not treated as zero"——翻译过来就是：所谓"最高分"是在一个由数据可得性决定的子集上定义的。剩下两项的领先幅度是 DeepSearchQA **+0.1 分**、BrowseComp **+0.3 分**，跑在作者自建 harness 上，且不报多 run 方差。0.1 分的"SOTA"不是结果，是四舍五入。Table 1 的 caption 还写着数据取自 "official release website"——竞品数字不是作者跑的。Appendix B 交代的口径混乱同样惊人：Workspace-Bench 上 GPT 系走 Codex、其余走 Claude Code；Terminal-Bench 里所报的 "Claude Opus 5" 在部分任务上**实际回落到 Opus 4.8**；judge 换了五个（Doubao Seed 2.0 Lite / glm-5.3 / Grok-4.3 / GPT-5.5 / GPT-5.2），其中 GDPval 用 glm-5.3 当裁判，而 GLM 5.3 既是表内对比模型、又与 Atria 基座同门。愿意把这些写进附录值得肯定，但**写清楚不等于可比**——诚实地报告一个不可比的比较，结论照样不成立。

  落后的那一半反而最有信息量，因为落点高度一致：SWE-bench Pro 59.6 vs 74.7（−15.1）、JobBench 50.3 vs 68.0（−17.7）、GDPval 1583 vs 1768、Terminal-Bench 2.1 78.3 vs 90.2、τ³-Bench Banking 41.2 vs 55.2。全是长程专业交付与工程执行。一个在 search QA 上赢 0.1 分、在软件工程上输 15 分的模型，跟 "The Dawn of Agentic Superintelligence" 这个标题的距离，比它跟 Claude Opus 5 的距离还远。论文自陈 GDPval 与 JobBench "retain the clearest headroom"——这句克制是对的，只是它没能传到封面上。

  §4 才是这篇该被记住的部分，而且确实做出了新东西。把"谁提议"和"谁决定"拆开量化，是对当下"AI 研究员"讨论里那个粗糙二分的直接纠正：AI 的**提议**份额随决策层级从 16.9%（目标/范围）摆到 55.4%（方法/参数），三倍多的摆幅；而它的**最终决定**份额从头到尾卡在 6.1%–9.2% 不动。变的是谁生成选项，不是谁挑选项。最有说服力的是那个反直觉结果：151 条"无 AI 则不可行"的任务里，人选定最终目标的比例不降反升到 95.4%——最依赖 AI 的任务恰恰是人类判断权最集中的任务，这对"依赖度 = 自主度"构成直接反例，而且这不是能顺手编出来的方向。困难处置的构成同样比频率有信息量：588 条有困难记录的任务中 76.0% 靠人推进，但拆开看是补上下文 35.2% + 诊断换法 34.7%，真正上手的局部编辑只有 3.2%、接管 0.7%——稀缺的是判断不是执行。同一逻辑解释了那条最容易被误读的曲线：action/prompt 日中位数从 11.0 涨到 28.5，作者**自己拒绝**把它读成自主性上升，因为人的决定权份额纹丝不动，所以真实含义是每一次人类判断现在要穿过更长的 agent 工作链。这个"责任还在人手上、可审查性已经跟不上"的剪刀差，比 Table 1 里任何一个数字都值得带走。

  但 §4 的方法学天花板必须认。全部角色归属与"无 AI 不可行"都是**同一批人对自己项目的事后自评**，无对照组、无盲测、无 inter-rater 一致性。"无 AI 不可行"尤其难——它要求受访者对"我本来能不能做成"这个反事实做估计，而提问方是一个正准备发表《Agentic Superintelligence 的黎明》的团队。这个激励梯度不算隐蔽。分母还一路在漂：769 → 739（有明确 AI 回答）→ 455（已完成且可用）→ 588（有困难记录）→ 627（有处置记录），每一步的缺失量和缺失机制都没报告。而且这篇的招牌统计量自己都对不上账：55.4% 在 §4.2 同时被当成"AI 提议+人选择"的联合占比和"AI 的提议份额"两个不同的量用，§5.1 沿用后一种读法，§6 结论又写"567 条方法与决策中 AI 提议 64.6%"——三处原文从未调和。差值 9.2 个百分点恰好等于"AI 最终决定"份额、逻辑上讲得通，但那是**读者替作者补的**。核心数字在三个章节里指称不一致，这不只是校对问题，是分析没走完。另有 95.9% vs 100−1.0−3.2=95.8 的 0.1 点对不齐（不影响结论，但同一节里出现两次算术松动就不是巧合了）。加上样本是同一机构、同一项目、同一个月的 56 人，外推到别的研发组织没有依据——作者自己用的词是 "an initial perspective"，这个定级是准的。

  Case study 那节按作者自陈是 selected demonstrations 而非平均成功率，读的时候要连着图注一起读，因为图注里藏着否定项：天气预报案例做了 >0.4B 参数 ViT、训 45,000 步、建模 69 个气象变量，**图注明写不报预报精度**——没有精度的气象模型是截图不是结果。GDN 的 1.46× 是开发期测量，54 个正式 workload 过了 52 个但缺完整正式均值，这个比值不是 benchmark 分数。CAD 图注同样声明"不是机械或制造验证"。全文没有独立的 Limitations 章节。还有一个没人问但很关键的数字：§2.1 说只有链条完整的经验才入训，却不给筛除比例——如果 curation 通过率很低，环境搭建 + 验证器构造的真实成本才是这个 pipeline 的门槛所在，而这恰恰是唯一完全没披露的部分。

  最后说定位。这是 vault 里第三篇"标题谈 RSI、正文不 claim RSI"的 2026 技术报告（前两篇是 FrontisMA1 只训到 generation 1、NeoHorse1 自陈"递归从未真正发生"）。[[Topics/SelfEvolvingAgents-Survey]] §7.5 早已把这个模式命名为"术语与实物的系统性错位"，所以 Atria 在 RSI 叙事上提供的是第三个确证样本，不是新洞见——它在 survey §7 的框架里甚至连 generation 1 都算不上，因为它根本没做演化搜索。它相对 §7 的真增量只有一处，但这一处 §7 完全空白：**把人在 agentic 研发回路中的位置量化出来了**。§7 谈了半天 credit assignment、parent selection、scaffold vs weights 天花板，全部默认人是循环外的旁观者；Atria 的 769 条记录第一次给出了人在循环内的经验分布。§5.2 那句关于 Codex yolo 与 Claude Code skip-permissions 的坦白——"Convenience, rather than any deliberate allocation of authority, is what set the boundary in practice"——是全文最有价值的一句话，也是对整个行业当前实践最准确的一句描述，比标题诚实一百倍。
- **Rating**: `2` 👀 ，§4 的提议/决定分离与 18:1 信息型介入比是真贡献、值得追踪，但模型那半篇零 ablation 零基座对照、"5 项最高分"里 4 项靠缺项与 0.1–0.3 分的余量撑着，而 §4 本身是无对照的回顾式自评——撑不起封面上那个词。

### RSIAgent
- **Title**: RSIAgent: Autonomous Exploration for Recursive Self-improvement in New Environments
- **Institutes**: Aether AI / UC San Diego / UIC
- **Source**: [link](https://arxiv.org/abs/2609.15364)  🔥 HF Trending ⬆️ 71   **📒 论文笔记**: [[2609-RSIAgent]]
- **核心**: 三个 agent 组成 training-free 循环——curriculum 出练习题、actor（GLM-5.3，code-as-policy）去环境里跑、verifier（Kimi-K3，隔离 context）判 PASS/FAIL，actor 把验证过的经验蒸馏进一组自己写的 markdown 文件；探索分 BRS（并行铺面）与 DRS（顺序钻深）两段，跑完把记忆冻结、关掉写回，再由官方 evaluator 打分。OSWorld 2.0（0808 offline，82 任务）partial 从 71.97 到 78.98，ALE Near-term（67 任务）从 83.75 到 84.82。GameCraft-Bench 上还有一组四 generator 的同底座对照。这套 pipeline 的实物形状是：探索全程被目标 query 条件化，记忆按每道目标任务从空建起。
- **锐评**: 先说标题。按 [[Topics/SelfEvolvingAgents-Survey]] §7.5 那三条判据——generation ≥2、演化系统本身是否被演化、权重更新是否发生在部署后——这篇一条都不满足：Table A3 白纸黑字 "Model parameters: Fixed"，三个 agent 的架构与 prompt 全程不变，记忆评测时冻结。这里的 "recursive" 是 curriculum→act→verify 把输出喂回自己，那叫 loop，不叫 RSI。这已经是该谱系里第三个同形样本（前有 [[Papers/2607-FrontisMA1]] 与 [[Papers/2608-MacaronV1]]），三篇的病灶一模一样：正文和附录把边界划得清清楚楚，标题和 abstract 装作没看见。第三次了，这就不是个别夸张，是这条线的默认叙述方式。

  更要命的是增益归在谁头上。ALE 上 w/o RSI 的 83.75 **已经越过** GPT-6 Astra 的 82.26，RSI 只再加 +1.07——"开源反超闭源"这个卖点在自我改进机制登场之前就完成了，是 harness 交付的；而 ALE Binary 上 RSIAgent 的 50.75 反倒**输给** GPT-6 的 52.24，这条作者自己写在附录 10.4 里。真正干净的对照是 GameCraft-Bench 那张表：同底座同起点，四个 generator 上 harness 分别贡献 +5.07 / +11.33 / +14.18 / +12.52，RSI 再贡献 +3.44 / +3.76 / +3.99 / +3.64。RSI 的边际死死钉在 +3.7，是 harness 的三分之一到四分之一。全文最像受控实验的那组数据，说的是"自我改进"是小项。

  再说主表怎么攒出来的。OSWorld 那一行 82 个任务里只有 41 条是真 RSI 结果，ALE 67 个里只有 19 条，其余保留基线分；而任务分配规则是——只有基线**未拿满分**的任务才获得探索，满分任务原地冻结但仍留在分母。翻译一下：只能跌的被锁住，只能涨的被砸算力。这个估计量在构造上就是上偏的，78.98 / 84.82 不是任何一次统一协议下的系统性能，把它和 leaderboard 上的闭源模型并排塞进一张表是有误导性的。附加折扣还有两条：OSWorld 用的是 82 任务 offline 子集而非完整 108，T082 setup 失败按 0 计入；作者自陈跨系统对比 "does not use a matched evaluation protocol"。

  然后是这个领域早就该过的那道闸：**没有任何 equal-compute / equal-token 对照臂**。基线就是"把探索和持久记忆关掉"，而 RSI 条件额外烧 8+ 个 BRS project、每个 practice 配 2,000 iteration / 86,400 秒上限，全文却没有一个探索阶段的 token 总量、费用或 wall-clock 数字，附录自己承认 "not a matched-budget estimate"。[[Papers/2606-SkillMemoryBudget]] 已经在 WebArena 上用 token-matched vanilla 把三种自积累记忆方法打得全面失守，[[Topics/CUA-Survey]] §7.11 据此定下的规矩是：此后任何 online memory 增益主张默认要求 budget-matched 对照。这篇一条没做。于是 OSWorld 上那 +7.01 里，"记忆结构有用"和"多烧一两个数量级推理算力有用"在数据里无法分离。[[Papers/2607-RethinkSkillEvolve]] 暗示答案是分场景的——多步流程类任务上记忆可能真能保住优势——但那得做实验，不是靠标题。§4.4 那个 Full 74.54 / BRS-only 65.52 / DRS-only 56.50 的消融也撑不住：四个任务选自一个"按已记录基线有改进"筛出来的 cohort，Full RSI 取两次历史评测均值而单阶段条件用单次记录分，条件根本不对齐。

  整个闭环的地基是 verifier，而这块地基**从没被测过**。判对错的信号来自 Kimi-K3 自判，全文没有一个 precision 数字、没有与官方 rubric 的一致率、没有人工抽检比例。同时 §4.6 自己举了 verifier 在字段值无依据时误返 PASS、导致"把缺失数据标记当有效答案"的规则被写进记忆并在后续 run 继续复用的具体案例。CUA 那条线上被反复独立验证的结论是：增益来自验收闸门而不是积累本身（SKILL.nb 去掉 gate，hard subset 回归率 3.3%→18.6%）。这篇把唯一的 gate 交给一个未经量化的模型自判，还观察到它失效——那记忆的净值在更弱的 verifier 底座上完全可能是负的。Figure 5 的失败计数也救不了场，图注写明来自 "selected case audits" 且 "cases may contribute to multiple panels"，那是案例计数，不是发生率。

  "causal" 这层更是纯包装。keyword 挂 "Agentic Causal Discovery"，abstract 承诺可复用的 action–condition–consequence 因果关系，实物是 "a collection of actor-authored files, with no required schema, file count, or length"——一堆自然语言 manual 和失败记录。"causal" 在正文之外只出现在 prompt 模板里，还是软约束（"Make causal claims only when your trajectory and evidence support them"），全文零消融证明这层结构有贡献。删掉这个词，方法一个字都不用改。

  最后一刀落在摊销结构上。记录的三条轨迹 T044 / T049 / T065 **各自从空记忆起步**，DRS 在"探索"期间就在反复攻打那道最终要被打分的题，T044 冻结时记忆已涨到 316,541 bytes。这是按题付费的 test-time search 加笔记，不是"适应一个新环境、之后所有任务共享"。那句 "adapt to new environments" 撑不住，而唯一能撑住它的实验——同一环境内一份记忆服务 k 道任务、报告第 k 道的边际探索成本——恰恰没做。

  夸的部分同样要具体：信息边界这套工程是真货，值得后续 memory 系统直接抄——verifier 看不到 actor 的私有推理与记忆（切断相关误差）、探针跑在 checkpoint 副本上查完即还原（防污染产物）、curriculum 只拿一次性记忆副本且无写权限（防出题人塞答案）、官方 evaluator 在所有 agent context 之外且不回传分数、BRS 同 wave 共享不可变快照判完后串行提交（解并行写冲突）、记忆文件树 hash 校验冻结完整性。记忆会缩也是真信号（T065 一次合并 13,243→11,510 bytes），说明 reconciliation 在重组不是拼接。§4.6 那条"探索打不到点 → 验证不完整 → 错误记忆固化"的失效链是全文信息量最高的部分，[[Papers/2604-ExperienceSafetyRisks]] 那一路关心的正是这个。附录 10.3 / 10.4 的坦诚也远超均值，几乎把自家卖点的所有折扣都写明白了——问题是 abstract 和 Figure 1 显然没收到附录发的通知。
- **Rating**: `2` 👀 ，工程边界和失败审计是真货、GameCraft 那组受控对照也有信息量，但 recursive 与 causal 两层卖点全是空头，主表按构造上偏且零 budget-matched 对照，结论撑不到标题许诺的位置。

### Dream-RSI
- **Title**: Dream-RSI: Recursive Self-Improvement through Evolving Worlds
- **Institutes**: Google, Google DeepMind, University of Maryland College Park, University of Virginia
- **Source**: [link](https://arxiv.org/abs/2609.14858)  🔥 HF Trending ⬆️ 286   **📒 论文笔记**: [[2609-DreamRSI]]
- **核心**: AlphaEvolve 一系把算力全砸在"生成更好的候选解"上，而"在哪条分支上继续、开几条、什么时候停"的 exploration 策略是手写且全程固定的。Dream-RSI 把跑完一轮的 discovery tree 原地冻结成一个 replay simulator——每个节点存着当时的 workspace、产物、评测诊断和分数——让新写的 exploration policy 在这棵录好的树上重走一遍，拿到零执行成本的 off-policy 反馈，再据此改写策略代码放回线上。全程不动任何模型权重，变的只有一段可读的策略代码。在 Lasso path、三个数学优化任务和四个 KernelBench kernel 上，它比同初始化、策略冻结的 Recursive Fixed 用更少的 discovery-agent 调用（Lasso 侧 317 vs 550、1879 vs 3200）拿到持平或更好的结果。
- **锐评**: 核心 idea 是对的，而且是那种"听完就想自己实现一遍"的正确：执行成本已经付过一次，凭什么只用一次。不训 dynamics model、不做额外执行、策略是代码而非权重、选择规则保证 replay 分不退步——这套设计干净得不像一篇 17 作者的大厂论文。§5.1 那个负面消融比主结果更值钱：把历史压缩成 prompt 里的方向性建议，在等预算下对两种范式**都**更差——历史的价值在于它是可重新检索、重新排序的结构，一旦被总结成语义先验就只剩损失的多样性。可惜到此为止，剩下的全是问题。**最硬的伤是 replay 的保真度从头到尾没被验证过，而全文说服力全押在它上面**：策略是在开发它所用的**同一批** replay world 上按平均分选出来的，没有 held-out replay tree，没有"replay 分 vs 线上实际收益"的相关性散点图——这张图是 replay simulator 这个概念能不能承重的唯一判据，成本几乎为零，论文没做。更根本的是覆盖：非 root 节点只有唯一一个录好的孩子，replay 里压根不存在"换个方向会怎样"的反事实，所以被 dreaming 优化的只可能是预算分配、批处理与停止规则，"exploration policy"这个词在本文里比字面窄得多，而论文没把这条边界写出来。**数字更经不起拆**。Pro 侧头条的 3587.1→2931.0，逐列看是 6 个 held-out 里输 5 个；按未加权算术均值反算（笔记推算，非论文陈述），RCV1 一列独贡献 +822.4 ms，Gisette 倒吐 −163.2 ms，剩下四个小数据集合计只动了 −3.1 ms——号称六任务的平均，实际是一个 RCV1 减一个 Gisette，另外四列在均值里连噪声都算不上。而 Avg. 的计算口径论文从未定义。Flash 侧 6 战 5 胜，那一侧的 claim 是真成立的，作者本该只讲这一侧。Table 1 更尴尬：Circle Packing 六方同分到小数点后第六位，Auto Correlation 上 Dream-RSI 输给**自己的** Recursive Fixed（1.456375 vs 1.456001）还输给 AlphaEvolve 和 SimpleTES，加粗的是别人家，论文措辞是 "remaining competitive"；三个任务里对受控 baseline 的净胜只有 Sum Diff 的 +0.0014。差距落在小数点后第四位、而全文零种子、零重复、零 error bar——在这个精度上没有重复实验，增益和噪声就是不可分的。**成本口径也不对齐**：Compute 只数线上 discovery-agent 调用，offline dreaming 里 policy-development agent 的 M 次改写 + 在 t 棵树上的重放评估全是真实 LLM 推理，M 连个数值都没有，全部不计入；replay "negligible cost" 只对 executor 成立，162× 和 1.7× 不是端到端口径，而且随 t 增长 offline 成本至少线性上升。**最朴素的对照缺席**：只有 Recursive Fixed 一个受控 baseline，没有随机重启、没有 Best-of-N、没有"随机 meta-policy 在同一批 replay world 上"的地板。这个缺口在本文格外致命，因为省钱是靠**少花**实现的——317 是在 550 的上限里只用了 317，不是同样花费下做得更好；没有随机对照就无法排除"策略只是学会了变保守"。附带一提，Figure 3(a) 那个 SimpleTES†（Avg. 8318.4，比 SimpleTES 自报的 3804.8 差一倍以上）全文没有任何地方解释 † 是什么，而它正是"两个数量级更少调用"那个对比的分母。笔记 `verification_status: partial` 也得说清楚：C1–C20 有独立 verifier 逐条回原文核对过（还纠了两处误读），但 C21–C23 未经独立核查——其中"超出冻结轨迹宽度/深度的 plan out of support、拿不到 replay reward"这条**若**属实，那"学会省算力"（550→317、110→50）就有个平凡解释：它是目标函数支撑集的产物，不是学到的洞察；同一处摘出的 `pareto.reward = pareto.auc - lambda * parallel_penalty` 与正文 Eq.(1) 的标量 V **若**确非同一函数，那正文的形式化和实际实现就对不上。这两条是本篇最该补的实验与最该补的说明，强调一次：**未经独立核查，不能当结论用**。顺带戳破标题：policy-development agent 及其 prompt 全程固定，只有被它改写的 exploration policy 在变——这是同一层策略被反复替换，不是改进机制本身被改进，与 [[Papers/2607-MetaSkillEvolve]] 的两级递归不在一个量级，RSI 这个词用大了。
- **Rating**: `2` 👀 ，"把跑完的搜索树当零成本 off-policy 评估环境"是可以搬到任何 tree-structured agent search 上的通用原语，但全文没测过 replay 保真度、没有地板对照、单次运行零方差、头条均值被一个数据集撑起——好 idea 配上立不住的证据，值得跟进，不值得相信。

### GAI
- **Title**: Generalized Agent Iteration: One Formal Framework for Iterative Policy Improvement and Recursive Self-Improvement
- **Institutes**: Tianjin University, Shanxi University
- **Source**: [link](https://arxiv.org/abs/2609.13406)  📰 HF Daily ⬆️ 57   **📒 论文笔记**: [[2609-GeneralizedAgentIteration]]
- **核心**: 把 generalized policy iteration 和 recursive self-improvement 写成同一个 evaluation–improvement 循环的两个实例。系统被定义为五组件配置 χ = (π, V, m, U, ρ)，agent 是其中"可被修改的那个子集" Ag；两个 dial 决定坐标——modifier m 在不在 Ag 里（在 = RSI，不在 = GPI），evaluation base ρ 接不接地于 agent 之外（anchored / goal drift / fully self-referential）。用这套坐标重排了 Gödel machine 谱系、fixed outer loop 和 co-evolving evaluator，并把 RSI 的四个 defect 各自钉到一条被违反的 GPI 前提上。全文没有实验、没有定理、没有 ablation，附录只有一张符号表，唯一的经验数字是从 RSIBench-Data 转引的。
- **锐评**: 标题写着 "One Formal Framework"，正文里 theorem / proposition / lemma 一个都没有——全部家当是 2 个 Definition、3 条 Remark、4 张表，唯一像结果的 Eq. 4 自洽条件被作者亲手降级成 "characterization conditions, not enforced updates，没有任何外部机制保证它们成立"。作者甚至自陈 RSI 到 GPI 的归约"是散文而不是带显式假设的命题"。诚实值得加分，但诚实不等于交付：这是一套记号，不是一个能推出新结论的框架。更要命的是坐标本身没有判别力——Table 3 六行里四行挤在 anchored，goal drift 格子里只有 Red Queen Gödel Machine 一个系统，fully self-referential 格子里只有 Schaul 的 position paper 一个条目，作者自己在 §3.3 承认了这点。一个把当今几乎所有实物都塞进同一格、而两个"有意思"的格子基本是空的分类学，眼下真正在工作的只有 Dial 1，Dial 2 的三档没有任何实证张力。最硬的伤是**没有时间轴**：Dial 1 问的是 m 是否*可*改，不问它是否*被*改过、改了几代。于是只跑到 generation 1 的 [[Papers/2607-FrontisMA1]]、[[Papers/2608-MacaronV1]]、[[Papers/2609-RSIAgent]] 与真正多代迭代的 DGM 在 GAI 坐标里完全同格。论文开篇立的靶子是"RSI 这个词被滥用"，结果它给出的判据只是"结构上有没有自改钩子"——而这从来不是争议所在，争议在于有没有人真的递归起来过。用这套坐标写综述，会把"RSI 已有实物"这个结论平白抬高一档。组件粒度也漏了这条线最要紧的边界：DGM 谱系的真天花板是"只改 scaffold、权重冻结"，而 weights 和 harness 都在 π 的 content space 内部，不是五组件里的两个组件，于是这条边界只能写进 Table 3 的括号注——而 [[Topics/SelfEvolvingAgents-Survey]] §7.4 已经把它拆成两个可测量、[[Papers/2608-MacaronV1]] 实测二者差一个数量级。世界与目标被"按假设"固定在系统之外，agent-environment co-evolution 这条 2026 年最活跃的线直接在框架里没有位置，Remark 1 一句"自设任务仍从属于外部目标"就把 proposer-solver 整体归并掉，这是定义性处置不是论证。证据卫生上还有两处自伤：Table 4 给 goal drift 标 "Structural; observed"，§6 却承认"我们是引用它而不是测量它"——该读作 structural-only；转引的 78.26% 更是近乎条件重言（只统计"拿到最好分后仍继续搜索"的 run，而继续搜索则终局要么持平要么更低），真正承重的只有 58.33% 那一半。**但确实有两块该被抠出来留下的**：一是把 agent 从"策略"重定义为"系统里可修改的那部分"，让"改进机制是否属于被改进对象"从修辞变成可判定的二元事实；二是 Remark 2 对 judge 的切分——外部 judge 训得再不忠实也算 anchored，忠实的 judge 一旦进了 Ag 就变 goal drift，标准的**位置**与标准的**忠实度**是两件独立的事，这条写 verifier gating 时能省一整段含混。三是 Minimal Example：同一个 coding agent 的自洽构造在测试 held-out / 放进自己 repo / 换成自我判断三种放置下**全部成立**，而只有第一种服务目标——这是解释"自洽的自我报告为什么不等于真的变好"最省字的例子。跟 [[Papers/2508-SelfEvolvingAIAgentsSurvey]] 是正交不是替代：那边按 model/memory/tool/workflow 的演化对象切，GAI 把"改进机制本身在不在优化对象里"提成一等坐标，代价是对 memory、tool、prompt 一个字不谈。
- **Rating**: `2` 👀 ，Remark 2 与 Minimal Example 是真能拿来用的两把刀，但"formal framework"零定理零实验、坐标里四分之三的格子是空的、且判不出"改过几代"这条最关键的差异——当词汇表可以，当结论生产装置目前一无所出。

### PhysBrain 1.5
- **Title**: PhysBrain 1.5: From Vision-Language Models to Physical Foundation Models
- **Institutes**: 全文无任何机构 affiliation，署名仅 "DeepCybo Team" + 53 位按姓氏字母序排列的 contributor
- **Source**: [link](https://arxiv.org/abs/2609.14973)  🔥 HF Trending ⬆️ 175   **📒 论文笔记**: [[2609-PhysBrain15]]
- **核心**: 把 embodied understanding、末端动作、未来视觉状态三类输出压成同一套离散 token，挂在 Qwen3-VL-Instruct 8B 的同一个 embedding table 与 LM head 上，用同一个带 mask 的 next-token prediction 训练；动作侧是自研 ActionPiece（512 词表、每腕 32 token、H=16 的 10 维相对 EEF chunk），未来状态侧是 RGB/depth/robot-mask 三模态按空间位置交错的 VQ token（16,386 词表、770 token）。embodied 预训练监督全部来自人类交互视频（约 30,000 小时 curated、97.2M 样本），机器人与仿真数据只在 SFT 阶段进入。作者自建统一口径重跑 28 个 embodied understanding benchmark，8B 拿到 overall average 72.5，开源第一（次优 Hy-Embodied-VLM-1.0 66.0），略低于最低 thinking 档的 GPT-6-Astra 73.3 与 Gemini 3.6 Flash 73.0。动作与未来帧两条支柱只有定性可视化和 perplexity 曲线，没有任何闭环成功率。

  更难看的是执行侧的净倒退。PhysBrain 1.0 在 OpenWAM 的附录里作为 VLA baseline 有 RoboCasa-GR1 64.5 的数字，1.5 一个策略成功率都没有。同样从人类 egocentric 视频出发的 EgoSteer 用 9.6K 小时交付了 40 任务 75% 真机成功率，本文把人类数据推到约 30,000 小时 curated，然后不回答"规模换来了什么"。动作侧唯一的量化证据是 perplexity：ID 17.12→5.07、held-out RoboDojo 12.39→6.57。注意 OOD 的起点（12.39）本来就低于 ID（17.12），两条曲线跨源根本不可比，"OOD 也在降"只能读成"该源的 token 分布被逐渐拟合"。更要命的是所有轨迹预测都以 ground-truth 前序 16 步 chunk 为条件，而论文最有 taste 的那个设计——拒绝全局坐标归一、改用动作历史做隐式 system identification——恰恰把待证命题塞进了输入：前序 chunk 直接泄露了该源的局部坐标约定。论文自己说 z⁻ 是 optional，那就把它消掉再测一遍啊。不做，"隐式系统辨识"就只是"抄前一段的坐标系"的体面说法。

  "open-source SOTA" 这个数也要打折。SFT understanding 混合里至少九个是被测 benchmark 的官方训练集（RefSpatial-Train、RoboSpatial-Train、MindCube-Train、RoboVQA-Train、SAT-Train、EgoPlan-IT…），另有 VLABench / ShareRobot / PixMo-Points 以无后缀形式列入。**按笔记对 Table 4 的重算（非论文陈述）**，相对 Hy-Embodied 的 6.55 分总差里 56% 集中在 VLABench(+25.5)、Part-Affordance(+21.2)、MindCube(+20.8)、RoboVQA(+20.3)、EgoPlan-Bench2(+14.6) 五项，其中四项的同族训练数据就在混合里；相对 base model 涨幅前五（MindCube +52.3、VLABench +31.6、EgoPlan-Bench2 +30.0、Part-Affordance +27.6、Q-Spatial +26.7）是同一个形状。行业都这么干不假，但正因为都这么干，这张表度量的是各家 SFT 混合与这 28 个测试集的重合度，不是 embodied 理解能力。全文 "contamination"/"overlap" 0 命中，一个字不提。

  真正好笑的是它自己给出的反例：RefSpatial-Bench 训了训练集还是开源第 6（50.9，落后 RynnBrain1.1 的 63.2 整整 12.3 分），SAT 上比 Hy-Embodied 低 2.0，ERQA 低 3.5。这说明同族训练不自动兑现位次，也说明 referring-spatial 上有真实能力缺口——最该被一次 ablation 解释的地方，恰恰是空白。

  对照的公平性两头不靠，得两边都说。吃亏的一侧：Hy-Embodied-VLM-1.0 是 30B total / 3B active 且开 thinking，Cosmos3 Nano 是 8B+8B，PhysBrain 是 8B dense 无 thinking，active 参数和推理预算上本文确实是弱势方。占便宜的一侧：闭源一律按**最低** thinking 档评（Gemini minimal / GPT low / Claude adaptive-low），所以 abstract 的 "on par with GPT-6-Astra and Gemini 3.6 Flash" 的准确读法是"与低思考预算下的它们差 0.8 / 0.5 分"，既不是持平也不是超越。而全文没有一条误差棒——variance / standard deviation / error bar / confidence interval 全文 0 命中，通用多模态那侧还是 temperature 0.7 / top-p 0.8 的随机解码单 seed 单跑，embodied 表的解码设置干脆没交代。0.5 分的差在这个预算下不具备可判别性，却被用来撑 "on par"。另外 Overall Average 是 28 项非加权宏平均，五个能力组的 benchmark 数是 2/9/6/9/2，spatial 与 grounding 两组独占 18/28 权重；**笔记按组内等权重算后**确认五组全进开源前二（grounding 与 trajectory 两组是第 2），但两种口径的领先幅度差很多，后人引用必须注明。

  该记功的也得记。§5.3.1 末尾与 Fig. 4 图注两次主动写明"这是与 ground truth 的对比，不是执行 rollout""是离线轨迹预测，不是闭环执行或整任务成功"；Fig. 5 点明各例保留各自源的坐标约定；Appendix B.3 点明 ID 测试集与训练集共享数据源、RoboDojo 全部带 ground-truth history。在一个把 unified physical foundation model 写进标题的报告里，宁可把动作与预测降级为定性说明也不去拼一张 LIBERO 表充数——这个自律在同类技术报告里罕见。B.1.2 把十个 point benchmark 原本 precision-only / recall-only 的异质口径统一成 micro-averaged F1、并修正 RoboRefit 的 instance mask，同样是给自己加难度。代价是这张表从此与既有文献不可比，2026 年 9 月之后 embodied brain 榜单多出第二套互不兼容的口径。

  跟前作对齐后，本文的真实增量只剩两条。"语言 + 动作码同词表、单一 next-token CE、单 decoder"不是贡献，G0.5 早做了，还是在同数据同算力的真机对照里做的（76.7% vs π0.5 53.3%）；人类 egocentric 视频显式重建成统一 state-action 也不新，EgoSteer 的 EgoSmith 做过。剩下的是：(a) 把未来视觉状态也折进同一个 LM head，且用三模态按空间位置交错的序列化，这个形式确实新；(b) 人类视频推到约 30,000 小时且 embodied 预训练完全不含机器人数据。但 (a) 只有 Fig. 6 的几帧图，没有 FVD / PSNR / LPIPS，没有任何 video prediction 或 world-model baseline 对比，也没有"预测帧能否用于下游"的证据；(b) 没有"预训练加不加机器人数据"的对照。两条增量，零量化证据。通用能力那侧 12 项 7 降 5 升，MVBench −2.46、MME −62.6、ScreenSpot 91.59→90.17，"retaining general multimodal capabilities" 成立在"没塌陷"的意义上，不是没代价。顺手一提，§5.2.2 把交叉引用写成 "As shown in Table 6 and Table 6"，HTML 与 PDF 皆然。

### RealTimeVLA-RL
- **Title**: Reinforcement Learning for Real-Time Vision-Language-Action Policies
- **Institutes**: Stanford University
- **Source**: [link](https://arxiv.org/abs/2609.18207)  📄 arXiv   **📒 论文笔记**: [[2609-RealTimeExpoFT]]
- **核心**: 大 VLA 推理慢，执行时用的观测已经过期，于是 RL 的 Bellman backup 建在一个非 Markov 的过程上。这篇把慢与快拆成两条时间线：VLA 提前 d 步异步采样 32 个候选 action chunk，一个零延迟的小 edit policy 在执行时刻读最新观测给每个候选加一个 [-β, β] 有界增量，action critic 从 64 个候选里 argmax 选一条执行；chunk-level TD backup 靠一个在 noise 空间打分的 filter critic 预筛，使每次 backup 只 decode 一次 VLA。Kinetix 4 步延迟下平均 96.2%，DROID 真机四个动态任务在 10 分钟在线数据预算内从 SFT 的 12.5/30 做到 29/30。真正值钱的数字不在 abstract 里：delay-unaware 的 EXPO-FT 拿 18.8/30，和完全不做 RL、只加 RTC 的 SFT（18.0/30）打平。
- **锐评**: 问题抓得准，这是全文最值得肯定的地方——[[Topics/VLA-Survey]] 里 real-world RL（[[Papers/2511-PiStar06]] 的 RECAP）和部署延迟（[[Papers/2604-Pi07]] 训练时注入 0–12 step delay、[[Papers/2604-SnapFlow]] 274→83 ms）一直是两条各走各的线，这篇第一次证明它们不独立：在动态任务上延迟感知不是 RL 的增益项，是 RL 能不能起作用的开关。这条结论比头条有价值得多，也比 [[Papers/2607-VLACorrector]] 那种 training-free 截断重去噪彻底，因为 edit policy 是被 Q-value 训出来的，每个执行步都在动。**但 abstract 在撒谎的边缘。** 那句「10 out of 10 environments 上优于 delayed 与 non-delayed 方法」被自己的 Table II 反驳（笔记 C2 标 contradicted）：10/10 只在「0.95x 最优 RL 结果」这条容差带里成立，而该加粗规则白纸黑字把 BC 和 RTC 排除在比较外——作者转头又把被排除的 BC 算进「non-delayed methods」。逐格严格取最高，全列口径是 6/10，仅比 RL 方法是 7/10；Cartpole Thrust 98 输给零延迟 BC 的 100，Hard Lunar Lander 94 输给 95，Chain Lander 92 输给 DSRL w/RTC 的 96。头条的 42% → 97% 同样是挑软柿子：12.5/30 的起点是作者自己设的（SFT 训到「around 30% or higher」就停），对最强基线 EXPO-FT w/RTC 的真实边际是 25 → 29，也就是 12.5→29 这条链里只有四分之一归本文的新机制。更要命的是，「base + edit 的组合相对 s_t 重新变回 Markovian」是整套设计的全部合法性来源，§IV-A 用一整段把非 Markov 性立成问题，§IV-B 用一句话宣布解决，没有推导、没有成立条件、没有指向附录——而这句话要成立显然需要 edit 覆盖得了 base action 与最优动作之差，偏偏 edit 被硬压在 [-β, β] 里，论文连一次 β 敏感性扫描都没做。其余问题按分量排：Kinetix 那 10 个环境里根本没有 VLA，base 是 state-based flow policy + MLP encoder，这组实验支持不了任何关于 VLA 的断言，而它恰恰是唯一带强量词的实验；真机每格是单次 30 trial，无 seed、无重复、无误差棒，28/30 对 23/30 这种差在二项噪声下并不宽裕；四个真机任务里三个的延迟是往 67 ms 上人为加 100 ms 造出来的，只有 Dynamic Picking 跑在实测部署延迟上；§VII-F 承诺要报的 baseline 实测 optimizer step 数全文没有出现，于是「梯度不对齐但有利于 baseline」只是一句口头担保；§II 点名的 VLASH、FutureRTC、Leave No Observation Behind 等四条 real-time 路线一条都没比，而唯一进 baseline 的框架、noise filtering 全是同一第一作者三个月前的前作——所谓 SOTA baseline 就是作者自己。最后，项目页 Paper / arXiv / Code 三个按钮 href 全是 `#`，BibTeX 还是 `author={Author One and Author Two}` 的占位模板，这套异步 rollout + noise-space filtering 的工程栈靠附录复现不现实。
- **Rating**: `2` 👀 ，延迟感知是 VLA RL 前置条件这条对照值得所有做真机 post-training 的人看一眼，但核心机制断言无推导、旗舰量词被自家表格反驳、仿真无 VLA、真机单次跑，够 Frontier 不够 Foundation。
