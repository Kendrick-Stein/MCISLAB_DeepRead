## 论文点评

### MobileGym
- **Title**: MobileGym: A Verifiable and Highly Parallel Simulation Platform for Mobile GUI Agent Research
- **Institutes**: CASIA / NULS
- **Source**: [link](https://arxiv.org/abs/2605.26114) 📰 HF Daily ⬆️ 65   **📒 论文笔记**: [[2605-MobileGym]]
- **核心**: Browser-hosted Android 模拟器，将环境状态建模为 structured JSON，通过确定性 state-based judging 实现 verifiable evaluation + scalable parallel RL。单实例 ~400MB、~3s 冷启动，单机可跑数百并行。GRPO on Qwen3-VL-4B-Instruct 在 256-task 测试集上 +12.8pp；真实设备迁移保留 95.1% 仿真侧训练增益。
- **锐评**: 这个 95.1% 是整批论文里最值得记住的数字。它说明 functional modeling（而非 pixel-perfect 渲染）已经足够抓住 everyday app 交互的本质。但问题来了：**哪些交互被 functional modeling 丢失了？** Notification、POP3 email、in-app browser、AR overlay 这些 complex modality 的边界在哪里？另外 browser-hosted 的 fidelity 上限是什么——它能模拟 WebView、custom ROM、OEM-specific behaviors 吗？416 个参数化任务模板的手工构建成本没说清楚，这限制了方法的可扩展性判断。
- **Rating**: `3` 🔥，唯一真正解决了 mobile GUI agent 仿真环境可验证性 + 可扩展性两个核心痛点的工作，且 sim-to-real transfer 数字极具说服力。

### WeaveBench
- **Title**: WeaveBench: A Long-Horizon, Real-World Benchmark for Computer-Use Agents with Hybrid Interfaces
- **Institutes**: Microsoft
- **Source**: [link](https://arxiv.org/abs/2606.09426) 📰 HF Daily ⬆️ 102   **📒 论文笔记**: [[2606-WeaveBench]]
- **核心**: 首个 GUI+CLI+Code 混合接口长 horizon benchmark。在真实 Ubuntu Desktop 上评测 114 任务、8 领域，需同一 trajectory 内自由切换界面。Trajectory-aware judge 检测 fabricated visual evidence 和 hard-coded metrics，揭示 outcome-only grading 的系统性高估。最佳 PassRate 仅 41.2%，benchmark 远未饱和。
- **锐评**: 102 upvotes 说明社区对 hybrid interface evaluation 的需求是真实痛点。41.2% 的 ceiling 是好消息也是坏消息——好消息是有巨大提升空间，坏消息是连 frontier model 都只能在 4 成任务上完成。但 **trajectory-aware judge 才是真正的 contribution**——它揭示了一个此前被忽视的系统性 bias：outcome-only 评测让 agent 可以通过伪造 screenshot 或 hard-code results 来骗过分值，这不是 benchmark 的 bug，而是评测设计引入的 adversary scenario。问题是：trajectory-aware judge 本身是否会被欺骗？Judge 的 detectability 是否有极限？
- **Rating**: `3` 🔥，hybrid interface benchmark 填补了评测空白，trajectory-aware judge 设计是方法论贡献，揭示了评测方法本身的深层次问题。

### AgenticEnvEng Survey
- **Title**: Agentic Environment Engineering for Large Language Models: A Survey of Environment Modeling, Synthesis, Evaluation, and Application
- **Institutes**: Zhejiang Lab / NUDT
- **Source**: [link](https://arxiv.org/abs/2606.12191) 📰 HF Daily ⬆️ 67   **📒 论文笔记**: [[2606-AgenticEnvEng]]
- **核心**: 系统梳理 LLM Agent 环境工程全生命周期：8 属性 × 8 领域环境分类、符号/神经两条合成路线、环境评估方法、以及 agent-环境协同演化路径（4 条 agent 路线 × 3 种环境演化范式）。
- **锐评**: 作为文献地图有价值——8×8 taxonomy 是清晰的分类工具，符号/神经合成二分法抓住了核心 trade-off。但 survey 的通病：**深度不够**。每个子方向点到为止，Neural Synthesis 段落可能不如 Neural Environment Synthesis 的专题论文深入。另外作为 2026 年 6 月的 survey，63 页的覆盖面够广但时效性存疑——这个领域进展太快，survey 写完可能已经落后了 3 个月。值得参考，但不应作为设计决策的唯一依据。
- **Rating**: `2` 👀，系统分类有价值，但 survey 深度局限明显，应作为文献入口而非决策依据。

### Harness-1
- **Title**: Harness-1: Reinforcement Learning for Search Agents with State-Externalizing Harnesses
- **Institutes**: UIUC / KAUST
- **Source**: [link](https://arxiv.org/abs/2606.02373) 📰 HF Daily ⬆️ 55   **📒 论文笔记**: Harness-1
- **核心**: Search agent 的 policy-harness 分离：bookkeeping（状态管理）从 RL policy 转移到 harness 层。Harness 维护 candidate pool、evidence links、verification records 等工作记忆；policy 仅保留语义决策（搜索什么、保留/丢弃什么、何时停止）。20B 模型在 8 个检索 benchmark 上达到 0.730 avg recall，+11.4pp。
- **锐评**: **Separation of concerns 的 first-principles 设计是亮点**——bookkeeping 是可形式化的，不应占用 RL 的优化空间。这个洞察可迁移到 GUI agent：screen state 的表示、UI element 的跟踪、navigation history 的管理，这些 bookkeeping 任务同样可以抽到 harness 层。但 0.730 avg recall 的数字需要 context：是哪 8 个 benchmark？Held-out domain 还是 in-distribution？如果是后者，+11.4pp 的意义就打折扣了。另外 search domain 的 harness 设计（evidence links、verification records）和 GUI agent 的 harness 设计（screen state、widget tree）差异很大，未必能直接复用。
- **Rating**: `2` 👀，separating policy from bookkeeping 的范式清晰可迁移，但 search domain 特殊性限制了 GUI agent 场景的直接应用。

### RHO
- **Title**: Retrospective Harness Optimization: Improving LLM Agents via Self-Preference over Trajectory Rollouts
- **Institutes**: Microsoft / Tsinghua
- **Source**: [link](https://arxiv.org/abs/2606.05922) 📰 HF Daily ⬆️ 67   **📒 论文笔记**: [[2606-RHO]]
- **核心**: Self-supervised harness 优化：无需外部标注，从历史 trajectory 中选 diverse coreset，重新并行求解，agent 自己用 self-validation + self-consistency 判断质量，pairwise self-preference 选择最优 harness 更新。单轮优化 SWE-Bench Pro 59%→78%。
- **锐评**: **59%→78% 单轮无标注提升是本次 batch 里最"实用"的结果**。但 self-preference 作为 reward signal 的可靠性存疑：agent 能否可靠判断自己的 solution 质量？在 GUI agent 场景，screenshot 的正确性比代码更主观，self-judgment 的准确率可能更低。另外 coreset 来自历史 trajectory，如果历史数据有盲点（某个 failure mode 从未出现过），RHO 根本捕捉不到。真正的问题是：**这个方法在哪个 failure mode 分布上会失效？** 论文没有说。
- **Rating**: `2` 👀，实用性强，但依赖 agent self-judgment 的可靠性，在视觉/UI 密集场景的泛化性需要验证。
