Overview

一个 web agent 的 RL 训练能否带来增益，在训练开始之前就已经由三件事决定：策略是否还有 sampling headroom、环境能否以足够吞吐提供可复位的 rollout、奖励判官的噪声是否小于期望增益；具体用哪一种 GRPO 变体是次要变量。

区分这一族工作的四条轴：

  • 交互方式：live rollout（策略在环境里在线采样，奖励来自环境或判官）/ 离线动作匹配（在 teacher 轨迹或筛选过的关键状态上做 step-level 对齐，训练期不执行浏览器；AutoWebWorld 的 GRPO 虽在合成站上生成数据，训练时也属此类）。这是第一级分类轴，因为它决定了方法的上限是环境可达的成功率还是 teacher 的成功率。
  • 环境供给：Docker 复刻站（WebArena 系）/ 轻量容器（WebServ）/ 真实互联网（WebGym、OpenWebRL、AliyunConsoleAgent）/ HTTP 缓存与 LLM 合成站（Weblica、VeriEnv、WebFactory、Trustworthy Worlds、AutoWebWorld、InfiniteWeb）/ 学出来的 world model（DynaWeb、DreamGym）。每一种都在吞吐、可复现性与奖励可验证性之间取舍，目前没有一种同时满足三者。
  • 奖励来源：程序化规则（MiniWoB++、WorkArena 的 cheat 函数）/ 后端或插桩状态（云审计日志、数据库谓词、InfiniteWeb 的代码插桩 evaluator）/ 训练出的 ORM（WebRL，自报约 80% 准确率）/ LLM 或 VLM judge（OpenWebRL、WebGym、Weblica、DynaWeb、OpAgent）/ step-level PRM（WebArbiter、CLIFT、TGPO）/ 主动核验 judge（VeriCUA，桌面训练、web 评测）。judge 的误判率与 RL 增益常在同一量级，这使得多数跨论文数字不可直接比较；在 WebArena-Verified 上，连经 RL 训练、可在环境里主动取证的 judge 与可执行 evaluator 的一致率也只有 62.75%，比同一 judge 在 OSWorld 上低约 20 点，web 是三类平台里最难核验的。
  • 起点：SFT 热启动的必要性随 base 能力变化，不是一条与规模无关的铁律。≤8B 的 VLM 上，无 SFT 的 RL 失败或接近零增益（WebAgent-R1 3B 6.1→4.8；Statistical Diagnosis 在 WorkArena 上 RL-only 等于 Instruct 基线；OpenWebRL 4B 从 base 直接 RL 在 hard 子集上只有 +2.3 对 SFT 起点 +22.3，整体全程落后约 10 点），Weblica 在 2B/4B/8B 三个规模上 SFT→RL 都高于 Base→RL；但 32B 的 Thinking 模型（OpAgent）不经 SFT 直接在 WebArena 上做 RL 拿到 +10.7 pass@5，AgentGym-RL 的 7B 在自选 27 任务子集上也到 26.0。SFT 的作用不是加速而是把策略放进更好的行为区域（OpenWebRL 的表述），这一优势在 ≤8B 上到训练结束都没有被 RL 抹平。

证据结构有两个系统性偏斜。第一，sandbox 结果与 live 结果不互通：sandbox 上有竞争力的方法在 Online-Mind2Web 上可以低到个位数（Go-Browse WebArena 21.7 对 Online-Mind2Web 5.33），而 live 站点的成功率又随时间漂移。第二，判官是 benchmark 的一部分而非中立测量：RMSWeb 复核 WebTailBench 原生 judge 的失败判定后发现大量 false negative，其中 42% 源于 judge 只看 DOM 证据，作者因此换用自家 judge，其数字从此不与其他 harness 可比；VeriEnv 自己的程序化验证器实测只有 76% 正确。本文所有横向数字都应在”同 judge 同时期”条件下读。

范围限于浏览器内的 web/GUI 任务。deep-research 式 search agent（AEPO）、桌面（2508-ComputerRL）与移动端（2502-DigiQ）只作为边界证据引用。桌面侧 2026 年 10 月的一批 GUI RL 工作（Adaptive-Group Process Rewards、VeriCUA、MAI-Gym、2610-SoftwareGym）与 WebShop 文本环境上的 agentic RL（2609-PROPD、2610-SRD、2511-AgentPRM）同样只作边界证据：前者回答”web 上缺的对照在桌面有没有”，后者回答”无 SFT 的 GRPO 在简化环境里是否成立”。更广的 GUI RL 综述见 CUA-Survey §7.6–7.8 与 2604-RLGUIAgentsSurvey；trajectory-level reward 如何分解到步的机制讨论见 StepCreditAssignment-Survey，本文不重复。

技术路线

Web RL 的问题结构在 LLM 之前就已经定型。MiniWoB（Shi et al. 2017）把网页任务缩成百余个小程序化环境，奖励由任务代码直接给出；WGE（Liu et al. 2018, arXiv 1802.08802）发现纯探索在这些环境里几乎学不到东西，必须用少量演示约束探索空间，论文称相对 behavioral cloning 的样本效率提升超过 100 倍；DOM-Q-NET（Jia et al. 2019, arXiv 1902.07257）把 DOM 当图做 Q-learning。三者留下的遗产是今天仍然成立的三条约束：状态要结构化、探索要被演示引导、奖励要可程序化验证。WebShop（2022）把场景放大到电商 sandbox，2307-WebArena 再把它放大到五个 Docker 复刻站。LLM 时代改变的是策略来自预训练模型，因而瓶颈从表示学习转移到环境吞吐与奖励可验证性，这正是 2025 年之后四条路线分化的原因。

路线 1：Live rollout 多轮 GRPO 族

这条路线从 2411-WebRL 开始。WebRL 的贡献不是算法而是闭环：失败任务被改写成新任务形成 curriculum，一个训练出来的 ORM 替代人工标注，KL 约束的 actor-critic 防止策略漂移，Llama-3.1-8B 在 WebArena-Lite 上从 4.8 到 42.4。它的 8B ORM 在 WebArena-Lite 测试集上自报约 80% 准确率、高于 GPT-4 与 GPT-4V 直接判定（Table 3），这一数字此后没有被任何工作独立复核；所有验证都在 Docker 沙箱内。Table 1 还给出同一 SFT 起点下的一组基线：Llama-3.1-8B 上 Filtered BC 23.0、AWR 28.5、DigiRL 30.3 对 WebRL 42.4，GLM-4-9B 上 24.8、27.9、31.5 对 43.0，是库内最接近”同模型下在线对离线”的数字，但这些基线都不是路线 2 的 teacher 动作匹配，且 Filtered BC 与 AWR 的训练数据来源原文表述不足以确认为同数据离线版本。WebAgent-R1 把这一套简化为 M-GRPO：多轮交互、二值 outcome reward、动态上下文压缩，Llama-3.1-8B 到 44.8，与 WebRL 持平而少了 ORM 与 curriculum。最有信息量的不是主结果，而是两个消融：不做 SFT 直接 RL 时 3B 模型从 6.1 掉到 4.8，说明 RL 不能从零注入能力；用 long-CoT SFT 起步时 RL 增益从 13.9 点缩到 5.8 点，说明起点越强、RL 可重塑的空间越小。

后续工作沿两个方向推进。一是把环境换成真实互联网：2606-OpenWebRL 在 K8s 沙箱里跑真实站点，平均从 52.0 到 68.4，但 51% 的失败来自 bot detection，约 300 B200 GPU 小时；2606-WebGym 把任务供给扩到 292,092 个，但它用的无 baseline REINFORCE 在数学上等价于 filtered BC；2606-AsyncWebRL 用异步 rollout 池把吞吐提高 2.4 到 2.9 倍，并指出按轨迹长度归一会让长轨迹在梯度里占比膨胀，改按固定 k 归一。二是把 reward 建在后端：AliyunConsoleAgent 用云平台的 ActionTrail 审计日志判定资源是否被正确创建，双 LLM judge 兜底无日志的任务，与人工一致 96.7%；它也是这一族里少数报告置信区间的工作，GRPO 对 SFT 的增益 CI 为 [2.97, 9.64]，但环境与数据私有。

这条路线的支撑边界由两篇诊断性工作给出。Statistical Diagnosis 用 Llama-3.3-70B 做 teacher、8B 做 student，在 1,370 组配置上 bootstrap：MiniWoB++ 上 SFT+RL 用约 55% 的算力达到纯 SFT 的峰值，但 WorkArena held-out task 上 SFT+RL 28.8±2.0 对 SFT 26.4±2.0，差值小于合并标准误（按 Table 1 推算，原文未作显著性判断），且 33 个任务里 14 个从未被解出；curriculum 与 error log 只在没有 SFT 热启动时有用。2607-GRPONullWebAgent 则在 11 个 MiniWoB 任务、5 个种子、18 组配置下得到 null：SFT 49.1 对最佳 GRPO 52.7，p = 0.50；学习率像开关，1e-6 量级无事发生，1e-5 降 15.8 点，2e-5 崩到 0，机制是后层有效秩从 9.2 坍缩到 1.2。同一 pipeline 在仍有 headroom 的任务上从 20.0 到 42.0，给出可操作判据：训练前测 sampling 成功率与 greedy 成功率之差。

继承的假设：环境可复位且可采样数千次；outcome 判官的噪声小于期望增益；存在可用的 SFT 起点。遗留的研究债：方差报告普遍缺失（WebAgent-R1、AgentGym-RL、WorkForceAgent-R1 均未报），超参数 G 与训练步数常不披露，benchmark 子集由作者自选。2509-AgentGymRL 宣称无 SFT 可行且在 WebArena 27 任务子集上到 26.0，用的是 Qwen2.5-7B 与自选子集；OpAgent 则在 Qwen3-VL-32B-Thinking 上不经 SFT 直接在自托管 WebArena 上做 RL，pass@5 从 27.4 到 38.1，奖励是规则式决策树 RDT 的过程奖励与 Webjudge 三维打分（任务完成、动作有效、轨迹效率）的混合，但任务数、步数上限、judge 准确率与方差都未报告，pass@5 也放大了对弱基线的差距。把这两篇与 OpenWebRL 的 Fig 2（4B 从 base 直接 RL 在 hard 子集上 +2.3，SFT 起点 +22.3，增益集中在 easy / medium；整体上 SFT 起点的约 10 点优势到训练结束都在）和 Weblica 的 Fig 5（2B/4B/8B 上 SFT→RL 分别 24.1/35.2/39.2，均高于 Base→RL）合看，“无 SFT 是否可行”不是一个有统一答案的问题：它由 base 的 sampling headroom 决定，≤8B 的 VLM 在 WebArena 级任务上没有足够 headroom，32B 的 Thinking 模型有。这与 GRPONull 的 headroom 判据是同一件事的两面。AMBER 补了一个长程记忆维度，9B 上比 WebAgent-R1 复现高 8.5 点，但 zero-shot 全上下文 Qwen3.5-9B 就有 34.22，高于训练后的 WebAgent-R1 复现 28.35，论文没有解释，也没有”全历史 + 同样训练”的对照。

路线 2：离线 step-level RL 与动作匹配

这条路线的共同特征是训练期不执行浏览器。WorkForceAgent-R1 在 WorkArena 上做单步 GRPO，reward 是动作与 cheat 函数真值的匹配，14B 从 23.79 经 SFT 30.20 到 46.79，3B 从 2.62 到 36.85；但测试与训练同分布，dense reward 诱发了作者自己记录的 reward hacking。RMSWeb 更进一步：用 GPT-5.1 收集带反思的轨迹，挖掘出 4.5k 个失败关键状态，在这些状态上做 step-level GRPO 变体 Salvage-DS，Qwen3-VL-8B 在 WebVoyager/Online-Mind2Web/WebTailBench 上从 SFT 的 82.7/59.4/55.4 到 86.4/66.4/57.7，而在全量语料上做同样的 RL 只有 84.4/60.8/53.0。WebFactory 在 10 个合成站上用 teacher 轨迹做 replay buffer，reward 是 click 是否落入真值框或文本 F1，3B 在三个真实站上从 20.4 到 53.4。

把这三篇放在一起读，结论是它们的增益来自状态筛选而非探索。Salvage-DS 的”全量不如筛选”直接说明这一点；WebFactory 的 reward 对齐的是 teacher 动作而非环境状态；WorkForceAgent-R1 的 reward 来自真值函数。它们在形式上是 GRPO，在效果上是分级奖励的离线蒸馏，接近 hard-state filtered BC。上限因此是 teacher 或真值的成功率。2408-AgentQ 是这条线的前身，用 MCTS 加自评生成偏好对再做 DPO，OpenTable 上配推理期 MCTS 到 95.4，但没有 MCTS 时增益有限；2509-TGPO 把树结构偏好用到 web 任务上，库内笔记只到摘要层，无数字可引。

AutoWebWorld 是这条线最新也最容易被误读的成员。它把 29 个合成站建成有限状态机，用 BFS 在状态图上生成任务与轨迹，再以到达 FSM 目标状态为准回放校验，得到 11,663 条轨迹、每条 0.04 USD；随后的 GRPO 不在站点上采样，奖励是动作类型匹配、坐标与 ground truth 的归一化距离和格式三项，与 WebFactory 的 teacher 动作对齐同构。7B 在 15 步上限的 WebVoyager 上 27.42，与 UI-TARS-1.5-7B 的 26.51 持平；Online-Mind2Web 随训练数据从 8 条到 16,253 条由 1.22 升到 14.02，是路线 2 唯一的数据 scaling 曲线。它的贡献在数据侧：FSM 让”轨迹是否正确”可程序化判定，解决了路线 2 的 teacher 来源问题；但训练形式仍受 BFS 轨迹成功率的上限约束，FSM 终态没有进入 RL 奖励。

继承的假设：teacher 或真值可得；测试分布与 teacher 轨迹分布相近。遗留的研究债：没有一篇在同模型同 benchmark 上与 live rollout 直接对照；DynaWeb 复现的 WebRL-offline 在 WebArena 上 26.7，而 WebRL 原文在线版 42.4，两者 backbone 不同，不构成对照。优点是对环境吞吐零要求、训练稳定、小模型增益最大；缺点是不能超过 teacher，dense shaping 下有 hacking 风险，且 RMSWeb 的附录 B 复核原生 judge 后发现 false negative 的成因可归类（42% 只看 DOM 证据、37% 截图读取不全、21% 推理错误），作者因此换用自家 judge，WebTailBench 上的增益不能与其他 harness 的数字对照。

路线 3：环境供给

WebArena 系 Docker 站是 RL 的瓶颈。2510-WebServ 量化了它：单实例启动 8.96 秒、6.78 GB，换成 Incus 加 ZFS 写时复制后 1.78 秒、28 MiB、200 路并发，但没有做端到端 RL 实验。2511-DreamGym 的作者在 WebArena 侧只能跑 4 路并行 session。2608-EnvHarness 把可用环境限定为有 reset 与 step 接口的 gym，live GUI 被排除在外。三条解法从这里分化。

第一条是真实互联网。2606-WebGym 从 127,645 个站点生成 292,092 个任务，2606-OpenWebRL 用 K8s 沙箱跑真实站。它们付的代价是可复现性：OpenWebRL 51% 的失败来自 bot detection，live 站点的成功率随时间漂移，judge 噪声约 10%。AliyunConsoleAgent 是真实环境里唯一有后端奖励的，但环境私有。

第二条是缓存与合成。Weblica 用 Playwright 录 HTTP 流量回放真实站，146K 站只留存 15.6K 个可完成任务的缓存环境（约 10.7%，由两数推算，原文未给比例），另用 Claude Opus 4.5 合成 2,560 个无后端静态站；单步 50 到 150 毫秒对 live 的约 1.5 秒，但端到端 RL 只快 30% 到 40%。最反直觉的发现是合成站训练在三个 live 基准上的泛化优于真实缓存站。VeriEnv 用 GPT-5.2 coding agent 从截图重建带数据库的站，每站 3.6 USD、83.5 分钟，136 个候选 97 个可用，验证器通过 SDK 查数据库终态，但人工评估验证器只有 76% 正确；训练只是 rejection SFT，且 LLaMA-3.2-3B 在 Mind2Web-Online 上对 ADP 基线只多 0.46 点。Trustworthy Worlds 走得最远：LLM 生成站点 scaffold 后用四个 verifier 与规则检查修复，再把后端状态谓词编译成 dense reward，500 个环境 6,842 个任务，verifier F1 89.3；作为对照的 GPT-4 ReAct 15.3 被限制在同一 DOM 接口与 20 步内，作者自己声明不构成优于 GPT-4 的主张。代价是 policy 是不到 10M 参数的 DOM 模型，结论能否迁移到 VLM 完全未知。WebFactory 的 10 个站规模太小，不构成可扩展性证据。2507-WebSynthesis 与 2510-UISimulator 是更早的合成路线，用于推理期规划或数据生成而非 RL。

InfiniteWeb 是唯一一篇把合成站直接接进 live GRPO 并以程序化终态为奖励、策略为 LLM 的工作，补上了 Trustworthy Worlds 留下的空白。InfiniteWeb（2600-InfinitewebScalableWebEnvironment）用 LLM 生成带功能的站点并在代码里插桩 evaluator，600 个任务上对 UI-TARS-1.5-7B 做 GRPO，OSWorld 从 24.5 到 31.4、Online-Mind2Web 从 23.0 到 28.7，100 个抽样任务里 95 个通过人工校验；它最有信息量的实验是 Table 9：同样流程换成 Claude-Code 生成的站点，Online-Mind2Web 只有 +0.7，而自家站是 +5.7，说明合成站内部的方差与”合成对真实”的差异同量级，站点生成器本身就是实验变量。AutoWebWorld 同样用合成站，但它的 FSM 只用来生成与校验轨迹，GRPO 是离线动作匹配，归入路线 2；它说明合成站的另一种用法是做可校验的 teacher 数据源，而不是 rollout 环境。2609-MintAct 是 Weblica 环境的第二个使用者，8B 在 Weblica 评测集 74.7、Online-Mind2Web 39.1，与 Weblica 自家 8B 的 70.6 / 39.2 相当，但它的 web 能力经 specialist RL 再蒸馏进统一模型，没有合成站对缓存站的拆分。

第三条是 world model。DynaWeb 用 NNetNav 轨迹 SFT 一个 GPT-oss-120B 的 world model，预测 accessibility tree 的状态变化，策略在其中 dream 至多 5 步，WebArena 31.0、WebVoyager live 38.7，都高于重训后的 WebRL。但消融显示纯 imagined 训练低于 SFT 基线，约 40% 真实轨迹之后才显著超过，主实验配方实际用的是 50%；world model 对局部转移匹配 97%，对整页转移（占 36%）有 12% 完全错；reward 是未报准确率的 self-assessment。2511-DreamGym 用抽象状态的经验合成，WebArena 3B 从 7.3 到 13.3，绝对值低。2411-WebDreamer 与 2609-DiscriminativeWM 把 world model 用在推理期规划而非训练，后者的判别式 world model 在 WebPRMBench 上 BoN 72.70，接近 WebArbiter 的 74.60。2610-Trace2Env 给这条路线补了一个警示：无约束的语言 world model 在 ALFWorld 上让策略的模型内成功率到 97%，真实环境里只有 3%，经 trace 约束后两数变为 88% 与 85%。模型内成功率本身不是可信指标；DynaWeb 与 DreamGym 报的 WebArena 数字都在真实环境测得，这一点它们做对了，但两者都没有报告 dream 内成功率与真实成功率的差。

三条解法各付不同的货币：真实网付 bot detection 与不可复现，合成站付奖励可验证性，world model 付整页转移误差与对真实轨迹的依赖。在”吞吐”与”可验证奖励”两项上同时拿到的只有 Trustworthy Worlds，但它的 policy 不是 LLM。吞吐这一项在 2026 年 10 月之后不再是 web 独有的瓶颈：MAI-Gym 报告浏览器实例复位中位 6 秒（桌面虚拟机 37 秒、Android 165 秒），测试过 20,000 实例并行，并把 WebVoyager、Online-Mind2Web 与 WebArena 全集接进同一平台，但其 9B 模型只报了 MobileWorld 78.4 与 OSWorld-Verified 76.2，没有任何 web 基准数字；WebArena-Verified 把 812 个任务的 evaluator 改为基于 agent 响应与 HAR 网络轨迹的确定性判定，后端变更从网络事件里读出而不查数据库，并提供容器 reset 接口。两者合起来意味着”在 WebArena 上以后端状态为奖励做大规模 RL”的基础设施已经齐备，但还没有一篇论文用它训练。桌面侧 2610-SoftwareGym 给了与 Weblica 方向相反的数据点：各 3,715 条轨迹，只用合成环境训练的 Qwen3.5-9B 在 OSWorld 上 56.97，只用 OSWorld 原生环境训练 61.48，两者拼接 58.61；它做的是 SFT 而非 RL，不能直接对冲 Weblica，但足以说明”合成优于真实”不是跨平台成立的规律。2412-PAE、2410-NNetNav、2502-InSTA、2502-Explorer 解决的是任务与轨迹供给，多数止于 SFT；2506-GoBrowse 的结构化探索在 WebArena 到 21.7，在 Online-Mind2Web 只有 5.33，是 sandbox 不迁移的最直接证据。

路线 4：奖励来源与 step-level 判官

奖励来源决定了一篇论文的数字能不能被另一篇引用。程序化奖励（MiniWoB++、WorkArena 的 cheat 函数、WebArena-Lite 的规则 evaluator）是可信的，但只覆盖可枚举真值的任务。后端状态奖励（AliyunConsoleAgent 的审计日志、Trustworthy Worlds 的数据库谓词、VeriEnv 的终态查询）覆盖状态变更任务，但 VeriEnv 实测 76% 正确说明”程序化”不等于”准确”，数据库复位不保种子是主要错因。训练出的 ORM 只有 WebRL 一例，自报约 80% 准确率且无人复核。LLM 或 VLM judge 是 live 基准的默认选项，噪声从 OpenWebRL 的约 10% 到 VeriEnv 程序化验证器的 24%，RMSWeb 复核 WebTailBench 原生 judge 后发现 false negative 主因是只看 DOM 证据与截图读取不全，因而换用自家 judge；2504-AgentRewardBench 与 2510-CUARewardBench 专门测量 judge 质量，结论见 CUA-Survey §7.6。Weblica 的训练奖励与评测 judge 同为 LLM judge，论文没有排除策略学到”让 judge 满意”的可能。VeriCUA 给出了目前唯一跨平台同协议的 judge 准确率对照：一个在 OSWorld 上用 REINFORCE++ 训练、可以在执行后的环境里主动导航取证的 4B judge，与可执行 evaluator 的一致率在 OSWorld 82.00、MobileWorld 77.50、WebArena-Verified 62.75，GPT-5.4 few-shot 分别为 81.40、66.25、58.50；从 4B 到 GPT-5.4 的 prompted judge 宏平均都停在 68% 到 70%。web 比桌面低约 20 点，作者未解释；一个与 WebArena-Verified 自身设计一致的解释是 web 任务的完成态多在后端数据库而不在屏幕上，靶向 GUI 的取证看不到它。VeriCUA 的 judge 只在 OSWorld 上训练并作为 actor 的 RL 奖励（pass@4 47.14 对 ZeroGUI 奖励 45.36），web 侧只做了 judge 评测，没有训练。移动端 2500-A3AndroidAgentArena 训练出的小 judge precision 95.7 高于 Gemini-2.5-pro 的 87.3，且 Gemini 作 judge 时 10 个 agent 里 8 个分数更高，是”商业 judge 偏宽松、专用小 judge 可更准”在另一平台的数据点，但该 judge 的训练任务与评测任务同为那 100 个任务。桌面侧 model-based reward 对 rule-based reward 的强弱是三点分布：2607-SeekJudge 高于、2607-InteractiveRewardAgent 接近、2608-GSAR 低于，细节见 CUA-Survey §7.6；web 上这三类对照一个都没有。

step-level 判官有两种用法。WebArbiter 做的是推理期搜索：从任务与 accessibility tree 归纳带权重的 principle，逐条评估两个候选动作输出 pairwise verdict，o3 蒸馏加 GRPO 训练；7B 在 WebPRMBench 上 Avg BoN 74.60，同数据的 WebShepherd-8B 43.28，GPT-5 65.50；作为 GPT-4o-mini 的 BoN 判官把 WebArena-Lite 从 23.48 提到 40.52，其中无搜索与 WebShepherd 两行转引自 WebShepherd 论文而非重跑。消融显示 principle 是跨域泛化的主因，但 Mind2Web 上无 principle 的变体反而更高；附录 J 记录了 safe-action 偏置，hover 被系统性判优于 click。作者明说它没有用于策略训练。CLIFT 是训练期用法的唯一案例：把 Claude Opus 4.6 的逐步打分蒸馏成按 URL 分层的 YES/NO 问题库，用 Mondrian 共形校准决定哪些问题可信，可信问题的加权投票作为 GRPO 的附加 step reward；WAI 上 vanilla GRPO 只有 +2.9 且步数变长，CLIFT +10.8 且步数不增。但共形保证的对象是与 Opus 的一致性而非任务成功，没有 outcome-only RLVR 对照，认证率低于 5%，四个组件没有逐一拆解。

两种用法的证据状态不对称：PRM 作为 BoN 判官的收益有 WebArbiter、2609-DiscriminativeWM 两个独立来源；PRM 作为训练奖励的收益在 web 上只有 CLIFT 一个混杂了多个组件的来源。2511-AgentPRM 虽然名为 PRM，RL 阶段只把 PRM 的终步分数当轨迹奖励，等于一个学习型 ORM，逐步 dense reward 在闭环里没测；它的 WebShop 结果（Qwen2.5-3B beam @8×8 76.0 对自训 ORM 57.0）是推理期用法。web 上缺的那个对照在桌面已经有了一例：Adaptive-Group Process Rewards 用 Qwen3.6-27B critic 给 UI-TARS-1.5-7B 的 GRPO 组内逐步打分，OSWorld 的 Chrome/Impress/Calc 任务上 3-run 平均 outcome-only GRPO 30.4、SeekJudge 奖励 31.4、该方法 34.5（1-run 分别 35.7 / 37.1 / 40.6），同策略同环境同任务只差 reward，但没有方差。它把”PRM 对 outcome-only”从”没有人做过”改写为”桌面有一例无方差的正结果，web 没有”。trajectory-level reward 分解到步的通用机制在 StepCreditAssignment-Survey。

失败模式与负证据

  • 无 SFT 直接 RL 在 ≤8B 上失败或接近零增益：WebAgent-R1 3B 从 6.1 到 4.8；Statistical Diagnosis 在 WorkArena held-out goal 上 RL-only 8.0 对 Instruct 8.3；OpenWebRL 4B 从 base 直接 RL 在 hard 子集上 +2.3 对 SFT 起点 +22.3，整体约 10 点的 SFT 起点优势全程未被抹平；Weblica 2B/4B/8B 上 Base→RL 均低于 SFT→RL。反例集中在更强的 base 或更简单的环境：OpAgent 32B-Thinking 无 SFT pass@5 +10.7；AgentGym-RL 7B 自选子集 26.0；WebShop 文本环境上 2609-PROPD（Qwen2.5-3B GRPO Acc 55.5）与 2610-SRD（Qwen3.5-4B GRPO 77.21）的笔记均未提及 SFT 阶段。
  • 学习率门控的崩溃：2607-GRPONullWebAgent lr 1e-5 降 15.8 点，2e-5 降到 0，后层有效秩 9.2→1.2；WebAgent-R1、DynaWeb、Statistical Diagnosis 都独立选了 1e-6，AliyunConsoleAgent 用 5e-7。
  • SFT 数据更多反而更差：OpenWebRL 412 条优于 1.9K 条，差 2 点。
  • 纯 imagined rollout 低于 SFT：DynaWeb 0% 真实轨迹时不如 SFT 基线，约 40% 之后才显著超过。
  • dense reward 诱发 hacking：WorkForceAgent-R1 Fig 8；CLIFT 用 clip-at-zero 规避负极性问题，但 Online-Mind2Web 迁移问题库里仍有 25 个负 lift 问题（Table 5），未讨论。
  • sandbox 到 live 不迁移：Go-Browse WebArena 21.7 对 Online-Mind2Web 5.33；WebArbiter cold-start RL 在 Mind2Web BoN 86.00 而 WebArena 35.80 低于基座。
  • held-out 增益落在标准误内：Statistical Diagnosis WorkArena held-out task SFT+RL 28.8±2.0 对 SFT 26.4±2.0，差 2.4 小于合并标准误约 2.8（按 Table 1 推算）；AMBER 27B 三种方法 std 约 3 且区间重叠。
  • 判官噪声与增益同量级：OpenWebRL 约 10%；VeriEnv 验证器 76% 正确；Weblica judge 与人工一致 88%；RMSWeb 复核后换 judge，WebTailBench 数字跨 harness 不可比。

  • harness 单独可解释几十点差距：2610-WebFovea 在 live 站点上不改模型、四次提交只改坐标修正与 harness，同一 claude-opus-4-6 从 31.0 到 57.0；任何”训练后低于 zero-shot”的反常都需先排除复现 harness 的差异。
  • world model 内成功率不可信：2610-Trace2Env 无约束语言 world model 内成功率 97% 对真实 3%。
  • 环境供给的损耗率：Weblica 缓存存活约 10%；VeriEnv 克隆成功 97/136；OpenWebRL 51% 失败来自 bot detection；CLIFT 问题认证率低于 5%。

Key Takeaways

  1. 先测 headroom，再决定要不要 RL。 训练前在目标任务上同时测 sampling 成功率与 greedy 成功率，差值接近零时 GRPO 不会有可信增益，该补 SFT 或换任务。这条判据来自一篇受控 null，但 Statistical Diagnosis 里 14/33 从未解出的 WorkArena 任务与 WebAgent-R1 无 SFT 失败都与它同向。
  2. 没有可复位环境时选离线 step-level RL，但把它当蒸馏来设计。 它的增益来自挑哪些状态训，不来自探索；RMSWeb 筛选 4.5k 关键状态优于全量语料，WorkForceAgent-R1 的 dense reward 诱发 hacking。上限是 teacher，因此 teacher 的 judge 质量比 RL 超参数重要。
  3. 环境三条路各付不同货币，没有免费的那条。 真实网付 bot detection 与不可复现，合成站付奖励可验证性，world model 付整页转移误差且仍需约 40% 真实轨迹。目前唯一同时有吞吐与可验证奖励的是 Trustworthy Worlds，但它的 policy 不是 LLM，结论不能直接搬。
  4. 报告增益前先报 judge 与人工的一致率与方向。 VeriEnv 的程序化验证器 24% 出错，Weblica 的 judge 与人工 12% 不一致，OpenWebRL 约 10%，都与多数论文的 RL 增益同量级；RMSWeb 因原生 judge 误判而换用自家 judge，其 WebTailBench 数字从此不与其他 harness 可比；WebVoyager 上 8B 模型的数字从 35.2 到 86.4，跨度来自 judge 与时期而非方法。
  5. 学习率是 GRPO 的开关而不是细节。 1e-6 量级安全，1e-5 开始伤害，2e-5 崩溃；三篇独立工作在不披露彼此的情况下都收敛到 1e-6，AliyunConsoleAgent 用 5e-7。机制证据只在 4B 模型上，但在更大模型上没有反例。
  6. 把”要不要 SFT”改问成”base 有没有 headroom”。 ≤8B 的 VLM 在 WebArena 级任务上没有 SFT 就没有可用的 sampling 成功率，RL 增益接近零，且 SFT 起点的优势到训练结束都在；32B 的 Thinking 模型不经 SFT 直接 RL 有效。两类证据不矛盾，矛盾的是把这个问题当成与规模无关。
  7. 合成站按验证器与生成器拆开评价，不与真实站笼统对比。 同一流程换一个站点生成器增益差 5 点，桌面上同数据量合成低于原生，web 上 Weblica 合成高于缓存；决定增益的是任务可验证性与状态覆盖，不是”合成”这个标签。

Open Problems

分层说明：Validated Gap 指做过针对性检索、closest prior art 已列出且仍为空缺；Observed Tension 指证据冲突或缺失但未穷尽检索；标”已重述”的是原问题被新证据改写而非关闭。

  • Validated Gap：live rollout 与离线 step-level 动作匹配在同模型同 benchmark 上的直接对照仍然缺失。 针对性检索到的最接近对照有三类，都不满足条件：WebRL Table 1 在同 SFT 起点下给出 Filtered BC 23.0 / AWR 28.5 / DigiRL 30.3 对在线 42.4，但三者不是 teacher 动作匹配，且前两者的数据来源原文表述不足以确认为同数据离线版本；RMSWeb 明确把在线 outcome RL 列为 future work；JitRL 在同一 Llama-3.1-70B 上以非参数记忆估计 advantage、不做梯度更新，自报超过 WebRL 且成本低 30 倍以上（仅摘要），它比较的是”要不要更新权重”而非”离线对在线”。重要性不变：这决定没有可复位环境的团队损失了多少，也决定路线 2 “等价于筛选式蒸馏”的判断是否成立。
  • Observed Tension（已缩窄）：PRM 作为训练期 reward 对 outcome-only 的受控对照在 web 上缺失，在桌面已有一例。 Adaptive-Group Process Rewards 在 OSWorld 上同策略同任务只换 reward，3-run outcome GRPO 30.4 对 34.5，无方差；2511-AgentPRM 的 RL 阶段只用终步分数。web 侧 CLIFT 的对照仍不是 outcome-only。这个空缺正在被填：桌面结果出现在 10 月 13 日，web 版本只是时间问题，不宜作为新 idea 的核心。
  • 已重述：AgentGym-RL 的无 SFT 可行性与三篇独立工作的矛盾已被 scale 维度化解。 OpenWebRL Fig 2、Weblica Fig 5 把 ≤8B 上”SFT 起点优势持续存在”做成受控结果，OpAgent 把 32B-Thinking 上”无 SFT 可行”做成单点。剩下的问题变为：SFT 起点优势随 base 规模消失的拐点在哪，以及它是否等价于 GRPONull 的 headroom 判据，即只要 base 的 pass@k 过阈值 SFT 就不再必要。8B 与 32B 之间没有任何数据点，OpAgent 也没有 SFT→RL 对照组。
  • Observed Tension（已改写）：决定合成环境训练增益的变量未被分离。 Weblica 合成优于缓存，SoftwareGym 桌面 SFT 上合成低于原生，InfiniteWeb 同流程换生成器增益从 +5.7 变 +0.7，Trace2World 的 source-grounded 校验使模拟器内增益在真机上保留 94.0% 而自校验只有 54.7%（仅摘要）。四者共同指向：增益随环境的任务可验证性、状态覆盖与保真度校验方式变化，“合成对真实”是一个过粗的变量。没有一篇在同 policy 同任务量下只改其中一项。
  • Observed Tension（部分关闭）：后端状态奖励在 LLM 策略上的验证。 InfiniteWeb 用程序化终态驱动 7B VLM 的 live GRPO 并在 live 基准上有增益，是”LLM 策略能吃程序化终态奖励”的首个也是唯一案例（AutoWebWorld 经核对为离线动作匹配，不算）；它没有报 evaluator 的 precision/recall，VeriEnv 的 76% 仍是唯一审计数字。剩余空缺收窄为：WebArena-Verified 已提供 812 个任务基于网络轨迹的确定性 evaluator 与 reset 接口，MAI-Gym 把浏览器复位压到 6 秒，但尚无工作以它为 reward 训练并报告 evaluator 审计（针对性检索 1 次，未检索到）。
  • Observed Tension：AMBER 中 zero-shot 全上下文高于训练后 WebAgent-R1 复现。 2610-WebFovea 提供了一个候选解释：live 站点上不改模型只改 harness 可以让同一模型从 31.0 到 57.0，训练论文的 baseline 复现与 zero-shot 评测若 harness 不同，差距可能来自 harness 而非训练。这是假说；AMBER 原文无 harness 披露，目前无法检验。
  • Observed Tension：web 任务的可核验性比桌面低约 20 点，机制未证实。 VeriCUA 同一 judge 在 WebArena-Verified 上 62.75 对 OSWorld 82.00，prompted judge 不论规模都停在 68% 到 70%。候选机制是 web 的完成态在后端而非屏幕，GUI 取证看不到；可检验的预测是给 judge 增加 DOM、网络轨迹或后端查询工具后，web 一致率应向桌面靠近。2607-InteractiveRewardAgent 在桌面用 shell 与文件系统取证做到了类似的事，web 上没有对应工作（针对性检索 1 次，未检索到）。

挑战与可做的点

judge 偏差方向感知的 advantage 修正passive judge 的 over-accept 是否在 RL 中被策略利用预测：以 passive judge 为 reward 的 RL 会增加”成功宣言”类 token 而非后端状态变更；用 proactive 取证的否决做非对称修正可消除。可学习组件是按 judge 置信度与取证一致性加权的 advantage2607-OSReward（偏差测量，无训练）、Who Verifies the Agent’s Success Claim（10 月 21 日，仅标题）；web 上的训练期修正未检索到，但须先读 10 月 21 日的新工作候选，须先做 novelty 检索
合成环境的增益归因合成对真实的方向在 web 与桌面相反，哪个变量在起作用同 policy 同任务量下，只改验证器类型（judge 对程序化终态）、状态覆盖、生成器三者之一；预测增益随验证器类型变化最大Weblica（现象）、InfiniteWeb Table 9（只改生成器）、SoftwareGym（桌面 SFT）、Trace2World（校验方式）测量型。重要但无算法亮点，适合作为上两行工作的消融章节，不单独立题
离线 step-level 对 live rollout 的同模型对照没有可复位环境损失多少预测：离线增益在 teacher 成功率附近饱和，live 在 headroom 允许时越过 teacherWebRL Table 1（非 teacher 匹配）、RMSWeb（future work）、JitRL（非梯度）测量型。WebArena-Lite 加同一 8B 一周可做，结果直接决定路线 2 的定位；建议先做，但它本身不是 idea
