# 🔪 今日总结

抓取 30 篇，精读 8 篇。今天最值得记的不是任何单篇结果，而是一个高度一致的模式：八篇里有七篇的卖点归因不成立——净增益要么被一个正交技巧盖住（ABSeeker 的 +3.8pp 被 +18.0pp 的 context management 掩埋），要么被论文自己的消融砍掉大半（EnvACE 的"内化"只值 5.5 分里的 1.2 分），要么关键对照臂根本没做（EvoHarness-RL 缺 harness-free 臂、SKILL-KD 缺 token 配平臂、In-Context VLA 的跨方法基线各用各的 backbone），要么只在训练分布内成立（DreamGuard 跨 benchmark 后 PHIR 从 96.3 崩到 16.8）。

更有价值的是两条独立的同向负结果。When Memory Lies 跑了同行集体省略的 NoMemory 基线，结论是该组件净负——带过期记忆 74.4% 死亡率 vs 无记忆 28.0%。In-Context VLA 在完全不同的域（VLA 感知工具，而非 VLM 空间记忆）撞出同一现象：注入模型自猜的空间证据只有 84.3%，比根本不注入的 backbone（90.4%）低 6 分。两篇都指向同一条规律——**组件返回不可靠值时，agent 会比没有这个组件更差**，而这恰恰是"有组件 vs 无组件"这种二元消融照不出来的。这给 [[Topics/Harness-Component-Attribution]] 一个具体的设计修正：对照臂不该是有/无两档，而该是可靠 / 噪声 / 无三档。今天没有一篇拿到 🔥。

### ABSeeker
- **Title**: ABSeeker: Training Long-Horizon Search Agents via Answer-Backtracked Credit Assignment
- **Institutes**: Shanghai Jiao Tong University
- **Source**: [link](https://arxiv.org/abs/2608.05102)  📰 HF Daily ⬆️ 55   **📒 论文笔记**: [[2608-ABSeeker]]
- **核心**: 长程 search agent 只有末端 0/1 信号，作者先量了一把这个假设有多假：成功轨迹里约 4% 的步骤是坏步，失败轨迹里近 10% 的步骤其实找对了证据。对策是利用 BrowseComp「答案唯一且可验证」的结构——从已知答案出发跑一个带真实 web search 的反向 ReAct loop，回溯出一组锚定在网页上的 clue，再按固定 rubric（发现 clue +0.8 / 排除错误候选 +0.4 / 误弃正确 clue −0.8，基线 1.0）给每一步打分，同一套分数既做 SFT 的 loss 权重也做 GRPO 的 step advantage。Qwen3.5-4B + 8.5K 轨迹，BrowseComp 37.3（无 context management）/ 55.3（有），GAIA-text 81.6 为主表最高。
- **锐评**: 开篇那个 4%/10% 的测量是全文最值钱的东西——从「dense reward 直觉上更好」变成「outcome-only 监督正在往哪个方向发力错」，这是正确的做事顺序，比后面的方法本身有价值。锚点与 policy 解耦也确实比 IGPO（信号随 policy 漂移）和 CSO（只覆盖被反事实验证的少数步）扎实，同口径下 4B 的 37.3\* 超过它自己训练数据来源 OpenSeeker-30B 的 29.5\*，这个数据效率是真的。

  但摘要的叙事有问题。55.3 打头并挂在 ABC 名下，可 37.3 → 55.3 那 +18.0pp 全来自 context management——一个跟 credit assignment 完全正交的 inference-time 技巧，还是直接沿用一作自己的 LongSeeker。ABC-GRPO 对 standard GRPO 的净增益是 +3.8pp。两个数分开都诚实，摆在一起就是让读者替你把 18pp 记错账。Table 2 同样混 setting：QUEST-4B 的 40.0 不带星号，比 ABSeeker 无 CM 的 37.3\* 更高；55.3 也低于 MiroThinker-1.7-mini 67.9 和 RedSearcher 57.4 两个 30B。星号在 caption 里写了，不算撒谎，但「同规模最强」得读者自己对齐口径才能确认。「outperforms all reported 30B agents on xbench-2505」更是话术——那两个最强的 30B 在该列干脆记的是 "–"。

  真正的硬伤有三个。其一，整条 reward 链压在一个零校验的 LLM 上：DeepSeek-V4-Flash 同时做 clue recovery、step scoring 和 benchmark 判分，三个角色互相耦合，全文没有一处人工抽检、标注一致性或 clue precision/recall（笔记 C14 明确记为「未报告」）。判分和打分同源意味着 scorer 的系统性偏差在评测里根本照不出来——ABC 优化的到底是搜索质量还是 judge 的口味，论文无法回答。其二，回溯出的 clue 是一条事后合理化的路径，不是有效路径的集合，而 rubric 却拿它当 ground truth 扣 −0.8；走另一条同样能到答案的证据链会被无端惩罚，论文没测这个多样性代价（Fig 5 的轨迹变长只能说明探索没被压缩，跟路径多样性是两回事）。其三，关键路径上五个手调常数（+0.8/+0.4/−0.8、γ=0.25、`2σ(2(r−1))`）零敏感性分析，而 ABC-SFT 在 xbench-2505 上还掉了 1.0 被一句 "remaining comparable" 糊过去。另外「only 8.5K examples」的省事叙事站不住：clue recovery 是每题跑一整轮 web-search ReAct，step scoring 是每步一次 LLM 调用（轨迹上限 200 步），RL 阶段还要给 1000×8 条 rollout 在线逐步打分——全文没有 token、成本或 wall-clock 的任何交代，那凭什么说自己比 CSO「便宜」。最后，与两个月前 TRIAGE 的框架重叠（同 motivation、同「LLM judge + 固定常数 rubric」形式）既未引用也未对比，ABC 真正的 delta——锚点从抽象角色标签换成可验证 clue——因此无从定价。
- **Rating**: `2` 👀 ，问题诊断和 answer-backtracking 这个切入点都对，但净增益 3.8pp 被 18pp 的正交技术盖住，reward 全链依赖零校验的自判 judge，属于值得跟进方法、不值得相信数字的一篇。

### When Memory Lies
- **Title**: When Memory Lies: An Empirical Study of Spatial Memory Staleness in VLM Agents
- **Institutes**: Tencent LIGHTSPEED
- **Source**: [link](https://arxiv.org/abs/2608.04574)  📰 HF Daily ⬆️ 12   **📒 论文笔记**: [[2608-MemoryLies]]
- **核心**: 在一个会变的 8×8 FrozenLake 上，先给 agent 写一份"每格一句"的空间记忆（共 64 条），然后偷偷翻转部分冰面/冰洞，看模型能不能发现自己的记忆已经过期，以及发现之后行为会不会变。文字模态下检测几乎满分（closed-source 加 GLM-5.1 平均 F1 > 0.88），换成同一批网格的 384×384 渲染图就崩：Qwen 0.887 而 GLM-5.1 只有 0.067，差 13 倍。导航侧的头条数字是 GPT-4o L2 text：带着过期记忆 14.4% 成功 / 74.4% 死亡，完全不给记忆反而 28.8% / 28.0%。读时逐批审计（OMCD）能收回大半损失（L1 +14.4 pp → L3 +24.4 pp），但换成 oracle 标签不再有可检出增益，且 per-seed 检测 F1 与成功率零相关，作者据此判定瓶颈已从"检测过期"移到"拿着过滤后的记忆做决策"。
- **锐评**: 这篇最聪明的一步是跑了 NoMemory 对照——记忆类论文集体性地只比"我的记忆 vs 你的记忆"，于是"记忆本身是负资产"这个结论根本没机会出现，74.4% vs 28.0% 全靠这条大多数人省掉的基线撑着。Figure 4 那个知觉对照也漂亮：GLM 对"真安全"和"真是致命洞"的 cell 标记 stale 的比例是 5.0% vs 4.5%（不显著），Claude 是 92.5% vs 1.4%——标记率对图像内容纹丝不动，就说明它压根没看图而是在背记忆，而且推理串里既不拒答也没有 uncertainty 标记，流畅文本完全不能当视觉审计落地的证据。按结局条件化的轨迹长度（NoFilter 死亡 8.5/7.8 步 vs 成功 14.5/14.6 步，Claude NoMemory 死亡 16.1 步）把死亡率拆成"照记忆冲进坑"和"探索到死"两种机制，便宜且可复用。问题也一样刺眼。第一，环境完全可观测，当前观测已含全部 ground truth，记忆在信息上严格冗余——在这种设置下记忆只可能加噪，"过期记忆比无记忆致命 2.7 倍"部分是设计的产物，作者虽然限定了 conditional on using memory，但这个数字被外部引成一般性结论几乎是必然的；真要有力就得去部分可观测环境重跑。第二，全文最有转述价值的那句"瓶颈已转移到动作选择"，坐在最薄的证据上：Oracle 消融、轨迹分解、F1–成功率相关性全部只在 GPT-4o 一个模型上做；而 vision 导航侧的"审计不可靠时过滤无稳定收益"只有 10 seeds × 3 episodes（每格 30 个 episode，作者自标 exploratory），text 侧却是每格 250 个——结论强度和样本量正好反着分配。而且笔记指出更要命的一点：作者自己承认 aggregate F1 不记录漏掉的条目是否落在 agent 路径上，那条零相关很可能就是聚合口径稀释出来的，用已有 traces 重算 path-conditioned recall 成本极低却能直接反转结论，论文偏偏没做。第三，OMCD 就是"分批问 LLM 是否 stale 然后删条目"，没有可学习组件、没有机制假设，当测量仪器很诚实，写进 contribution list 就有点撑门面。另外 §5.2 说 vision 下这几个模型"reach at most 0.40 success"，Table 2 里 Claude L3 SelfVerify = 0.433 已经越线；GLM 的 0.067 是本地 vLLM 0.6.3 serving 出来的，知觉对照排除了"图不可读"但没排除这套 serving/prompt 组合的视觉通路本身有毛病，当成模型属性引用是有风险的。
- **Rating**: `2` 👀 ，数字属于玩具世界且机制分析全押 GPT-4o，但 NoMemory 对照 + detection-navigation 配对 + oracle 消融这套协议是可移植的，此后任何"给 agent 加持久记忆"的工作都该被要求报一次无记忆基线。

### AppDeltaWorld
- **Title**: AppDeltaWorld: Transition-Grounded Delta Code World Model for Mobile GUI Agents
- **Institutes**: 未标注
- **Source**: [link](https://arxiv.org/abs/2608.05891)  📄 arXiv   **📒 论文笔记**: [[2608-AppDeltaWorld]]
- **核心**: 把 mobile GUI world model 从"自由生成下一屏"改成"先查表再补差分"：离线给每个历史屏建 HTML 索引和细粒度簇，再用 app 级 action-transition index（click/long-press 落点量化到 6×12 网格）圈出当前屏做该动作后**真实可达**的 target cluster，只在这个集合里检索 Level-1 骨架，生成 Level-2 delta code，diffusion 填图片槽，浏览器渲染出截图。用它闭环 rollout 出 33,133 条轨迹混公开数据 SFT 出 AppDeltaAgent-8B。CMGUIBench-500 总分 73.51 排第一（GPT-Image-2 72.34），AndroidLens 全 split AMS 第一（Total-LL 90.28），但 MobileGym SR 只有 14.1%，落后三个同量级开源模型。
- **锐评**: 方法的核心直觉是对的，而且是这个赛道里少见的对：GUI world model 真正的失效不是像素糊，是幻觉出真机根本不存在的后继页面，把可达性做成显式可查表比"让模型更会画"更贴问题本体。消融也干净——去 RAG 功能逻辑分崩 14 分，去 diffusion 视觉分掉 6-7 分，两个组件各管一头不互相顶替。逐 action type 的归因是全文最值钱的一段：wait 14.19→72.97、type 77.66→89.37，而 click 只从 91.82 到 95.88，说明合成环境教的是"该做哪类动作、什么时候停"，压根不是坐标定位——这条结论比任何 SOTA 数字都更可迁移。但 claim 和证据的缝隙一样明显。abstract 里不加限定的 "state-of-the-art" 在 AndroidLens 只在 AMS 口径成立，ATP 口径 Total-LL 46.63 输给 UI-TARS-7B-DPO 的 52.45；MobileGym 那句 "surpasses several competitive 8B baselines" 是表里赢了两个、输给三个，而且 USE 19.7% 是全部开源 GUI 专用模型里最高——完成率上去的同时副作用也上去了，论文一个字没讨论。MobileWorld 表里别人都报 Overall SR，唯独自家留白，这种"刻意的空格"在审稿里是要被点名的。CMGUIBench 的"总分第一"更是加权口径产物：功能逻辑分 S_ad/S_id 输 GPT-Image-2 整整 12 分，靠视觉细节赢 12 分凑出 1.17 分优势，作者自己还承认 S_lay 评不了绝对坐标一致、人工评估里 GPT-Image-2 元素对齐更好——那这个"最高保真度"到底保的是什么真？成本侧几乎不谈：平均 8309 tokens/步是最贵 code baseline 的 1.7 倍，叠加 1/10 的质检通过率，而作者批模拟器的理由恰恰是"扩展成本高"，两条路线的边际成本从没放进同一张表。最伤的是覆盖面：world model 训练数据 95.47% 来自 CMGUI 单一来源，数据 scaling 12K 就吃掉 75% 增益、20K 饱和，作者诚实归因于"多样性受限于 world model 的经验"——这句话直接把 abstract 的卖点打了对折，因为合成经验只在 world model 见过的 app 分布内有效，而"敏感 app 缺真实轨迹"这个原始问题恰恰在分布之外。另外笔记里那条"推理时不查 world model"是从评测章节的沉默里读出来的（Evidence Ledger 标 unsupported），论文既没声明也没否认，别当结论用。负结果倒是给了作者分：ADW-only 单独训练掉点 1.16/1.15、consensus reward 均值 0.412 且 23.5% 的 group 无唯一赢家，都写在正文不是附录，这份坦率在当下不多见。
- **Rating**: `2` 👀 ，可达性约束和 action-type 归因是真 insight，但 SOTA 叙事靠口径挑选撑着、下游硬指标落后同量级模型，值得读方法与负结果、不值得信 abstract。

### EvoHarness-RL
- **Title**: EvoHarness-RL: Learning Self-Evolving Runtime Harness for Long-Horizon LLM Agents
- **Institutes**: University of Illinois Urbana-Champaign, Meta AI
- **Source**: [link](https://arxiv.org/abs/2608.05446)  📄 arXiv   **📒 论文笔记**: [[2608-EvoHarnessRL]]
- **核心**: 把 agent 读写外部 harness 的操作变成可训练动作：外部状态统一抽象成 Belief / Progress / Experience 三类，配 track / commit / recall / note 四个 meta-action，与环境动作共享同一个 70 步预算。先用 Claude Opus teacher 轨迹 SFT 教会动作语义（87 条轨迹 / 1153 pair），再用 cost-aware GRPO 学「什么时候值得花一步去查外部状态」。ALFWorld seen split 上 Qwen3-8B 从 ReAct 的 47.9% 拉到 96.9%，unseen 86.6%；训练收敛后 harness 调用退火到约每 episode 一次，其中 recall 存活、commit 与 note 归零。
- **锐评**: framing 是真的好——整个 harness 文献都在雕 harness 本身，这篇指出没人训练过"策略侧的使用决策"，并且把成本写进优化目标（共享步数预算、效率奖励只在成功时发），这一手比那些把 memory 模块当免费附加物的工作干净得多。动作级退火曲线是全文最有信息量的东西，也是该方向罕见的可测量读数。**但主 claim 的证据链是断的**。缺"同管线 SFT+GRPO 但去掉 BPE"的对照臂——最近的 standard GRPO 65.6% 同时少了 SFT、少了 Opus 蒸馏、少了 BPE，三重变更，归因无从谈起。更要命的是论文自己的两个数字互相拆台：收敛后 harness 只用约 1 次/episode，而 teacher 用到 18% 的 turn（≈4.7 次），推理期信息注入掉了近 80%；同时 Opus teacher 光跑 ReAct 在同一 split 上就有 96.4%，学生最终 96.9% 基本等于教师基线。"harness 被内化了"和"harness 只是训练期 curriculum、推理期贡献≈0"两种读法用本文数据完全无法区分——SESA 早就做过的 inference-time 关闭对照，这里一次没做，成本是重跑一遍现成 checkpoint。Table 2 的消融只在 56.4% 的冻结臂上做，96.9% 那条策略零消融；而且表里三个消融臂的 Heat 全都比完整 BPE **高**（75.0 / 68.8 / 62.5 vs 50.0），正文却写去掉 Experience "heavily impacts Heat"——Heat 只有 16 题，这是 4 题之差，全文无 seed、无误差棒、无显著性检验（笔记标为 negative/methodology），这类方向性解读没有任何统计支撑。"state of the art" 也站不住：笔记推算显示两个可训练行的 per-family 分数在 1–3 run 下还原不出任何 k/n，且 96.9 恰等于六族未加权均值（题数加权应为 97.1），冻结行却是加权的——两组行很可能不在同一评测口径上；再加上 vault 里 Skill1 早已报 97.5%、RetroAgent 94.9%，本文均未引。结论不是"它不是 SOTA"，而是 ALFWorld 上这批 95%+ 的数字彼此根本不可比。另外：只有 ALFWorld 一个纯文本环境，belief tracker 是 rule-based 写死的 parser，"换适配器、接口不变"的通用性主张一次都没被检验；skill bank 的采纳判决全交给 Opus 读 note 文本，无 held-out 判据、无污染率测量，而附录 8 那个"self-correction 正面案例"恰恰证明错误 prior 进过 bank 并被检索出来了。无 Limitations，无代码，+25.7 那个数还跟表里 24.3 对不上。
- **Rating**: `2` 👀 ，问题切得比方法本身值钱——framing 值得跟进，但一个关掉 harness 重跑的对照就能定生死的实验没做，96.9% 现在只是一个和教师基线撞车的数字。

### EnvACE
- **Title**: EnvACE: Internalizing Environment Dynamics via World Rehearsal for Agentic Reinforcement Learning
- **Institutes**: Shanghai Jiao Tong University, Zhejiang University, National University of Singapore, Sun Yat-sen University, Central South University, The Chinese University of Hong Kong, Tencent Inc.
- **Source**: [link](https://arxiv.org/abs/2608.06197)  📄 arXiv   **📒 论文笔记**: [[2608-EnvACE]]
- **核心**: 让同一份 policy 兼任两个角色：Act 角色出 tool call，Rehearse 角色紧接着把这个 call "该返回什么"编出来，接回 history 继续展开——训练期整条轨迹自产自销，不碰任何外部环境或外部 simulator，用按角色分 baseline 的 GRPO 联合更新同一份参数。推理期把这套内化的响应预测当 test-time scaling 用：先私下彩排 N 次、自评汇总成 rehearsal memory，再去真实环境里做一次 committed execution。EnvACE-8B 在 BFCL-v4 / τ²-Bench / VitaBench 三者算术平均上拿 32.91%，压 EnvScaler-8B（31.92）和 AWM-14B（32.54）。TTS parallel N=2 把 Overall 从 36.7 推到 40.9。
- **锐评**: 先夸真该夸的：Per-role Policy 这条对照臂是全文最值钱的东西——它把"有没有自生成 rollout 通道"和"通道是否与 acting 共享参数"拆开了，绝大多数同类工作根本不敢做。问题是这条臂把作者自己的卖点做没了：GRPO 31.2 → EnvACE 36.7 的 5.5 分里，4.3 分来自"有条自生成通道"（DreamGym 那一族外挂 simulator 同样提供），只有 1.2 分来自标题里那个 *Internalizing*。也就是说论文最新颖的部分只值 22% 的可测增益，单 benchmark、单次测、无方差。主表更难看：BFCL-v4 输给 EnvScaler 和 AWM-14B，VitaBench 输给 AWM-14B，τ²-Bench 只排第二，唯一的"赢"来自把单轮 function calling 的 BFCL 和多轮服务场景等权相加得到的 Overall，领先 AWM-14B 0.37 分——全表不报标准差，这个数和 run 间噪声无法分离。最要命的是 C13：全文包括附录**一次都没测过彩排保真度**，"内化了环境动力学"这条因果链的中间环节完全空着，只有下游分数背书；而这是个几小时就能做完的实验（τ²-Bench 真实执行结果逐条对账）。再看 Rehearse prompt（C12）就更尴尬——它被明确要求"few-shot 里有同名近参调用就直接复用其 execution result"，所以"训练期零外部环境"字面成立但内涵掺水：环境知识来自 CM2 预采集的调用/返回对加一个 Qwen3-30B-A3B 外部 judge 的 reward 通道，论文对后者的外部依赖只字未提。C18 又让 standard GRPO 的 observation 来源全文无交代，那 +5.5 到底赢的是"真实环境交互"还是"某个合成环境"，读者无从判断——DreamGym 至少写清楚了对手是谁。TTS 那 +4.2 单次 run、temperature 拉到 1.0、N=3 就回落（非单调本身就是高方差的味道），而且缺最该有的 budget-matched 臂："把同等算力花在真实环境里多跑几次并复位"完全没试，"必须靠内化 world model"因此没被证明。附赠两个不专业的地方：§5.3 把 Figure 3 引成 Figure 4，Table 1 和 Table 3 采样配置不同却共用 36.7 这个数字。倒是有个反向观察值得说——Simulator-8B 在 τ²-Bench 拿 38.5、Irrelevance 拿全表最高 86.54，但 BFCL Multi-Turn 只有 1.47、VitaBench 1.8，这更像一个高度倾向拒答的退化策略，拿它当"τ²-Bench 上的更优者"其实低估了 EnvACE 自己。
- **Rating**: `2` 👀 ，ablation 做得比同行诚实，诚实到把自己的核心 claim 证伪了 1.2 分；主表靠聚合方式险胜、零保真度测量、baseline 环境来源不明，是个有价值的对照物而非可信的新方法。

### DreamGuard
- **Title**: DreamGuard: Efficient Runtime Guardrail for LLM Agents via Risk-Aware World Model
- **Institutes**: 未标注
- **Source**: [link](https://arxiv.org/abs/2608.05695)  📄 arXiv   **📒 论文笔记**: [[2608-DreamGuard]]
- **核心**: 把 DreamerV3 式的 RSSM 塞进 LLM agent 的 pre-action guardrail：GRU 在冻结的 Qwen3-4B embedding 上维护固定维度轨迹状态，对候选动作先"想象"出 successor latent，再从这个预测态上读 immediate-hazard 与 prefix-risk 两路分数，noisy-or 融合 + split-conformal 标定后输出 PASS/HOLD/BLOCK。核心卖点是延迟：平均 0.025 s/call，比 SafePred 快 424×、比 GuardAgent 快 250.6×。长程风险 benchmark SafetyDrift 上 F1 96.4 / FPR 3.7 / PHIR 96.3。但训练与阈值标定只在 SafetyDrift 做，其余三个 benchmark 零样本迁移。
- **锐评**: 延迟这一半是真货——把 guardrail 从"每步喂 LLM 读整条轨迹"改成"定维 recurrent state + 轻量 head"，25 ms 才够格进实时执行循环，秒级的 SafePred/GuardAgent 在生产 agent 里就是摆设。risk-supervised 阶段冻结 GRU core 只解冻 risk head 通路，以及"w/o successor prediction"这个对照（F1 82.9→76.3、FPR 9.8→25.4），都是有品味的做法。但"多视野风险"这个真正的 novelty claim 只在同分布里成立：模型和阈值全在 SafetyDrift 上拟合，而 SafetyDrift 正是唯一的长程 benchmark，迁出去 PHIR 从 96.3 崩到 16.8–34.8、MAS 从 3.63 掉到 0.27–0.61——0.27 步的"提前量"跟在动作边界上拦截毫无区别，prefix-risk 通道压根没迁移，作者却包装成 "stringent evaluation of transfer robustness"。第二，"world model"名不副实：observation predictor 只在训练期当一个 embedding 余弦辅助损失存在，推理期不产出任何可读后状态，这就是个带时序归纳偏置的风险分类器；更要命的是作者自己提的挑战 (ii)"预测应保留风险证据"，解法是直接拿风险标签监督预测——同义反复，代价是预测失去独立语义，也就没有任何可解释证据能返给 agent（输出空间只有三值标签，§5 自陈不生成替代动作，被拦下的 agent 除了重试无事可做）。第三，AgentDojo 上 FPR 29.4%，比 SafePred(5.1)/Llama-Guard(6.3)/AgentDoG(19.6)/TRACES(20.0)/PolicyGuard(24.7) 全都差，F1 74.9 也输给 AgentDoG-1.5 的 80.0，正文一句 "avoiding excessive false alerts" 就带过去了。第四，在线 Pareto claim 撑得很勉强：100 例、48 个 unsafe，72.92% 约等于 35 例，一例就是 2.08 pp；而无防护基线 utility 94.23% 这条参照线只躺在附录 Table 8，主文 frontier 叙述里不见踪影，90.38% 还跟 AgentDoG-1.5/TRACES/TS-Guard 三家完全持平——赢的是同 utility 下的 safety，不是双赢。最后，三个 benchmark 的首个 hazard step 是作者用 GPT-5.1 预标 + 人工复核造的，精确一致率最低 79.6%（恰在 ASSE-Security，也恰是消融和在线实验的主场），而 PHIR/MAS 直接定义在这条边界上——用 20% 分歧的标签去论证"提前 0.61 步"，这个精度预算是超支的。标注审计做了值得肯定，但 judge 侧没有同等审计，标注器/被测 agent/judge 三者同源 GPT-5.1，自评闭环风险没处理。
- **Rating**: `2` 👀 ，工程侧的延迟收益是实打实的且消融扎实，但撑起 novelty 的"多视野风险"claim 一出分布就归零，"world model"更像血统而非功能。

### SKILL-KD
- **Title**: SKILL-KD: Contrastive Skill Distillation for LLM Agents
- **Institutes**: 未标注
- **Source**: [link](https://arxiv.org/abs/2607.28048)  📰 HF Daily ⬆️ 9   **📒 论文笔记**: [[2607-SkillKD]]
- **核心**: student 和 teacher 在同一道题上各跑一遍，把两条轨迹的分歧交给一个 consolidation agent 写成文本 skill patch；patch 要进库，必须让 student 带着它重跑这道题并通过 benchmark 原生 scorer（最多改 3 轮，不过就丢弃）。合并环节是带工具的多轮 agent，能按 trace-link 取回历史编辑背后的原始轨迹，再决定 add/modify/delete/skip。五个 benchmark 上 Group 1 宏平均 43.5 → 66.8、Group 2 57.9 → 74.6，均高于最强 baseline SkillOpt（63.5 / 68.6），且只用 38 条规则 3,010 词，比 Student-only 自反思的 96 条规则少一半还多拿 6.7 分。student 权重全程冻结，推理期把整份 benchmark skill 文件全文注入 context。
- **锐评**: 标题里的 "Distillation" 是碰瓷。经典 KD 的定义性特征是 teacher 行为进 student 参数、推理期不再需要 teacher 侧产物；这里 student 冻结、每个 benchmark 各训一份库、推理期全量注入 skill 文件且作者明说不做检索或 routing（C7）——关掉 skill 文件它立刻退化成 No Skill。这是"执行验证过的 per-benchmark cheat sheet 生成器"，叫 distillation 只是给 prompt engineering 镀层。真正扎实的地方是采纳判据：patch 入库要过 benchmark 原生 scorer 而不是 LLM 自评，这比多数 skill 生成工作硬；Table 2 把规则数和词数当一等指标报，让"分数换膨胀"可见，这个习惯值得抄。但硬伤有三处。**一，全文没有 token 预算配平对照，也不报任何方法的推理 token 或 prompt 长度（C8，否定性检索确认）**——No Skill 臂零额外 token，SKILL-KD 臂每次多吃 3,010 词，Group 1 那 +23.3 里有多少是内容、多少是 context 变长，现有数据分不出来；加一条注入等词数无关文本的 length-matched 臂是零成本的，作者没做。**二，采纳判据是 in-sample 的**：patch 只在生成它的那道训练题上验证，从不回测是否弄坏此前已成功的实例（C16）。这和论文自己主打的 "drift-aware" 正面冲突——drift 的三种形态（坐标级修补 `P6:Q6`、规则被后续 patch 覆写）全是 case study，一个回归数字都没有。更难堪的是它把 validation 分区明确划给 baseline 自己不用（C9），而它的 baseline SkillOpt 本来就要求 held-out validation 严格提升才接受编辑。**三，统计强度**：单次运行、无方差、无显著性（C10），LiveMath test 只有 124 题、ALFWorld 134 题。Table 4 用来支撑"teacher 失败也能产出有用 patch"的格子分母小到不可解读（LiveMath 的 accept-on-T-success 是 0.0% 而 accepted-from-T-failures 是 100.0%，ALFWorld 恰好反过来），那个 38.5% 只能当假说不能当结论。再补两刀：Appendix C 暴露 SearchQA 的 15 条规则几乎全是答案格式约定（人名 middle initial、Jeopardy "CATEGORY - Clue" 解析），LiveMath Rule 002 直接写"看到声称更强结论的元选项就选它"——这是在拟合出题与判分习惯，不是 procedural knowledge，而论文偏要 claim 增益体现 "reusable procedural guidance rather than benchmark-specific prompt tuning"，同时零跨 benchmark 迁移实验。ALFWorld 的 +56.0 也别急着鼓掌：所有 skill baseline 都能把 30.6 抬到 63.4–70.1，大头是补上了动作模板这个格式性修复。最后一个巧合请作者自己解释：LiveMath 上 Group 1 和 Group 2 两条完全不同的 student/teacher 管线，SKILL-KD 得分都恰好是 54.8。
- **Rating**: `2` 👀 ，执行式采纳判据 + 把 library 规模当一等指标是真货，但"distillation"名不副实、缺 token 配平臂、drift 主张全靠 case study 无回归数字，卖点和证据之间隔着好几个没做的对照。

### In-Context VLA
- **Title**: In-Context VLA: Endowing Vision-Language-Action Models with Language via In-Context Post-Training and Agentic Tool Use
- **Institutes**: 未标注
- **Source**: [link](https://arxiv.org/abs/2608.05738)  📄 arXiv   **📒 论文笔记**: [[2608-InContextVLA]]
- **核心**: 主张 VLA 需要的是"读懂语言"而不是"生成语言"。把 GroundingDino 定位、DepthAnything 深度、解析式 gripper 投影和 Qwen2.5-VL fallback 组成的只读感知级联产出的结构化空间证据，以 `<spatial>` 标签在 keyframe 注入 prompt，loss 只加在 action token 上（指令与证据 token 全 mask），再用 GRPO 做轨迹级对齐。LIBERO 97.4 / RoboCasa-GR1 59.5 / SimplerEnv 72.4，真机 AgiBot G1 八子任务上多任务成功率 28.1 → 45.0。全文真正有信息量的不是 SOTA 表，而是同证据同 backbone 只改"生成 vs 注入 + 监督掩码"的三行：81.5 → 89.7 → 97.4。
- **锐评**: 承重件只有一张表，但这张表结实。Table 3 把"注入 vs 生成"和"loss 要不要覆盖证据 token"两个变量拆开测，第二行 89.7 单独隔离出监督掩码值 7.7 分——这是全文唯一干净的因果证据，比 LIBERO 上 97.4 对 VLA-Thinker 97.0 那 0.4 分有价值一百倍。Table 12 把 tool loop 换成模型自猜掉到 84.3，比根本不注入的 backbone（90.4）还低 6 分，这个负收益是全文最该被引用的数字：不可靠的 affordance 比没有 affordance 更糟，而作者只把它当消融的一行埋掉了。反过来，"生成式 CoT 有害"这个核心论断整个压在自建的 Gen-CoT 上，而这条基线在 5/10/25/50 每一档数据预算上都跑不过纯 BC（87.6 vs 90.4）——一个连 behavior cloning 都打不过的 CoT 实现，第一解释是没调好，不是生成式 CoT 本身有毒。要立这个论断，最小检验是拿已发表 CoT-VLA 权重同 backbone 同数据重训后再比，作者没做。"objective interference"（语言 token 淹没 action 梯度）被当机制解释反复讲，却从没测过梯度分配，连语言/动作 token 比例都没报，纯属讲故事。跨方法对照全不 matched：π0.5、GR00T N1.5、LangForce 各用各的 backbone 和数据，三 seed 只覆盖自家三条臂，SOTA 框架不成立。Table 2 更难看——展示四个代表任务、Avg 却报 24 任务均值，而展示的 Bottle 76.0 / Cup 48.0 / Milk 58.0 全部输给基线，SimplerEnv 的 Carrot 56.3 也输给四个基线，可见数字和 Avg 讲的是两个故事。还有两处内部问题：正文说去掉 tool loop 会"退回 BC 水平"，但 84.3 对 BC 的 90.4 差 6.1 分，措辞与表格不符；另有一个**待核疑点**（笔记本轮未回原文核对、口径可比性也未验证）——Table 4 的 backbone 行 90.4 疑似低于 vault 中 OpenVLA-OFT 单视角配置的 95.3 记录，且 Table 1 干脆不列自己的 backbone。若该疑点成立且口径可比，净增益会从 +7.0 缩到 +2.1，全文的量级判断要重写。这一条必须先核。另外 Table 10 只给 per-decision latency，没单列 GroundingDino + DepthAnything + 8.8–16.4% keyframe 上的 7B VLM 的 wall-clock，12.8 Hz 与 action-only 13.6 Hz 只差 6% 这件事很可疑。与 ECoT 的本质区别就是 Table 3 的 (a) 行 vs (c) 行——同一套证据源，一个学生成一个学 attend，这个拆法（证据从哪来外包给感知栈，证据怎么用才交给 policy）不需要人工 reasoning 标注，确实比继续往自回归序列里塞 CoT 更容易 scale。但 keyframe gating 是手搓固定触发器，GRPO 只学会了少调工具（3.4 → 1.8）没学会何时该调，tool selection 完全不学，比 SpaceTools 那条路线保守得多。
- **Rating**: `2` 👀 ，机制拆解和那张监督掩码消融值得读，但 SOTA 框架建在不 matched 的对照上、核心论断压在一条打不过 BC 的自建基线上，且 backbone 数字有未核实的疑点。
