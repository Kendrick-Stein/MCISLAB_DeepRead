## 论文点评

### Resource2Skill
- **Title**: RESOURCE2SKILL: Distilling Executable Agent Skills from Human-Created Multimodal Resources
- **Institutes**: Microsoft Research, UC Santa Cruz, Shanghai Jiao Tong University
- **Source**: [link](https://arxiv.org/abs/2606.29538)  🔥 HF Trending ⬆️ 137   **📒 论文笔记**: [[2606-Resource2Skill]]
- **核心**: 把 tutorial video、源码仓库、文章、参考 artifact 四类人类多模态资源自动蒸馏成可执行 skill，组织为 4,893 条带 domain taxonomy 的分层 Skill Wiki，经 MCP 供软件创作 agent 检索组合调用。在 PPT/Excel/Web/Blender/Reaper/CAD/UE5 七个 domain、四个 GPT-5.x backend 上，带 skill 平均 56.8% vs no-skill 45.0%，28/28 model-domain cell 全胜，26/28 胜过 ClaudeCode-H/Codex-H。关键 ablation：去掉 video 源掉 9.5 pp、video 单源即达 66.8%（近全量库），200 个 skill 就吃掉大部分收益。
- **锐评**: 这篇的实验卫生在 skill-library 论文里罕见地干净——四轴 ablation 各控一变量、brief 生成 wiki-blind、online pool 与离线库隔离不污染主对比、外加 5 人 200 条 A/B 人评（非平局胜率 85.5%）兜底，Wilcoxon 88/99 cell 达 p<10⁻⁸。"video 不可替代"也不是口号：held-out 掉分最重的恰是时序/视觉编排型的 Excel 和 Web，机制解释与数据自洽。但硬伤同样清楚：**全文最该做的对照恰好没做**——所有 retrieval baseline 都跑在蒸馏后的 skill 上，matched token budget 下直接 RAG 原始 transcript/代码的对照被作者自己踢进 future work（Appendix M），于是"蒸馏"这一步的净价值至今悬空，你无法排除收益主要来自"给了外部知识"而非"蒸馏成了 skill"。其次，标题挂着 computer-use 的 tag，七个 domain 却全走 programmatic 接口（openpyxl、bpy、ReaScript），agent 从不看 screenshot、不点 GUI——对真正的 screenshot-based computer-use agent 这套结论一寸都没验证。judge（GPT-5.4）与被测 agent 同为 GPT-5.x 家族，ρ=0.71/ICC 0.66 只是中等一致性，self-family 偏好风险真实存在；backend 也全是 GPT 家族，跨 family 迁移零证据。dense retrieval 大幅输给 BM25（60.0 vs 66.0）这个反常识结果作者一笔带过不深挖，可惜。相比 SkillWeaver 一系从 agent 自身 trace 自蒸馏，本文把 skill 来源换成人类既有多模态资产，方向上确实互补且更 scalable——这是它的真正差异点，不是检索或执行框架。
- **Rating**: `3` 🔥 ，"tutorial video 是 agent skill 的高价值矿藏"这个论点有干净的 ablation 撑着且工程可复制，尽管 raw-resource RAG 对照缺失让"蒸馏"本身的净价值仍是张空头支票。

### PATS
- **Title**: PATS: Policy-Aware Training Scaffolding for Agentic Reinforcement Learning
- **Institutes**: 未披露（论文未标注机构）
- **Source**: [link](https://arxiv.org/abs/2607.21419)  📄 arXiv   **📒 论文笔记**: [[2607-PATS]]
- **核心**: 把 skill/guidance 从"要长期积累的资产"重构为**训练期一次性 scaffold**：每个 GRPO rollout group 压成 evidence card，competence-conditioned controller 在 EXPAND/REVISE/COMPRESS/FORCED_PRUNE 间调度受约束的 scaffold 编辑，部署时整个 scaffold 连同 refiner 全部丢弃。ALFWorld/WebShop 上无 scaffold 评测比同规模 GRPO 最多 +18.6 SR points、交互 tokens 减 30–39%；七个 search QA benchmark 上以少 32.1% prompt tokens 逼近保留 skill 库的 SkillRL（45.2 vs 46.0）。核心论点是 "inference utility ≠ training utility"：RL 要的不是最大化即时成功率的完整指令，而是能制造组内奖励差异（mixed-outcome groups）的 attempts。
- **锐评**: 这篇的真贡献不是那个四模式 controller，而是 problem formulation——把"外部指导对 RL 的价值"落到 mixed-outcome group 存在性这个可测量的量上，并且给了直接机制证据而非讲故事：静态 55-entry skill 库在 step 20 把 mixed groups 从 0.62 提到 0.78，step 30 却反手压到 0.72，同一根拐杖随 competence 从助力变毒药，这是全文最硬的一张牌。它与 GRPONullWebAgent（组内全成功→零信号）恰好构成对偶两端，共同指向 "GRPO 有效性 = mixed-outcome group 存在性" 这个跨论文 pattern。部署零残留也是实打实的：SkillRL† 在 7B ALFWorld 高出 2 分（91.43 vs 89.29）但要付 2.86× 交互 tokens，且 1.5B 去掉 skill 直接崩到 47.38——PATS 至少证明了拐杖可以扔。但 headline 数字要打折扣看：消融里 w/o interface initialization 掉 32.85 points，而 w/o training scaffold 只掉 7.14，说明相当一部分收益来自 scaffold-interface SFT 初始化而非在线 scaffold 机制本身，且 GRPO baseline 是否共享同样的 SFT 起点文中未说清——这是主表最大的 confound，复现时第一个该跑的对照。WebShop 1.5B 的 +3.5 埋在 ±7.06 的 seed 方差里等于没有，且该设置下带 scaffold 的 Pats†（59.47）仍高于 scaffold-free（56.33），"scaffold 可无损移除"并非处处成立。机制还系着一个未消融的外部依赖：独立 Qwen2.5-7B refiner 的编辑质量、以及跨环境阈值（0.30/0.85 vs 0.2/0.4）的调参代价全无分析。全部证据限于文本环境 + verifiable reward，视觉 GUI 场景能否成立未知；代码未开源、机构匿名，可信度先扣一档。
- **Rating**: `3` 🔥 ，"训练期支持强度应随 policy competence 动态调节且不留部署税"是有机制证据支撑的真 insight，SFT confound 和 WebShop 1.5B 的噪声不足以掩盖它。

### SearchOS-V1
- **Title**: SearchOS-V1: Towards Robust Open-Domain Information-Seeking Agent Collaboration
- **Institutes**: Gaoling School of Artificial Intelligence, Renmin University of China; Ant Group
- **Source**: [link](https://arxiv.org/abs/2607.15257)  🔥 HF Trending ⬆️ 69   **📒 论文笔记**: [[2607-SearchOS]]
- **核心**: 把 long-horizon open-domain search 从"越滚越长的 conversation history"外化为带 citation 的 relational schema completion：每个填入的 cell 必须锚定 source URL 与 excerpt。SOCM 用四类持久状态（Frontier Task / Evidence Graph / Coverage Map / Failure Memory）让多 agent 共享进度与负面经验，orchestrator 做 pipeline-parallel continuous dispatch，middleware 在 model-tool 边界拦截做 state projection 与 loop/stall 检测，外加 280 个分层 skills。WideSearch 上 Item F1 80.3（最优 baseline 76.0），GISA Set F1 较最优 baseline 提升 13.4 个百分点；continuous scheduling 同时降时间（629→476 秒）、降 LLM call、升 F1。
- **锐评**: 这篇的真贡献是把 coordination object 从 prompt 搬进 transaction-like shared state——Coverage Map 不静默覆盖 conflict、Failure Memory 跨 agent 共享失败，这是对"multi-agent = 多开几个 agent 传消息"套路的实质升级，而且最硬的数字是动态 schema planning（70.6/48.9）打赢了 per-case oracle 固定 schema（62.4/41.2），说明中途重构 schema 是真信号而非工程噱头。但账面有三处要扣钱：其一，主实验是每 case 三跑取 Max@3，单次部署表现被系统性高估，这在比 baseline 时是不对称优势；其二，continuous scheduling 的 ablation 里 F1 从 79.66 跳到 86.75——一个调度器凭什么涨 7 个点的答案质量？最合理的解释是 budget/timeout 混淆（跑得快=截断少），论文若没拆这个 confound，这条 ablation 就是在替 scheduler 冒领功劳；其三，280 个 skills 全家桶只换来 Item F1 +2（78.3→80.3），且一次关掉全部 layer 不拆分贡献，重工程、轻归因。另外 backbone 锁死 GLM-5 + Qwen3.5-35B-A3B，Row F1 天花板仍在 56 上下——exhaustive enumeration 这个真正难的问题没被解决，只是被更好地记账了。
- **Rating**: `2` 👀 ，state-as-schema 的架构思想和 dynamic-schema-beats-oracle 值得借鉴，但 Max@3 计分与 scheduling ablation 的 confound 让账面提升打折，工程堆料大于机制洞察。

### VisPlay
- **Title**: VisPlay: Self-Evolving Vision-Language Models
- **Institutes**: University of Illinois Urbana-Champaign, Washington University in St. Louis, University of Maryland, National University of Singapore, Hefei University of Technology
- **Source**: [link](https://openaccess.thecvf.com/content/CVPR2026/html/He_VisPlay_Self-Evolving_Vision-Language_Models_CVPR_2026_paper.html)  🎓 CVPR2026   **📒 论文笔记**: [[2606-VisPlay]]
- **核心**: 把 R-Zero 式 self-evolution 搬进视觉域：单一 base VLM 分饰 Questioner 和 Reasoner 两角，在 47K 无标注 web 图像上交替 GRPO——Questioner 以 frozen Reasoner 的 confidence 趋近 0.5 为 reward 自动追踪能力边界出题，Reasoner 拿自身 majority-voting pseudo-label 当 verifiable reward 学答题，全程零人工标注、零外部 verifier。三个 backbone 在 7 个 benchmark 上随迭代提升（3B 平均 30.61 → 47.27），平均分与用人工标注跑 standard GRPO 相当。
- **锐评**: 配方干净得令人愉悦——uncertainty reward 把"课程难度"压缩成一个可计算量（|2c−1|），加 diversity penalty、format filter、informative filter 四件套防 collapse，没有 reward model 也没有游戏引擎，这是同期 self-play 竞品里最轻的实现。但三处硬伤必须点名。其一，"competitive with human data" 是 HallusionBench 一项撑起来的门面：拆开 Table 3，3B 的 MM-Vet 38.1 vs 49.5，MMMU 也输，通用理解能力根本没追平；而 HallusionBench 从 32.81（yes/no 题远低于随机水平）暴涨到 94.95，更像 RL 修好了 base 的输出格式问题而非幻觉真的没了，论文没做这个分解。其二，Table 2 是作者自己递上的刀：pseudo-label 准确率逐代 72→65→61，监督信号越练越脏——机制上 Questioner 被激励去出 Reasoner "半会不会"的题，而这恰是 majority voting 最不可靠的区间，难度激励与标签质量存在内生冲突，Limitation 里作者承认无解。其三，迭代根本不稳定：7B Iter2 平均掉 3.6 点、MiMo Iter1 低于 base，只报 3 轮不敢往后跑，Figure 1 画到 Evo 5 但表格只到 Iter 3，口径都对不齐；连 Abstract 的 "eight benchmarks" 都和正文 7 个自相矛盾。值得肯定的是诚实度：主动量化自己最大软肋的论文不多见，Table 2 的 72→61 恰好实证了 SpatialEvo 对 majority-voting 自噬的批评。
- **Rating**: `2` 👀 ，机制设计干净、自曝家丑诚实，是 self-evolving VLM 这条线的有效数据点，但监督信号自噬未解、"追平人工数据"的 claim 靠单项 benchmark 撑场，范式天花板肉眼可见。

### ZonUI-3B
- **Title**: ZonUI-3B: Competitive GUI Grounding with a 3B VLM Trained on a Single Consumer GPU
- **Institutes**: DeepCAT Lab, National Yang Ming Chiao Tung University
- **Source**: [link](https://openaccess.thecvf.com/content/WACV2026/html/Hsieh_ZonUI-3B_Competitive_GUI_Grounding_with_a_3B_VLM_Trained_on_WACV_2026_paper.html)  🎓 WACV2026   **📒 论文笔记**: [[2601-ZonUI3B]]
- **核心**: 用 Qwen2.5-VL-3B + LoRA，不加任何架构改动，靠 24K 跨平台多分辨率数据、balanced sampling 和两阶段训练（Stage 1 cross-platform → Stage 2 high-resolution specialization），在单张 RTX 4090 上 48 小时训完一个 GUI grounding 模型。ScreenSpot 84.9%、ScreenSpot-v2 86.4%、GroundUI-1K 82.4%，均超过 UI-TARS-2B 等 sub-4B baseline；ScreenSpot-Pro 28.7%，甚至压过 Qwen2.5-VL-7B（26.8%）。最有信息量的发现是数据消融：16.1K 随机子集（82.8%）与 119.4K 全集（82.9%）几乎无差，diversity 碾压 volume。
- **锐评**: 这是一篇诚实的数据工程论文，别指望 mechanism。真正值钱的是那个 16.1K ≈ 119.4K 的消融——它直接宣判了"堆同源截图"这条路的死刑，这一条比主表所有数字都有用。但硬伤同样明显：其一，去冗余就是 random sampling，没有 semantic clustering、没有 coverage 分析，"diversity > volume" 的机制解释等于没有；其二，主打对比对象 UI-TARS-2B 比自己少 1B 参数，+2.6 / +1.7 的 margin 有多少来自 recipe、多少来自 3B vs 2B，论文没拆；其三，balanced sampling 这个"贡献"只带来 81.9→82.8 的 0.9 点，接近噪声量级还要单列一节；其四，全程 static point grounding，零多步 agent execution，坐标准确率能否兑现成任务成功率完全未验证。ScreenSpot-Pro 的 breakdown 最诚实：text 39.2% vs icon 11.7%——所谓 high-resolution specialization 只是让模型看清了小字，专业 icon 的 semantic gap 一分没解决，28.7% avg 是被 text 项撑起来的门面。作为"消费级 GPU 可复现的 SFT baseline"它合格且有用，作为研究贡献它止步于 recipe。
- **Rating**: `2` 👀 ，数据消融给出一条对社区真正有用的经验（diversity > volume），但 recipe-only、无 agent 级验证、icon 短板原封不动，值得记住结论而非追读方法。

### OVOD-Agent
- **Title**: OVOD-Agent: A Markov-Bandit Framework for Proactive Visual Reasoning and Self-Evolving Detection
- **Institutes**: Wuhan University
- **Source**: [link](https://arxiv.org/abs/2511.21064)  🎓 CVPR2026   **📒 论文笔记**: [[2511-OVODAgent]]
- **核心**: 针对 OVOD 推理时退化为静态类别名单次匹配的问题，提出一个不用 LLM 的轻量方案：定义 7 个可解释的视觉原语动作（颜色/纹理/几何/空间等），训练期用 UCB Bandit 采样 prompt 改写轨迹、以 GT-IoU 弱奖励 + Dirichlet 转移先验做监督，蒸馏出一个 20MB 的双头 Reward-Policy Model，推理期由它逐步引导文本描述细化。在 4 个 OVOD backbone（含很强的 DINO-X Pro）上 LVIS rare-category AP_r 一致 +1.2~+2.7，overall AP +0.5~+1.2，代价是每图 +90~155ms 延迟。
- **锐评**: 方向选得聪明——"把 LLM 从决策中心移走、只蒸馏离散推理结构进小模型"是条务实路线，DINO-X Pro 48.0→49.2 这种在强 baseline 上仍有正增益的结果比刷单点 SOTA 有说服力，Sec 4.3 的失败分析（非 canonical 形态依赖 linguistic prior、tiny/occluded 下噪声奖励致 policy 退化为 dictionary lookup）也难得诚实。但执行层面漏洞密集：其一，"self-evolving" 纯属包装——监督全部来自训练集 GT boxes 和检测器自身分数，RM 训完即冻结，这是标准离线弱监督蒸馏，部署后什么都不进化；其二，标题里的 "Markov" 框架名不副实，摘要吹 "eight state spaces" 但全文从未定义这 8 个 state 是什么，Eq 7 的 GT 奖励和 Algorithm 1 的 UncertaintyReduction 是两套未调和的信号，理论外壳厚于内容；其三也最致命，三处已核实的内部数字矛盾——引言 "<100ms" vs Table 2 实测 +120/+145/+155ms、Table 5 的 37.7 vs Table 2 同 setting 的 37.0、Table 4 基线量级（AP_r 19.0）与其他表完全对不上且零解释——单处或可归为 setting 差异，三处叠加就是实验记账混乱，主表数字的可信度跟着打折。另外 Table 3 用 GPT-5 blind 评分 + 自定义指标评探索质量，软得没有外部可比性。
- **Rating**: `2` 👀，路线（LLM 推理结构蒸馏进 20MB policy 头）对轻量 agent 设计有借鉴价值，但三处数字矛盾加 "8 状态" 悬空定义让这篇的证据链撑不起它的框架叙事。
