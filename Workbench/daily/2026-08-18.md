## 论文点评

### OpenART
- **Title**: OpenART: Scaling Agent Red Teaming via Open-Ended Environment Evolution
- **Institutes**: Fudan University, Shanghai Artificial Intelligence Laboratory, XSafeAI
- **Source**: [link](https://arxiv.org/abs/2608.00677)  📰 HF Daily ⬆️ 257   **📒 论文笔记**: [[Papers/2608-OpenART]]
- **核心**: 把 agent red teaming 的评测单元从 prompt 换成可执行环境：固定 benign objective 与隐藏 safety contract，只演化 target 可见的环境状态。10K 个跨 50 domain 的 stateful scenario（median 97 tool calls，对照既有 benchmark 的 1–15），每个 runtime 配一个 adapter 把同一 scenario 投到 8 个 attack vector 上，在 15 个 CLI coding agent × 5 个 foundation model 共 75 个配置上做统一评测。reference policy EMHA 是黑盒的 hypergraph 搜索（soft-Q + RUDDER credit + MAP-Elites），双方模型全程 frozen，pooled Strict ASR 85.0%。最有信息量的不是 ASR 而是 Insight 2/3：从消费 evolved state 到产出 unsafe output 的 median 传播距离是 37 个 action，latency 占 workflow 的 41%；失效模式集中在"安全判定被向下游继承而非在每个消费点重算"。
- **锐评**: 全文最值钱的是 formulation 而不是那个 85.0%——把 benign objective 与 evaluator 钉死、只让环境变，使 ASR 提升能干净归因到搜索而非评测漂移，这个不变量别人可以直接抄。adapter 投影层是当前 agent 安全评测里真正稀缺的基建，八个 attack vector 的统一命名比任何一张 ASR 表都更可能被沿用。但 85.0% 必须带限定词才能引用：EMHA 的目标函数是 best-of-K，Fig 5 显示第一轮只有 42.9%，"至少成功一次"和单轮成功率差了一倍，作者在 abstract 里没写清楚。更硬的问题是能力与安全没隔离：Aider 同时是 benign completion 最低（70.74%）和 ASR 最低（59.1%）的 agent，"更安全"和"根本没跑完任务"在数据里分不开，作者把 completion 塞进方差分解却始终不给 completion-conditioned ASR——这是唯一能 flip agent 排序的实验，恰好缺席。方差分解那句 "runtime implementation plays a significant role" 也偏了：作者正文自认 "does not identify the underlying mechanism"，且前两项已吃掉 91.3%，再加一个 15 水平 categorical 变量涨 7.6% 本就是自由度红利，没报调整量也没交叉验证。Judge 是 GLM-5.2，而 GLM-5.2 自己就是被测的五个模型之一，零 judge 敏感性分析，self-judging 偏差方向不明。99.3% 人工审计只验了 evaluator 能区分 safe/unsafe 这种机械正确性，10K scenario 是真变体还是模板换皮从论文判断不了。Table 5/6 的 75 个 cell 全都没给 N 和 CI，跨模型次序整齐到可疑。EMHA 本身也偏胖：archive 和 credit redistribution 各只贡献 3.9%/2.6%，一个纯 hypergraph 路径采样的简化版能到多少，作者不敢做这个 ablation。最后，一个 pooled ASR 85% 的攻击框架配开源 repo，全文没有 Limitations、没有 Ethics、没有 responsible disclosure，2026 年的 agent-safety 论文这样交稿说不过去。结论边界也比标题窄得多——15 个 target 全是 terminal+filesystem+MCP 生态的 coding agent，不碰 GUI/browser，也没有多 agent。
- **Rating**: `3` 🔥 ，问题 formulation 与跨 runtime 投影层是能被反复复用的真基建，长程传播的定量结果直接指向可做的防御设计；ASR 口径与 completion 混淆需要打折读，但不影响核心贡献的分量。

### ABot-World-0
- **Title**: ABot-World-0: Infinite Interactive World Rollout on a Single Desktop GPU
- **Institutes**: ABot-World Team（论文未标注 affiliation；笔记据代码库 org `amap-cvlab` 推断为 AMAP, Alibaba）
- **Source**: [link](https://arxiv.org/abs/2607.19191)  🔥 HF Trending ⬆️ 311   **📒 论文笔记**: [[Papers/2607-ABotWorld0]]
- **核心**: 以 Wan2.2 为底座、8 键键盘（WASD 移动 + IJKL 转视角）作为唯一动作接口的 action-conditioned video world model。训练走 teacher forcing → ODE distillation → LongForcing 三段蒸馏，把双向 teacher 压成因果 few-step student；部署侧堆 LightVAE、DiT 低比特量化、Fast-RoPE、bounded KV cache，在单张 RTX 5090 上跑 1280×704、最高 16 FPS、1.2 s action-to-first-frame、峰值显存 ≤19.3 GiB。能力侧在 WorldRoamBench 上以 5B 参数与 Genie 3 打得有来有回，但七个子维度**全部第二或第三，一项第一都没有**。
- **锐评**: 系统那半篇是真活儿，算法那半篇是 PPT。Table 2 是全文最值钱的东西：Base 和只换 SageAttention2 双双 OOM，第一个能跑的配置来自 LightVAE，逐配置给出 DiT/VAE 分项耗时、FPS、显存，latency 按"按键到首帧可用"的端到端定义报——比 [[Papers/2607-Wonder]] 那种"我也 16 FPS"但不说硬件、不给组件分解的报法高一个段位。但请注意 16 FPS 是 MXFP4 最激进档的 15.831，作者自己声明的质量优先默认配置 FP8 只有 12.4–13.3 FPS；而 Table 3 的质量分**根本没说跑在哪个量化配置、多少步**上，速度轴和质量轴是两个悬空的孤立点，全文最该量化的 trade-off 恰恰被塞进了 future work。更难堪的是标题写着 "Infinite Interactive World Rollout"，memory 子分 0.5041 却是七项里相对差距最大的（落后 Genie 3 / HappyOyster 约 0.10–0.13）——bounded KV cache + rolling eviction 在设计上就把窗口外历史丢了，reference-character memory 只保住了主角长相，场景级状态持久压根没有对应机制，论文对这个矛盾一个字没解释。小时级、天级 rollout 全是关键帧条，唯一的定量长程证据是 60 秒的 LongForcing 曲线图且无数值表；作者自己的措辞是 "without observable collapse at the evaluated timestamps"，诚实，但那叫"抽样时刻还没崩"，不叫"世界状态自洽"。评测独立性也要打折：WorldRoamBench 虽是引用他文，但其作者与本文 Benchmark Team 高度重叠，"在自家 benchmark 上平 Genie 3"和"在第三方 benchmark 上平"不是一回事；而 14B 的 LingBot-World 和 8.3B 的 HY-World 1.5 被 5B 模型全维度翻倍碾压（0.11–0.32），这更像 baseline 没配对协议，论文对这两行异常低分零解释——顺手贬低对手抬高自己，是技术报告的老毛病。方法侧几乎无消融：加性动作注入 vs 其他注入、negative RoPE + 非对称 memory attention、Fast-RoPE 重锚定全无对照，三段蒸馏只消融了第三段。加上训练语料规模完全不透明、核心数据（AAA 游戏 + 自有 3DGS 扫描）明确 proprietary，开源代码库救不了复现性。
- **Rating**: `3` 🔥 ，系统口径是当前实时 world model 里最可复算的一份部署清单，值得对照；但能力比较结论和"infinite rollout"叙事都要按打折读——引部署数据，别引它的 benchmark 排名。

### AI4AI at Test-Time
- **Title**: AI4AI at Test-Time: Strong-to-Weak Capability Transfer via Harnesses
- **Institutes**: Salesforce AI Research, University of Illinois Urbana-Champaign
- **Source**: [link](https://arxiv.org/abs/2608.12307)  📰 HF Daily ⬆️ 110   **📒 论文笔记**: [[Papers/2608-StrongToWeakHarness]]
- **核心**: 让强 builder model 在只看得到 5% validation 的条件下，为参数完全冻结的弱 target model 迭代搭建 inference-time harness，把 capability transfer 从改权重挪到改任务呈现。在四个 ToM benchmark 共 3900 道隐藏测试题上，57 个 scaffolded run 把 GPT-5.4-mini 的 macro 平均从 0.488 抬到 0.763，最好单次 run 达 0.912，全部 run 超过 baseline。作者做了十个 aspect 的受控扫描，得出两条反直觉结论：validation 迭代次数与最终成绩几乎不相关（r=0.17），而 builder 的 reasoning effort 单调有效（ρ=0.77）；增益大小由 target 剩余 headroom 决定，强 target 上 9/20 格反而退化。
- **锐评**: 协议设计是这篇最值钱的部分——test set 全程隐藏、builder 只见 validation、最终由人类评测者跑导出的 entry point，乐观偏差 0.021，比这条线上大多数只报 bundle 级增益的 harness 论文干净一档；"多探无效、想深有效"和"强 target 上 scaffolding 反噬（弱 target 0/20 vs 强 target 9/20 退化）"这两条负面结果，信息量远超那个 +0.275。但核心叙事有个躲不掉的洞：vanilla baseline 在 BigToM 0.503、MMToM-QA 0.412 两个二选一任务上处于或低于抛硬币水平——一个二分类打不过随机的 baseline，失败大概率出在输出格式与解析上，而 format enforcement 恰恰出现在 57/57 个 scaffold 里，论文自己的归因表这一行只能填 "–"。于是"transfer cognitive structure"与"把丢在格式上的分捡回来"在数据上根本分不开，缺的实验极其廉价：format-enforcement-only 单臂。BigToM 单个 benchmark 在最佳 run 里贡献了约三成 headline 增益，而它正是作者自承有 explicit reasoning shortcut、determinism fraction ≈0.94 的那个；作者辩护"发现可编译结构也是 builder 能力"，可以接受，但那已经把 claim 悄悄改写成"发现 benchmark 的可编译性"了。headroom law 的 r=0.75 也要打折：uplift 与 headroom 两侧共享 −baseline 项，天然正相关，论文没给 recovery-fraction 之类的归一化口径（结论方向靠 9/20 那条独立撑住，但数字被高估）。更难看的是数字校对：Sec 4 说 validation 195 题（5%），Appendix A 里真正交给 builder 的指令文件写的是 "a random 2% sample"（约 78 题），差 2.5 倍；正文写 χ²≫10⁴，Fig 10(a) 表里是 1424.4。前者尤其要命——若 builder 实际只见 78 题，"乐观偏差仅 0.021"反常地小，选择性偏差的账就得重算。另外 12-technique taxonomy 全靠作者手工阅读 scaffold code 编码，无 inter-rater reliability，scaffold 与代码均未公开，"polarity logic 值 +0.090"这类结论的可复核性接近零。self-scaffolding 对照倒是老实：弱模型给自己搭 harness 已拿 +0.217，换强 builder 只多 +0.05——同一批数据其实也支持"strong-to-weak 里的 strong 没那么关键"这个更弱的读法。最后，自动 scaffold 的 0.912 仍低于人工 UserHarness 的 0.939，且只在 BigToM 上赢，MMToM-QA 0.84 vs 0.98 差得相当难看。
- **Rating**: `3` 🔥 ，协议干净、负面结果扎实、determinism fraction 与 headroom 两个度量可迁移，尽管最关键的 format-enforcement 归因缺口和两处内部数字不自洽让 headline 明显虚高。

### Alaya-EVOKE
- **Title**: Alaya-EVOKE: From Linear-Scaling Supervision to Endless World
- **Institutes**: MoE Key Lab of BIPC, USTC; Shanghai Innovation Institute; Alaya Lab
- **Source**: [link](https://arxiv.org/abs/2608.13546)  📰 HF Daily ⬆️ 124   **📒 论文笔记**: [[Papers/2608-AlayaEvoke]]
- **核心**: 把 interactive world model 的持久性、响应性、长时程三个冲突需求拆开安置：空间持久性外置成一个用 camera pose 直接寻址的几何 world state bank（denoiser 内只留 19 个 latent frame 约 3.2 s），时间一致性交给一个 chunk-wise 稀疏注意力、支持 per-chunk 文本条件的 14B teacher，再用 31.4 s 全窗口 DMD 蒸馏成三步无 CFG 的 student。关键训练技巧是 supervision horizon 与 gradient horizon 解耦——chunk 间 detach 使反向图只覆盖单 chunk，但 teacher/critic 仍对完整 189 帧联合打分。结果侧报告 WBench navigation split 公开榜 Average 80.8 第一、8 段 65.5 分钟连续 rollout，以及 revisit 窗口覆盖离开时长时 +2.3–3.2 dB 的 pose-addressed recall。
- **锐评**: 这篇的证据纪律在 world model 这个 demo 至上的领域里几乎是异类——图注自己写 "A stability claim, not fidelity (n=1)"，附录声明 7 处 VBench 协议偏离，WBench 榜单行加脚注说明是自评、非 step-matched、0.1 的领先幅度不该读成胜利，还主动构造 13 组扰动扫描去推翻自己的机制解释然后报告失败。问题是**这份诚实全部住在附录里，摘要一句也没带**：摘要写 "state-of-the-art on WBench"，实际是 80.8 对 80.7、作者本人已在 Appendix 11 否认过的量级；VBench-2.0 的 66.77 vs Veo 3 的 66.72 同理，0.05 的差距建在一套自己声明有偏离的协议上。更要命的是错配：§3.2 整段论证是为 **content drift** 构造的——那种"每个局部窗口单看都合理、只有远隔时刻对照才暴露"的失效——但唯一显著的长/短 teacher 差异是光度稳定性（亮度 74%→101%，n=8，Wilcoxon p=0.016），而按论文自己的理论光度这类退化本来就在短窗口内可见；content descriptor 上两个 student 没有显著差异，sharpness 不改善，post-distill 无额外收益。为难问题造的机制，只在容易的问题上被证明有效，摘要却仍写 "improving resistance to long-term content drift"。标题的 "Endless World" 同样要打折：保留预算 90 s / 2160 像素帧，两小时 rollout 只有 90 秒的世界记忆，endless 的是生成不是世界状态；即便在覆盖范围内 recall 也只有 15.4–17.8 dB，是"认得出"不是"对得上"；而把预算拉到 10 分钟的存储与检索代价从未被刻画，这恰恰决定它能不能真替代 KV cache 路线。延迟侧：diffusion 2.11 s/1.5 s chunk（H200、384×640），几何路径每 chunk 另加 1.84 s（相当于一个不走几何的递归步的 93%）；论文只分项报告、主文没有任何端到端数字，按分项相加约 3.9 s（**本笔记推算，非论文结论**）——对一个通篇以 "interactive"/"low-latency" 立论的系统，这个缺口不小。还有几处硬伤：Navigation 78.63 在 9 个 few-step 系统里排第 6、Perspective 排第 4，交互轴恰恰是弱轴，作者只丢下一句"相机控制通路的限制"就没了；而 camera pose 同时是控制信号**和**记忆地址，pose 跟随越差取回的几何越对不上视图，这条污染链路全文零测量。几何是一叠彼此独立的静态快照（刻意不跨 chunk 融合以避 scale drift），动态物体没有任何表示，HybridMemory 定位的 exit–reentry 失效原封不动。"锚定内容改不动"（4% vs 67%）被写成良性分工，反过来说就是**你看过的东西再也编辑不了**，城堡进了库就烧不掉，这是能力边界不是设计优点。训练数据规模完全未披露（Sekai + "additional internal video data"），recipe 与数据的贡献无法分离。相对同实验室三周前零定量评估的 AlayaWorld，这次是实打实的兑现；真正值得带走的不是那个 80.8，而是"supervision horizon ≠ gradient horizon"这个可迁移的训练观察，以及 §3.2 那条"正确答案是否已被本次会话生产出来"的可证伪分派判据。
- **Rating**: `3` 🔥 ，机制论证与证据纪律都属上乘、训练技巧可直接迁移，扣分在摘要 overclaim、核心机制只在最容易的指标上被验证、以及 "endless" 名不副实。

### UI-Mate
- **Title**: UI-Mate: Advancing Open-Weight Foundation GUI Agents with In-Context Demonstrations
- **Institutes**: Tencent Hy Frontier Team
- **Source**: [link](https://arxiv.org/abs/2608.15930)  📰 HF Daily ⬆️ 25   **📒 论文笔记**: [[Papers/2608-UIMate]]
- **核心**: 腾讯的开权重桌面 CUA 技术报告，两条主线：环境接地的数据/RL 训练栈（capability tree 做覆盖诊断、verifiable task 双探针精炼、decision-turn centering 的 GRPO 变体），以及 DemoCUA——把一条人类/agent 示范切成带完成判据的子任务工作流塞进上下文，指针由屏幕状态而非步数推进。27B 在 OSWorld-Verified 77.0、WindowsAgentArena 66.2，是其对比表内开权重最好成绩；自建 OSWorkerBench（100 个跨 41 个 mock 办公应用的长程任务）上 41.0%，比 Kimi-K2.6 的 40.67 险胜，落后 GPT-5.6-Sol 30pp。但这篇真正的信息量在 §7.4 的自曝负面结论：adaptive curriculum 与 process credit 只加快收敛不抬终点、historical reasoning 进 RL 会触发 entropy collapse、通过执行不变量筛选的 verifier 仍有约 18% 与指令语义不对齐。
- **锐评**: 先说该夸的：18% verifier 语义不对齐（过严 40% / 空洞 23% / 打错目标 19%）是我见过对"合成 reward 到底多不可靠"最直接的公开量化，它把 `R(E_0)=0, R(E*)=1` 这条 CUA-Gym 系的标准收敛检查钉死为"只保证内部一致性"——参考解和 reward 完全可以共享同一个语义盲点。这条对任何做 GUI RLVR 的人都比 77.0 重要。§7.4 整节的诚实度在大厂技术报告里罕见：明说自家两个 RL 组件不提终点、自家机制在 RL 里熵坍塌、自家 9B 在 OSWorld-Verified 上低于同尺寸 ScaleCUA（66.2 vs 68.7）。训练期只给 key action、推理期给全序列这个不对称也确实漂亮，逼模型先建立"以截图为准"的先验再加大引导密度。<br>问题在头条 claim。示范增益的大小与"测量设置对示范有多友好"几乎单调相关：OSWorld-Subset-30 的 +25.48pp 建在一个按"UI-Mate 无示范会失败"反向筛出来的子集上，且这组数字在 Table 5 叫 Progress Score、§7.3.4 叫 average score、附录 Table 14 叫 mean success rates，三处口径互相打架，连 binary success 都没报——摘要却拿它当旗舰证据；OSWorkerBench-33 的 +18.18pp 用的是更强 agent 在**同一任务**上的成功解，等于把答案路径喂进上下文，作者自己在 §10 承认这不算程序迁移；到了无子集筛选、无同任务泄漏的 GameDev，增益只剩 +4.39pp，10 个任务里 4 个变差。更尴尬的是 GameDev 上 Kimi-K2.6 无示范 83.46、有示范 88.46（+5.00），两种条件下全面高于 UI-Mate 的 76.76 / 81.15，增益还更大——数据躺在附录 Table 12，正文只写"我们观察到类似提升"。也就是说，没有任何证据表明 DemoCUA 那套训练管线让模型比一个通用长上下文强模型更会用示范，而全文最该做的对照（同基座 Qwen3.6-27B：只加 demo prompt vs demo-augmented 训练）恰好没做。再补两刀：真正对应论文动机（用户示范自己的私有流程）的 variant-demo 只有 10 任务 pilot，还得"复制示范片段以匹配目标实体数量"才勉强净正，说明模型根本抽不出"这步对每个实体重复一次"的可外推结构，只会按字面抄；预算口径也只对齐了上限（1000 步），实际消耗在 OSWorkerBench-33 上从 173.3 涨到 216.0 步（+24.6%），而 §7.4.3 的小标题却叫"Demonstrations improve execution efficiency"。此外 §6.2/§10 说 self-demo 是强 agent 成功 rollout 的直接转换，§7.3.2 却说标注者会"补完 agent 未能解决的部分、移除纠错循环"——若真需要人工补完 agent 解不出的部分，"self-demo 可规模化"这个隐含前提就塌了一半。基准侧，OSWorkerBench 全建在 mock 企业应用上，覆盖不了加载延迟、权限弹窗、A/B 界面这些恰恰构成论文动机的失败源；基线也偏旧，EvoCUA 用的是 32B 的 56.7 而非续作的 63.2。组件级归因基本缺席：数据侧和训练侧没一项独立消融，唯一有消融的三项恰好是被判"没用"的那两项加一个会熵坍塌的。
- **Rating**: `3` 🔥 ，示范增益的证据结构比标题弱一大截、且被 Kimi 的附录数字直接反将一军，但 18% verifier 语义不对齐的量化、decision-turn centering 的偏差诊断和整节自曝负面结论，值得任何做 GUI RLVR 的人精读 §7.4。

### DarwinX
- **Title**: DarwinX: Evolving Agent Harnesses Through Natural Selection
- **Institutes**: Salesforce AI Research, Salesforce Agentforce
- **Source**: [link](https://arxiv.org/abs/2608.07545)  📰 HF Daily ⬆️ 97   **📒 论文笔记**: [[Papers/2608-DarwinX]]
- **核心**: 冻结 base model，只让 harness（skill 层 prompt/memory + code 层 tool/control flow）演化，用一份 preserve-and-extend contract 决定谁能留下：子代必须净增益为正且回归有界，再由 reasoned verifier 两阶段裁决与 avg@k 复测确认。archive 保留全部变体（含全局更弱的 specialist）供跨 lineage merge，merge 只接纳覆盖双亲赢面之并集的子代；学习信号按任务状态分派 failure- / teacher- / self-derived 三类证据。四个 benchmark 按"演化信号与测试集分离度"递增排列：TB2.1 75.5%→83.2%、TerminalWorld held-out 25→28/41、WAI 真实任务 audit-clean 43.5%→93.0%、TB2.1 harness 零改动迁到 SWE-bench Verified 得 84.2%。附带一份两阶段 action-validity 审计，显示 base 的 raw 53.0% 里有 293 条无效轨迹。
- **锐评**: 评测阶梯和 validity 审计是真货，标题宣称的贡献是虚的。先说好的：WAI 那一档训练用 LLM judge 打的合成 intent、报告用确定性 verifier 上 1,260 道真实任务，被优化的和被测量的完全不重合，这种设计比任何单点 SOTA 都更能回答"学到的是能力还是补丁"；附录 D.2 的静态去混淆 + taint 追踪 + 独立 judge 审计出 155 条 evaluation-plane 越界、26 条 exploit/提权，意味着 WebArena 系未经审计的 pass@1 都该默认含不明比例注水，这套 rubric 单独拿出来就有价值。现在说坏的。论文自我定位是"archive 是公共基建，population selection 才是贡献"，可支撑 population 的实证只有 TerminalWorld 一处：四个 specialist 24–27 题、merge 后 28 题，在"一题 = 2.4 点"的 41 题集上只高出最佳 specialist **一题**，而附录 C 自己承认一个 pre-TW 的 skill-bundle 参考 harness 同样打 28/41——搜索了半天没超过一个演化之前就存在的 harness。更狠的是增益最大的 WAI 上**每一次 merge 都被 revert**，收益全部沿单条主 lineage 累积，正是它用来批评 DGM 的那个形态。数字层面两处会骗读快的人：摘要"平均约 17 点"全文没说明怎么算（Ledger 记为 unsupported，别当论文口径引），而四个 delta 里 +49.5 比其余三项高一个量级，等权平均必然被它主导；那 +49.5 的起点是 Monet 这个 coding agent 硬套 browser harness，Elation prescriptions 上 base 只有 20.0 而同模型标准 Browser Use 是 90.8、Gmail 25.0 对 85.0——大部分增益是把一个不适配 harness 修到及格线，真正与前沿相关的是 93.0 对 86.1 的 +6.9，正文报了、摘要没有。TB2.1 的 +7.7 没控住 effort：base 跑 default、DarwinX 跑 high，论文拿 Terminus-2 在 xhigh 只有 78.0% 反驳算力质疑，但那是**另一个 harness**，缺的恰恰是 base Monet 在 high 下的那一格；可辩护的干净数字是 +5.2。TerminalWorld 对 Claude Code 的一题优势 McNemar p=1.0，训练 proxy 从 0.505 饱和到 1.000 而 held-out 68.3%，31.7 点落差——这些作者都自己写了，诚实度在同类工作里排前列，但也说明多数批评只是把 §9 读到底。最致命的缺席实验：7 个 TB2.1 skill 和 4 个 WAI skill 全部收敛到"先声明 acceptance contract 再核验"这一个形状，pattern 跨模态跨 reward source 重现确实有说服力，可正因为它单一到能用自然语言复述——**把这 11 条手写进 base harness 能拿回多少？** 论文没做，而这比任何算子级消融都更能决定这条路线的死活。外加 Monet 专有、零代码零 artifact、全文找不到单次 run 的 rollout 数或算力成本（C17: not-checkable），而核心论点偏偏是"把 evaluation compute 换成持久能力"——承重的兑换率数字没了。
- **Rating**: `2` 👀 ，评测设计与 validity 审计值得抄走，但 population/recombination 这个 headline 机制在最强的 benchmark 上每次 merge 都被 revert、在唯一支撑它的 benchmark 上只赢一题且不敌一个演化前的参考 harness。

### DreamX-Phi 1.0
- **Title**: DreamX-Phi 1.0: Action-Conditioned Video World Model for Robotic Manipulation
- **Institutes**: 论文未列机构（arXiv abs 页与全文均无 affiliation，GitHub org 为 AMAP-ML）
- **Source**: [link](https://arxiv.org/abs/2608.13489)  📰 HF Daily ⬆️ 94   **📒 论文笔记**: [[Papers/2608-DreamXPhi]]
- **核心**: 把 PRoPE 从"相机相对位姿"重定向到"末端执行器轨迹"：在 Wan2.2-TI2V-5B 上按 attention head 分组（每臂一组）注入 SE(3) 相对变换，夹爪标量作 per-arm additive bias 旁路，外挂 action-derived optical-flow 线索、单向 depth 分支、SAM3 mask 重加权与 frozen V-JEPA 的 Gram 矩阵关系损失，最后 DMD2 蒸馏出 few-step student。WorldArena 2.0 Track 1 的 2026-08-12 快照上 31 条目排第一（EWMScore-P 60.65），Track 2 的 Adjust Bottle 67.19% 并列第二。WA1.0 的 76.88 是作者离线自测，论文自己在脚注里说明它不是该快照的 leaderboard 条目。全文零 ablation，六个组件没有一个被隔离。
- **锐评**: 立论是对的——photorealism ≠ action faithfulness，这句话该被更多 video world model 听进去；PRoPE 迁移的三处适配（统一坐标系、per-arm 持久 head 容量、夹爪旁路）也确实把"相机 ≠ 末端执行器"拆成了可执行约束，不是包装。zero-init residual 与单向 depth cross-attention（depth 读 RGB，RGB 永不读 depth）是有纪律的设计：辅助监督不污染主推理路径，代价只在训练期。**但这个第一名经不起细看**。笔记作者按 Table 2 逐项相减推算（这是笔记的推算，不是论文的结论，复算 15 项差值和 7.79/15 = 0.519 与论文自报的 0.52 吻合）：Trajectory Accuracy 一项贡献 +0.53，其余 14 项合计 **−0.14**，净负——领先 Alpha-World 的 0.52 分完全由轨迹忠实度撑起，Image Quality 63.25、Aesthetic 43.38、Semantic Alignment 90.53 全部落后。讽刺的是这恰恰是对论文核心主张最强的实证，而论文自己却以"strong system-level performance in video prediction"作结，比证据允许的宽得多。真正的硬伤是**零 ablation**："结构化几何接口优于 token 化接口"这个最响亮的主张，唯一支撑是整系统的榜单名次——一份自称贡献是新动作表示的报告，没有一个组件被隔离，PRoPE / flow / depth / SAM3 / V-JEPA / DMD 全部打包上榜，连"3,700h Ego4D 这类 action-free 预训练是否必要"这种最便宜的对照都没做。DMD 那节的唯一动机是 efficient deployment，却没有步数 N、没有延迟、没有 NFE，甚至没说榜单提交用的是多步 teacher 还是 few-step student，整节等于悬空。开篇拿"抓空、移错臂、grasp/release 混淆"立论，最后只给作者挑选的 Figure 3 定性 rollout，没有一个针对这些失效模式的定量诊断。适用域也比标题窄得多：动作张量 A ∈ R^{2×T_lat×4×4} 硬编码双臂、head 分组训练时固定、清洗规则明确删掉灵巧手与移动底盘，实际就是**固定底座 + 双臂 + 平行夹爪**；intrinsic 置 identity 后通道里根本没给相机运动留位置。还有一处该让读者警觉：25,000 条 RoboTwin 2.0 clip 进了训练池，而 WA1.0/2.0 评测集同样由组织方从 RoboTwin 2.0 轨迹 curate，论文没有说明二者是否不相交（这是"未说明"，不是"已知污染"），叠加 RoboTwin 训练视频经自研 DreamX-Refiner 超分而评测输入是否同样处理亦未交代——那个"超过官方榜首 3.24 分"的离线数字应当保守读。跨版本引用 EWMScore-P 也有风险：论文只陈述了 WA2.0 对 Dynamic Degree / Flow Score / Motion Smoothness 按 ground-truth 封顶，并未主张两版分数不可比，笔记的尺度分析属于读者推断。加分项是诚实：PRoPE 归功 Li et al. / Miyato et al.、"matched ablations are still needed" 写进 Limitations、WA1.0 是离线自测也用脚注挑明——比同类 challenge report 干净不少。但代码仓库 4 KB、只有 .gitignore / LICENSE / README，权重要等 IROS challenge 结束，眼下无一物可复现。
- **Rating**: `2` 👀 ，per-arm SE(3) 注意力是个之前没被写清楚的动作条件接口、值得记住，但零 ablation 让"几何接口 > token 接口"仍只是个有吸引力的假设，榜首本身则几乎只是一项 Trajectory Accuracy 的产物。

### Spatial Memory Agent
- **Title**: Spatial Memory Agent: Experience-Grounded Procedure Memory for Spatial Intelligence
- **Institutes**: Zhejiang University, Shanghai Jiao Tong University, Shanghai Innovation Institute
- **Source**: [link](https://arxiv.org/abs/2608.12743)  📰 HF Daily ⬆️ 42   **📒 论文笔记**: [[Papers/2608-SpatialMemoryAgent]]
- **核心**: 冻结 VLM 权重、推理时也不调 depth/3D 专家工具，只靠一个外部 memory bank 做空间推理自演化。在带 ground-truth verifier 的 environment split 上把每次 rollout 反思成一条 transferable lesson 写卡，为每张卡维护一个由后续访问校准的 Transfer Reliability Score（收缩均值 `v=(λv0+c)/(λ+n)`，λ=2、v0=0.5），deployment 阶段用 semantic filter 加"相似度+TRS" z-score 组合排序取 top-3 前置进 prompt，bank 全程冻结。5 benchmark × 4 base VLM 主表上每个 block 的 macro average 最高（+1.7~+2.9pp），20 格里严格最优 18 格。最有价值的是 §4.6.2：相对纯相似度检索 MemP，SMA 把检索卡片平均相似度从 0.792 降到 0.698，macro accuracy 反而从 66.8% 升到 69.8%。
- **锐评**: 诊断做得比主表漂亮，主表本身却经不起看。最硬的伤是**比较不是 selection-matched**：主表每个 SMA 数字取 10 次 pass 的 best checkpoint，而全文（§4.1.3 + Appendix C.4/C.6 逐节核过）没有一处说 baseline 享有同等规则，Appendix C.6 逐格 Pass 值在 2–10 之间无规律跳动（27B 是 3/9/2/10/6）——这就是 max 操作的典型形态，而且这个 max 是在 deployment split 上取的。温度为 0、单次确定性运行、无多 seed 无置信区间，而所报 margin 折算成题数（笔记按各 split 规模自行推算，非论文陈述）在 27B block 上只有约 30 题，其中 15 题落在两个 ~200 题的小 split 上。这个信噪比下，"每个 block 都最优"是未知，不是已知。第二，**呈现偏斜太明显**：SITE-image 与 ViewSpatial 是 deployment split 最大的两个（2224 / 2856），偏偏进了附录，也偏偏就在这两个上 MemRL-GT 于 ViewSpatial 两次反超（122B 62.8 vs 59.7、27B 64.3 vs 63.2），122B block 的两 benchmark 均值 MemRL-GT 66.9 > SMA 65.6；附录还没给这两个的 δ 与 Pass。主表那 5 个恰好是全胜的 5 个，样本量还都是三位数以下——读者得自己翻附录才看得到另一半。第三，**算法增量被包装放大了**：检索式与 MemRL 逐项对应（阈值预筛 + 相似度/价值 z-score 加权、权重同取 0.5、δ 都逐 benchmark 调），真正换掉的只是把 order-dependent 的 EMA 换成 order-invariant 的收缩均值——合理，但这是"MemRL 范式往多模态空间域的移植 + 估计量换形"，不是新机制，作者列里有 MemRL 一作也说明了这一点。第四，**消融缺的正好是中心主张那一格**：两张消融表都把 semantic filter 排在最大贡献项（−5.8 / −7.2），TRS 却没有 η=0 的对照行，只有 sensitivity sweep 的峰值——"TRS 相对纯相似度的净增益"在实验里是空的。第五，Table 3 的 63.5 vs SpatialEvo-7B 47.1（Δ+16.4）跨了整代 backbone，同 backbone 的 no-memory 已经 60.6，笔记据此推算 16.4 里约 13.5 是 backbone、memory 只值 +2.9；正文措辞留了保留，表格没有。第六，**成本零记账**：每题 prepend 3 张卡、environment 阶段每题多一次反思调用，全文无 token/latency 数字，"给 no-memory 等量 context 预算"的对照也没有——在 memory 类工作已被系统性质疑预算不对称的背景下，这不是可以省的一栏。还有个自打脸的地方：Table 5 显示成功源卡片下游 accuracy 85.7% vs 失败源 61.4%，差 24.3pp，Appendix B.1 却把 uniform initialization 定为显式设计要求，主动扔掉了自己测出来最强的先验，连一行"差异化 v0"的消融都没做。夸的部分要给足：§4.6.2 那组配对测量（相似度 −0.094 而准确率 +3.0pp，方向在每个 benchmark 一致）实打实证伪了"最近邻即最优检索"这条 convention，Table 5/6 把"记忆质量从哪来"变成可观测量，E.2 承认三个 TRS≥0.6 的高质量记忆仍纠不过 movement direction / object count 的误读也很诚实。可惜这些机制级证据被一张口径不干净的主表拖着走。代码 "Coming Soon"，短期内无法复现比较。
- **Rating**: `2` 👀 ，机制诊断密度和相似度—准确率解耦结论值得单独引，但主表 best-of-10 无 baseline 对等选择、大 split benchmark 藏附录且在那里被反超、核心 TRS 缺 η=0 消融，方法本身相对 MemRL 只是换了个估计量。
