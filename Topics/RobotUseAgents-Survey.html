Robot-Use Agents：通用 Agent 如何使用机器人

Overview

Robot-Use Agents 研究通用 Agent 如何通过机器人接口完成需要物理行动的任务。

一次 Robot-Use 交互至少包含目标、可用观测、可执行指令和动作结果。Agent 可以打开相机或请求深度，选择抓取、导航等技能，也可以发末端动作或写出可执行代码，再用机器人的反馈确定下一步。机器人负责实现物理动作，Agent 对当前任务的进度和后续决策负责。研究的核心变量是 Agent 对执行有多少决定权，以及它在什么时刻能得到足够的信息修正决定。2610-OpenRUA · 2610-RobotWorld · 2611-RUIBench

“agent use robot” 对应论文中常用的 Robot-Use Agent（RUA）、Agentic Robot Control（ARC） 和 Agentic Manipulation Policy（AMP）。狭义 RUA 指模型在任务内直接发出机器人动作或写代码，并读回执行反馈。广义用法也包含模型通过技能或 VLA 调度机器人。Agentic Robots 还研究 Agent 对训练、数据、环境和运行框架的改进，本综述以执行任务期间的 use 为中心。 OpenRUA §3 · Towards Agentic Robots §3 · On Agentic Manipulation Policies §3A

截至 2026 年 11 月，已有在受控真机中经接口直接完成多步操作的证据。开放环境覆盖、成本和可靠性仍需逐项测量。在 RobotWorld 的仿真广覆盖测试中，至少有一个模型完成的任务只有 21/84。RUIBench 的真机试验进一步表明，在仿真中受益的交互形式到了真机可能反转。2611-AMP1 · C1–C2 · C1–C3

感知和行动共同构成接口。一次工具调用完成只说明执行服务返回，任务验收还要检查现实中的目标状态。

2. Agent 怎样使用机器人

2.1 调用技能和 VLA

SayCan 把语言选出的下一步技能与机器人环境中的 affordance 相乘，减少语义上合理而物理上不可执行的决定。Inner Monologue 把动作成功、对象观测和必要时的人类反馈送回规划器。早期系统由此把固定指令序列变成状态依赖的技能调度。它们的任务能力受技能库覆盖和反馈质量限制。2204-SayCan · Inner Monologue §§3–4

将 VLA 接进技能库，可以把连续控制委托给已训练模型。Gemini Robotics 1.5 让 GR-ER 1.5 负责任务编排与工具调用，GR 1.5 负责动作。Harness VLA 把冻结策略用在局部接触步骤，外层以几何原语、工作记忆和执行结果决定何时调用。它在 LIBERO-Pro 同论文协议中将 πRLinf 的 50.0% 提高到 few-shot Claude Code 的 82.4%，标准 LIBERO 上增益较小。真机演示由人重置和验收。2510-GeminiRobotics15 · C1–C4

具备验证器也未必会重新规划上层目标。2025 年同名《Agentic Robot》的主循环在开头分解任务，之后监测、推进或重试当前子目标，定量实验在 LIBERO 仿真。PLanAR 把预期结果写进 PDDL predicates，并用机器人观测检查用于真正重规划的状态变化。它报告 UR5e 与 Franka 真机试验，其中一个扰动对照展示了目标水果被取走后重新发现和规划。 Agentic Robot Appendix E · PLanAR §4.3

2.2 写代码，通过机器人软件栈操作

Code as Policies 用 LLM 生成调用感知和控制原语的 Python。程序内部可以消费传感结果，生成阶段通常在执行前。OpenRUA 把 coding agent 放回执行循环，让它在同一任务中使用终端、读取原生 ROS 2 接口与文档、写程序、检查新观测、再改程序。工作区和机器人 API 构成 harness，Agent 自己组织具体操作流程。2209-CodeAsPolicies · 2610-OpenRUA

OpenRUA 的主要仿真结果包括 CaP-Bench 99.0% 与 LIBERO-PRO 八个测试条件 87.0%。这些数字描述的是完整系统。表内跨论文对照使用的基座模型、经验和执行预算各有不同，无法据此估计 ROS 2 接口本身的净贡献。程序化接口能合并多个动作、复用控制逻辑，也可能让计划在新观测到来前执行得过久。C1–C3 · 2611-RUIBench

2.3 逐步发动作，让模型直接在执行环中

Show-Harness 将相对运动、旋转和夹爪动作做成带语义的离散指令，由硬件解释器落地。AMP1 让通用模型直接使用感知与运动接口，分析弱模型和强模型如何利用不同粒度的控制。后者的量化真机试验中，同规格 Franka 系统上 12 项任务各运行 9 次，AMP1 成功 104/108，FLUX 3 Action 成功 49/108，π0.5 成功 30/108。各方法使用适配自己的视角和执行接口，AMP1 的 5 分钟预算只计算运动时间。结果支持特定任务集上存在竞争力，比较并未控制所有系统差异。2609-ShowHarness · 2611-AMP1 · AMP1 v4 §2A.2、§4F、Table S1

逐步动作接口让 Agent 能在接触失败、目标移动或遮挡变化后马上重新观察。调用次数也会上升。需要短时连续纠偏的部分仍可交给已稳定的控制器。RUIBench 用两种交互形式和不同动作抽象级别做交叉实验，以同一机器人的对照区分这个取舍。2611-RUIBench · 2611-JustRUA

2.4 训练模型学会使用接口

K1 将分割、几何估计、抓取建议等做成可调用感知工具，并用带工具调用的轨迹监督较小模型。uni-robot-agent 用同一模块化接口接闭源及开放权重模型，比较运行成本、感知和控制表现。PEAR 将真实与仿真包装为同类机器人接口，用仿真中的结果训练模型发动作和推理，保留部署时的相机、本体状态、逆运动学与执行闭环。2609-RoboHarnessK1 · 2611-UniRobotAgent · 2611-PEAR

PEAR 在双臂 YAM 上做 sim-to-real：同样的两类任务共 30 次，未做机器人后训练的 Qwen 为 0/30，只做 LIBERO RL 后为 7/30，加入对应两种 RoboDojo 仿真任务后为 18/30。这组正证据来自仿真相应任务到真机的迁移。额外真机新任务采用演示协议。它还报告语义改写、换物体和新任务三种扰动上的相对优势方向不同。C1–C3

在 EmbodyAgent 的固定仿真任务中，蒸馏、SFT 和 outcome-based RL 是另一条把执行反馈写进权重的路线。ASPIRE 和 ENPIRE 则分别把反馈用于积累程序经验、搜索训练配方。按更新对象区分这些工作，有助于识别一次回合里的工具使用和跨轮训练获得的机器人能力。 EmbodyAgent §§3–5 · ASPIRE §3 · ENPIRE §§2–3

3. Robot-Use 接口的比较

同一动作可以表示为任务技能、参数化子技能、空间原语或脚本。脚本与逐次调用是执行节奏的选择，和抽象层级可以分开设计。观测能力也可独立变化，例如能否读深度、查询遮挡、观察触觉或校验实际位置。

在 RUIBench 对应设置里，Claude Code 的程序接口在仿真比逐次动作高 23.3 个百分点，真机则是 36% 对 42%。论文的工具层和任务定义允许测这种交互形式的反转。它为反馈频率的作用提供了证据，不能单凭这一对照把差异全部归给接触噪声或观察延迟。C2–C3

Robot-Use 也适用于移动机器人。HomeRobot 和 BUMBLE 把导航、找物、抓取和放置连接起来。TAMPAgent 将目标和未观测状态带进 belief-space 规划，让机器人在寻找对象、获取新观测和实际移动之间选择。移动操作把主动感知变成任务动作，且导航状态、物品位置和手中持物必须同时维持。RobotWorld 将覆盖扩大到移动操作、行走、驾驶和飞行的仿真；当前高强度定量真机证据仍更集中在操控。 HomeRobot · BUMBLE · TAMPAgent · 2610-RobotWorld

5. 失败模式与负证据

仿真和真机可能排序相反。 RUIBench 的程序接口在仿真占优，在匹配真机任务上却低于逐次动作。AMP1 的真机表现也受相机标定、碰撞规划和工位结构约束。关掉控制器错误恢复后，AMP1 由 104/108 降至 94/108，说明错误处理本身也是系统能力的一部分。2611-RUIBench · AMP1 §2A.2、Table S1

Agent 可能在任务完成之前推进。 RoboARCade 统计，在各自 VIA 接口上，Astra 和 Opus 对已尝试子任务的错误成功声明分别为 24% 和 39%。现象包括提前结束或提前切换。LIBERO-RECOVER 发现恢复训练能改善从已知失败态开始的表现，标准初态下的总成功率变化没有一致方向。两条证据分别针对完成判定与恢复迁移。C2 · C1–C3

更多接口、经验或推理的边际回报不稳定。 JustRUA 中部分示范和自动改进轨迹改变了动作行为，也增加了试验消耗。作者最终采用未保存经验的配置，报告未观察到稳定优于默认配置的证明。AMP1 的抓放辅助消融中，弱模型常受益，几个强模型反而下降。需要把每个额外组件的收益与配套成本一起测量。C3 · C2

Key Takeaways

  1. 先评估接口，再比较模型。 机器人脚本、参数化技能、VLA 与直接动作可以共存。用同一观测、任务和控制栈改变接口，才能判断性能来自模型、先验技能，还是反馈更新频率。2611-RUIBench · 2611-JustRUA
  2. 任务验证与执行回执各自提供证据。 运动到达和夹爪闭合可用于诊断，但应另验物体、布局或环境是否进入目标状态。记录误判完成与在线恢复率能暴露总成功率遗漏的失效。2611-RoboARCade · 2609-LIBERORecover
  3. 真机和仿真可以回答互补问题。 仿真适合比较接口与策略的覆盖面，真机用于检查延迟、接触、标定和故障处理。最强证据来自共享任务和验收规则的配对。2610-RobotWorld · 2611-RUIBench
  4. 报告自主性的具体来源。 给定人工技能库、写程序、使用预训练 VLA 和在仿真中后训练是四种不同资源。部署前为任务提供了什么，决定评测时“零样本”和“自适应”的含义。2610-OpenRUA · 2611-PEAR

Open Problems

Observed Tension — 多细的动作接口才能兼顾成本与恢复。 在同一模型、帧率、控制器和真机任务下，比较单次动作、带早停条件的动作块、可观察反馈的代码。随机注入可逆的遮挡或目标位移，记录重新观察后的首次有效修正和任务耗时。RUIBench 给出 sim/real 反转，JustRUA 给出受控仿真接口对照。2611-RUIBench · 2611-JustRUA

Observed Tension — 如何解决机器人报告成功但物理状态未达成。 把同一组失败分别交给模型自判、独立传感 verifier、可计算的目标谓词，并固定重试和执行预算。分别测漏报、误报、检测时延和修复后的最终成功。RoboARCade 的误判完成与 PLanAR 的效果检查提供直接可对照的实验。2611-RoboARCade · PLanAR §§3–4

Observed Tension — 什么在换机器人后还能用。 将技能级接口、ROS 2 接口和连续动作接口置于同一组机械臂和移动机器人任务中，保留目标语义而改变可达性、视角或夹持能力。分别报告工具调用协议迁移、新硬件首次成功、为新本体写适配的时间。最接近的证据来自 RobotWorld 的多本体仿真、OpenRUA 的原生接口和 PEAR 的真机迁移。2610-RobotWorld · 2610-OpenRUA · 2611-PEAR
