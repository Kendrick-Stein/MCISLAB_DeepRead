# 🔪 今日总结（focus: GUI agents / benchmarks / Web agents）

今日 GUI/agent 方向两条主线清晰：**runtime/memory 基础设施**（OpenRath 把 session state 做成一等值、AgentMemorySystem 系统评测 12 个 memory 系统、MemGUI 把"记什么"内化为 action）与 **mobile/web agent 的免标注自适应**（MobileForge 的 hint-contextualized GRPO 最系统、GUIAgentExploration 是 HER 在 GUI 上的落地）。安全侧 PrivacyAlign + OverPrivilegedTools 双双指向"训练侧对齐 + 最小权限"，后者"safety alignment 不迁移到 least-privilege"是个扎实的反直觉 negative result。最值得读的是 MobileForge（4）和 Qwen-AgentWorld（4，fictional-world sim-to-real 是少见真 insight）。

## 论文点评

### MobileForge
- **Title**: MobileForge: Annotation-Free Adaptation for Mobile GUI Agents with Hierarchical Feedback-Guided Policy Optimization
- **Institutes**: Zhejiang University, Kuaishou Technology, Tsinghua University
- **Source**: [link](https://arxiv.org/abs/2606.19930)  🔥 HF Trending   **📒 论文笔记**: [[2606-MobileForge]]
- **核心**: 解决免标注移动 GUI Agent 适应问题，提出 MobileGym（App 自主探索 + 分层 rollout 评估，生成 outcome label、step-level process label 和 corrective hint）与 HiFPO（hint-guided 多次 rollout + 基于成功率的任务过滤 + hint-contextualized step-level GRPO）。核心思路是把 corrective hint 作为 GRPO 的状态条件而非奖励项，让组间比较在相同 feedback-aware context 下进行。ForgeOwl-8B 在 AndroidWorld 达 77.6% Pass@3、MobileWorld GUI-only 41.0%，当前最强 open-data 移动 GUI Agent。
- **锐评**: 系统设计闭环、消融扎实，explore→mine→rollout→evaluate→optimize 整链统一是亮点，hint-contextualized GRPO 的 framing 干净。两个隐忧：（1）评估器重度依赖 Gemini 2.5 Pro，换开源决策模型 Pass@1 从 47.4%→44.8%，hint 质量是软肋却缺单独分析；（2）ForgeQwen3-8B 在 MobileWorld 只有 10.3%（ForgeOwl 41.0%），跨域泛化几乎完全由 base model 决定，方法增益独立性难厘清。计算成本（8×A100 80h + 大量真机交互）被轻描淡写。
- **Rating**: `4`🔥 — 问题定义清晰、系统完整、结果扎实，mobile GUI Agent 自适应方向目前最系统的工作，值得深读。

### QwenAgentWorld
- **Title**: Qwen-AgentWorld: Language World Models for General Agents
- **Institutes**: Alibaba Group (Qwen Team)
- **Source**: [link](https://arxiv.org/abs/2606.24597)  🔥 HF Trending   **📒 论文笔记**: [[2606-QwenAgentWorld]]
- **核心**: 提出 Language World Model (LWM)，训练 Qwen-AgentWorld（35B-A3B / 397B-A17B）覆盖 MCP/Search/Terminal/SWE/Android/Web/OS 七域，CPT→SFT→RL 三阶段学预测 agent 操作后的 next environment state。LWM 既可作独立 simulator 支持 Sim RL（controllable fictional world 训 Search agent 超 Real RL），也可作 agent warm-up 提升下游多 turn tool-calling（OOD +9–11 点）。新建 AgentWorldBench，397B 版以 58.71 超 GPT-5.4（58.25）。
- **锐评**: 工作量无可挑剔，但"language world model for agents"方向不新（WebArena/OSWorld simulator 早在做）。真正增量在规模（10M+ trajectory，7 域）和可控模拟：完全虚构的 fictional world 训出的 Search agent 迁移真实居然比 Real RL 还好，既反直觉又有理论意义。但机理停留在"mental simulation" intuition，没严格 ablation 区分 world knowledge vs 推理 pattern。GUI domain 坚持 accessibility tree 放弃像素，自己 benchmark 上 GUI 项输 Claude Opus，略尴尬。成本是核心隐患，工程 paper 定位更准确。
- **Rating**: `4`🔥 — 有清晰理论动机（Richens et al. 必要性证明）+ fictional world sim-to-real 真 insight + 规模够大，值得关注；但非"必读"级，核心贡献更多是工程 scale-up。

### MemGUI-Agent
- **Title**: MemGUI-Agent: An End-to-End Long-Horizon Mobile GUI Agent with Proactive Context Management
- **Institutes**: Guangyi Liu 等 10 人（机构未在 abstract 披露）
- **Source**: [link](https://arxiv.org/abs/2606.19926)  🔥 HF Trending   **📒 论文笔记**: [[2606-MemGUI]]
- **核心**: ReAct-style 在 long-horizon 的缺陷是被动追加历史 → prompt explosion + 关键事实稀释。MemGUI 提出 Context-as-Action（ConAct），把上下文压缩/折叠作为与点击同级的 first-class action，由同一 policy 统一输出，维护三个结构化字段（folded action history / folded UI state / recent step record）。配套 MemGUI-3K（2,956 条 ConAct 标注轨迹）SFT，MemGUI-8B-SFT 在自建 MemGUI-Bench 达 open-data 8B SOTA，泛化到 OOD 的 MobileWorld。
- **锐评**: 理念干净——把"该记什么"内化到 policy 而非外挂模块。但三个 context 字段仍是人工设计，"折叠"粒度不透明，和 ReAct passiveness 本质同层（人类先验决定什么重要）。最大信任危机是 MemGUI-Bench 自建：自建 benchmark 上的 SOTA 比 community benchmark 弱一个说服力等级。只有 SFT 无 RL，long-horizon reward 稀疏如何解决语焉不详。
- **Rating**: `3`🔥（→ Frontier）ConAct framing 有新意，数据集+benchmark 对 mobile long-horizon 有参考价值；但 self-contained benchmark 暂无法验证主要 claim。

### AgentMemorySystem
- **Title**: Are We Ready For An Agent-Native Memory System?
- **Institutes**: Shanghai Jiao Tong University, Tsinghua University, MemTensor
- **Source**: [link](https://arxiv.org/abs/2606.24775)  📰 HF Daily   **📒 论文笔记**: [[2606-AgentMemorySystem]]
- **核心**: 从数据管理视角对 12 个 agent memory 系统做迄今最系统的实验研究，分解为四模块（表示存储 M1 / 提取 M2 / 检索路由 M3 / 维护 M4），5 workload × 11 数据集，得九条结论。核心发现：无单一架构通吃，workload-memory 结构匹配度决定有效性；graph-based 最能处理动态更新；局部化 maintenance 比全局重组成本效益高数倍；raw text retention 优于摘要压缩。代码数据开源。
- **锐评**: 名副其实的"工程师体力活"——工作量真实，但本质"把所有人跑了一遍"而非"发现别人没注意的问题"。结论普遍不惊讶：graph 处理动态更新更好（当然）、append-only 返回 stale facts（废话）、保留原文更精确（显然）。覆盖边界是大问题：所有 workload 都是文本对话/数据库，**完全没有 GUI/computer-use 的 visual memory 场景**——而 memory 在这些场景的挑战远比对话 QA 复杂。"Are we ready? No"，但给的方向都是工程修补，没触及 agent-native memory 需要什么抽象层次这个根本问题。
- **Rating**: `3`🔥（→ Frontier）系统评测有参考价值，结论偏工程经验向，对 GUI agent 直接相关性有限但可作 memory 设计量化参照。

### GUIAgentExploration
- **Title**: Empowering GUI Agents via Autonomous Experience Exploration and Hindsight Experience Utilization for Task Planning
- **Institutes**: Institute of Automation, CAS; University of Chinese Academy of Sciences
- **Source**: [link](https://arxiv.org/abs/2606.27330)  📄 arXiv   **📒 论文笔记**: [[2606-GUIAgentExploration]]
- **核心**: 针对小型开源 MLLM（3B/7B）web 任务 planning 弱、跨站泛化差，PEEU 分两阶段：(1) GPT-4o 在目标网站自主探索构建 planning tree；(2) hindsight 把轨迹反向对齐生成高层任务，消除 task-trajectory mismatch。配套 TDHAF 分析 low/mid/high 三层组合泛化，发现 low-level 训练无法向上泛化（80.5%→9.1%）。Qwen2.5-VL-7B + PEEU-SFT（2k 轨迹）在 WebVoyager 30.6%，超 32B Vanilla 的 22.7%。
- **锐评**: Hindsight relabeling 不新——就是 HER（2017）在 GUI agent 上的直接应用，novelty 主要在工程落地和 TDHAF 框架。更麻烦：exploration 依赖 GPT-4o，要帮"cost-efficient small model"但数据生成全靠商业大模型，成本账算不过来。WebVoyager 是 2024 benchmark，当前商业 SOTA 已 60%+，拿它做主要对比有刷分嫌疑。Data leakage 隐患：GPT-4o 既探索又总结，测试网站公开，信息隔离无法保证。TDHAF 的 low-level 向上泛化失败发现有独立价值但不令人意外。
- **Rating**: `3`🔥（→ Frontier）7B 超 32B 有实用价值 + TDHAF 有方法论贡献；但 novelty 有限（HER 变体）、商业模型依赖削弱成本论点、单一旧 benchmark 支撑泛化结论偏弱。

### OverPrivilegedTools
- **Title**: When Lower Privileges Suffice: Investigating Over-Privileged Tool Selection in LLM Agents
- **Institutes**: IIE CAS; BAAI; CUHK; Peking University
- **Source**: [link](https://arxiv.org/abs/2606.20023)  📰 HF Daily   **📒 论文笔记**: [[2606-OverPrivilegedTools]]
- **核心**: LLM agent 在有功能等价低权限工具可用时仍系统性选高权限工具——agent 级 PoLP 违规。构建 ToolPrivBench（544 场景，8 域，5 风险类型）：6/11 主流模型 OPUR>30%，小模型尤甚（Qwen3-8B 65%）；瞬时工具失败把权限升级放大约 7 倍；现有 safety alignment（AgentAlign）几乎不迁移到最小权限遵守。提出 SFT+GRPO 的 privilege-aware post-training 缓解。
- **锐评**: PoLP 是 1970s OS 原则，"agent 不遵守最小权限"本身不新。真正有价值的是反直觉 negative result：safety alignment 训练完全不迁移到 least-privilege（Qwen OPUR 甚至 50.4%→60.7%），说明"拒绝有害请求"和"遵循最小权限"是两种独立技能。但实验有 confound：(1) transient failure 只注入低权限工具，agent 升级一部分是 rational adaptation，归为 bias 过武断；(2)"功能等价"由 frontier LLM judge 验证，calibration 存疑；(3) post-training 只在 Qwen3-4B。对 CUA safety：privilege overreach 直接映射为"走 sudo API vs UI 路径"，与 PersonalizedSafety-CUA 高度相关——尤其 CI 视角：什么算"过权限"依赖用户身份+任务上下文，本文用静态二分标签未解决这个更深问题。
- **Rating**: `3`🔥（→ Frontier）"safety alignment 不迁移 ≠ least-privilege"是扎实 empirical contribution；但 PoLP 不新、confound 较多、缓解规模有限。

### NatureBench
- **Title**: NatureBench: Can Coding Agents Match the Published SOTA of Nature-Family Papers?
- **Institutes**: Frontis.AI / Horizon Research, Tsinghua, Peking, Harvard
- **Source**: [link](https://arxiv.org/abs/2606.24530)  🔥 HF Trending   **📒 论文笔记**: [[2606-NatureBench]]
- **核心**: 从 Nature 系列 10 刊 ~5,500 篇论文经三级过滤 + 校验 + 容器化，构建 90 个跨 6 领域任务，评估 AI coding agent 能否在未见方法下超越已发表 SOTA。评 10 个前沿 agent（Claude Code / Codex CLI / Gemini CLI 三 harness），最强 Claude Opus 4.7 仅 17.8% 超越、47.8% 持平。分析 900 run：82.7% 成功靠通用 ML 工程化而非科学推理，45.1% 失败来自方法选择错误。
- **锐评**: 亮点：三阶段 pipeline + 信息防火墙 + reproduce-mode 校准认真，SOTA-normalized relative gap 解决 81 种 metric 跨任务可比性。问题：**90 任务不够**，5,500→90 的 98.4% 漏斗主要被"数据必须公开免申请"卡死，最终严重偏向 Nature Machine Intelligence（36/90）+ Methods（26/90），偏 ML 而离真自然科学远。**SOTA anchor 信效度存疑**（不同实验室不同划分跑出的数，当金标准是循环论证）。**Calibration 循环性**（Opus 4.6 验证可复现再用 4.7 测，可能偏向"对 Claude 友好"任务）。**Harness 偏差未控**（Claude Code 7 模型，Gemini CLI 1 个，harness 与模型差异耦合）。
- **Rating**: `3`🔥（→ Frontier）discovery vs reproduction 区分真实，工程认真，failure mode 有诊断价值；但 90 任务偏小、覆盖偏窄、calibration 有潜在偏差。对 auto-research / AI Scientist 方向有直接参考价值。

### OpenRath
- **Title**: OpenRath: Session-Centered Runtime State for Agent Systems
- **Institutes**: Tsinghua University
- **Source**: [link](https://arxiv.org/abs/2606.19409)  🔥 HF Trending   **📒 论文笔记**: [[2606-OpenRath]]
- **核心**: 把 agent 系统中碎片化的运行时状态（对话、工具日志、沙箱效果、分支血缘、内存事件）统一为第一类值 `Session`，类 PyTorch 编程模型（`Agent/Workflow/Tool/Memory/Selector` 均遵循 `forward(session)->session` 契约），主张 multi-agent 可审计性根本取决于"状态跟着程序值流动"而非从侧信道重建。当前是 technical report，提供确定性 runtime 的 evidence packet，无 benchmark 数字，memory 模块尚未完成。
- **锐评**: 设计理念有吸引力——"Session 之于 agent runtime，如同 tensor 之于 neural network"类比精准；claim ledger + evidence-gated 发布协议业界少见的诚实。但根本是框架白皮书：无任何量化对比，memory 核心组件是空的，与 LangGraph `thread state` 功能重叠存疑但回避实证对比，只用"读者不同"概念推搪。现有框架（LangGraph、OpenAI Agents SDK）已往同方向演进，OpenRath 差异化优势语焉不详。
- **Rating**: `2`👀（→ Archived）设计原则值得了解，但核心功能不完整、无实验支撑，待 benchmark 结果再关注。**与 Agent-Facing Environment Runtime 方向相关**：session-as-first-class-value 正是 agent-facing observable state 的一种工程实现，可作为 affordance 设计参照。

### PrivacyAlign
- **Title**: PrivacyAlign: Contextual Privacy Alignment for LLM Agents
- **Institutes**: University of Waterloo
- **Source**: [link](https://arxiv.org/abs/2606.21710)  📰 HF Daily   **📒 论文笔记**: [[2606-PrivacyAlign]]
- **核心**: 现有 agentic privacy 工作用不可靠 proxy 训练/评估，PrivacyAlign 把人类判断放中心：1,350 个 agent 实际泄漏场景 + 599 标注者的 3,516 条注释，同时改进 LLM judge（annotation-conditioned）和 reward model（annotation-conditioned RL），让小型 open-weight agent 在多个 privacy benchmark 显著提升对齐。卖点是 training pipeline 而非只做 benchmark。
- **锐评**: 与 [[2606-AgentCIBench]]/[[2606-MyPCBench]] 是互补第三极：MyPCBench 问"能力够不够"、AgentCIBench 问"哪里泄漏"、PrivacyAlign 问"怎么训练才不泄漏"。但问题：**是否真用了 contextual integrity 框架？abstract 连 CI 都没出现**——理论基础可能更模糊，本质"人觉得不对"而非"信息流违反场景规范"。**Runtime intervention 增量实验完全没有**：比的是 RL-trained agent vs base model，无 prompt-level guard baseline，无法回答"比直接写 prompt 好多少"。1,350 样本能泛化到 frontier closed-weight 部署吗？
- **Rating**: `2`👀（→ Archived）方向对（training-side agentic privacy alignment 是真需求），annotation-conditioned reward 有新意，但与 CI 理论关系不明、无 runtime baseline，对 PersonalizedSafety-CUA 贡献是"提供 training 路线对比点"。
