# 🔪 今日总结

今天是 harness 日：StateM、Zetta、SemaPLC、HarnessEval-W 四篇从四个完全不同的领域（CLI agent、VLA、PLC 代码、world model 评测）收敛到同一个动作——不动模型权重，把控制、检查与评测外置成可读写、可审计的运行时组件。四篇里只有 SemaPLC 把"agent 不许自判完成"做成了可证伪机制（edit invalidation + 交付字节 hash attestation），其余三篇的共同病灶一模一样：零组件 ablation、零 token/rollout 预算对齐，于是"增益来自这套治理机制"这个核心论断在证据上都还悬着。另一条暗线是**指标与决策脱钩**：DA-LeWM 证明 probe R² 差 0.03 而 planning success 能跨 43 pp、且 planner 真正下决定的 elite 区间里 latent cost 与真实 cost 基本无关，HarnessEval-W 的榜单被 interface 表达力污染，Towards GUI Agents 则给出反面例证——diffusion 在最有利的短输出区间仍打不过 AR，且它的 headline gap-narrowing claim 经核查 unsupported。

## 论文点评

### SemaPLC
- **Title**: SemaPLC: A Project-Grounded, Verification-Gated Agent Harness for PLC Code Generation
- **Institutes**: Midea AIRC, KUKA, SJTU, ZJU
- **Source**: [link](https://arxiv.org/abs/2608.18565)  📰 HF Daily ⬆️ 112   **📒 论文笔记**: [[2608-SemaPLC]]
- **核心**: 一个 PLC 代码生成 harness，卖点不是工具集而是 completion discipline——agent 不许自判完成，必须拿出 spec audit、编译、live runtime 三类带日志的检查结果；任何编辑作废此前全部 verdict，无日志的自称 pass 一律降级为 unchecked，交付前还要过一道 delivery gate（交付字节 hash 必须匹配最后一次成功编译的输入、session log 必须带部署与强制输入证据）。117 个 independent-POU 任务上七个 backbone 全部拿到最高 strict verified pass rate（均值 72.6% vs Agents4PLC 63.9%）；65 个 project-context 任务上 dynamic behavior 52.2，对 baseline 的 22.4–31.4。评测拆成 integrated compilation 89.4 / static behavior 81.6 / dynamic behavior 52.2 三层，让失败停在它发生的那一层。另外作者顺手测了评测侧形式化管线自己的盲区：32 个含 TON timer 的程序、174 条 property，conclusive 率 0.0%。
- **锐评**: 先说最硬的一刀——project track 的对照根本不是 budget-matched，SemaPLC 每任务 34.1 次模型请求，Agents4PLC 6.9，五倍预算差下的 52.2 vs 30.3 里有多少来自 verification gate、多少来自单纯多跑，这篇论文答不了；Table 3 的 layer ablation 也救不了场，因为加层和加预算是同一件事（8.9 → 47.8 请求同步发生），缺的正是"None arm 跑满 47.8 请求"那条线。function track 的对照倒是干净的（6.5 vs 6.3），所以 72.6% 可以按面值收下，但读者别把这份预算清白挪用到 project track 的结论上。第二刀：所谓三层 "external verification" 外部性梯度差得离谱——spec audit 是同一个 model 走 Markdown checklist，live runtime 的期望值也是 agent 自己从 task spec 派生的，真正无条件外部的只有 RuSTy 编译器和 delivery gate 那层字节与日志的 attestation；论文在 §4.4 和 Table S4 里写明了，却在正文用 "external verification results" 一词把梯度抹平，这叫 execution-grounded, self-oracled，不叫 externally verified。第三刀：Appendix B 那个"工程"含 130 个 body 为空的 function-block 实现，任务是往骨架里填 body，没有既有实现要兼容、没有回归风险——"project-grounded" 这个词收得比标题给的印象小得多。但骂完必须承认亮点很实：edit invalidation + 字节 hash attestation 是我近期见过为数不多把"agent 自称完成"真正变成可证伪的机制，跟 [[2607-LongHorizonTerminalBench]] 记录的 14 个 false finish 正面对上，那篇只能观测现象，这篇给了机制。Table 5 的 timer 组 0% conclusive 更是全文最有信息量的数字——它既是"需要另一层证据"的诚实论证，也反手暴露主指标的问题：VerifiedPass 阈值 0.80 意味着这 32 个程序无论实现对错都自动判死，聚合分数里"程序错"和"judge 测不了"混在一起，看不出来。至于 §6.3 那句 "an evaluation that stops before execution cannot separate reliable methods"，证据只支撑到"文本 substring/常量级 static oracle 无区分度"，用一个弱代理证明所有静态评测不够，论证是循环的。最后一个被作者一笔带过、其实最该追的洞：full harness 下仍有 18.2% 的 scenario–port 检查是 port missing——程序压根没驱动那个输出端口，spec-review checklist 漏掉了五分之一的覆盖需求，而它恰好是三层里 oracle 外部性最低的那层，这两件事大概率是同一回事。
- **Rating**: `3` 🔥 ，方法论可迁移物（执行外部性 / oracle 外部性 / 声称可证伪性三维审计 + 字节级 delivery gate）直接可拿去过一遍 agenda 主线 Agent-Facing Environment Runtime 里的所有 harness，尽管 PLC 域红利让 golden-trace differential 本身不可移植、且 headline 的 dynamic 领先没有预算对照。

### StateM
- **Title**: StateM: Reaching 95.3% Raw Accuracy, or a $15 Frontier Run, on Terminal-Bench 2.1 via Harness Scaling
- **Institutes**: Somewhere on the Earth（作者声明个人时间完成，不代表任何机构）
- **Source**: [link](https://arxiv.org/abs/2608.15089)  🔥 HF Trending ⬆️ 431   **📒 论文笔记**: [[2608-StateM]]
- **核心**: 把 long-horizon CLI agent 的执行控制外置成一份 agent 与用户共同可读写的 YAML runbook 状态机——阶段级 `in_hook` 刷新上下文、`before_transfer` 在交接前查证据、per-run 记录支持崩溃恢复、practice 可版本化——不动模型权重做 harness scaling。Terminal-Bench 2.1 上 GPT-5.5 xhigh 从 83.1% 到 92.1%，同一份冻结 profile 迁到 GPT-5.6 Sol 拿到 95.28% raw；跨 provider 冻结迁移直接失效（DeepSeek-V4 Flash 82.7%→82.0%），花 \$37 适配后回到 88.09%。作者把"转移层级"设计成了实验：同模型 → 同家族冻结 → 跨 provider 适配 → 跨任务 held-out，四级递进，每级都报了对自己不利的数字。BusinessBench 上冻结一次性 held-out 只有 +0.55 macro / +1.34 micro，两个 family 出现负迁移。
- **锐评**: 这是我今年见过披露纪律最好的 harness 论文，也是标题最会做生意的——两件事必须分开算账。真结果是同模型 +9.0/+10.4 点，远超同期一次模型换代的 1.8 点，这个对比有分量；宣传的是 "Last Generation + StateM is Already SOTA"，而支撑它的三个"超过下一代"论断（92.1 vs 91.9、85.4 vs 84.9、88.76 vs 88.8）全部落在 0.87 pp 的 SE 之内，正文用 "numerically above" 对冲了，Fig. 3 的横幅没有。标题里的 \$15 和 95.3% 来自两套完全不同的系统（DeepSeek Flash 和 GPT-5.6 Sol），而 \$574.68 那个对照的成本和 88.8% 的分数根本不来自同一次评测——作者在脚注 5 里自己招了，摘要装作没看见；真要比成本，StateM 的 GPT 提交是 \$1,062.95，1.85× 于对照，在质量前沿这一侧它更贵不是更便宜。方法学上最大的洞是四条机制里三条零隔离证据：`in_hook` 和 durable recovery 各自只有机制叙述加一条 22 小时的 n=1 轶事，全文没有任何 token 预算对齐的基线臂，按本 vault 里 [[2607-HarnessEvolution]]（token +70% 而 resolve rate 无趋势）和 [[2606-SkillMemoryBudget]] 的前车之鉴，效率主张只能记 "no"；再叠上正式提交换到 AWS 是因为"超时更少"、参考臂用 Codex 0.125.0 而提交用 0.144.1，这个 A/B 里塞了至少两个方向偏向处理臂的未控变量。更讽刺的是，一个把"证据闭合完成"当卖点的 runtime，最好那次提交里仍有 9 条轨迹被标为疑似 reward hacking（作者认了 4 条），加上自曝的 DNA 任务 verifier 最左边界约定被 profile 在没读过 verifier 代码的情况下学会——让完成变得可检查，不等于让完成变得正确，failure-driven 循环会系统性地朝评测器语义而非任务契约漂移，这是全文最有价值的发现，而且是顶着自身利益报出来的。真正诚实的泛化估计不是 95.3% 而是 BusinessBench 那个 +0.55 macro，差整整一个量级，且每实例每臂只有一条随机轨迹、无方差估计，本质上不可分辨；作者还"合理地"弃权了唯一一个自己预判无收益的 family。最该做而没做的实验它自己已经写好了配方：把 `before_transfer` 里的 `command`/`predicate` 全换成 `checklist` 自证，看掉多少——它建立了检查的证据强度谱系，却从没量过这条谱系的斜率。
- **Rating**: `2` 👀 ，转移层级的三层分解（同族可零成本迁移 / 跨 provider 失效 / 跨分布只剩方法论）和评测器语义污染是真数据点，但零组件 ablation、零 token 对齐、标题跨系统拼数字，够不上 Foundation。

### Zetta
- **Title**: Zetta ζ: An Efficient Closed-Loop Embodied Harness for Self-Evolving Physical Intelligence
- **Institutes**: Institute for AI Industry Research (AIR), Tsinghua University; Z-Trans AI
- **Source**: [link](https://arxiv.org/abs/2608.16590)  📰 HF Daily ⬆️ 135   **📒 论文笔记**: [[2608-Zetta]]
- **核心**: base VLA 权重全程冻结，只演化外挂的 harness。关键改写是频率：不让大模型在线跑得更快，而是让它离线生成能在 action chunk 频率执行的**代码 critic**，critic 只提议、由 Orchestrator 审证据后批准切入 recovery skill，再按 re-entry contract（原始失败证据清除 + 接触力进入稳态）交还控制权。离线侧按 Earliest Observable Divergence 聚类失败、走六层 top-down 诊断生成最小 patch，用"cluster 内 100% 回归 + held-out ΔSR"双闸门决定是否入库。配套 Z-Infra 把 rollout 吞吐从 1.72 拉到 35.1 episodes/min。RoboCasa 18 任务 73.56% → 93.56%，LIBERO-Pro 全量 40 对 32.00% → 71.13%。
- **锐评**: formulation 是这两年 harness 论文里少见的对味——把"闭环"从"让 agent 推理更快"重写成"把在线检查编译成廉价代码谓词、把大模型赶出关键路径"，而且真的去做了 infra，因为他们正确判断出 self-evolving 的 rate limiter 是采样不是 idea。但证据结构撑不起 claim。全文 ablation 零命中（C5），三条 loop 一条都没单独拆：去掉 runtime critic 退回 episode 反思塌多少、critic 只报警不接管塌多少、不设闸门塌多少，全部未测——而这三条恰恰是论文的全部机制主张。更致命的是成功率表里唯一的非 Zetta 行就是自家 frozen base policy（C10、C19），HarnessVLA/Guava/CaP-X 都躺在 related work 里一个没进表，小节标题却敢写 "vs other SOTA"；唯一比过的 RPent 只比了延迟。加上没有 budget-matched 对照（C6）——Zetta 白拿了额外执行步数、bounded retry、GraspGen 抓取器、motion planner、segmentation，baseline 一样没有——那 +20 pp 里到底多少是"闭环治理"、多少是"多试几次并挂了个专用抓取器"，论文自己也回答不了；而演化烧了多少 rollout、多少次 agent 调用、多少 GPU-hours 全文一个数都没有（C18），摘要那句 "under our current rollout budget" 是个没有数字的限定语。摘要 headline 的 90.8% 是 Goal 两个 setting 的均值，全量口径 71.13% 藏在正文（C1）——LIBERO-10 这种长程组合任务本该是这套方法的主场，S setting 却只有 40.0%、四对任务从 0% 停在 0%，选择性呈现得很明显。最后，critic 监控信号里包含 official grasp predicate、成功判定直查 official task predicate（C17），这些量在 simulator 里免费、真机上不存在，而全文没有 limitations 节讨论换成纯感知估计后掉多少——这决定了它是一条真机路线还是一个 simulator 内的方法。数字口径也没统一：11.1× vs 11.9×（C8）、20.6× 是拿 concurrency 16 的 baseline 比 concurrency 64 的自己（C9）、benchmark 跑 4090 而 infra 评测跑 A100（C11）。
- **Rating**: `2` 👀 ，frequency-separation 这个拆法对 GUI/web agent 同样成立，值得借鉴 formulation；但零 ablation + 只比自家 base policy + 无预算对齐，让"增益来自闭环机制"和"SOTA"两个 claim 都只是姿态。

### HarnessEval-W
- **Title**: HarnessEval-W: Agentifying the Evaluation of Visual Worlds
- **Institutes**: 未列（正文与 arXiv abs 页均无 affiliation block；项目方自称 MirroS Lab）
- **Source**: [link](https://arxiv.org/abs/2608.16859)  🔥 HF Trending ⬆️ 121   **📒 论文笔记**: [[2608-HarnessEvalW]]
- **核心**: 把 world model 评测从固定 rubric 改写成 agentic harness——按 case 从 skill library 路由出适用的评测技能，每个技能拆成可测量子问题派给 sub-agent，父 agent 校验证据后聚合成 evidence tree 而非单一标量。三条评测轴（Observation Quality / Transition Correctness / World Persistence，共八个设置）来自把 interactive WM 的预测分布分解为观测似然、状态转移与初始分布。330 个 agentic 构造的 case 上评了 18 个 world model，Seedance 2.0 以 Overall 75.5 居首，前八名清一色是 prompt 驱动的通用视频生成器。评测器自身用 9 模型、5000 条人类 A/B 锚定：Intentional / Physical 上模型级 Spearman ρ=0.93 / 0.87，pairwise accuracy 相对 WBench 对应协议从 60.2% / 31.9% 提到 77.8% / 71.7%。
- **锐评**: 真正值钱的是 routing 层而不是 judge 层——为**每个被跳过的技能**留一条基于证据的理由（"动作都在视野内，故跳过 Offscreen Evolution Verifier"），把"这个 case 没被测什么"变成可审计对象，这个设计可以原样搬到 agent harness 上，是本文唯一的一等贡献。但那个 +39.8pp 的 headline 主要买到的是"敢不敢分胜负"而非"分对了多少"：用论文自己的数字反推，Physical 上 WBench 决断率仅 47.8%、决断内正确 66.7%，HarnessEval-W 是 98.2% / 73.0%；Intentional 那侧 Event Edit 决断内正确 94.2% 反而**高于** HarnessEval-W 的 87.5%——Causal Fidelity 拿 0–3 整数分压缩整段 rollout 逼出 52.2% 的打平，这个对比一大半是刻度粒度差异，不是分解与否，而唯一能同时吸收决断率与置信度的 Brier score 论文只说"我们更低"、不给数值。更要命的是全文未报标注者人数与任何 inter-annotator agreement（C4），没有人类上限可参照，77.8% 到底是逼近天花板还是差得远读不出来；人类对齐只覆盖 8 设置中的 2 个、18 模型中的 9 个（C16），其余六项指标零人类锚。而支撑核心论断的因果部分整个缺席：没有固定 rubric、只切换"单体 judge vs 分层 sub-agent"的 ablation（C13），skill routing 与子问题分解本身的错误率一次没测（C14），evidence tree 的 faithfulness 只有 Figure 7 的定性展示（C15）——摘要那句 "complete reasoning chain justifies the result" 在语义层是未经检验的，而模型级 rank correlation 对"所有模型被一致地测错"这类系统偏移恰恰不敏感，ρ=0.93 与"分解可能是错的"完全可以同时成立。最重的硬伤在 Overall 榜单：Trans-I 的 #1–#10 全是 Prompt I2V、#11 之后全是 action / camera，一个只接受相机位姿的模型无论世界建模多好也没法把"把方块拿起来"表达成一条轨迹，它那个 48.6 度量的是接口表达力，而 Overall 是 330 个 case 的无权算术平均、排名跨全部 18 个模型给出，于是榜单结构性地把"接口不支持"记成了"做得差"。同一个 confound 吃掉了论文最有意思的结果——微调 delta（HY-WorldPlay 的 Intentional −24.2）里接口随微调一起变了，"能力重分配"与"新接口表达不了受命干预"分不开；Figure 9 那个 r=0.98 也与"interface 二值分组主导"这个单因子完全兼容，作者的能力语义解释并非唯一读法。对照同期的 [[2608-WorldExam]]：人家不出全局总分、两条 track 分开、报 3 名标注者多数票与分任务最低值、还做了几何后端切换的敏感性分析；这里 §5.3 号称测 "robustness under different VLMs"，实际只是同一 GPT-5.5 在温度 0 下跑三轮（C8），全文更是没有 Limitations 节（C20）——一篇主张"让评测可被检视"的论文，对自己的口径问题一条都没检视。
- **Rating**: `2` 👀 ，routing + skip 理由的可审计设计值得抄，但可信度证据弱于同期 WorldExam、榜单被 interface confound 污染——机制可引用，排名不可引用。

### Agentic ESOpt
- **Title**: Agentic ESOpt: Fine-Tuning Long-Horizon LLM Agents with Minimal GPU Requirements
- **Institutes**: National University of Singapore, Southern University of Science and Technology, Oxford
- **Source**: [link](https://arxiv.org/abs/2608.17310)  🔥 HF Trending ⬆️ 96   **📒 论文笔记**: [[2608-AgenticESOpt]]
- **核心**: 用 evolution strategies 取代 backprop 训练 long-horizon LLM agent：采 G 个全参数 Gaussian 扰动，只靠终局 scalar reward 做 population z-score 加权更新，因此训练显存等于推理显存（Qwen3.5-4B 8.41GB vs GRPO 58.88GB / PPO 89.40GB），唯一的算法新增件是 σ 的 cosine decay。理论上的卖点是估计量结构：policy gradient 的 score 项要沿 H 个动作累加，ES 的 `ε/σ` 不含这个求和，于是终局 reward 不必被"摊回"每一步。最干净的结果是受控 Sudoku 上的次序反转——H\*=5 时 PPO 最强（90.63）、H\*=10 时 GRPO 最强（67.71）、H\*=15 时才轮到 ESOpt（53.13，比 GRPO 高 12.50 点，PPO 崩到 0.00）。另外三个场景是 Math/DocVQA（比 GRPO +8.3 点均值）、WebArena-Lite 27B（29.47 → 36.16）与测试时 AHD（28/36）。
- **锐评**: 这篇的实验设计比它的方法值钱得多。方法拆开就是 ES + z-score + σ 退火，组件薄到只有一条能被 ablate；但"我在 H\*=5 输给 PPO、H\*=10 输给 GRPO、H\*=15 才赢"这种自曝式呈现，把论断从排名主张降级为条件性主张，可证伪性一下子上来了——这是本 vault 第一个在固定环境内扫 horizon 的受控实验，而且答案是反直觉的：horizon 变长时赢的不是更细的 credit 分解（PPO 的 turn-level critic 直接归零），而是彻底不分解。可惜论文的包装完全背叛了这份克制。摘要里两个 headline 数字恰恰来自 horizon 最短的两个设置：WebArena-Lite 每任务上限 30 个浏览器动作、AHD 每个候选就是一次 ≤768 token 的单轮生成，跟"long-horizon"没什么关系；而 +6.69 那一栏根本没有任何 RL 对照臂（C13，作者理由是 27B 全参 RL 在 4×H100 上不可行，逻辑自洽但结果就是只证明了"微调比不微调好"），LoRA-based GRPO 这个显存可行的对照做都没做。更尴尬的是论文唯一的算法创新在旗舰实验里被关掉了——WebArena 的 σ 是常数 1.5×10⁻³（C15），27B 上跑的其实是 Vanilla ES，群体规模研究同样如此；σ schedule 的全部证据只剩 Sudoku 一张表和 AHD 里一格 0.26% 的差。算力对齐只在 model-FLOPs 一个轴成立，环境 rollout 上系统性偏向自己（Sudoku 4×、Math 2×、DocVQA 1.78×，C5/C28），而这个交换方向对 web agent 恰好是错的——作者自己在 limitation 里承认了（C25），Math 那条 GRPO 基线还被压缩过生成配置（C7，披露了但没量化），所以 +8.3 点不是纯算法差。分母也都小得吓人：Sudoku 每档 32+32，12.50 点 = 4 道题；AIME 30 题；WebArena 的 Trace2Skill 增益 +2.42 直接小于该基线自身标准差 ±3.37，这一栏不该被当结论用。AHD 的 28/36 是未加权计数（含 1 平 7 负，C18），ACO 侧多数差异在 0.1–0.4%，KP 那个 p=0.0100 的效应量是 40.1562 → 40.1578，第四位小数——p 值小只是因为方差小。还有一个最该报却没报的诊断量：稀疏 reward 下一代内 G 个扰动全零的比例，WebArena G=8、成功率 30%，全零绝非罕见事件，而 Figure 6 已经显示 reward contrast 随 H\* 在跌，这正是"ES 更适合长 horizon"最可能的失效边界。评价证据边界：C16 被独立 verifier 判为 contradicted（原笔记误称 σ ablation 只在 H\*=15 报告，实际三档均有）并已更正，其余 34 条 source-verified，`verification_status: partial`。真正值得留下的是两件事：把 long-horizon credit assignment 重述为"要不要分摊"，以及证明 27B 全参 agent 适配能在 4 张 H100 上做——后者意味着瓶颈从 GPU 侧搬到了 environment runtime 侧，这对 Agent-Facing Environment Runtime 方向的含义比论文本身的 SOTA 大。最该补的实验一句话：固定环境 rollout 数（G 降到 8 或 GRPO 升到 32）重跑 H\*=15，看那 12.50 点还剩多少——机制论断完全押在这上面，成本却只是重跑一列。
- **Rating**: `2` 👀 ，机制重述与受控 horizon 扫描是硬货，但旗舰实验既无 RL 对照又关掉了自家唯一创新，算不上 Foundation。

### Co-RL
- **Title**: Co-RL: Unsupervised Reasoning Emerges from Diverse Cohort in Multi-agent RL
- **Institutes**: Johns Hopkins University, UC San Diego, University of Exeter
- **Source**: [link](https://arxiv.org/abs/2608.17253)  📰 HF Daily ⬆️ 86   **📒 论文笔记**: [[2608-CoRLCohort]]
- **核心**: 把 label-free RL 的 reward 从"自己的 majority vote"换成"环上邻居的 majority vote"——N 个不共享参数的 policy 互相打分，`r = 1[自己的答案 == peer 多数票]`，各自跑 GRPO，全程不用 GT label。方法改动实质只有一个下标：agent 不再参与构造自己的监督目标。四个 LLM 在七个文本 benchmark 上平均 +3.0~+8.6 点，五个 VLM 在四个多模态 benchmark 上 +2.3~+7.2 点，并在 Appendix D.4 的 budget-matched 对照里胜过"两模型各跑 TTRL 再 ensemble"。理论侧给了 Prop 2（self-rewarding 在 p<1/2 时必然把正确答案压向 0）与 Thm 1（cohort 在 p_A+p_B<1 时收敛到错误共识）。
- **锐评**: 问题被压到一个二元变量上（reward 的构造者是不是正在被优化的那个 policy），这个 formulation 干净得值得记住，把失败条件写进定理而不是塞进 Limitations 也比同赛道多数论文诚实——但 headline 被论文自己的附录拆穿了。Table 10/11 四组 budget-matched 数据方向完全一致：强 agent +0.3 / +0.53 / +1.43，弱 agent +10.1 / +3.19 / +4.86，被测出来的主效应更像"弱模型隔着 majority vote 从强模型吸能力"，而不是标题卖的双向 emergence；而分离这两者的对照——把 peer 换成一个冻结不训练的强模型——几乎零成本，论文偏偏没做，于是 Co-RL 与在线 distillation 在证据上目前不可区分。标题里的 "emerges" 更站不住：verifier 全文检索确认没有任何 pass@k / coverage / capability-boundary 分析（C20 为 absence claim，只能读作"未提供证据"而非"边界未扩展"），而 majority-vote reward 在机制上就是把 policy 推向已能采到的多数答案，先验上更像 sharpening，论文自己引的 Yue et al. 2025 正是这个立场，它却连区分两者的最基本测量都没放。"diversity consistently improves" 在 per-model 层面也被自家表推翻：四个模型里只有两个 Same→Different 单调，Qwen2.5-7B 上 Same family 51.4 输给全部四个 self-rewarding baseline，摘要那句 "consistently outperforms" 只有逐模型取最优变体才成立；更讽刺的是唯一四模型全最优的 Different family+ 靠 DeepSeek-V3 改写全部训练题，这份外部算力与外部能力从没进过任何预算对照，也就是说最稳的增量来源恰好不是标题强调的 cohort diversity。compute 对照同样只做了一半：D.4 回答了"2× 算力分给两个异构模型"，没回答"把 2× 全给最强那个"（K=24 的 TTRL 或 best-of-24），而表里 TTRL 单模型 65.6 已经压过 TTRL ensemble 64.9，这个方向不是可选项；且 budget-matched 只覆盖 GSM8K/MATH-500/AMC 三个数学 benchmark，用 maj@8 T=0.6，与主表口径不可对读。CoMAS 对比是引用数字 + 换过 coding grading 协议 + partner 模型身份未给 + CoMAS agent 数未给，"只用一半 agent"这句话的分母全文找不到。加分项要给到位：作者主动把 κ 与 c 降级为"同一次测量的两个读数"（r=−0.98），又把自己从 CoMAS pass@5 loophole 里白拿的 2.4% 也一并去掉，这种披露姿态在这条线上罕见。真正对本 vault 有用的不是方法而是它写清的适用条件——GUI/web agent 上没有 canonical answer、wrong-agreement `w` 远高于数学的 1.8–5.2%、且 OSWorld 类任务普遍不满足 p_A+p_B>1，按论文自己的定理直接搬过去就是往 (0,0) 吸引盆里跳；而论文证明了这个盆存在却一次都没实证过，这是它最该配、也最缺的那个负结果。
- **Rating**: `2` 👀 ，formulation 与自曝式理论值得读，但核心 claim 被自家 matched-budget 表指向"非对称 distillation"、"emerges" 零能力边界证据，是有用的经验事实而非 foundation。

### DA-LeWM
- **Title**: Decision-Metric Alignment in Latent World Models: Diagnostics and Action-Conditioned Objectives for MPC Planning
- **Institutes**: 未列（论文 v1 无 affiliation block）
- **Source**: [link](https://arxiv.org/abs/2608.18746)  📰 HF Daily ⬆️ 15   **📒 论文笔记**: [[2608-DALeWM]]
- **核心**: 论文指出 JEPA 系 latent world model 做 MPC 时，评价标准一直问错了问题——大家在测"latent 里编码了什么"（probe 能否解码出 state/action/reward），而 planner 真正消费的是 `‖ẑ_H − z_g‖²` 这一个标量，它必须能把候选动作序列按真实任务进展排序。作者把这个性质命名为 decision-metric alignment，给出 Plan-Real Spearman 与 CEM-stage（random/mid/elite）Spearman 两个诊断，并在 LeWM 上加 inverse-dynamics 与 demonstration-conditioned goal-action 两个只在训练期存在、评测时整体丢弃的辅助头。PushT 一 epoch matched budget 下 online success 从 49.3±12.2% 升到 92.7±1.2%，而四个非坍缩变体的 probe R² 差不超过 0.03。但两个新诊断都解释不了这个提升的主要部分。
- **锐评**: problem formulation 是真本事——"审计对象应该是 selection rule 实际消费的那个标量，而不是表示本身"，配上 probe R² 差 0.03 而 success 跨 43 pp 的证据组合，这条原则值得从 world model 一路搬到 GUI 的 step-level verifier 上。但方法叙事被自己的 ablation 打穿了：inverse-only 拿走了几乎全部 ranking lift（Plan-Real +0.420，全场最高）却只有 64.0% success，再加 goal-action head 后 Spearman 反而降到 +0.412、success 却跳到 92.7——贡献最大的那 +28.7 pp 在两个诊断上几乎不留痕迹，全文也没给它任何机制假设。stage-wise 诊断更是自我否定：文章的 pitch 是"CEM 执行的是 elite candidate，不能只看随机 plan"，测完发现所有变体的 elite Spearman 都在零附近甚至为负（Appendix E 的局部 Pearson 只有 +0.05~+0.09），也就是说在 planner 真正下决定的那个区域 latent cost 与真实 cost 基本无关，而 success 照样 92.7%——那 92.7% 到底从哪来？大概率是 random 阶段的粗排把 proposal 推进了好区域，那整个故事就得从"排序质量"改写成"proposal 初始化质量"，论文提出了诊断、承认了观测，却没追下去。43.4 pp 这个 headline 也要打折：一 epoch 的 LeWM 在 PushT 只有 49.3%（±12.2 抖得厉害），而 published LeWM 是 96，在严重欠训的 baseline 上任何加速收敛的辅助 loss 都会被放大成巨大百分点，到 epoch 10 差距已缩到 2.7 pp；Table 5 又是拿 published 数字而非同预算复跑，DA-LeWM 在 Cube 落后 DINO-WM 5.3 pp、TwoRoom 同时输给 DINO-WM 和 PLDM，甚至 Table 1 里 LeWM 一 epoch 的 TwoRoom（98.0）就高于 DA-LeWM 十 epoch 的 96.0，摘要那句"across all our experiments … higher online success than LeWM"只在各自表内配对读才成立。另外 budget-matched 只匹配了 epoch 数不匹配监督量（DA-LeWM 把 demonstration action 当回归目标额外消费了两次），每配置只跑一次训练、误差棒只覆盖 evaluation 变异，而全文连主实验的 GPU-hour 都没报，读者无从判断多跑几个 training seed 是否真的负担不起。诚实度是加分项（R/V proxy 的 bug 主动标注、Cube 因 tie block 直接放弃 Spearman、Appendix D 声明 μ_f/L_f/ε_H 全未估计所以 Prop 1 只提供词汇不施加约束），元数据层面则有个小瑕疵：作者顺序在 arXiv abs 页与 v1 HTML 之间第 2/3 位互换、v1 无任何机构名，笔记已标注为 contradicted 并按 abs 页采用，不影响技术结论但说明这版稿子还没定型。最该做而没做的实验只有一句：冻住 CEM 的 elite 集合，用 real cost 的 oracle 排序替换 latent cost 排序去选最终动作——不涨，则 decision-metric alignment 的叙事必须重写。
- **Rating**: `2` 👀 ，问题问得极准且内部对照诚实，但 headline 数字建在欠训 baseline 上、核心诊断解释不了自家方法的主要增益，属于有用的经验事实而非可靠结论。

### Towards GUI Agents
- **Title**: Towards GUI Agents: Vision-Language Diffusion Models for GUI Grounding
- **Institutes**: Arizona State University, AWS Agentic AI
- **Source**: [link](https://openaccess.thecvf.com/content/CVPR2026/html/Kumbhar_Towards_GUI_Agents_Vision-Language_Diffusion_Models_for_GUI_Grounding_CVPR_2026_paper.html)  🎓 CVPR2026   **📒 论文笔记**: [[2606-TowardsGUIAgents]]
- **核心**: 把 discrete diffusion VLM（LLaDA-V 8B）原样拿来微调成 single-turn GUI grounding 模型，架构一行不改，唯一方法贡献是 hybrid masking：先用线性调度学 action type 和锚点 `(x1,y1)`，再在锚点已知的条件下把 `(x2,y2)` 全 mask 掉强制学 extent。四个 web grounding 数据集上 hybrid 相对 linear 稳定涨 +1.5 到 +6.1 SSR。但在对齐的 120K 训练语料下，8B 的 diffusion 模型在四个数据集中三个仍落后 3B/7B 的 Qwen2.5-VL，延迟高 4-6 倍。论文自称是 discrete DVLM 做 GUI grounding 的首次系统研究。
- **锐评**: 问题切口选得聪明——十几个 token 的 action string 恰是 diffusion 并行解码理论上最占便宜的区间，在这里都赢不了 AR，基本就宣判了这条路在长输出 agent 场景的死刑，可惜作者没敢把这句话说出口，反而在 Intro 塞了一句"把与 AR 的差距从约 25 分收窄到 15 分以内"——这条被独立核查判为 **unsupported**：按最强 AR 逐 benchmark 算，linear 的均值差距本来就是 16.0 而非 25，hybrid 收到 12.5，而 ScreenSpot-Web-Icon 和 VisualWebArena 两个真正的大窟窿在 hybrid 之后仍有 21-22 分，任何一种读法都拼不出"25 → 15"这个叙事。同一篇里正文与自家表格还打了两次架：§6.3 的 "+2.68-point" 表内实为 +2.64，§6.5 的 "+1.6 (Mind2Web)" 表内实为 +1.50（均为 **contradicted**），外加 Figure 3 的 83.2 与 Table 4 的 82.40 是同一个模型——单条都不翻案，合起来说明表格和正文压根没对过账，CVPR 审稿人也没查。更致命的是归因：数据配方对齐了（这点值得表扬，GUI 圈里少见），但 8B NAR 对 3B/7B AR、预训练语料、解码预算三项全没控，作者自己在 Limitations 承认 AR 领先可能来自 grounding-specific pretraining，等于亲手把核心对照拆了；而 hybrid 相对 linear 的比较同样不是延迟对齐的——把收敛步数压到 11-15 步逼近 linear 延迟后，四个数据集 SSR 全线回落，VisualWebArena 跌到 59.20，反而低于 linear 的 61.40，所谓增益是拿 6.5s 的延迟买来的。评测口径也被悄悄换过：判正是 center-point-in-GT-box 外加 action type 匹配，与 ScreenSpot 原始 protocol 不同量纲；只挑 Web-Text/Web-Icon 两个子集，避开了 ScreenSpot-Pro 的高分辨率密集小图标——而论文恰好承认自己对分辨率敏感；把交互式的 VisualWebArena 当单步 grounding 集用，这些数字别拿去横向引用。真正有信息量的两条结果反倒不在 diffusion 上：多域数据同时提精度并把收敛步数从 25 降到 16-18（精度与延迟同向改善，说明置信度上升让 remasking 提早停），以及 icon 紧框标注改成 OCR text region 带来的 +2.64 SSR——后者与整个 hybrid masking 的贡献同量级，等于自己承认瓶颈在数据口径不在解码范式。另外 hybrid 的机制解释也未必成立：deterministic 阶段本质是人为制造"anchor 可见、extent 被 mask"样本的训练分布重加权，与 diffusion 目标并不强耦合，AR 侧用 token 顺序或 loss reweighting 大概率能复现，这个对照没做。无代码、无 license、无 project page，Mind2Web 连用了哪个 split 都没写。
- **Rating**: `2` 👀 ，作为"diffusion 在最有利区间也打不过 AR"的负面经验事实值得存档，加上分辨率与标注边界那两条数据侧发现可直接迁移；但核心 gap-narrowing claim 站不住、正文与表格多处对不上、归因对照全缺，够不上 Foundation。
