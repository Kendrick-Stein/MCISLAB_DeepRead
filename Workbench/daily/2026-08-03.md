# 🔪 今日总结

今天 7 篇必读经独立复核后**全部落在 `2`**——没有一篇的核心机制断言被自己的实验测到。共同的失效形状是：诊断实验做得漂亮（MAGA 的 oracle type intervention、WCM 的 $\lambda=0$ 对照、SafeKeep 的表示/语义双向对照、SESA 的 Off/On 分解），但从诊断到方法之间的那一环——"表示变了 → 中间量变好 → 指标涨"——没有一篇量化过中间量，而主表增益普遍落在自己的 std 或缺失的误差棒里。

### MAGA：把蒸馏预算还给 action token
- **Title**: MAGA: Multi-Platform Self-Fusion of GUI Agents via Structured Action Distillation
- **Institutes**: Ant Group
- **Source**: [link](https://arxiv.org/abs/2607.29320)  📄 arXiv   **📒 论文笔记**: [[2607-MAGA]]
- **核心**: 要把 mobile / desktop / web 三个 domain-specific GUI expert 合成一个 agent，weight merging 会在专家分歧处毁掉可执行动作，而 routed on-policy distillation 把 response 当扁平 token 序列均匀加权。作者量了一刀：真正被执行的 structured action 只占 response token 的 3.9%–7.1%，也只拿到 4.0%–7.0% 的蒸馏信号。MAGA 据此按动作正确性分三档重分配 token 权重（全对整条置零 / type 对参数错则放大整个 action span / type 错则只放大 type 并 mask 参数），并在训练时给 teacher（不给 student）追加一条只含正确 action type 的 hint。8B 上 MobileWorld / OSWorld / WebVoyager 拿到 34.2 / 45.3 / 74.3，mean SR 51.2%、TNS 99.9%，比最强 baseline UI-MOPD 高 2.0 点。注意 teacher 和 student 同为 Qwen3-VL-8B、同一 mid-train checkpoint 出身，这是同尺寸专家回炉，不是压缩蒸馏。
- **锐评**: 动机段是这篇最硬的部分——"只有 action token 会被执行，而它拿到的监督份额和它的 token 份额一样低" 是可量化的结构性错配，比一票 "重要 token 加权" 类工作的动机扎实得多；oracle type intervention（136 条 type 错的 response，只换 type、参数由 frozen student 重生成，救回 68.4%，坐标类 57/87，且"还原 type 可复现全部 136 条"这个对照做得干净）是全文最有信息量的实验，独立于主表直接支撑 Rule 3。可惜结论撑不住这个开局。**头条 +2.0 拆到题目上是 9 道题**：MobileWorld +3.4 = 4 题（分母 117）、OSWorld +0.6 = 2 题（分母 369）、WebVoyager +2.2 = 3 题（分母 140），总计 626 题里赢 9 题，而全文对主表没有报任何置信区间或显著性检验——Appendix B 顶着 "Statistical Tests" 的标题，里面只有指标定义，唯一那套 2000 次 bootstrap 用在了 Sec 4.6 的 teacher-likelihood 交互项上，没碰过 SR。Table 2 也在自打脸：w/o Rule 2 在 WebVoyager 与完整方法同为 74.3、w/o teacher-side 在 OSWorld 与完整方法同为 45.3，两个组件各有一个 benchmark 上贡献恰好为零，作者还写 "separate rules also demonstrate their effectiveness"。**更尴尬的是自家 baseline**：8B 上最朴素的混合数据 SFT 就到 mean 48.3 / TNS 94.8，已经压过 Weight Soup（48.1）和 TIES（47.7）、只落后 UI-MOPD 0.9——也就是说 "merging 会退化" 这个卖点主要打的是参数合并这条路，而整套 routed OPD + 三条规则 + hint + 3 个 frozen 8B teacher + 32×H20，在同一份 343k 数据上只换来相对 SFT 的 +2.9。同一张表里 GRPO 崩到 34.5（比 SFT 低 13.8 点，2B 上同样崩），说明那个 rule-based exact-action reward 做 RL 信号时相当糟糕——可 MAGA 的 student 侧门控用的正是同一个 reward，这个矛盾全文没提一句。方法论上还有两处该讲没讲：teacher-side hint 让 advantage 变成 "teacher 在含 ground-truth type 的 prompt 下打分 − student 在原 prompt 下打分"，两边条件不同，本质是把参考 type 偷偷注入 advantage 的 oracle-conditioned scoring，包装成 "更可靠的 teacher 监督"，off-condition 会不会引偏置作者只给了直觉；Rule 1 把所有匹配单步参考动作的轨迹整条移出蒸馏、Rule 2/3 把不匹配的一律 2× 放大，等于对等效可行路径施加加倍惩罚——而作者自己的诊断已经测到 3.0% 的动作不匹配任何 teacher 但是正确的，测出来了却没往回接到 gate 的合理性上。唯一超参 β=1 全程固定、零 sweep。摘要那句 "achieves almost the same average performance with teachers" 只在 8B 成立且未限尺度：2B 上 TNS 只有 77.1（teacher mean 32.6 vs MAGA 25.3），比 Weight Soup 也就高 0.8，融合掉了近四分之一能力。评测三选二是自定子集（MobileWorld GUI 子集 117、WebVoyager 自选 140），343k 数据因 NDA 不发、代码也没有——外部无法复现，只能信表。作者自陈的 single-step offline 训练与多步执行不对齐，是这条线真正的天花板。
- **Rating**: `2` 👀 ，问题定位和 oracle type intervention 值得记住，但 626 题赢 9 题、没有显著性检验、朴素 SFT 只差 2.9 点、数据代码全不公开，够跟进不够反复读。

### SESA：自演化技能库在推理期几乎没用
- **Title**: Self-Play Meets Skill Evolution: Self-Evolving Search Agents that Pose, Solve, and Remember
- **Institutes**: 未标注（arXiv 版正文仅有 1–7 角标，无机构名列表）
- **Source**: [link](https://arxiv.org/abs/2607.29468)  📄 arXiv   **📒 论文笔记**: [[2607-SESA]]
- **核心**: 在 SSP 式 proposer–solver 搜索自博弈上挂一个可检索的 procedural skill bank：challenger 出题、参数独立的 solver 独占检索权，失败 rollout 被 LLM judge 蒸馏成带触发条件/反模式/query template 的 skill 写回库（0.93 余弦去重、helpful−hurt 淘汰、800 条上限）。由于检索上下文进入 on-policy rollout，作者主张收益可同时沉进参数和外部库，于是设计了 SESA-Off（同权重关库）/ SESA-On（开库）双路对照。7 个开放域/多跳 QA、3,125 道保留题上，SESA 比 SSP 平均高 1.2–3.2 分，比统一协议下的 SkillRL released checkpoint 高 0.9 分。最关键的一张表是 Table 2：SESA-Off 已经拿到 1.8–2.2 分中的绝大部分，重新打开同一个 final bank 只再加 0.5–1.0 分，且 dataset 级效果 mixed。
- **锐评**: 这篇最诚实、最有价值的结果，恰好是把自己标题打脸的那个。摘要卖的是"bidirectional loop makes task generation and skill memory co-evolve"——一条四段因果链，但论文只测了链条两端的聚合分数：没有任何实验固定 challenger 只变 bank 去看生成题目的难度/主题分布是否移动，Fig. 3 的 challenger 抽取成功率也没按 memory 状态拆开。笔记 Evidence Ledger 把这条判为 unsupported，而论文自己在正文写明动态证据是 correlational——那 contribution 列表和标题为什么没跟着降级？第二个硬伤是归因没排平凡解释：SESA 相对 SSP 多了更长的检索 prompt、DeepSeek-v4-pro 的蒸馏调用、异步 consolidation 作业，原文只声明同初始化/同搜索后端/同答案格式，**从未**声明训练步数、rollout 数、token 或算力预算匹配，最该做也最便宜的 placebo——注入等长无关文本——不存在（C11，unsupported）。第三，全文没有种子数、标准差、误差棒或显著性检验（C16，unsupported），每题 1 条 greedy rollout 的单点估计，而 LLaMA 的 +1.2、Qwen2.5-7B-Instruct 的 +1.5、SkillRL 对比的 +0.9 全都落在这个没被量化的噪声带里；Introduction 那句 "In the completed runs" 更像是实验矩阵没跑满的自供状。第四，dataset 级回退披露不诚实：正文只点名 2 处例外，Table 1 实际有 11 个 cell 低于 SSP，其中 **Bamboogle 在 7 个 backbone block 里回退了 6 个**（Qwen3-8B 甚至 67.2→63.2），而 Bamboogle 恰恰是最需要新颖分解、最抗模板的那个集合——检索到的 query template 诱导模板化分解、对真正需要即兴分解的问题产生负迁移，这是一个系统性 pattern，论文一个字没提。再加上全文没展示过任何一条实际蒸馏出的 skill，也没报初始 157 条与最终 bank 的重叠度——"human-readable / inspectable"这个外部记忆相对参数化方法的核心卖点直接烂尾，"演化"到底演化了多少完全是黑箱。真正的讽刺在于论文自己的结论段把 bank 降格成 "optional, model- and task-dependent augmentation"：如果部署期只值 0.5–1.0 分还 mixed，那这篇的正确命题应该是"用 skill 检索塑形 on-policy 训练分布"（一种课程/数据塑形技巧），跟 evolving external memory 的叙事根本不是一回事。方法论上唯一值得后人抄的就是 Off/On 分解本身：它把"skill library 有效"拆成训练期塑形效应和部署期检索效应，然后发现后者几乎不剩什么——这条负面校准对整个 skill-memory 文献的价值，远大于 SESA 这个系统。
- **Rating**: `2` 👀 ，系统本身是缝合与工程细节的堆叠、核心 co-evolution claim 无隔离实验且无方差可言；但 Off/On 分解应当成为该方向的报告标配——之后任何声称 skill library 有效的工作，不做这个对照就无法排除"skill 只是训练期数据塑形"这个更简洁的解释。

### WCM：给 VLA-RL 的 critic 补一个预测目标
- **Title**: WCM: A World Critic Model for Vision-Language-Action Reinforcement Learning
- **Institutes**: Tongji University, Shanghai Innovation Institute, Fudan University
- **Source**: [link](https://arxiv.org/abs/2607.29613)  📄 arXiv   **📒 论文笔记**: [[2607-WCM]]
- **核心**: 出发点是 VLA-RL 的 critic 几乎都从单帧观测回归 value，而机器人操作是 POMDP，单帧看不到运动与接触进程。作者的关键论断不是"给 critic 喂历史"，而是"喂了历史也没用"——标量 return 对学跨帧动态是过弱的监督。方案是 World Critic Model：借 LeJEPA 骨架搭一个 causal Transformer trunk，同一表征上分叉出 value head 与 action-conditioned 的下一帧 latent 预测 head，联合优化 $\mathcal{L}_{\text{value}} + \lambda\mathcal{L}_{\text{pred}}$，可直接替换 PPO / Flow-SDE / AWR / RECAP 的 critic。结果覆盖 149 个仿真任务与 7 个 WidowX-250S 真机任务，OOD 增益普遍大于 IND；LIBERO-Plus 上 one-shot SFT 起步约 250 步 RL 即反超 20k 轨迹的 Full-SFT。
- **锐评**: 全文最值钱的一个实验是把历史 ViT critic 明确定义成 $\lambda=0$ 特例并报告它仍然无效——这一刀把本文和满地"加个 world model 辅助 loss 就涨点"的工作切开了，配上沿用 RLinf 官方超参、统一训满 1,000 步、同一 SFT 起点的对照纪律（这是 VLA-RL 论文里少见的自觉），实验可信度在及格线以上。但因果链的中间那一环压根没测：论文主张"预测目标 → 表征抓到时序结构 → value 更准"，全文却拿不出任何 value 估计精度的定量对比（无 explained variance、无 TD error），Appendix E/F 只有定性 value 曲线和 heatmap。$\lambda=0$ 只能证明"预测 loss 有用"，完全不能排除它是靠正则化/防塌缩/稳梯度起作用的——尤其作者自己的 $\lambda$ 消融显示 OOD 波动 10.6pp 而 IND 只有 2.7pp、Appendix C 里把 value 直接固定为 0 反而改善 OOD，这两条恰恰更像"过拟合缓解"而非"value 更准"。一个便宜到不能再便宜的实验没做，却把结论直接写成 more accurate value estimation。数字层面同样别被 SOTA 叙事糊弄：OpenVLA-OFT 上 OOD 只比 PPO 高 0.8（IND 97.7→99.0 已近饱和）、$\pi_0$ 上只比 $\pi$-stepNFT 高 1.1 且 vision 维度打平，而 Table 1 的 baseline 行清一色单点无 error bar，只有 WCM 自己报 ±0.8~±1.5——误差棒和增益同量级，这种对比方式本身就该扣分。真正扎实的收益集中在 $\pi_{0.5}$（OOD +4.9）和 LIBERO-Plus 低数据设定，即"监督稀缺 + 分布偏移"，这个故事比 "consistently SOTA across 149 tasks" 诚实也有意思得多，可惜被自己稀释了；LIBERO-Plus 的 total 优势也只有 0.8–2.3 分，且 $\pi_{0.5}$ 的 language 维度 65.0 对 Full-SFT 的 73.8、OFT 的 layout 63.6 对 70.3 都是净亏。架构层面 LeJEPA 和 SIGReg 都是借的，本文贡献只是"接进 critic 并联合优化"，而 SIGReg 在 on-policy 里因开销被关掉——意味着所有仿真主结果里真正额外生效的只有 $\mathcal{L}_{\text{pred}}$ 一项，卖点自己塌了一半，而"没有防塌缩机制却没炸"这件事作者一句没解释。真机部分任务设计（形变物体、传送带动态抓取、长程 stovetop 从 1/50 到 15/50）确实不是走过场，但 baseline critic 是 SigLip 400M + Gemma 270M 预训练 VLM、WCM 是 107.2M 从头训，参数量/预训练来源/训练目标三个变量同时变，这个对比归因不干净。至于 "12,551% 提升"，分母是 0.78%，写成五位数百分比是修辞不是证据，审稿时该被要求删掉。另外全文没给 WCM 相对 MLP critic 的训练开销对比，只有推理 throughput——多帧编码加预测头的代价是任何人复现时的第一个问题。
- **Rating**: `2` 👀 ，$\lambda=0$ 对照实验值得记住，但核心因果链未测量、两个 backbone 上增益仅 ~1 分且 baseline 无误差棒，结论强度撑不到 Foundation。

### ST-WAM：换表示扛住视觉偏移，机制未测
- **Title**: ST-WAM: Semantic-Temporal World Action Model for Robust Manipulation under Visual Distribution Shifts
- **Institutes**: 未标注（笔记 institute 字段为空，原文抽取文本只有编号 1–6 无机构名）
- **Source**: [link](https://arxiv.org/abs/2607.28993)  📄 arXiv   **📒 论文笔记**: [[2607-STWAM]]
- **核心**: 作者观察到 video-generative WAM 在视觉偏移下会把预测未来"拉回"训练域外观（Training-Distribution Hallucination），但不去修预测未来，而是把冻结的 DINOv3 同时用在两端：Dual-Space Future Experts 让 VAE future、DINO future、action 三个 DiT 以 Mixture-of-Transformers 联合 flow matching；CAIR 用 Qwen3-VL 的当前视觉-语言语义作 query，从近 4 帧 DINO history 检索 8 个 intent token 只注入 action expert。一个结构化 attention mask 让 action token 读不到任何 future 流，因此推理时两条 future 分支可以整个切掉，退化成 action-only policy，代价 1.24× 延迟。结果：LIBERO 98.7%、RoboTwin 2.0 92.77%（都是零点几个点的表内第一），零样本 LIBERO-Plus 72.8% vs Fast-WAM 51.5%，真机四类视觉偏移 61.5% vs 25.8%。
- **锐评**: 值钱的部分很清楚：真机那组是全文唯一干净对照（同 50 条示教、同 post-train 流程），偏移下 61.5 vs Fast-WAM 25.8、掉点 17.8 vs 38.9，这个不是调出来的。消融比主表有信息量得多，而且三条都是能改变别人设计决策的**负结果**——DINO-only future 掉到 39.7%，比纯 VAE 的 51.5% 还差，直接否掉"语义表示可以替代像素动力学"；无锚点 DINO history 检索 56.5%，比压根不用 intent 条件的 66.4% 更低，说明"多喂上下文"是负收益，只有 query 被当前状态锚定 + 被检索表示对扰动不变时才转正。attention mask 那个设计也干净：训练多目标、推理零开销，可迁移。骂的部分更长。第一，全文问题定义压在"pixel-generative 监督把 action-relevant transition 与 task-irrelevant 视觉内容纠缠"上，而原文措辞一路是 "can entangle" / "potentially entangling"，从未定义、更没测过任何 entanglement 指标（笔记 Ledger 直接标 unsupported）；真正被证明的是弱得多的命题——某个自建 triplet 集上 DINOv3 更稳、换表示后 OOD 成功率更高。中间那段因果推理链是白送的。第二，两条诊断都是自建 setting 且细节推给 supplementary：180 条预测的 hallucination "70.6% 明显"是单次人工判读，无评分细则无一致性统计；290 triplet 的 cosine 0.904 vs 0.686 是跨表示空间比绝对值，本来就不是尺度无关量，唯一能读的是 95.2% vs 60.0% 那个排序指标。第三，也是最伤的：LIBERO-Plus 的 baseline 数字明确抄自第三方论文，LIBERO/RoboTwin 两张表连数字来源都没交代，全文没有一个参数量——ST-WAM 是 5B+1B+1B 三分支外挂冻结 Qwen3-VL-4B 和 DINOv3，那 21.3 个百分点里有多少来自表示设计、多少来自更多参数和更多预训练先验，读者无从核验；Q2 那个被称作 "parameter-matched" 的变体同样没有任何参数数字支撑这个形容词。第四，评测的 shift 全是 background / lighting / appearance / viewpoint / sensor noise 这类外观级扰动，而 DINOv3 恰好是对外观扰动不变的 encoder——拿一个已知对该扰动不变的表示去解一个由该扰动定义的问题，赢了不奇怪，换成物理动力学或 embodiment 偏移没有任何理由期待同样效果（作者自己在 Conclusion 认了）。至于 novelty，LDA-1B 和 LaWAM 早就在 DINO 空间建未来，本文的区分点是"不需 embodied pretraining + 单阶段 + 保留 VAE 细粒度动力学 + 加历史检索"，是组合工程而非新机制。另外只有 project page，代码权重一个字没提。真正最值得记的反而是被埋在真机表里的一个数：π0 在 nominal 只有 47.3%、低于 Fast-WAM 的 64.7%，但偏移下 32.8% 反超 Fast-WAM 的 25.8%——pixel-generative 未来监督的收益在 ID 为正、OOD 为负，这个符号翻转比 ST-WAM 自己的绝对数字更有信息量，作者却没展开。
- **Rating**: `2` 👀 ，真机对照和三条负结果确实值得 VLA/WAM 做表示设计的人跟进，但核心机制断言全靠间接证据、主表可比性和参数量都无法核验、且赢面高度依赖"用抗外观扰动的 encoder 打外观扰动 benchmark"，够不上 Foundation。

### TokenSwap：概念级换图测 MLLM 模态差
- **Title**: TokenSwap: Benchmarking and Reducing the Modality Gap in Multimodal LLMs
- **Institutes**: University of California, Santa Barbara; Google DeepMind
- **Source**: [link](https://arxiv.org/abs/2607.28640)  📄 arXiv   **📒 论文笔记**: [[2605-TokenSwap]]
- **核心**: 把纯文本里可视化的概念 span 换成语义等价的图片，从而机械地把任意文本 benchmark 转成 image-interleaved 版本；以 MMLU 为源得到 TokenSwap-Bench（1,516 样本 / 6,946 处替换 / 平均 4.58 处）。42 个 MLLM 全部掉点，范围 4.2%（Gemini-3-Flash）到 47.4%（InternVL2-8B），均值 19.6% ± 3.3%；CoT/few-shot 效果方向不定，10× training FLOPs 只买到 2.8% absolute gap。作者进一步把同样的替换用在 Magpie-Pro 上做训练增强（116,722 样本，base 为 Qwen2-VL-7B），post-training gap 相对配对的纯文本训练从 0.268 降到 0.167，且 GQA/TextVQA/MME 不退化。反向结果同样干净：纯文本训练把 gap 从未增强 baseline 的 0.232 主动推高到 0.268。
- **锐评**: 测量协议是这篇真正值钱的部分——概念级替换而非整页渲染文本，上下文与题目结构原样保留，三重过滤里的 caption round-trip（图→caption→填回原位，要求重建文本仍答对）是同类"换个模态就掉点"论文普遍不做的功课。训练侧的 paired 设计也守规矩：text training 与 TokenSwap training 用完全相同样本，只差换不换图，所以收益不能推给数据量。**但最关键的 sanity control 缺位得刺眼：全文从未让被评测的 42 个模型自己去识别那些替换图片。** validity/importance/caption 三道过滤全用 Gemini-2.0-Flash 当 proxy，人工核验（213 概念，92.0%/89.2%，随机 25%）验的是"人能不能认出这张图"。这两者都不保证 InternVL2-8B 或 LLaVA-OV-7B 认得出同一张图，于是弱模型那 35%–47% 的"modality gap"里究竟有多少是语义不变性失败、多少只是它压根看不清，论文无法区分——后者是个平凡得多的结论。补丁便宜到荒唐：沿用人工核验的四选一格式给每个被测模型跑一遍，拿识别率做偏相关即可，没做。更难堪的是 Appendix B.4：gap 随替换图片数从 1 处的 14.0% 单调升到 7 处的 24.9%——这正是作者自己列出的"视觉 token 变长 / 多图处理"confound 会预测的形状，论文却把它当作 gap 稳健性的**补充证据**摆出来，而不是当作对自身解释的挑战。作者对 confound 的全部辩护只有一句"所有模型/设置/图源下 gap 都一致存在"，可一个同样普遍存在的 confound 恰恰也会长这样，一致性证明不了因果。第二处站不住的是 reasoning 那条线：10.1% vs 25.5%、Welch's $t=-7.48$ 看着漂亮，但这是**跨模型分组统计**，两组在家族、规模、训练数据上全不匹配，relative gap 归一化只控住了文本能力一个维度；全文唯一的同族同规模对照只有 Qwen3-VL-4B/8B 的 Instruct vs Thinking 两对，而且其中 8B 的数字论文自己都对不上——§4.4 正文写 12.4%，Table 2 是 0.928/0.808 = +0.120（笔记 Evidence Ledger C16 标为 contradicted）。作者措辞只敢到 "may be partly associated with reasoning-oriented training"，任何转述都不该比这更硬。第三，benchmark 的成员资格条件就是 Gemini-2.0-Flash 的行为（importance filtering 要求它在原文答对、删概念后答错），保留下来的必然是 Gemini 家族擅长的子集——"Gemini-3-Flash gap 最小 4.2%"这类跨家族排名因此存在结构性利好偏差；**这是笔记作者的推测、论文完全未讨论也未换 proxy 重跑过滤管线**，但换个 proxy model 验一遍排名稳定性本是一天的活。数字层面还有两处该被点名：其一，标题里的 "Reducing" 用 0.268→0.167 讲故事，参照系是配对的**纯文本训练后**模型，而不是未增强 baseline 0.232——对 baseline 的真实增益只有约 6.5 个点，且残余 0.167 是缓解不是消除；其二，与 SEAM 的对比里 text 准确率 $r=0.811$、image $r=0.914$ 都高度相关，唯独 modality gap 本身 $r=-0.028$，作者读成"两个 benchmark 测的是 gap 的不同侧面"，同样合理的读法是这个"construct"根本不稳定、测出来的更像每套图的具体难度。剩下的短板按常规扣分：训练侧只在 Qwen2-VL-7B 一个 base、一个规模上验证；Table 5 显示跨域迁移基本失效（OCR 数据训完，natural interleaved 从不训练的 0.4466 反而掉到 0.4393），所谓 "seamlessly integrated into existing training pipelines" 目前无大规模证据；正文没给 benchmark 与训练数据的公开发布链接，对一篇主交付物是 benchmark 的论文是硬门槛。真正让人记住的其实是那个反向结果——**当前主流的"多喂纯文本数据"路线会主动恶化跨模态一致性**，这比正向的增强收益更有信息量，也更该被下游看见。
- **Rating**: `2` 👀 ，测量协议扎实、"prompt 和 scaling 都救不回来"对 GUI agent 这类图文交错常态输入的系统是直接可用的坏消息；但没做被测模型自身的图片识别对照、confound 未隔离（gap 随图数单调上升的反向证据被误当佐证），核心归因目前只到相关性，跟进可以，别当定论。

### SafeKeep：工具 schema 格式稀释安全信号
- **Title**: Tool Specifications Matter: Uncovering and Mitigating Safety Risks in AI Agents
- **Institutes**: Beijing University of Posts and Telecommunications, Beihang University, Tsinghua University
- **Source**: [link](https://arxiv.org/abs/2607.29254)  📄 arXiv   **📒 论文笔记**: [[2607-SafeKeep]]
- **核心**: 同一个 LLM 在 chatbot 下会拒绝的有害请求，包装成 agent 后照做——本文把这个降级归因到 tool specification 的 **schema 表示形式**，而不是工具语义。证据是三级消融：组件级定位（加 tool spec 造成的 refusal-direction AUROC 下降最大，三模型平均降 0.136，长度对照 Chatbot-Long 排除"上下文变长"）→ 表示/语义正反对照（schema 转 flattened 文本恢复到 0.885/0.845/0.898，伪词换语义保结构只到 0.776/0.770/0.827）→ activation steering 因果验证。据此提出 SafeKeep：安全判断阶段把 tool spec 转成扁平文本、执行阶段保留原 schema，不动 pipeline、不需参数或激活访问。四个 backend 上 AgentHarm 平均 refusal 23.8%→70.6%，InjecAgent 整体 ASR 25.6%→2.5%。
- **锐评**: 诊断这一半做得干净，值得单拎出来读。绝大多数 agent safety 论文停在"现象 + 更厚的外挂守卫"，这篇真去问了"模型自己的 refusal 为什么失效"，而 §3.3 的双向对照（改表示保语义 vs 改语义保表示）是全文最硬的一块证据——一正一反把归因钉住，比单侧消融强一个量级；SafeJudge 消融（判断阶段留 schema，refusal 只有 45.0% vs 70.6%）也干净地排除了"增益只是多一次自审"。但**防护那一半明显是诊断的赠品**，问题一大堆。第一，机制证据全部只在 Llama3.1-8B-Instruct 上跑（Schema Direction、逐层 cosine、first-token 投影、steering 全是），跨模型只有 AUROC 数字，趋势一致 ≠ 机制一致，"schema 稀释 refusal"的普适性目前是外推。第二，steering 曲线反过来伤了自己的解释：α=4 时 refusal 5%→47.5% 看着漂亮，α=8 时 harmful exec 掉到 2.5% 而 refusal 只有 20%、invalid output 冲到 77.5%，α=12 直接 100% 崩坏——如果减去 Schema Direction 真是在"复原 refusal 开关"，加大力度该是更多有效拒绝而不是语无伦次；更省事的读法是中等强度把生成推离了执行模式，大强度推离了正常流形。第三，**over-refusal 全文没报**（笔记 C15 明确标为未报告），而这方法的机制就是"让模型更容易说不"，误拒率恰恰是最该单独测的一格；AgentHarm Acc 60.9%→79.6% 把"正确拒绝 harmful"和"正确处理 benign"混在一个数里，替代不了 benign 侧的 utility，InjecAgent 的 Valid 率更只是输出可解析性。第四，作者自己写的机制解释（tool-use 训练把 schema 与"采取行动"绑定）在文中标为 "one possible explanation"，没有任何训练侧验证，别当结论读；同理 C20——只控了长度和语义，没控 tool spec 在 prompt 里的**位置**，也没有"与工具无关的结构化 JSON"作对照，所以"schema 特有的执行线索"和"任何 OOD 结构化文本块都稀释 refusal"两种解释目前分不开。第五，绝对水位不体面：70.6% 意味着近三成 harmful 请求照旧通过；GPT5.4-mini 上 SafeKeep 的 refusal 只有 57.4%，**低于**消融基线 SafeJudge 的 66.4%，这是"flattened 表示是必要的"这一核心论断的现成反例，论文一句不提。开销同样是零量化——每请求多一次 LLM 调用，只有一个 "lightweight" 的形容词（C22 全文未报延迟与 token 成本）。总结：把它当一篇归因论文读是赚的，把 SafeKeep 当能上线的防护读是亏的。
- **Rating**: `2` 👀 ，诊断部分的表示/语义双向对照足够改变你对 function-calling / MCP 接口安全代价的判断，但机制单模型、缺 over-refusal、GPT5.4-mini 自打脸这三条把它按在 Frontier 而非 Foundation。

### QQWorld：QQ matching 治 latent 重尾
- **Title**: QQWorld: Quantile-Quantile Matching for World Model Regularization
- **Institutes**: Xi'an Jiaotong University
- **Source**: [link](https://arxiv.org/abs/2607.28415)  📰 HF Daily ⬆️ 9   **📒 论文笔记**: [[2607-QQWorld]]
- **核心**: LeWM 那一路把 normality test（Epps–Pulley）当可微正则来把 latent 拉成各向同性 Gaussian，但训出来的 latent 照样重尾（radial tail rate 0.315 vs Gaussian 参考 0.10）。作者把 EP 改写成单位带宽 Gaussian kernel 的 MMD，直接求梯度拆出 pairwise repulsion 与 center attraction 两项，指出恢复力 ~ h·e^{-h²/4} 在 h=√2 之后超指数衰减——样本一旦跑出 kernel 的交互尺度，惩罚项就"看不见"它了。替代方案朴素得可疑但有效：把投影后的 order statistics 直接对齐 rank-matched Gaussian quantile，L_QQ = Σ(x̂_n − q_n)²，梯度 2(x_n − q_ρ(n)) 随偏差线性增长永不饱和；再配一个 FIFO detached 队列扩大排序池，把 ranking pool 与 backprop batch 解耦。四个 control 环境 6 seeds 平均成功率 79.75 → 85.08。
- **锐评**: 诊断部分是这篇的全部价值，而且质量确实高——"能有效**度量**分布差异的统计量未必是有效的**训练目标**，它还得处处给出不消失的梯度"，这条判据可以拿去把 LeJEPA 之后一整批"拿检验统计量当正则"的工作重审一遍：凡是 kernel-based discrepancy（MMD/EP/energy distance），bandwidth 就天然划出了一块梯度盲区。最漂亮的自洽证据是 QQWorld 的 EP 统计量反而低于**直接拿 EP 训练**的 LeWM（119.909 → 82.294），这不是刷点，是在打对方主场。可惜实证部分完全撑不起这个野心。第一，"drop-in replacement"是嘴上说的：所有增益都来自 LeWM 单一 backbone 的 EP→QQ 替换，DINO-WM、PLDM 上一次都没插过——那么"QQ 优于 EP"至今只是"在 LeWM 这套配置下 QQ 优于 EP"，重尾究竟是 EP 目标的普遍缺陷还是 LeWM 训练配方的产物，论文没有回答。第二，5.33 pp 的平均增益有一半在噪声里：Reacher +2.66、OGBench-Cube +3.00，都小于双方各自的 std，真正超出噪声的只有 Two-Room（+9.34）和 PushT（+6.33），全文零显著性检验。第三，最高平均成功率这个说法经不起看表——对 DINO-WM (w/o proprio.) 只领先 0.33 pp，而后者的数字是从 LeWM 论文里转引的、无 std、非本文复现；OGBench-Cube 上 QQWorld 70.33，SMWM 84.33、DINO-WM 86.00，被按在地上。所以成立的 claim 是"QQ 是比 EP 更好的正则项"，不是"QQWorld 是更好的 world model"。第四，全文机制论证的三个支点 Proposition 1/2/3，13 页正文无附录无证明；Prop 1 的渐近式从梯度表达式看还算可信，Prop 3 里那个"与 X、N 无关的常数 C"和 log N/N 项则纯属天降。第五，cross-batch 的 bias–variance 分解（Eq. 21）是个带 ≈ 的一阶展开，staleness bias 项没有任何可估界——它能事后解释 K+1 从 3 加到 4 反而掉到 81.75、N=64/128 加队列全线变差，但预测不了最优 K，这是叙事不是理论。另外还有一个作者自己没提的失效条件：QQ 的线性梯度对**真实的**离群观测同样会硬拽，当数据本身就该有重尾时这是个错误先验。亮眼的数字是 cross-batch 那一栏——N=32、K+1=3 拿到 83.50% 就已超过 LeWM，显存 3.4 GB vs 大 batch 配置 12.7 GB（batch 缩 4×、显存降 73%），这个把排序池和梯度池解耦的技巧比模型本身更容易被别人抄走。无代码，Table 2/3 无 std 无 seed 数。
- **Rating**: `2` 👀 ，诊断链条（EP→MMD→梯度消失）和那条"检验统计量≠训练目标"的判据值得抄进自己的工具箱，但单 backbone、小规模 benchmark、半数增益落在 std 内、命题无证明，撑不起 foundation。
