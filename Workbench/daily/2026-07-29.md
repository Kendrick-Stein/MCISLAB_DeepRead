# 🔪 今日总结

今天最值得追的是两条“把问题放对位置”的路线：HiFi-UMI 把 manipulation 的瓶颈从 policy 花活拉回高保真 robot-free data production，RARG 则把 relevance 从 top-k 内容筛选器提升为 corpus interaction 的 execution prior。Mage-VL 与 Wonder 都给出可复用的系统原则，但前者被混合训练 recipe 与选择性 speedup 混淆，后者缺 component ablation、公开 benchmark 和硬件归一化速度证据。抓取阶段 HuggingFace 与 OpenAlex 可用；arXiv API 遇到 HTTP 429，CVF 源出现 gzip decode failure，故本轮候选不是全部来源的完整快照。

## 论文点评

### HiFi-UMI
- **Title**: HiFi-UMI: Learning Deployable Manipulation Policies from High-Fidelity UMI Data Alone
- **Institutes**: 笔记未提供
- **Source**: [link](https://arxiv.org/abs/2607.25895)  📰 HF Daily ⬆️ 100   **📒 论文笔记**: [[2607-HiFiUMI]]
- **核心**: HiFi-UMI 的关键不是发明新 policy，而是把 pose accuracy、双手 relative pose、硬件同步、FoV 与 quality control 做成一条高保真 robot-free 数据生产链，让 UMI data 能直接用于 target-task post-training。四个双臂任务、三个 backbone 的 960 次 real-robot rollouts 中，UMI-only 相对 in-domain teleoperation 的 aggregate success gap 分别为 -2.5、+3.1、-0.6 percentage points。4,000-hour UMI pre-training 还将十个 unseen tasks 的 mean action error 降低 41%，并在 StarVLA-QwenPI 上把 aggregate real-robot success 提高 18.1 points。公开的 HiFi-UMI-2K 包含 2,000 hours、482,100+ episodes 与 110+ scenes。
- **锐评**: 这是少见的真系统贡献：它挑战的不是某个 benchmark 小数点，而是 manipulation data collection 的成本结构；相比既有 UMI 主要做 pre-training，它真正把 robot-free data 推到了 deployment post-training。但“匹配 teleoperation”别吹过头——3,200 条 UMI 对约 300 条 teleoperation，且 scene exposure 不同，只能证明整条 practical pipeline 可竞争，不能证明 equal-sample efficiency。所谓 960 rollouts 分摊后每个 task-policy pair 只有 40 次，2.5 points 恰好就是一次成功，task-level 小差异几乎没有统计说服力；评测也仅限四个 tabletop bimanual tasks 和单一 robot/interface，“zero-robot”更不等于 base model 历史无 robot data。更致命的是 pose、synchronization、relative geometry、FoV 被整包升级却没有 controlled degradation ablation，所以论文证明了“整套系统有效”，没证明究竟什么必要。41% OOD error 与 18.1-point success gain 很亮眼，但后者只在一个 backbone 上成立。不是灌水，但证据边界必须焊死。
- **Rating**: `3` 🔥，它切中了 Embodied AI 最硬的数据瓶颈，并用跨 backbone 的真实机器人结果证明系统路线有价值，尽管 sample matching、统计分辨率与因果 ablation 都还欠账。

### RARG
- **Title**: A New Role for Relevance: Guiding Corpus Interaction in Agentic Search
- **Institutes**: Tencent, IIE-CAS
- **Source**: [link](https://arxiv.org/abs/2607.24223)  📰 HF Daily ⬆️ 77   **📒 论文笔记**: [[2607-RARG]]
- **核心**: RARG 不再把 relevance 当作 top-k 内容筛选器，而是用它控制 corpus interaction：document score 决定 `rg` 扫描顺序，相关 paragraph 提供搜索起点，match score 决定有限 observation budget 下哪些片段可见。在 100-query BrowseComp-Plus 上，GPT-5.4-mini 的 RARG++ 达到 84% accuracy / 23.9 tools，对比 RISE 的 78% / 28.7 和 DCI 的 78% / 99.1。扩展至 1M documents 后仍有 79% accuracy，但长噪声文档造成的 lexical interference 并未消失。BRIGHT 上更强调 breadth 的 RARG+ 反而优于 RARG++，说明 relevance granularity 必须随任务结构变化。
- **锐评**: 真正的新意不是又造了一个 retriever，而是把 retrieval ranking 从“给模型喂什么”提升为“agent 按什么顺序执行、看见什么”的 control primitive；这比大多数堆 planning module 的工作更简洁，也更可能迁移。实验没有回避反例：RARG++ 在 BRIGHT 输给 RARG+、generative reranking 少调用却掉 9 points，证明作者至少没有拿单一 leaderboard 糊墙。但主结论仍压在 100-query sample 和 GPT-5.1 judge 上，缺 human audit；更致命的是 tool count 把 `-j1` 串行扫描和额外 embedding reranking 的 latency 藏了起来，23.9 tools 绝不等于更快或更便宜。相较 RISE 的 bounded interaction space 和 DCI 的无差别 corpus interaction，RARG 的区别足够本质；不过 fixed local corpus 到 open-web 之间还隔着 freshness、权限、重复内容与 source trust，这个 generality 目前只是待验证方向。
- **Rating**: `3` 🔥，抓住了 agentic search 中一个被长期放错位置的核心变量，方法异常克制、机制证据扎实，虽评测窄但 insight 明显大于榜单增益。

### Mage-VL
- **Title**: Mage-VL: An Efficient Codec-Native Streaming Multimodal Foundation Model
- **Institutes**: Microsoft
- **Source**: [link](https://arxiv.org/abs/2607.24904) 📰 HF Daily **📒 [[2607-MageVL]]**
- **核心**: Mage-VL 真正有价值的设计，是在昂贵 ViT 之前利用 codec motion vector 与 residual energy 筛掉可预测 patches，再用 event gate 控制何时调用 language decoder。64-frame 设置减少约 75% visual tokens；NExT-QA 上达到 80.8 / 415s，对比 Qwen3-VL-4B 的 79.8 / 1460s，但这是 8×B200 上的峰值案例，TempCompass、VSI-Bench 反而由 Qwen 更快。HEVC→DCVC-RT 无 retraining 时均分仅从 58.0 降至 57.7，说明 codec-native interface 确有迁移性。Streaming 端却远未成熟：SoccerNet gate 的 F1 仅 16.35、PR-AUC 9.30，OVO Backward Tracing 也只有 48.15。
- **锐评**: `codec-native pre-encoder sparsification` 是硬贡献，所谓 “System 1 / System 2” 基本是认知科学 cosplay——前者只是 `silent/speak` 二分类 gate，后者只是 local-window causal generation，既没有独立快速推理，也没有慢速 planner。更麻烦的是，论文把 Mage-ViT、350M recaptioned images、五阶段 curriculum、空间/GUI/video mixture 一锅端后再和 Qwen 比，根本没有资格把 spatial 或 long-video 增益归因于 codec sparsity；作者自己也承认缺 single-variable ablation。`3.5×` headline 同样挑食：缺 latency breakdown、variance 与跨硬件复测，表内还出现 tc16 比 tc32 慢数倍的非单调计时。Zero-Vision SFT+RL 又来自另一套 LLaVA-OV/OpenMMReasoner checkpoint，拿来给主模型贴金属于典型 appendix 膨胀。好在 cross-codec 零适配结果够硬，证明这不只是 HEVC-specific trick；但距离“foundation”还差一套干净、matched-data、matched-backbone、matched-hardware 的因果实验。
- **Rating**: `2` 👀，核心系统原则新且值得追踪，但证据被训练配方混杂、选择性 speedup 和孱弱 streaming gate 卡死，尚不足以升格为 Foundation。

### Wonder：会导航的视频生成器，不是通用世界模型
- **Title**: Wonder: Video World Model Done Better
- **Institutes**: Adobe Research, Johns Hopkins University
- **Source**: [link](https://arxiv.org/abs/2607.26037)  📰 HF Daily ⬆️ 9   **📒 论文笔记**: [[2607-Wonder]]
- **核心**: Wonder 在 Wan2.1-I2V-14B 上组合 Pixel-Space Coordinate Field、sparse KV retrieval、autoregressive distillation 和 streaming runtime，实现统一的 I2V camera exploration 与 V2V re-shotting。其 camera condition 直接渲染为 pixel-aligned lattice/environment-map video，比抽象 pose embedding 更贴近 video backbone 的输入结构。作者自建 benchmark 上，I2V average score 为 0.8558、translation/rotation RPE 为 0.0132/0.0784；V2V 为 0.8527 和 0.0187/0.1119，并报告 minute-scale 16 FPS。它控制的是 camera trajectory，不是 agent action，也没有显式 state、physics 或 outcome verification。
- **锐评**: 想法够狠，证据却薄得离谱。Pixel-aligned camera evidence 与 full-fidelity sparse retrieval 确实区别于普通 camera embedding 和 sliding-window generation，但四个核心组件连一个 quantitative ablation 都没有，谁在起作用完全说不清。16 FPS 不交代 inference GPU 数、分辨率和 matched-hardware baseline，基本是宣传数字；“long-term memory”只靠 Figure 9 几张 revisit 图，full historical KV 还会持续增长，stable attention latency 不等于 bounded memory。I2V 的 RPE 改进值得重视，V2V 却只打一个 baseline；benchmark 又未公开，所谓 “general-purpose world model” 更准确的名字是昂贵但能打的 camera-controllable navigable renderer。
- **Rating**: `2` 👀，系统设计值得拆，但零消融、私有 benchmark 和无硬件口径的 16 FPS 让 headline 暂时不配 🔥。
