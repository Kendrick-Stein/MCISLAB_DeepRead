# 🔪 今日总结

本周的主题是**自进化循环的 collapse**，三篇论文分别找到了它发生的不同层面。R-Quest 发现 consistency 过滤器会系统性地挑出 ill-posed 题，问题出在训练数据被污染。ReSAIL 发现下一轮 teacher 被顺带训坏，问题出在监督源。RRSI 发现 harness 在有限 evolve set 上 hill-climb，问题出在搜索过程本身。三者是同一个模式：自我产生的信号被当成真值。最硬的证据来自 R-Quest 和 RRSI，它们都在同一 base、同一 budget 的条件下把 in-distribution 涨、OOD 不涨这件事直接测了出来。反例是 Trinity：它用 EMA 自评当 verifier，却连 Verifier 消融都没做，训练曲线也和 rubber-stamp 分不开。

GUI 方向的增量集中在 harness 层面。GUI-HARVEST 把重复执行的方差当作诊断信号，是这批论文里唯一能直接搬用的方法。WebFovea 用一个坐标降采样 bug 说明，参考实现可能整套失效，这值得写进评测可信度的 checklist。AdvSim2Real 的 success-flip 反事实奖励设计得好，但 robustness 数字全部来自 world model + LLM judge 内部，"Sim2Real"名不副实。像素级 GUI world model（Infinite-Dreamer）被自己的 ablation 否定了：长程想象的存活率只有 9.3%，真正有效的部分只是外观增强。具身方向只有 Long-WAM 一篇，它的头条组合"78.7% + 107 ms"并不在同一个工作点上，摘要把两个数字并列容易误读。

### GUI-HARVEST
- **Title**: GUI-HARVEST: Self-Improving GUI Agents through Evidence-Driven Harness Evolution
- **Institutes**: The Chinese University of Hong Kong, Shenzhen; Tianjin University; Harbin Institute of Technology (Shenzhen); East China Normal University; Shenzhen Research Institute of Big Data
- **Source**: [link](https://arxiv.org/abs/2610.00948)  📰 HF Daily ⬆️ 11   **📒 论文笔记**: [[2610-GUIHARVEST]]
- **核心**: backbone 冻结，只让 Claude Sonnet 5 扮演的四个角色自动改写 GUI agent 的 harness（prompt、动作接口、控制流、恢复/终止逻辑）。诊断时每个任务跑 3 次，把成功 run 和失败 run 按截图逐步对齐，找出分叉的那一步；再跨任务聚类成 behavior mode。补丁跑 GUI 评测之前必须先写下可证伪的行为预测，之后要同时过 score hard gate 和 behavior soft gate 才会被采纳。OSWorld-Verified 的 sealed Test 上，六个 backbone 全部提升（+1.49~+10.16 pp，Qwen3-VL-32B Full +12.33）。同起点、同 optimizer 下明显好于 Self-Harness（+2.00）和 Meta-Harness（+4.38）；harness 冻结后直接迁移到 WAA，GPT-5 +13.87。
- **锐评**: 这是这批里唯一真正有 insight 的一篇。它把执行方差（11.8–20.4% 的任务在 3 次执行里时成时败）当诊断信号用，而不是当噪声扔掉，消融也站得住：K=1 选出的 harness Full 43.1，K=3 是 50.9。只用 hard gate 跑了 9 轮，反而选出更差的 harness（48.08 vs 50.94），这条数据直接说明在 80 题的小 split 上按分数 hill-climb 就是在拟合噪声。问题也很明显，主要有四个。第一，不少"自我进化"出来的东西其实是 runtime bug fix，比如 OpenCUA 的 zero-duration drag、`computer.*`→`pyautogui.*` 的 API 映射、LibreOffice 保存前置。对本来就调得很好的 harness，空间可能小得多；OpenCUA 只涨 +1.49 已经露了底。第二，Task Card 把 feasibility 标注和公开 hint 都喂给了 optimizer，而 infeasibility misjudgment 恰好在六个 backbone 上都被针对性修补，有 OSWorld-specific 拟合风险，论文完全没讨论。第三，split 方差很大（Qwen3-VL-32B 初始 harness 的 Search 31.07 和 Test 43.02 差了 12 分），optimizer 本身也只跑了一次，没有重跑方差。第四，"推理便宜 72%"那个对比把四角色 Sonnet 5 加上每个候选 160 题×3 次 rollout 的优化开销全部剔掉了，Figure 1 里和 published 系统的对比口径也不一致。干净的证据只有 Table 1/2 的配对实验。另外 behavior soft gate 本身靠 LLM 判断，准确率没有单独评估，而残余失败恰恰是"截图上看起来成功"的错误动作，两者很可能是同一个盲点。
- **Rating**: `3` 🔥 ，目前 GUI harness 自动优化做得最完整的闭环；"重复执行方差可以当信号"和"残余错误集中在看起来成功的动作"这两条结论，直接指向 GUI verifier / process reward 该攻的方向。

### RRSI
- **Title**: RRSI: Regularized Recursive Self-Improvement of Agent Harnesses
- **Institutes**: Google Cloud AI Research, Stanford University, Washington University in St. Louis, UNC-Chapel Hill
- **Source**: [link](https://arxiv.org/abs/2609.24972)  🔥 HF Trending ⬆️ 222   **📒 论文笔记**: [[2609-RRSI]]
- **核心**: Harness 自演化反复用同一个有限 evolve set 打分、提议、挑选，本质上是 adaptive overfitting。RRSI 不限制能改哪些组件，只约束搜索过程：每轮 edit 数逐步退火到 1；用 base harness 重复评测测出噪声地板 ε；由一个只读 diff 的 critic 拦截 leakage；token 增长必须用更大的分数增益来换；长期无增益的组件交给 proposer 删除。在 Harvey LAB 上，RRSI 的 evolve 分数是所有演化方法里最低的（90.5，Meta-Harness 为 93.0），但 OOD 均值是唯一明显高于 base 的（43.6 vs 39.7）。每 trial 的 token 为 2.42M，不加正则的演化是 3.80M。
- **锐评**: 这是这批里唯一把"evolve 涨、OOD 不涨甚至掉"这个现象在同一 base、同一 budget、同一 policy 下摆出来的论文。Table 1 的排序翻转比任何 SOTA 数字都有信息量：AHE 和 TTHE 演化完低于起点，TTHE 低 1.7。Table 9 揭示的 rubric leakage 也比"写死答案"更阴险：Meta-Harness 积累了一段 730 词复述评分规则的系统消息，关键词检查根本拦不住。噪声地板是实测出来的（agentic workspace 上 ε=0.004），不是调出来的，这是整套方法最硬的一环。下面开骂。
  - 文字和表格对不上：摘要写 OOD "up to 4.3"，正文 JobBench 是 +4.7；"30% fewer tokens"按表算约是 36%。引言"比 prior baseline 高 up to 12.5%"在笔记里标为 unsupported，Figure 1 推算是 1.8/10.7/22.9%，这个数字不该引用。
  - 评测自循环：policy、proposer、analyst、critic 全是 Opus 4.8，JobBench 的 judge 一半也是 Opus 4.8，agentic workspace 的 OOD 结论全部来自 LLM judge。
  - 七个正则组件只做了整组消融，所以不知道真正起作用的是噪声地板、critic 还是 token 预算。
  - 和其他演化方法的对比只在一个 domain 上做过。coding 和 engineering 只有 RRSI vs base，bootstrap CI 也是对 base 算的，不是对其他演化方法。
  - 横向看：同样讨论 collapse，R-Quest 和 ReSAIL 管的是权重层的数据或 teacher 被污染，RRSI 管的是搜索层对有限评测集的过拟合，诊断层面不同但同构，都是自我产生的信号被当成真值。
- **Rating**: `3` 🔥，它把 harness 演化需要正则、评测必须看 OOD 这件事钉死了，噪声地板加 token 门槛可以直接搬进任何演化循环。

### R-Quest
- **Title**: Questioning the Questions: Sustaining Self-Evolution in Reasoning Models
- **Institutes**: Washington University in St. Louis, University of Michigan, Ann Arbor
- **Source**: [link](https://arxiv.org/abs/2610.04299)  📰 HF Daily ⬆️ 54   **📒 论文笔记**: [[2610-RQuest]]
- **核心**: 诊断 R-Zero 式 questioner–solver 自进化为什么会崩，原因有两个。一是 invalid 题（矛盾、缺条件、无解）随轮次从 23.5% 涨到 60.5%，consistency ∈ [0.3, 0.8] 过滤反而把训练集 valid 率压到 27.64%。二是 BLEU 去重识别不了换皮同题，最大题型被拆成 22 个簇，惩罚被稀释。方法是先用 GRPO 训 solver 学会输出 INVALID 当 validity gate，再让 frozen base 和 K=8 道随机题两两判"是否同题型"当 novelty gate。Qwen3-4B 跑 10 轮不崩，第 10 轮 51.92，同轮 R-Zero 已跌到 34.60。
- **锐评**: 这批里诊断最漂亮的一篇。"uncertainty 过滤器系统性富集 ill-posed 题"是一个机制性发现：坏题的答案天然处在中等一致区间，正好被过滤器偏好。它适用于所有拿 self-consistency 当难度代理的流程，包括 Trinity 批评的 VisPlay。1,273 题的匹配对照（49.91 vs 46.54）把相关推进到了局部因果。R-Zero 第 10 轮 valid 题上多数答案正确率只有 2.06%，说明伪标签也一起死了。但也有几处要骂。
  - "17.32 分领先"是 R-Quest 峰值对 R-Zero 崩溃后的值，峰值对峰值只有 2.82。
  - 主表每个方法取测试集最高的那一轮，没有 validation，也没有多 seed，5 轮内各方法差距只有 1.8–2.5 分。
  - "self-contained"有水分：拒题能力来自 GPT-5.6-Sol 标注的 2,240 题，而且就是从同一 backbone 的 R-Zero 失败题池里采的。诊断和过程指标的裁判也是同一个 GPT-5.6-Sol，过程指标天然偏向 R-Quest。
  - R-Zero 行有没有用 validity 初始化、w/o validity 的定义是什么，正文都模糊。这直接影响"validity 是长程稳定主因"这条归因。
  - 方法本身只是在 R-Zero 上加两道 gate。
  - 横向看：R-Quest 和 Trinity 诊断一致（agreement 看不出坏题），解法相反。R-Quest 把外部真值前置蒸馏一次，Trinity 坚持用 EMA 自评。R-Quest 的数据反而支持"self-gate 需要外部锚点"。
- **Rating**: `3` 🔥，consistency 过滤反向富集 invalid 题这个诊断有因果实验支撑，每个做 self-evolving 数据的人都该读，方法本身只是增量。

### AdvSim2Real
- **Title**: AdvSim2Real: Training Web Agents Against Adaptive Prompt Injection in a Web World Model
- **Institutes**: Mohamed bin Zayed University of Artificial Intelligence; Amazon; Massachusetts Institute of Technology
- **Source**: [link](https://arxiv.org/abs/2610.08773)  📰 HF Daily ⬆️ 6   **📒 论文笔记**: [[2610-AdvSim2Real]]
- **核心**: 环境是冻结的 WebWorld-14B，在里面让 curriculum、injection adversary 和 web agent 三个 Qwen3.5-4B LoRA 一起 co-evolve。curriculum 奖励"agent 大约一半能做成"的任务（R-Zero uncertainty reward）；adversary 只有在把一条原本判为成功的 clean run 翻成失败时才拿奖励（success flip）。150 个表单任务上，clean 完成率 74.89→81.33，learned adversary 下 48.07→57.48，未参与训练的 Kimi-K3 adversary 下 23.00→30.72。
- **锐评**: success-flip reward 是好设计：回放已经判为成功的 clean control 再注入，构造出反事实对，把 agent 自己的失败从 adversary 的奖励里干净地剔掉了。这个思路可以搬到任何能做轨迹快照的扰动训练里。但标题里的 "Sim2Real" 名不副实：所有 robustness 数字都是 world model 渲染出来、再由 LLM judge 打分的，robust checkpoint 根本没在真实浏览器里测过。真实 Chromium 只验证了 Stage 1 的 capability（25.56→44.44）。更要命的是，learned adversary 要求的 marker 在渲染后的页面上可见率不到 0.5%（0.22–0.48%），Kimi-K3 是 72–81%。也就是说，Stage 2 里大部分"攻击"多半根本没有被渲染出来。再看 Stage 1，它从没见过 injection，第一轮就把 attacked mean 从 48.07 拉到 54.74，Stage 2 只多加了约 3 分，第一轮还是 clean 和 attacked 双降。所以 robustness 增益很可能主要来自"任务做得更完"，而不是学会了抵抗 injection（推测，论文的 ablation 区分不了这两种解释）。"匹配 9B"在 matched seed 下只差 0.44，比 seed spread 还小，只能算打平。judge 会接受 7.5–10.4% 在浏览器里 strict 失败的轨迹；conjunctive selection 在浏览器里 60 个 episode 全军覆没，judge 却放过了 40–58%。另外只有 150 个合成任务（其中 50 个是 8 个父任务的近似变体），单次训练，Kimi-K3 只跑了 2 个 seed，也没有同 backbone 的 SecAlign 式固定 injection baseline。"需要会变的攻击者"这个核心主张实际上没有被检验。好在自我审计异常诚实，上面这些负面信号都是作者自己报出来的。
- **Rating**: `2` 👀 ，success-flip 反事实奖励值得借用；但 robustness 结论完全困在 world model + judge 内部，主张远大于证据。

### WebFovea
- **Title**: WebFovea: When the Model Is Right but the Click Is Wrong -- Reliable Round Trips for Vision-Based Web Agents on Live Websites
- **Institutes**: Independent Researcher
- **Source**: [link](https://arxiv.org/abs/2610.03036)  📰 HF Daily ⬆️ 13   **📒 论文笔记**: [[2610-WebFovea]]
- **核心**: 这是 WebRetriever Challenge 2026 第 2 名（hidden set 57.0/100）的单作者技术报告。全程固定 claude-opus-4-6，只改 harness，四次提交把分数从 31.0 拉到 57.0。作者把每一步拆成 parsing → execution → feedback → observation 四段 round trip，逐段排查静默失败。最典型的是坐标 bug：API 在模型看到截图前就把 1920×1080 降采样到约 1440×810，参考实现却按恒等映射处理，结果每次点击都落在目标坐标的 3/4 处。修好之后，24 个 dev task 的成功数从 8 升到 20。
- **锐评**: 最值钱的是那个坐标 bug：参考实现 + 同一模型在 10 任务子集上 0 解，整套参考实现基本是废的。这对所有拿 closed API 做 GUI grounding 评测的工作都是警告：坐标系需要显式标定，不能默认正确。负结果写得也诚实。feedback note 送到了，模型在 thought 里也承认了，10 个 idle-looping 任务照样 0/10、步数照样 400；`read_text` 用了 5 次，一个任务也没修好。"预算要在 executor 里强制，不能写进 prompt"这个结论比任何正面数字都硬。但它作为研究，证据很薄。31→57 是四次捆绑改动、每次只跑一次，live site 还有 run-to-run variance，没有任何 per-component ablation。31.0 的起点已经包含了坐标修复等关键补丁，所以"harness 到底贡献了多少"没有干净的零点。组件级证据全部来自 1–24 个任务的定向小集合，8/24→20/24 也是版本级比较，混着别的改动，baseline 还能走 `goto` 捷径。坐标降采样和 chat-template token 泄漏这类修复是模型/API 特异的，能迁移的只有"按 stage 排查"的方法论。没有可学习组件，本质上是一份高质量的工程 debug 报告。
- **Rating**: `2` 👀 ，坐标对齐和 live-site 参考答案漂移（13/100）这两个发现值得记进评测可信度的 checklist，但它是一份 debug 报告，不是可以 follow 的方法。

### ReSAIL
- **Title**: ReSAIL: Mitigating Collapse in Iterative Agent Self-Distillation
- **Institutes**: Gaoling School of Artificial Intelligence, Renmin University of China
- **Source**: [link](https://arxiv.org/abs/2609.39306)  📰 HF Daily ⬆️ 26   **📒 论文笔记**: [[2609-ReSAIL]]
- **核心**: 在 OEL/SDPO 这种"部署 → 抽经验摘要当 privileged information (PI) → 自蒸馏 → 学生当下一轮老师"的循环里，作者发现带 PI 的成功率也会逐轮下降：只训练 ordinary view 会顺带改坏共享参数下的 privileged view。ReSAIL 做两件事。一是只蒸馏 PI 敏感度（两视角 JSD）最高的 top-ρ step，并按轨迹均衡 loss。二是加一项 KL，把学生的 privileged view 拉回冻结 teacher（PR）。ALFWorld/TextCraft × Qwen3-4B/8B 三轮后，Cycle 3 平均比本体高 22.5 个百分点，6 个设定三轮都不掉。
- **锐评**: 把"老师退化"从猜测变成可测量的量，是本文最有价值的地方。固定 PI 测 PI-conditioned 成功率：不加 PR 时从 61.5 掉到 44.8，加 PR 时从 58.9 升到 70.3。Top/Random/Bottom 同 ρ 对照（62.2/49.7/40.1）也排除了"只是稀疏化"。但 22.5 点的分母是已经塌掉的基线。4B TextCraft 上 OEL+ReSAIL 只比没训练过的 ReAct 高约 2.7 点，"防塌"成立，"自我改进"谈不上。
  - SD 只反映 decoding 方差。"主结果是单训练 seed"笔记里只标为推断，但全文确实没有报告任何训练 seed 方差。三轮复合过程下的"非递减"趋势因此偏弱，SDPO 4B OOD 的"崩塌"只是 44.8→44.3，在噪声以内。
  - 最关键的一刀：ordinary-view retention（72.9/65.9）和 PR（74.2/67.2）在部署指标上差距落在 SD 内。privileged 视角的必要性只靠作者自定义的代理指标撑着，增益很可能大部分来自"随便哪种锚定冻结 teacher 的 KL"。
  - ρ/λ 直接在评测集上 sweep，两个 benchmark 各用一套超参。
  - AITZ 的 +1.06 是单 seed、843 步、只用了 SGS 当静态过滤，不能拿来说明适用于 GUI agent。
  - 所有消融只做了 OEL × 4B × ALFWorld，没有代码。
  - 横向看：R-Quest 说 collapse 来自训练分布被污染，ReSAIL 说来自监督源（老师）被优化目标顺带改坏，两者是互补的两个失败通道，都在权重层；RRSI 的 collapse 在搜索层。
- **Rating**: `2` 👀，"老师是需要显式维护的状态变量"这个诊断值得记住，但证据只覆盖三轮、单一消融设定，privileged view 的必要性还没在部署指标上得到证明。

### Long-WAM
- **Title**: Long-WAM: Scaling the Context of World-Action Models
- **Institutes**: NVIDIA, MIT, HKU, UCSD
- **Source**: [link](https://arxiv.org/abs/2610.10528)  📰 HF Daily ⬆️ 67   **📒 论文笔记**: [[2610-LongWAM]]
- **核心**: 论文研究 world-action model 的视觉历史拉长后，控制能力会不会跟着变好。做法分两步：先用约 10,000 window-equivalent 小时的 robot/egocentric 视频做 action-free 的 autoregressive 视频预训练（LongLive2.0-Robot），再接一个 action expert。这个 expert 走 IDM 模式：先把未来 latent 部分去噪到 σ★=0.9，再以它为条件去噪 action。RoboCasa GR-1 上，context 从 0.0 s 拉到 19.2 s，AR 初始化的成功率从 63.3% 升到 78.7%；Wan2.2 bidirectional 初始化走 61.7→64.1→61.6，最后回到起点。工程上有纯异步执行、streaming VAE 和 NVFP4，2.4 s context 下 RTX 5090 每个 chunk 107.4 ms。Unitree G1 传送带抓杯在 7.5 cm/s 下还有 90%，同条件下 Fast-WAM 和 π0.5 都是 0%。
- **锐评**: 全文最值钱的是 GR-1 上那组三条曲线：同一套 causal 适配下，bidirectional 初始化给了更长历史也不涨分，AR 初始化一路上升。它把"能看到历史"和"会用历史"分开了，直接质疑 DreamZero 那种"bidirectional video DiT 改 mask 就当 WAM"的路线。毛病同样明显。
  (1) **混杂没拆开**：Wan2.2 和 LongLive 不只是训练目标不同，模型、数据、训练序列长度（16–30 s）都不一样。"AR 目标本身"和"长序列训练经验"在这组对照里分不开，标题级结论其实只是相关性。
  (2) **单点结论**：长窗口扫描只在 GR-1 上做了。LIBERO-Long 在 2.4 s 就饱和到 99.5%，帮不上忙。GR-1 每个点跑了多少 trial、方差多大，正文都没给。
  (3) **头条数字不在同一个工作点**：78.7% 要 19.2 s context，这时延迟是 341.0 ms；107.4 ms 对应的是 2.4 s。摘要把两个数并排放，读者容易以为长 context 和实时同时做到了，其实没有。
  (4) **真机证据缺位**：LIBERO、RoboTwin、DOMINO 的主结果最多只用 2.4 s context。真机实验没有 context-length ablation，作者自己在 Appendix A 把它列为 next step。所以"长 context 在真机上有用"目前**没有证据**。G1 的漂亮数字证明的是异步加未来预测这套系统好用，跟"Long"无关。
  (5) **饱和区刷分**：RoboTwin 2.0 的 94.4 只比 ABot-M0.5 高 0.3、比 LingBot-VA 2.0 高 0.8，在噪声量级。
  (6) **归因是推测**：异步下只掉 0.2 点（Fast-WAM 掉 15.4），作者归因于连续未来预测带来的 chunk 一致性，但没报 w/o V 在异步下的对照，这个机制还是推测。38.4 s 时成功率回落到 75.2%，作者说是历史覆盖不足（80.4% 的帧是 padding），这同样只是 hypothesis，没有验证。
  (7) **数字有内部矛盾**：Table 4 把 63.3% 标成 2.4 s，正文写 CoD 97.8%，Table 1 却是 95.8%。跟基线比较时以 Figure 6 为准。
  值得肯定的是，作者主动交代了 window-equivalent hours 的口径、训练和推理时未来 latent 分布不一致这些限制，诚实度在线。
- **Rating**: `2` 👀，问题提得对、代码开源，"预训练目标决定历史可用性"值得关注。但核心结论只在 GR-1 一个 benchmark 上成立，混杂没拆，真机上长 context 的收益也没证据，还撑不起 must-follow。

### Infinite-Dreamer
- **Title**: Imagine to Act: High-Fidelity Data Synthesis via Image Editing World Model for Scalable GUI Agent Training
- **Institutes**: Jilin University; OPPO
- **Source**: [link](https://arxiv.org/abs/2610.05861)  📄 arXiv   **📒 论文笔记**: [[2610-InfiniteDreamer]]
- **核心**: 把 GUI 状态转移改写成 image editing。先用 VLM 把真实转移抽成结构化的 delta-text（新增/消失了哪些元素、下一步能做什么），再在 AndroidControl 上对 FLUX.2-Klein 做 LoRA 微调，得到一个像素级 GUI world model。用它合成两类数据：单帧外观增强，以及由 LLM App Designer 驱动的多步想象轨迹。只用合成数据 SFT 的 Qwen3-VL，在 AndroidWorld 上比 zero-shot 提升 +4.45（8B）到 +9.20（4B）Pass@1，MobileWorld 8B 约翻倍（8.77→15.20）。
- **锐评**: 有一个有信息量的数字：去掉 delta-text、只给 trigger action，单步 Acc 从 68.13 掉到 21.56。这说明编辑模型自己几乎不懂 GUI 的因果逻辑，"world model"的语义全靠 VLM 写好的 diff 撑着，它更接近一个条件渲染器，这个名字有包装成分。主表的比较对象是 zero-shot 基座，增益里混着动作空间和 prompt 格式的适配。而且 world model 本身就是在 AndroidControl 真实数据上训出来的，却偏偏没给"直接拿 AndroidControl 真实轨迹做 SFT"这个最该有的对照。同一组 4B ablation 里，纯合成 39.37 输给纯真实 OpenMobile 的 42.67。离线 AC-Curated 的 grounding 普遍倒退（4B Hard 的 Box Acc 77.00→64.70，Step SR 57.10→44.20），Hard 任务上混合数据也比纯真实低 2.7。标题里的 "scalable" 也站不住：10 步 rollout 的累计存活率只有 9.3%，9B 生成一张图要 57 秒，合成数据的总规模压根没报。长程合成基本不可用，这和"扩展到复杂多步工作流"的动机直接矛盾。评测还有自评问题：GLM-4.7v 既写 delta-text 又给 Table 2 打分，没有 pixel 指标也没有人工评估。全部结果单 seed，Hard 子集只有 19 个任务、每任务 1 个 episode。真正有用的是最便宜的单帧外观增强（在真实数据上 +4.74），但这本质上是数据增强，不是"想象"。
- **Rating**: `1` 💤 ，像素级 GUI world model 这条线有意义，但这篇的主张（合成数据可以撑起 agent 训练）被它自己的 ablation 否定了：最有效的部分只是外观增强，而长程想象实际不可用。

### Raven
- **Title**: Raven: The Harness of Harnesses for Composable Agentic Intelligence
- **Institutes**: EverMind AI
- **Source**: [link](https://arxiv.org/abs/2609.33439)  🔥 HF Trending ⬆️ 568   **📒 论文笔记**: [[2609-Raven]]
- **核心**: 把"model + harness"当作可组合单元。Host Agent 把用户目标拆成带类型契约的 DAG，派给自研 specialist 和通过 ACP 接入的 Claude Code、Codex 等第三方 agent，再配上 HarnessBank 自演化、EverOS 记忆和 Skill Forge。理论部分只给组合可靠覆盖的充分条件。在自建的 MAOB 规划 benchmark 上，Exact Match 比 Claude Code / Hermes 高约 10.5 pp；各 specialist 在 DeepResearch、SWE-Refactor、PresentBench 等上领先。
- **锐评**: 568 个赞买的是品牌和体量，不是证据。
  - 标题里的 "composable intelligence" 没有任何端到端验证。论文没有一个实验比较"多 agent 组合 vs 单 agent 在同一任务上的成功率"。MAOB 只比规划图和参考图的一致度，而且是自建的：参考图由 Opus 5 写，请求文本由 GLM-5.2 从图反向生成，平均只有 2.72 个节点。Raven 有专门的 orchestration guide 和 graph schema，baseline 只能用各自原生的 delegation 接口。10 pp 里有多少是 prompt/schema 和 benchmark 构造口径对齐，完全不知道。
  - 自演化和 skill 复用两块是直接复述 HarnessBank、SkillCorpus 的旧结果，不是在 Raven 集成系统上新跑的。HarnessBank 的 SWE-bench Verified 本身就没过判据。
  - DeepResearch 的 3.3–7.6 pp 领先，附录自己承认同一批题在开发 research flow 时用过，也没屏蔽 benchmark 的公开副本。这是 dev/test 重叠，应当打折看。
  - Design 只领先 0.3–2.8 分，用的是内部 grader；AI4AI 每个系统只跑一个 campaign；AI4S 是内部 17 题、人工判定。
  - completion judge 失败或超时时，正常返回的调用直接算完成，和理论里"自称完成不等于正确"自相矛盾。
  - 没有任何组件去掉后的增益归因。
  - 能抄的只有工程细节：handoff 走落盘 artifact、DAG 派发前过 admission check。理论写得克制，但实验没有检验它。横向看，同一批论文都在拆解 collapse，Raven 对演化失败模式一个字没提。
- **Rating**: `1` 💤，这是一份公司技术报告，核心主张没有端到端证据，两块关键结果是旧论文的数字。

### Trinity
- **Title**: Trinity: Self-Evolving Vision-Language Models with a Self-Verifier
- **Institutes**: Electronics and Telecommunications Research Institute (ETRI), KAIST, DeepAuto.ai
- **Source**: [link](https://arxiv.org/abs/2610.04469)  📄 arXiv   **📒 论文笔记**: [[2610-Trinity]]
- **核心**: 在 Questioner–Solver 式 self-evolving VLM 里加入第三个角色 Verifier，它是 policy 的 EMA 副本（α=0.999）。Verifier 负责三件事：检查问题是否 grounded、参考答案是否正确；按图像给 Solver 的推理打分；当 Solver 强共识和参考答案冲突时裁决。目的是替代纯 agreement 奖励。Qwen3-VL-8B 只用 Vero-600K 的图像训练，MathVerse +12.8，MMMU +12.6；Qwen2.5-VL-7B 只涨 +1 到 +1.5。
- **锐评**: 问题提得对：agreement 奖励看不出 ungrounded 问题，也看不出错误的参考答案，这和 R-Quest 的 invalid 题诊断是同一件事。数值 hard-mismatch guard、推理分只在答对时计入这些细节，说明作者有防 reward hacking 的意识。但证据撑不起标题。
  - 核心 claim 是"self-verifier 让自进化更可靠"，全文却没有一个 Verifier 消融：没有去掉 QA gate，没有去掉争议裁决，没有把 EMA 换成当前 policy。唯一的消融是换数据集。
  - 8B 的 +12 分混杂严重：起点做过 300 条带参考答案和 Thinking 推理的 SFT warm-up；Trinity 用温度 1.0，base 用 0.7；附录承认 base 在开放题上经常无法在预算内终止，而训练修好了这一点。DPE 在 MMMU 上也从 57.0 涨到 69.1，说明 MMMU 的涨幅大概率是格式和终止行为修复，不是 Verifier 的功劳（推测，原文没有拆解）。
  - 7B 只有 +1 左右，恰好暴露了上限：Verifier 就是 backbone 自己，Solver 读错图，Verifier 也会读错。
  - 训练曲线上 R_fact 0.27→0.57、R_reason 0.76→0.93，和 rubber-stamp（Verifier 越来越宽松）的曲线长得一模一样。作者自己承认分不开，这正是 CodeSelfReviewCollapse 警告过的失败模式。
  - 科学 benchmark 只跑一次，却声称"statistically indistinguishable"，没有给检验。
  - 横向看：同一个诊断，R-Quest 用外部标注做锚，有消融，有 10 轮长程；Trinity 用纯 endogenous 自评，只训 300 步，没有消融，只是推迟了偏差累积，没有引入真值。
- **Rating**: `1` 💤，问题陈述有价值，但核心组件没有消融，主增益和 SFT warm-up、解码设置、终止行为修复混在一起，归因无从谈起。
