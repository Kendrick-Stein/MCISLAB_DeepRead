## 论文点评

### SimpleMemVLA
- **Title**: SimpleMemVLA: A Simple but Effective Native-Video Memory for Vision-Language-Action Models
- **Institutes**: Huazhong University of Science and Technology, Zhongguancun Academy, Tsinghua University, Modelbest, Peking University, Renmin University of China, Beijing Academy of Artificial Intelligence
- **Source**: [link](https://arxiv.org/abs/2609.05533)  📄 arXiv   **📒 论文笔记**: [[2609-SimpleMemVLA]]
- **核心**: 不加任何 memory 模块。最近 T_w 秒的 head-camera 帧以 Qwen3.5-4B 原生的带 plaintext 时间戳视频格式直接放进 context，backbone 先生成一句 sub-task，flow-matching action head 只读这段 sub-task 的 hidden states 和 token embedding，所以历史信息只能经这个窄通道传到动作。动作执行期间预填共享历史前缀，60 s 历史下决策延迟从 1.02 s 降到 0.68 s，单帧基线约 0.65 s。四个 memory benchmark 都领先：RMBench 94.0%（+11.0）、RoboMME 88.3%（+43.7）、MIKASA-Robo 74.0%（+29.6）、RoboMemArena TSR 63.6%（+17.4）；LIBERO 97.5%，和最好的已报告结果持平。作者的核心论点是：现有 VLA memory 卡在 "write-time commitment"（需求还不知道就先决定存什么），而不是写入质量。
- **锐评**:
  - 最有价值的是机制实验，不是 SOTA。遮掉一次 pick-and-place，推断计数正好减一（"fourth time" 变成 "third time"），并多抓一次；换成另一条 rollout 的视频，目标跟着换。替换 hidden states 会改变目标，替换 token embedding 基本不变。这几组实验说明 policy 确实在读历史里的具体证据，而且控制信号走的是 contextual hidden state，不是可见文字。时间戳置零只伤计数任务 press-button，打乱帧序两个任务都失败。消融和预测对得上，这部分做得干净。
  - 同栈对照有稻草人嫌疑，正好是全文因果论点的支柱。RoboMME 上 88.3 对 31.5 / 22.6 / 20.6 看着吓人，但所谓 retrieval 是 8 帧均匀采样，还丢掉了顺序和时间戳，根本没有 query；compression 只有 64 token；recurrent 只有 16 token、4 步截断反传。作者自己的消融已经证明顺序、时间戳、旧帧是关键，三个变体却各删掉一项，这个差距有相当部分是构造出来的。C12 原文用的是 "suggesting"，属于归因推断。要证明 "write-time commitment 本身是瓶颈"，至少要补一个保留顺序和时间戳、带 query 的 retrieval，或者预算接近 5.6k token 的压缩变体。
  - Oracle 论证跨了 backbone。GroundSG 拿 ground-truth VLM 输出得到 84.1%，比 88.3% 低，作者据此说"oracle 写入的上限还不如原始流"。但 GroundSG 跑在 benchmark 方的 π0.5 栈上，本文是 Qwen3.5-4B 加 sub-task 监督，两者不是同条件比较。RoboMME 的 +43.7 同样把 backbone 差异算进去了；RMBench 的 baseline 大多是 per-task specialist，混了已发表数字和不同 seed 数。
  - "No memory module" 的说法有一半是措辞。Qwen3.5-4B 的 32 层里有 24 层是 linear attention，本身就是循环状态。SWA 变体从 94.0 掉到 91.0，Obs&PU 从 65 掉到 56，Battery 从 90 掉到 71，说明窗口外的东西一旦只能靠 linear-attention 状态保留，就开始丢。换成 Qwen2.5-VL 这类纯 softmax backbone 还灵不灵，文中没有测。
  - 窗口长度是按 benchmark 调的：MIKASA 3 s，RoboMemArena 126 s。在 cover-blocks 上换 15 s 窗口直接失败。这等于用任务先验定了 memory 预算，"无需决定保留什么" 的卖点在开放部署里打了折扣：write-time commitment 被换成了 window-size commitment。
  - 自己报出来的弱项要看：RoboMemArena Transferring 类 TSR 35.8，FrameSamp+Modul 是 63.8，CSR 37.4 甚至低于 π0.5 的 42.8；LIBERO-Plus Language 维度 68.6，MemoryVLA++ 是 88.7；RC-3 上 71% 不如非 VLA 的 GMP（80%）。真机只有 2 个任务（58.3% / 70.0%），没有任何 baseline，只能说明能跑。"Visual in-context learning" 这个提法有拔高之嫌：实验展示的是 policy 服从训练分布内类型的证据（位置、颜色、首步动作），并没有从示范里学到新行为。sub-task 是 history 到 action 的唯一通道，却依赖离线 cloud VLM 标注，标注粒度的影响没有消融。
  - 和已有工作的区别：LaMem-VLA 这类 learned compression 和本文在 LIBERO 上都停在约 97.5%，分不出高下，真正的分水岭在 RoboMME/RMBench。和 MEM 的张力也值得记下：MEM 里拼接的文本 sub-task 历史不如压缩摘要，本文里原始视频历史远胜压缩，差别很可能在存的是文本还是原始视觉证据。
- **Rating**: `3` 🔥，因果理论没证实，但"把原始历史视频直接交给长 context backbone，再加 sub-task 窄通道"在四个 memory benchmark 上全面领先，干预实验也扎实，以后 VLA memory 论文不和这个 native-context baseline 对比就站不住。

### FOCAL-VLA
- **Title**: FOCAL-VLA: Subtask-Guided Geometry Distillation and Implicit World Modeling for Vision-Language-Action Models
- **Institutes**: University of Bremen, Karlsruhe Institute of Technology (KIT), Robotics Institute Germany (RIG)
- **Source**: [link](https://arxiv.org/abs/2609.21228)  📄 arXiv   **📒 论文笔记**: [[2609-FOCAL-VLA]]
- **核心**: 在 π0.5 上加两组各 8 个 learnable query。一组回归 frozen VGGT 的几何特征，一组回归 frozen Track4World 的 future-informed 运动特征。两路 teacher 特征都只在当前 subtask 涉及实体的 mask 内 pooling，query 输出直接作为 action expert 的额外条件，推理时不跑任何 teacher。结果是 LIBERO 平均 97.9（π0.5 为 96.9），RoboCasa Atomic-24 Human-50 为 63.4（同设置复跑的 π0.5 为 55.2），4 个真机任务总成功率 47.5 → 63.8。
- **锐评**:
  - 真正站得住的发现不是标题里的 "subtask-guided"，而是"实体 mask 比全图好"。Table IV 里 full-image 58.7 → task 级实体 61.9（+3.2pp）→ subtask 级 63.4（+1.5pp）。1200 次 rollout、成功率 63% 左右时二项 SE 约 1.4pp，subtask 粒度的增益只有大约 1 个 SE，而且论文没有报告多 seed 结果或误差条。主打卖点恰好是证据最弱的一环。
  - 值得抄的设计是 supervision-only 对照：latent 只当辅助 loss、不接 action expert 时是 58.5，接上之后是 63.4。这一行把"蒸馏改善表征"和"蒸馏结果直接当 action 条件"拆开了，说明增益主要来自后者。这个结论比 mask 粒度更有用。
  - 缺一个关键对照：π0.5 + 语义 subtask loss + 16 个 query token，但不加任何蒸馏。w/o geometry（60.0）和 w/o motion（59.6）都还保留着语义 loss 和另一路 query，所以从 55.2 到约 60 这 4-5pp 里，有多少只是来自 subtask 文本监督和多出来的 token，论文没有拆。
  - full-image 版本（58.7）比两个单分支变体都低，说明全图 pooling 不只是没帮助，很可能有害。论文的动机是"无关区域分散注意力"，但这次退化没有任何注意力或表征层面的测量。把 2048 维 patch 特征均值压成一个场景向量本身就会让信息退化，这个更朴素的解释没被排除。
  - "Implicit world modeling" 名不副实：实际只是用 Smooth L1 回归一个 256 维的 pooled 特征，不 rollout，不能查询，也没有对未来 3D track 做 probe 来证明 Z_m 编码了运动。和 [[2606-HiFVLA]] 一样，foresight 是假设出来的，没有被测出来。
  - 和 GeoPredict、3DThinkVLA、Spatial Forcing 相比，本质区别只有两点：监督范围收窄到实体，蒸馏 latent 直接进 action expert。在 RoboCasa 上它只比推理时需要 3D 输入的 Robot-Centric Pointmap（62.9）高 0.5pp，这个优势体现在部署成本上，算不上性能领先。
  - LIBERO 表基本没有信息量。除 FOCAL-VLA 外的数字都取自各自原文，GR00T N1.7 用的还是 LeRobot 的初步评测。在饱和的 benchmark 上 97.9 对 97.0/97.1 排不出先后，而且 Long 输给 Track4Action（95.0 vs 95.8），Goal 输给 π0.5（97.8 vs 98.0）。
  - 真机部分每任务 20 次、单相机、baseline 只有 π0.5。Drawer opening 70 → 80、Microwave 75 → 85 都只差 2 次成功，只有 Two-fruit 25 → 50 和 Drawer storage 20 → 40 的幅度称得上信号。
  - 训练依赖特权标注：人工写的 subtask 描述、Qwen3-VL-8B 对齐，再加 simulator mask（真机用 Grounded-SAM-2）。仿真里的 mask 近乎完美，标注噪声的影响完全没有量化，擦桌这类实体不明确的任务也套不上。正文未见代码链接。
- **Rating**: `2` 👀，"实体 mask 加直接 conditioning"这两个设计便宜、可迁移，supervision-only 对照也有借鉴价值；但标题主打的 subtask 粒度只领先 1.5pp、在噪声范围内，缺"只加 query 和语义 loss"的对照，world modeling 也没有 probe 验证，撑不起 Foundation。

### DiVeR
- **Title**: DiVeR: Decision-Critical Verifier Learning for VLA Test-Time Scaling
- **Institutes**: Microsoft Research Asia–Tokyo（据致谢推断，仅为第一作者实习单位；HTML 无作者机构块）
- **Source**: [link](https://arxiv.org/abs/2610.04933)  📄 arXiv   **📒 论文笔记**: [[2610-DiVeR]]
- **核心**: 场景是 VLA 的 Best-of-N 选动作：从 frozen policy 采样 N 个 action chunk，由一个轻量 verifier 打分后执行最高分者。已有的 SVM 式 success-visitation verifier 把轨迹级成败标签平均分给每个状态。DiVeR 的做法是在每个训练状态上额外采样 K=32 个候选，计算它们 action-expert 表征的方差 u_t，在轨迹内做 z-score 后用 exp 加权并 clip，再用加权 BCE 训练一个约 66K 参数的 MLP，让监督集中在候选分歧大的状态（pre-grasp、pre-placement）。RoboCasa N=16 下，π0 / π0.5 平均成功率从 32.2 / 43.1 提到 38.1 / 54.7，比同表征、不加权的 Uniform 版本分别高 3.2 / 4.1。真机 Franka 四个任务上 Base / Uniform / Ours 平均为 58.3 / 65.6 / 71.9。
- **锐评**:
  - 好的地方是方法小而准。Table 4 把增益拆成两部分：换表征（Uniform 对 SVM，+1.0 / +3.7）和加权（+3.2 / +4.1），所有方法共用同一组候选，所以差异只可能来自 selection rule。这种归因在 test-time scaling 论文里少见。Table 5 也显示只用表征就够了，加图像特征没有收益（38.1 对 37.4），说明信号确实来自 policy 内部。
  - 硬伤是加权有效的干净证据只来自一个 benchmark，而且这个 benchmark 就是调参用的那个。超参在 RoboCasa π0.5 上调定（C17），这一格恰好是全文增益最大的（+11.6），论文没说调参用的是训练 episode 还是评测 episode。LIBERO 上没有报告 Uniform 对照；π0.5 在 LIBERO 已到天花板（97.5 对 SVM 97.0）；OpenVLA 上也只比 SVM 高 0.5（55.5 对 55.0）。离开 RoboCasa，"加权"本身的贡献基本看不出来。
  - 核心代理只是中等可靠。u_t 与 simulator branching 算出的 oracle criticality 之间 Spearman ρ=0.493。方差大可能只是因为有两种同样可行的抓法，"候选分歧"不等于"选错代价高"。而且轨迹内 z-score 的设计保证每条轨迹都会有一段被当作 critical，即使整条轨迹都很 routine。作者做了这个验证值得肯定，但这个数字撑不起"decision-critical"这个命名。
  - 真机统计力不足。每任务 24 个 episode，一个 episode 就是 4.2 个点，Ours 对 Uniform 的单任务差距多数只相当于 1-2 个 episode，Table 3 没有标准差。"四个任务都最高"听起来稳，实际上和噪声差不多大。
  - "比 RoboMeter 快 700 倍"是凑出来的对比。RoboMeter 的候选视觉轨迹靠 simulator branching 获得（C15），真机上根本跑不了；而且端到端瓶颈在采样（N=16 时 205-360 ms），verifier 0.743 s 和 0.001 s 的差距，同采样延迟一比工程意义有限。另一边，离线成本被略过了：RoboCasa π0 训练集约 28.6 万步，每步再采 32 个候选，就是上千万次 action 采样，论文一个时间数字都没报。
  - 和已有工作的本质区别：KDPE、CycleVLA 一类 mode-seeking 方法在候选分歧时投向共识，DiVeR 的主张正好相反，认为分歧大的状态才最需要按 outcome 来挑。这个立场比方法本身更值得记住，和 DelTA 在 RLVR 里按 token 重加权是同一类对"轨迹标签均匀摊到每一步"的修正。前提是白盒 policy，能多次采样并暴露 action-expert 表征；候选全错时无能为力；只在单臂桌面操作上验证过。
- **Rating**: `2` 👀 ，"按 policy 自身采样分歧给 verifier 训练样本重加权"是一个便宜、可直接借用的设计，Table 4 的归因也干净，但加权增益只在调参所用的 RoboCasa 上站得住，代理相关只有 0.49，真机每任务 24 个 episode，还不足以改变做 VLA test-time scaling 的方式。

### S2VOPD
- **Title**: Self-Supervised Visual On-Policy Distillation
- **Institutes**: UC San Diego, University of Maryland, College Park, Georgia Institute of Technology, Johns Hopkins University, University of Oxford, Independent Researcher
- **Source**: [link](https://arxiv.org/abs/2608.14144)  📄 arXiv   **📒 论文笔记**: [[2608-S2VOPD]]
- **核心**: On-policy self-distillation 需要 teacher 和 student 之间有信息差。以往做法是给 teacher 额外信息，比如 GT ROI 或参考答案。S2VOPD 反过来，把 student 的输入变差：student 在下采样到 0.3–0.6× 的图上 rollout，并以 0.5 概率加噪声；EMA teacher 在原图上给同一前缀打分，用 top-k JSD 做蒸馏。整个流程不需要标注、reward，也不需要更强的 teacher。Qwen3.5-4B 在 FineVision-12K 上训练后，6 项感知均分从 70.68 升到 77.44，和 Qwen3.5-397B 持平。在 Vision-OPD-6K 同数据对比中，4B 九项均分 75.33，高于 Vision-OPD 的 74.77。
- **锐评**:
  - 最有信息量的是诊断，不是主表。对称自蒸馏（T=identity）从 70.58 掉到 65.21；冻结 teacher 只比默认低 0.40（75.95 vs 76.35）。两条合起来说明信号几乎全部来自视图不对称，teacher 自身变强的贡献很小。crop 实验也有价值：强度越大 gap 越大，分数却从 71.53 单调降到 67.44，说明 gap 大不代表有用，student 的输入一旦变得无解，差异就只是噪声。
  - 感知 benchmark 和增强方式高度同构。V*、HR-Bench 4K/8K、ZoomBench、MME-RealWorld 都是高分辨率找小目标，训练恰好是"低分辨率学、全分辨率考"。+6.76 有多少是通用感知提升、有多少只是 resolution robustness，论文没法区分。OCR、chart、document、GUI 截图这些文字密集任务一个都没测，而降采样最可能在这类任务上删掉答题证据。按作者自己的 task-consistency 原则，这里很可能失效。
  - 标题级 claim 撑不住。"恢复 96% privileged 增益"只出现在 abstract，正文没有计算，也没说明用哪个尺度、哪个分母；按 Table 3 换个口径能算出 96%、112.5% 或 94.2%。9B 上 S2VOPD 总均分 76.35，低于 Vision-OPD 的 76.56，"超过 privileged 方法"只在 4B 成立。
  - 统计强度不足。全文没有多 seed，也没报方差。Table 4 默认配置 76.35 和 Table 6 同配置 JSD 的 76.05 差了 0.30，和"去掉 EMA 只差 0.40"、"JSD 比 reverse KL 高 0.56"是同一量级，所以这些消融结论基本落在噪声带里。对称自蒸馏在 §4.3 的 2,048-token 协议下是 65.21，在 Table 4 里却是 70.52（≈ base），前后不一致；"放大 confident errors"的解释也没有直接证据。
  - 基线比较不对等。self-rewarding RL 基线取 13 个 checkpoint 里最好的，S2VOPD 报最后一个。这个设置对 S2VOPD 不利，所以 4B 上 +2.0 的优势反而更可信；但 9B 上只有 +0.7，又没有方差，分不出胜负。
  - 方法的上限受 base 模型在原图上的能力约束，本质是把全分辨率能力迁移到低分辨率；base 模型在原图上就看错的样本，只会被推向同样的错误。数学提升 +3.7/+3.2 的机制完全没解释。附带的发现倒更扎实：privileged 感知蒸馏会伤数学推理，ZwZ-4B 的 MathVerse 从 67.56 掉到 40.48，对 Vision-OPD/ZwZ 一类方法是实打实的警告。
- **Rating**: `2` 👀，"从 student 减信息"的构造简单可迁移，对称自蒸馏和 crop 两条诊断值得借鉴；但评测集几乎只考增强所针对的能力，没有 seed 方差，9B 不占优，96% 这个数也没有出处，还够不上 Foundation。

### SkillZipGraph
- **Title**: SkillZip: Contract-Preserving Graph Compression for Scalable Agent Skill Libraries
- **Institutes**: UNSW, CSIRO
- **Source**: [link](https://arxiv.org/abs/2608.05604)  📄 arXiv   **📒 论文笔记**: [[2608-SkillZipGraph]]
- **核心**: 这篇论文认为，现有 skill provider 在检索、压缩、执行三个阶段用的是三种不同单元：检索按整包 package，压缩按文本，执行图要到检索之后才临时搭。它把三个阶段统一到带 procedural contract 的 section 节点上（9 种 execution role）。MotifZip 在 section 图上找跨 skill 重复出现的子图（motif），只有 interface、dependency closure、verifier reachability 都保得住，才把它改写成可逆 macro。PathHydrate 在 token 预算内取一个依赖闭合的子图，macro 按需从 name 逐级展开到 contract、outline、full source。ReZip 用新加入的 skill 和执行 trace 增量维护 macro。结果：SkillsBench（87 tasks，1K skills）和 ALFWorld（140 episodes）上，比 SkillDAG 高 2.8 到 12.2 点；CR 3.46×，DPR 99.2，VR 98.7，平均交付 1,941 tokens。
- **锐评**:
  - 标题主打 "Graph Compression"，但按 Table 3，涨分主要来自 section 级拆分。把节点换回 skill 级，reward 掉 5.4（33.3 到 27.9），Ret@1 掉 6.9。去掉 MotifZip 只掉 2.3（到 31.0），和 raw section graph 的 31.0 一样，而且这项消融没给 CI。87 个 task 上，2.3 点大约就是两个 task。所以压缩更像存储和 context 上的收益（Tok 2,967 降到 1,941，active storage 降 71%），不是任务能力上的收益。论文没做"固定 Tok 预算，只做 section 检索、不压缩"的对照，这一点就测不出来。
  - 最站得住的证据在对照实验里。用 LLMLingua-2 式文本压缩对齐到同一 CR 后，DPR 65.0，VR 60.0，45% 的查询要恢复原文，reward 25.5。"w/o checks" 只多压到 3.78×、多省 0.5 MB，DI 却从 2.7% 涨到 23.4%，fallback 从 7.2% 涨到 24.7%。"压缩要保 contract，不能只保文本"这个论点被数字直接支撑，是全文最值得借鉴的设计。不过笔记作者注意到，文本压缩 baseline 恢复原文后测出的 Tok 和 SkillZip 完全一样，按理恢复应该会抬高 token。这一点没进 Ledger，只算存疑。
  - Baseline 偏弱。MiniMax-M2.7 SkillsBench 上 Vector Skills 只有 10.4，比把全部 skill 直接暴露的 Vanilla Skills（17.2）还低。跨 6 个 backbone 报的 19.9 到 26.2 点提升，比的正是这个最弱的 baseline，水分很大。SkillZip 检索前先用 backbone LLM 把 query 解析成结构化 task object，等于比 embedding baseline 多了一步 LLM 处理。GoS / SkillDAG 沿用各自的公开设置，没有统一 token 预算。
  - "Scalable" 的证据基本靠合成数据。10K 和 100K 库是作者沿 Graph-of-Skills 的嵌套池做法自己扩出来的，新增 package 只当 distractor，不配评测 query。100K 下 Ret@1 65.1 vs SkillDAG 41.8，衡量的是抗干扰能力，不是在真实大库上的可用性。178 s 的构图时间不含 LLM contract 抽取，而对 100K skills 做 role/contract 抽取恰恰是部署成本最大的一块，正文没报。ALFWorld 库只有 37 个 skill，CR 1.62×，拿来证明规模几乎没有说服力。
  - 方法很依赖 LLM 抽取的 contract。抽取 macro-F1 91.6，precondition/guard exact match 只有 79.6；40% 字段污染时 reward 掉到 24.1，已经低于 SkillDAG 的 27.3。凡是没有显式 Verifier / Precondition 写法的 skill，verifier reachability 约束会变成空约束，这条边界论文没量化。未见代码链接（C25），复现门槛高。
  - 和 vault 里同名工作的区别：[[2608-SkillZip]]（2608.11079）和续作 [[2608-SkillZipPro]]（2608.30785）是另一个团队的工作，压缩的是单个自进化 skill 文档或单个 bundle 内部的冗余，并且不用执行评测（evaluation-free）。本文压缩的是整个 library 里跨 skill 的重复结构，目标是检索和 context 交付，ReZip 还会用执行 trace 修订 macro。三篇只是名字撞车，共同点只有"压缩要保 contract，不保字面"这一个主张。
- **Rating**: `2` 👀 ，"contract 校验必须进压缩"这组对照实验值得照搬，但标题里的 graph compression 只贡献约 2.3 点且没给 CI，scalable 的证据靠合成 distractor 和弱 baseline。

### AgenticArtifactCreation
- **Title**: Agentic Artifact Creation: Systems, Evaluation, Principles, and Opportunities
- **Institutes**: The Hong Kong University of Science and Technology (Guangzhou), Zhejiang University, University of Science and Technology of China, Tsinghua University, The University of Hong Kong, The University of Sydney, Sun Yat-sen University
- **Source**: [link](https://arxiv.org/abs/2608.28122)  📄 arXiv   **📒 论文笔记**: [[2608-AgenticArtifactCreation]]
- **核心**: 这是一篇 survey，分析单位是"交付物"（海报、幻灯片、代码库、3D 场景等），把 agentic artifact creation 定义为一种有状态的构建过程：系统跨步骤携带状态，并且至少有一次中间观测改变了后续动作。作者用 Operational Representation / Construction Policy / Runtime Verification 三个角色，编码了截至 2026-08-20 的 230 个系统和 29 个 benchmark。核心论点是：构建难不难，不取决于模态，取决于决策耦合度、失败可观测性和可修复性；诊断粒度必须和编辑接口粒度对齐。全文自己产出的定量数据只有两份。一是 Table 4 的 18 个代表协议里，只有 3 个评测了任务能力之外的系统属性（Mr. Dre、AuthorBench 测 Controllability，AgenticVBench 测 Reliability），Robustness、Efficiency、Update Stability 无一覆盖。二是一份 Design Arena 单日快照，显示 agent 排名高度依赖任务。
- **锐评**:
  - 框架里最值钱的一条判断是"精细诊断配上只能整体重生成的接口，等于没有局部修复能力"，可以直接当设计检查项。§6 把评测分成 artifact / trajectory / system 三层，每个系统属性绑定一种对照设计（reliability 要固定条件重复跑，update stability 要版本化重跑），比大多数 benchmark 论文的评测自觉强。拿它去审 GUI/CUA benchmark 只报单一平均成功率的做法，正好用得上。
  - 最大的硬伤：手上有 230 个编码好的系统，却没做一次跨语料统计。摘要里"learned judge 与生成器共享盲点时增益有限""分解会增加重组成本"这类强论断，完全靠引用文献加定性综合（C22），本文没有测。比如有多少系统用同源模型做 verifier，这个数本来数一下就有，作者没数。
  - "只有 3 个协议"这个最硬的数字，来自按影响力挑出的 18 行代表集，不是 29 个 benchmark 的全量统计。作者自己也写了这张表"支持比较，不支持频率估计"，但摘要的措辞很容易被读成整个领域的现状，引用时必须带上这个边界。
  - novelty 的边界要收窄：本文确实是 Table 1 里唯一以 Delivered Artifact 为主视角的 survey，但"construction state + feedback control 作为核心轴"并不是它独有的，Xu et al. [287] 已经把这两者标为 central axis（Ledger C10 标为 contradicted）。所以真正的增量只是"以交付物为单位做跨模态比较"这一个视角。
  - 可复现性差：各数据库的查询导出、分源产出量都没保留；259 条记录里只有 120 条已发表；正文写"截至 08-20"，Fig. 2 又出现"08-28 accounting update"，说明筛选口径后期还在变。
  - Design Arena 那段基本没有信息量。它把 Elo 名次换算成百分位，名次差被放大（Kimi K3 在 native Android 跌到 54.3，GPT-5.6 Sol 从 87.5 掉到 34.2），而且只是 2026-08-19 一天的快照。拿它论证"总排名会掩盖任务差异"属于常识，算不上发现。
  - taxonomy 叠得太多层：6 family × 16 profile × 6 应用场景 × 三角色各 3-4 个子类，归类靠判例；13 条视频记录归不进任何 profile，Spoken Audio 一个系统都没有。它只能当一套检查维度来用，不是能被证伪的分类。原则 4（Revalidate）作者自己也承认证据稀疏，§8 全部标为 hypotheses。
  - 对 GUI Agent 方向来说相关性是间接的：Behavioral family 讲的是"生成 UI/网页"，不是"操作 GUI"。能迁移过来的只有 §6 的三层评测框架和 §8.2 的同源 verifier 盲点问题。
- **Rating**: `2` 👀 ，"诊断粒度和编辑接口对齐"加上三层评测框架，可以直接拿去审 CUA verifier 和 benchmark 的 claim；但全文没有一条自己测出来的跨语料统计，最硬的数字也只来自一张 18 行的挑选样本，够不上 Foundation。
